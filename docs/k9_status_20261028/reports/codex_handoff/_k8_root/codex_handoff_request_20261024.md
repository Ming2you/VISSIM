너가 만든 SDMPC 버전 가운데 "RM(램프 미터) + TSC(도시 신호 제어)만으로 약 8 % 개선"을 보인 판을 다른 작업자(Claude)에게 인계하려고 해. Claude는 이 판을 독립적으로 다시 돌려 숫자를 확인한 뒤, VSL을 최적화 대상으로 켜는 수정을 맡을 거야. 아래 항목을 빠짐없이 모아서 넘겨줘. 모르는 것은 추측하지 말고 "모름"으로 적어 줘. 문장마다 [측정](직접 돌리거나 센 것) / [읽음](코드·파일에서 확인) / [추정] 중 하나를 붙여 줘.

## 1. "약 8 %"의 정체 (가장 먼저)
- 그 숫자를 낸 런 전부의 목록: 런 폴더 절대 경로, 시작·끝 시각, 커밋(전체 sha)과 비커밋 수정 여부, 시드, 시뮬 길이.
- 무엇의 8 % 인지: 지표 이름과 정확한 정의(링크 집합 또는 Ω 링크 목록, 미삽입 대기 포함 여부, 시간 구간), 기준선(무엇 대비인지), 같은 시드 짝 비교인지, 시드별 값과 평균.
- 그 런에서 VSL이 정말 꺼져 있었는지(VSL 명령 기록으로), 미터와 도시 신호가 실제로 움직였는지(결정별 녹색 값 기록으로).
- 같은 런의 대가: Ω 밖 대기, 입력별 미삽입 대기(특히 1098 FW_E 입구, 1099 FW_W 입구), 램프 대기, 망 전체 TTT + 미삽입.

## 2. 코드
- 그 판의 브랜치/커밋 전체 sha. 비커밋 수정이 있으면 diff 파일 그대로. 실행에 쓴 트리(동결본)가 있으면 그 경로와 파일 목록 sha.
- 제어기·plant·러너·평가 스크립트 전부. 실행 명령줄 그대로(인자 포함), 환경 변수, 파이썬 버전과 패키지 목록(pip freeze), VISSIM 버전.
- 미터 결정 경로: 이웃 검사(sdmpc_meter_neighbor_audit 같은 장치)의 설정값과 코드 위치, 녹색 0 금지·저장 보호(guard) 규칙, 램프 서비스 표(녹색별 대/주기/차로), 리더 예산 후보 수.
- 도시 신호(TSC) 쪽 제어 방식과 설정.
- VSL 쪽: 지금 VSL이 어떻게 정해지는지(고정 시간창인지, 최적화인지), 표지판 위치(DSD 번호), 허용 속도 집합, VSL을 최적화로 켜려면 어디를 바꿔야 한다고 보는지.

## 3. 설정·망·수요
- 설정 파일 전부(바이트 그대로) + sha256. 런에 실제로 들어간 설정과 git 판이 다르면 둘 다.
- 망 .inpx sha256. 64cf 망인지, 다른 망인지. 차량 입력 34개의 시간대별 수요표(특히 1099가 1098 ÷ 0.8 인지).
- 고속도로 희망속도 분포(DSD 110 등) 정의.
- plant 매니페스트(셀별 합류 항 δ_merge, expanded036 계수 등)와 그 값의 출처.
- Ω(목적 영역) 링크 목록(Ω701 등).
- 혹시 우리 기준 망 v3c3(sha 3de889f0257d998bed50611f798ea388bcf69396dbc40e5726b1e88ebdd31c2e, 1099 수요 4300/5600/6000/5200/3900/3450 veh/h)에서 돌린 런이 있으면 그것도.

## 4. 런 원자료 (8 % 런 + 짝 기준선 런 모두)
- 결정별 JSON·action CSV·영수증, 러너 로그, 신호·미터·VSL 읽기값(readback), .err, run 기록(run.json, provenance).
- VISSIM 출력: 차량 궤적 FZP, 링크 평가, 노드 평가, 네트워크 성능(차량 입력별 미삽입 포함).
- 짝 무제어(no-control) 런: 같은 망·같은 시드·같은 수요. 900 s 이전 궤적이 같은지 확인한 기록이 있으면 같이.

## 5. 몫을 가르는 런
- RM만 / TSC만 / RM+TSC / VSL만 / 이웃 검사만 끈 런 등, 효과를 나눠 본 런이 있으면 전부(1·4번과 같은 꼴로).
- 시드가 여러 개면 전부. 단 아래 10번의 봉인 시드는 빼 줘.

## 6. 우리 지표로도 계산해 줘 (가능하면)
- FW_E 본선 7링크: 74 · 10699 · 2 · 10613 · 119 · 10702 · 24 의 veh·h.
- 국소 19링크: 위 7 + 진입 커넥터 10484·10490·10639·10681 + 진출 커넥터 10481·10483·10643·10682 + 진입 접근로 129·31·68·70.
- 망 전체 TTT + 미삽입 대기, 입력 1098·1099 미삽입 대기, Ω와 Ω 밖 대기.
- 각 값은 시드별, 기준선 대비 차이와 %, 계산 스크립트와 sha.

## 7. 알려진 문제와 실패
- 실패하거나 멈춘 런(예: 서측 10480 적색 → 역류로 중단된 런), 그 원인 진단.
- 알고 있는 모형 결함(예: 경계 movement 용량 206.53 계열, 분할 사전값, 공유 링크 129·70 결합 등)과 고쳤는지 여부.
- 보고한 숫자 가운데 나중에 바뀌거나 철회한 것.
