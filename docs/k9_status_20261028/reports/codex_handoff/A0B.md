## 5. A1 에 주는 뜻 [추론]

- PRE_A1 r2 U9 의 읽는 법(`a0/PRE_A1.md:59`)을 이 결과에 놓으면:
  - A0 env_hsw T=900 과 A0b T=1050 은 기록 명령과 바이트 같았습니다 [실행]. 그래서 A1 이 같은 env·같은 코드로 돌고 VISSIM 이 같은 명령에 같은 상태를 내면, A1 의 1050·1200 결정 입력은 기록과 같아집니다.
  - 그러면 A1 은 **T=1200 에서 처음 기록과 갈라질 것**으로 봅니다. 그 차는 이번 재생과 같은 꼴(RM_C10646 720 대 540 veh/h, SC1004 offset +0.695 s 등)이어야 합니다. 이 PC 안에서 같은 입력이면 결정이 비트 단위로 같았기 때문입니다(A0_PROFILE §3, 재생 7쌍).
  - A1 이 1200 보다 앞에서 갈라지면: 실행 설정·관측 차(관측 checkpoint, readback 파일, 러너 환경 등)를 먼저 봅니다.
  - A1 이 1200 에서 갈라지지 않거나 다른 꼴로 갈라지면: A0b 입력 재구성 차(관측 checkpoint 없음, readback·mer_index 는 런 끝 판)를 먼저 봅니다.
- 1200 뒤로는 A1 의 VISSIM 상태가 기록과 달라지므로, A1 의 1350 이후 결정을 A0b 의 같은 T 와 직접 맞대는 것은 뜻이 약합니다. A0b 는 "기록 상태에서 결정했을 때" 의 차만 보여 줍니다.
- 기록 상태에서 다시 계산해도 11개 중 8개가 명령이 달랐고, 그중 2개(1200·1350)는 이산 명령(미터 단계)이 달랐습니다 [실행]. 그래서 A1 궤적은 1200 뒤 기록과 점점 멀어질 것으로 봅니다. 그 크기가 교통 지표에서 얼마인지는 이 단계에서 모릅니다.
