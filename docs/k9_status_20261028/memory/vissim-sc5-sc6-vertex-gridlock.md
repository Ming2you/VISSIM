## 아직 모르는 것

기준이 왜 이 래칫을 피하는지 모른다. 기준(w_F=3 · cap끔 · lambda켬)만 좋은 체제이고
지금까지 시도한 **네 섭동이 전부** 나쁜 체제로 간다 — 방향이 반대인 것들(램프 전개방 vs 폐쇄,
본선보호 제거 vs 유지)도 마찬가지다. 기준이 좁은 최적점인지, 아니면 나쁜 쪽이 자연 끌개이고
기준이 우연히 벗어나 있는지 미판정.

## 근본 원인 — SC5 서측 접근로가 관측에서 실명이다 (2026-09-05)

SC5 국소 모형의 q0 를 t=4500(C 팔)에서 직접 찍었다.

```
SC5_W_SC101_to_E_SC6      p3   origin SC101_to_SC5    q0 = 0.00
SC5_W_SC101_to_N_SC102    p4   origin SC101_to_SC5    q0 = 0.00
SC5_W_SC101_to_S_SC11     p3   origin SC101_to_SC5    q0 = 0.00
같은 시각 VISSIM 링크 1210014303 (SC101_to_SC5) = **185대, 전량 정지**
```

현시별 q0 합: p1 290.9 · p2 373.1 · p3 138.2 · p4 97.8 — **SC101 몫이 통째로 빠져 있다.**
그래서 p3/p4 가 싸 보이고 green_min 으로 깎이며, 실제 그 접근로가 잠긴다.

### 매핑 두 표가 서로 다른 답을 낸다

```
link_to_origins   [1210014303] = ['SC101_to_SC5']
link_to_movements [1210014303] = SC5_N_SC102_to_E_SC6 · SC5_S_SC11_to_W_SC101 · SC5_S_to_W_SC101
                                 (src = signal_head_phase_axis)
SC5_W_SC101_to_* 는 [265, 1220014303] 에서만 받는데 그 링크들은 C 런 관측집합에 없거나 ~0 이다
                                 (기준 6.6 / 1.7)
```
**한 자리 차이의 두 링크 121_0014303 · 122_0014303 가 갈린다.** origin 표는 둘 다 SC101_to_SC5 로
보는데 movement 표는 전자를 SC102/SC11 것으로 보낸다.

이건 [[vissim-ew-axis-observation-blind]] 와 **같은 부류**다 — "검지 매핑이 접근로를 못 봐
p3·p4 가 영구히 큐 0 → 컨트롤러가 그 축을 green_min 으로 굶는다". 2026-08-22 에 동서축을
고쳤는데 SC5 서측이 남아 있었다.

### 가격은 범인이 아니라 피해자다

부호 규약은 `cost += weight * g_ext * (p1 - ref)` (최소화)라 **g_ext > 0 이면 p1 을 내리라는 뜻**이다.

```
팔          SC5 녹색                 b2(SC5)    lambda_P
기준        51.5/28.1/38.4/20.0      0.0009      3.08
C          78.0/20.0/20.0/20.0      0.1114      9.23
G lambda=0 70.0/22.7/22.7/22.7      0.0350      0.00
objbase    78.0/20.0/20.0/20.0      0.1111      3.85
```
나쁜 팔의 b2 +0.11 은 전 신호 최댓값(0.0967)보다 크고 방향은 "p1 을 줄여라"인데 p1 이 상한으로
간다. lambda 를 꺼도 마찬가지다. 즉 **국소TTS 가 가격을 이긴다.** 가격을 현시벡터로 바꿔도
이 자리는 안 고쳐진다 — 국소 모형이 보는 큐가 틀렸기 때문이다.
