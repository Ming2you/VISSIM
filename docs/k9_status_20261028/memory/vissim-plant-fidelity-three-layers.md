2026-08-15 실측. **"plant 가 VISSIM 을 재현한다" 는 해상도를 밝히지 않으면 참이 아니다.**

MPC horizon(3스텝=180초) 기준, no-control 부모런 9셀:

```
망 전체 집계        13.2%  (집계 스케일 보정 후 3.0%)
고속 세그먼트 16개  15.5%  (속도는 6.1%)
도시 구간 119통     51.7%  G5 통과율 29%
```

**집계가 맞는 것은 링크별 오차가 상쇄되기 때문이다.** 집계 보정으로 3% 를 만들어도
구간 하나하나는 50% 틀린다. 심사에서는 세 층을 같이 보고해야 한다.

임계는 저장소가 이미 쓰는 G5 기준(`max(5 veh, 0.10 × 관측)`)을 쓴다 — 새 목표를 만들지 마라.

## 구간 오차의 원인 — 투영이 in-transit 예약을 잃는다

`traffic_state_from_vissim` 이 저류 **점유량만** 싣고 `urban_storage_release_buffer` 를
비워 둔다. 그 버퍼는 plant 내부(`urban_queue_model.py:578-579, :1162-1163`)에서만 채워지고
어댑터는 안 채운다. 그런데 방출이 전적으로 그 버퍼에 물려 있다.

```
내부 링크   버퍼가 비면 영원히 안 빠진다   -> 유입만 쌓여 +114~208%
sink(_out)  버퍼가 비면 전량 즉시 방출     -> 정확히 -100%
```

증거: 스텝 0(초기상태) **0.0%** → 스텝 1(60초) **54.8%** → 그 뒤 평평. 총량은 보존된다.

**어댑터는 결정마다 상태를 다시 짓는다** — 지금까지 모든 제어 결정이 이 상태였다.

## 기각한 가설 셋 (다시 시도하지 마라)

1. 장부 내부 재분류 artifact — 보존 단위로 재도 안 준다(54.9% 대 51.0%)
2. 용량 하한 10.0 — 하한 23통 중 jam168 로 회복하는 건 6개뿐, 링크 없는 통 0개
3. 용량이 29% 작아 투영이 버린다 — jam168 로 덮어써도 −29.4% → −29.1%

## warm-start 가 우리 버그분을 걷어낸다

버퍼를 손으로 지으면 유출만 복원돼 **더 나빠진다**(−37.4%). plant 가 짓게 해야 한다.
런타임엔 과거 관측이 없으므로 **현재 관측에서 W 초 굴려 스케줄만 짓고 점유량은
관측값으로 되돌린다**(스케줄은 같은 비율로 축소).

```
기준선            51.7%  G5 29.2%  부호 −25.8%
self warm 900     42.9%  G5 38.8%  부호  −6.7%
```

어댑터에 `RW_WARMSTART_SEC`(기본 0=꺼짐)으로 들어 있다. 비용은 결정당 ~3초.

남는 ~43% 는 실재하는 동역학 오차다.
