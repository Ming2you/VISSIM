**2026-08-26 전면 개정. 이전 판("사영 한 줄에서 N_P 가 소거된다")은 진단 키 오독이었다.**
그 오독 때문에 나는 이 질문에서 세 번 입장을 바꿨다. 아래가 실측으로 확정된 것이다.

## 먼저 — 이름이 거짓말하는 진단 키

`wu_faithful_follower.py:4747-4754`:
```python
realizable_veh = float(sum_nin)
control.diagnostics["wu_faithful_np_realized_sum_nin_veh"] = realizable_veh
control.diagnostics["wu_faithful_np_feasible_min_veh"]     = realizable_veh   # 같은 값
control.diagnostics["wu_faithful_np_feasible_max_veh"]     = realizable_veh   # 같은 값
```
**`feasible_min/max` 는 밴드가 아니다.** 실현값 하나를 세 키에 쓴 항등식이라 항상 min==max 다.
주석(:4734)이 일부러 그렇게 한다고 적어 뒀다. 같은 자리의 `projected_veh =
min(max(n_p_star, realizable), realizable)` 도 **진단 전용**이고 제어 경로가 아니다.

**진짜 밴드 `_np_feasible_range` 는 살아 있고 넓다** — 실측 [773.7, 1368.9](폭 595) ·
[649.6, 1029.8] · [601.6, 963.5]. 박스도 밴드도 점이 아니다.

## 진짜 사슬 (실측 24~33결정)

```
(1) 리더 목적함수가 N_P 에 평평       1위-2위 / 목적함수 = 2.7e-06
    -> n_p_star 가 둘 중 하나로만 간다: **상자 바닥(-250) 14결정 · Σnin 그대로 9결정**
(2) 바닥 < 실현가능 최소(535~958)     -> pd_target 이 pd_min 으로 클램프 -> 잔차 O(100~500)
(3) gain_pd = lambda_np_step_gain(0.01) x np_pd_gain_mult(25) = **0.25**
    -> lambda = clip(0 + 0.25 x 잔차, 0, cap) -> **언제나 cap**
    -> λ 분포 {0: 18, 10: 14, 7.2: 1} 순수 bang-bang
(4) cap 이 포화 구간이면 λ 값 자체가 무의미
```

## 무엇을 고치면 무엇이 움직이나 (전부 리플레이 실측)

| 수정 | λ | Σnin | 커밋 레버 |
|---|---|---|---|
| 없음(base) | 10.00 | 956.07 | — |
| 상자만 상태의존(`npband`) | 10.00 | 956.07 | **0/91** |
| gain 수정 cap 0.5 | **0.50** | 956.07 | 0/91 |
| gain 수정 cap 0.01~0.05 | 0.01~0.05 | **975.80** | **13/91** |
| gain 수정 cap 0.1 | 0.10 | 956.07 | 0/91 |

**gain 이 축이다.** cap 은 반응 구간 안이어야 한다 — **포화 문턱이 0.05~0.1 사이**다.
cap 0.5 와 10 은 둘 다 포화라 같은 답이고, 첫 시도에서 상단을 골라 헛돌았다.

**상자 수정만으로는 아무것도 안 바뀐다** — 밴드를 먹여도 리더가 밴드 **바닥**을 고르므로
(목적함수가 평평해서) 잔차가 그대로다. (1)이 살아 있는 한 (2)를 고쳐도 무효다.

## 배선이 빠진 자리 둘 (고칠 수 있는 것)

1. **`leader.py:661` `_np_candidate_bounds(self, state)`** 가 `state` 를 받아 놓고 안 쓴다.
   독스트링은 상태로 제한한다는데 본문은 정적 `N_P_star_range` 를 그대로 돌려준다.
   -> `install_np_state_band`(어댑터 사본 `..._npband_20260826.py`)가 `decide_with_info` 를
   감싸 `_np_feasible_range` 를 먹인다. 작동은 하나 위 표대로 **단독으로는 무효**.
2. **`dual_step_c`(:441)·`_measure_dual_gain`(:3996) 이 죽은 코드다** — 소비처/호출부 0곳.
   독스트링은 α = dual_step_c·cost_norm/max(G,G_floor) 라는 뉴턴 스텝을 적어 뒀다.
   게다가 켰어도 안 됐다: 탐침점 `lambda_hi = cost_scale/(nin_scale**2)` = **0.00071** 인데
   거기서 Σnin 이 안 움직여 G=0 -> 스텝 보류. `nin_scale` 이 한 번 더 곱해진 차원 오류로
   보이고, 한 번만이면 0.125 로 측정된 반응 구간 한복판이다.

## Σnin 의 λ 응답 (오프라인 실측, 3결정)

```
t=002250  λ=0 →1346 · 0.01→1281 · 0.02→1218 · 0.05→929 · 0.25→774(포화)
t=003600  λ=0 →1019 · 0.02→1002 · 0.05→995 · 0.1→830 · 0.25→659 · 0.5→650(포화)
t=004800  λ=0 → 964 · 0.02→ 964 · 0.05→795 · 0.1→649 · 0.5→607(포화)
```
거래구간 λ ≈ 0.01~0.1. 필요한 gain ≈ 1.2e-4 (잔차 O(400) 기준). 현행 0.25 는 **2,000배**다.

**Why:** [[vissim-lever-activation-roadmap]] 의 리더 레버가 전부 무력했던 이유가 (3)이다.
offset·metering·VSL 은 리더 층이고 λ 가 포화면 어느 N_P* 든 같은 팔로워 응답이 나온다.

**How to apply:** 듀얼을 살리려면 **gain 부터**다(`urban.dual.lambda_gain`, cap 은 0.01~0.05).
상자(`urban.leader_np.state_band`)는 그 위에 얹는다. 남은 벽은 (1) 리더 목적함수의 평평함이고,
그것은 스케일·상자가 아니라 설계 문제다 — λ 가 포화를 벗어나면 같이 풀릴 가능성이 있으므로
gain 팔의 `leader_candidate_objective_gap` 을 반드시 같이 봐라.

**N_UF 는 다른 방식으로 죽었다:** 전달은 정상(의도-실현 상관 0.998)인데
`leader_lambda_uf_committed = 0` 이 33/33 이라 듀얼 값 자체가 없다.

## 2026-08-26 실런 판정 — **기구를 고쳐도 TTT 는 안 는다**

gain 을 고쳐 λ 가 포화를 벗어나게 한 뒤 VISSIM 으로 실측했다.

```
tau_20260826       4688.4   -119.7      (참고: τ 팔이 현 최선)
dualg0p02          4721.2    -86.9      default 대비 **-2.7**   잡음 수준
default_20260825   4723.9    -84.2
dualg0p1           4785.4    -22.7      default 대비 **+61.5**  명백히 악화
nocontrol_s13      4808.1     +0.0
```

**기구는 설계대로 작동한다** — 팔 증거가 디스크에 있다:
```
                λ 분포                     Σnin 중앙   리더 상대차 중앙
default     {0: 18, 10: 14, 7.2: 1}        863.9      8.66e-07
dualg0p02   {0: 12, **0.02: 25**}          814.4      8.40e-07
dualg0p1    {0: 16, **0.1: 21}**           838.5      8.08e-07
```
λ 가 의도한 값에서 25/37 결정 발화하고 Σnin 이 863.9 -> 814.4 로 실제로 움직인다.
그런데 TTT 가 안 는다.

**그리고 "λ 가 포화를 벗어나면 리더 목적함수도 풀릴 것" 이라는 예측은 반증됐다** —
상대차가 세 팔 전부 **8e-7 로 동일**하다.

## 결론

**벽은 (1) 리더 목적함수의 평평함이다.** 전달(gain)을 고쳐도 **목표가 임의**이므로
그 임의 목표를 더 충실히 추종할 뿐이고, λ=0.1 에서는 오히려 해롭다(+61.5).

즉 듀얼 스케일·상자는 둘 다 **닫힌 문제**다:
- 상자(`npband`) — gain 위에서도 커밋 레버가 완전히 동일. 실런 안 함.
- 스케일(`dualg*`) — 실런했고 TTT 무변 또는 악화.

**How to apply:** 듀얼 쪽 추가 튜닝은 하지 마라. 남은 것은 리더 목적함수가 왜 N_P 후보를
못 가르는지이고, 그건 스케일·상자가 아니라 **목적함수 설계**다. 사본
`..._npband_20260826.py`(스위치 둘 다 보유)와 config 들은 그 설계를 고친 뒤 다시 쓰려고 남겨 둔다.
