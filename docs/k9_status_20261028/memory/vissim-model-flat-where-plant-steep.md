```
150초 구간 도시재차 Δ    중앙   최대(전부 t=900 워밍업 전환)   p90
```

꾸준한 누적이지 폭발이 아니다. 컨트롤러가 여러 번 본다. 예측도 궤적을 잘 따라간다.

**전개방 팔(미터 변화 0)도 졌으므로** 미터 슬루는 증상이다.

## ③ 잘못된 것을 보나 — 관측은 맞고, **행동 민감도가 평평하다**

관측·예측은 좋다: 1스텝 예측 r 0.99, 롤아웃 TTT 대 실현 450초 TTT r 0.96.
(주의: `prediction.state_summary.urban_total_veh`(4971)는 CSV `urban_vehicles`(3268)와
다른 양이다 — movement 큐+링크 점유+경계 큐 합. 편의 비교에 쓰지 마라.)

**결정적 검정 ③D** — C 팔 결정에서 국소 모형이 SC5 배분 후보를 어떻게 매기나:
```
t=2400  q0 p1 194 · p2 344 · p3 130 · p4 91
   꼭짓점(커밋 78/20/20/20)   88.937   <- 최소
   기준형(51/28/38/20)        89.417   (+0.5%)
   p3 몰아                    90.204
   균등                       90.752
   p2 몰아                    92.279   (+3.8%)
```
**후보 전체가 3.8% 안에 있고, 꼭짓점과 기준형은 0.5% 차이다.** 그런데 plant 는:

**③C** — SC5 p2+p3+p4 녹색을 늘렸을 때 다음 구간 접근로 큐가 줄어든 비율
```
기준       4/15  (상관 +0.25 — 큐가 없어 무의미)
C          6/6   (상관 -0.62)
blindfix   5/6   (상관 -0.57)
```
**레버는 먹힌다.** 나쁜 팔에서 p2-p4 에 녹색을 주면 큐가 준다. 모형만 그걸 못 본다.

## 통합 진단

모형이 평평한 곳에서 plant 가 가파르다. 국소비용이 후보를 0.5% 안에서 못 가르니
**가격항·수치 잡음 수준의 차이가 argmin 을 정한다.** 그래서

- 서로 무관한 아홉 섭동(cap·lambda·N_UF·w_F·램프국소·in_gne·blindfix)이 전부 같은 나쁜
  체제로 간다 — 평평한 면 위에서 어느 쪽으로 밀든 꼭짓점 하나로 굴러떨어진다
- 기준(7829)이 홀로 좋은 건 우연히 다른 꼭짓점(51/28/38/20 쪽)에 앉아서다
- blindfix 로 q0 를 고쳐도 소용없다 — q0 가 바뀌어도 비용 곡면이 평평한 건 그대로

**고칠 곳은 관측이 아니라 국소 모형의 방류 민감도다.** p2 에 344대가 있는데 p2 를 78초로
열어도 비용이 3.8% 밖에 안 내려간다는 건 방류 용량이나 s_eff 가 그 큐를 못 빼는 것으로
잡혀 있다는 뜻이다. [[vissim-price-local-term-drain]] 의 용량 과대와 반대 방향으로,
phased 국소 모형의 방류가 **과소**인지 봐야 한다.

관련: [[vissim-sc5-sc6-vertex-gridlock]] [[vissim-approach-blind-audit-20260905]]
[[vissim-phase-price-surrogate-leak]] [[vissim-flat-local-cost-vertex]]

## 평평한 이유 확정 — 방류용량이 물리 포화의 1/9 (2026-09-05)

사용자 가설 "하류 수용 제약이 없어서" 는 **반대**였다. 모형·plant 모두 SC5 하류는 비어 있다
(모형 점유 0~4, s_eff 만석 / 실측 진출 159). 문제는 **방류율**이다.

```
SC5 p2 movement cap_flow        207 x 3 = 620 veh/h
  78초 녹색 x 0.125h 로 뺄 수 있는 대수   40 대   (큐 344)
  p1 1859 -> 121 대 · p3 2065 -> 134 대
per_lane                        206.531   (install_movement_capacity_by_lanes, equivalent_uniform 330 정규화)
실측 포화 산출물 (SC5 SBT, 링크 1220019201)   3600 veh/h  = 2차로 x 1800
어댑터 주석 실측 예             SC6 1220021201 실측 7,912 vs 모델 1,320 (6배)
```

p2 용량 배율별 SC5 argmin (C 팔 t=2400, 오프라인):
```
x1  꼭짓점    (커밋 그대로)
x2  기준형    -0.8%
x4  기준형    -3.6%
x9  p2몰아    -17.1%   <- 물리 포화면 큐 344 를 빼는 게 압도적으로 좋다
```

**206.5 는 포화가 아니라 실현유량 중앙값이다.** `derive_measured_saturation.py`(2026-08-22)가 이미
같은 진단을 적었다 — "대부분의 주기는 수요제약이라 평균·중앙값을 쓰면 용량이 아니라 수요를
재게 된다" — 그리고 `max(실측, 차로수x1800)` 산출물(`outputs/movement_saturation_measured_20260822.json`,
90 차로군)까지 만들었다. **그런데 게이트 `urban.capacity.measured` 가 config 에 없어 한 번도 안 돌았다**
([[vissim-gate-outside-config-is-dead]] 여섯 번째 사례). 산출물의 observed_top 은 90개 전부 0 이라
사실상 기하값(lanes x 1800)이다.

온라인 갱신은 `value = max(obs, decay x prev_or_seed)` (decay 0.98). 바닥이 없어 정체 중 obs=0 이면
결정당 2% 씩 감쇠한다. `seed=plant`(207)는 나쁜 체제에서 obs 가 0 이라 사실상 무효. **`seed=geometric`
(3600) 이 진짜 검정**이고 30결정 감쇠 후에도 1980 > 현행 413 이다.

팔: `arm_satcap_plant_20260905` · `arm_satcap_geo_20260905` (둘 다 verify PASS, 미실행).

세 가설 최종: ① 전파속도 X ② 슬루 X ③ 관측 X — **모형의 방류 민감도**가 물리의 1/9 라
후보를 못 가른다. 기준이 홀로 좋은 건 SC5 큐가 155 를 안 넘어 그 평평함이 안 물었기 때문이다.
