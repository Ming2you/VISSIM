## 고정된 네트워크와 실제 실험

기준은 사용자가 직접 수정한 망이며, 동측 본선 입력 1098만 0.8배로 줄였다. 과거의 고속도로 전체 80%·도시 50% 조건이 아니다. seed 13 기준 입력 파일은 `diagnostics/demand_sweep/user_native_20260914/east080_v1/prepared/network/baseline.inpx`이고 SHA-256은 `3795b346d7eafbbdf47ede0673050c12a4dcea2e40bca7abc085abf71381d65c`이다. seed 13·17의 9000초 결과를 보존했다.

`native_fixed_profile_v3`의 무제어·VSL·RM·동시 제어 4조건은 모두 2250초까지 완료했다. 0–1350초는 같은 native 조건, 1350–2250초는 고정된 진단 명령이다. 모든 조건의 1350초까지 FZP가 정확히 일치한다. 무제어의 2250초 전체도 기존 9000초 무제어의 앞 8,152,944개 데이터 행 및 144개 SG의 native LDP와 일치했다.

`SimPeriod=9001`을 유지하고 `SimBreak=2250`으로 끝내야 한다. 앞선 v2는 SimPeriod를 2251로 단축해 2231초부터 기준 궤적과 달라졌으며, 실패 기록을 보존했다. 새 실행에서는 이 차이를 되풀이하지 않는다.

실제 개입은 VSL 분포 59–62와 램프 connector 10490(SC 9107/SG 1)뿐이다. VSL은 1350/1500/1800/1950초에 분포 ID 100/80/100/120을 적용했다. ID는 차량 모두의 일정 속도를 뜻하지 않는다. RM은 10초 주기, 황색 없는 적색·녹색이며 1350/1500/1650/1800/1950/2100초에 녹색 8/6/4/6/8/10초를 적용했다. 진단 개입이며 full follower game의 실행 가능성을 입증한 결과가 아니다.

신호는 명령 적용 시 readback과 native LDP로 검증했다. LSA 누락 때문에 사용자가 LDP를 대체 기준으로 허용했다. 무제어의 native OFF를 임의로 GREEN 또는 검증된 g10과 동일하다고 해석하지 않는다.

RM이 실제 합류량과 동측 본선 체류시간을 줄인 것은 확인했다. RM의 동측 본선 TTT는 197.2308→193.3385 veh·h, 해당 램프 TTT는 2.7475→5.4264 veh·h였다. 그러나 Ω 전체 개선은 없었다. 단일 seed의 작은 비용 차이로 정책의 우열을 확정하지 않는다.

삭제·미확인 소실·미삽입이 남는다. 해당 구간 Ω 내부 미확인 소실은 조건 순서대로 72/65/62/52대, native 삭제 경고는 12/18/12/6건이며 서로 겹칠 수 있어 합산하지 않는다. 실행 종료까지 미삽입은 11151/11121/11138/11157대다. 이들을 TTD로 세지 않았다. Ω 재고 수지가 손실 없이 닫혔다고 주장하면 안 된다.

## 정본에 반영한 것과 모델의 한계

- 21개 셀의 실제 길이·차로 수를 맞췄다. 동측 4→3 차로 위치는 6841.743m로, 이전 경계보다 약 166m 하류다.
- 진출 connector의 진입·배수·이동 지연·유한 저장을 보존식으로 계산한다. 관측 재고로 예측 중간 상태를 계속 덮어쓰지 않는다.
- 기존 FD 계열을 유지하면서 seed 13으로 동역학 계수를 보정했다. seed 17은 이미 여러 번 본 개발 검증 자료이며 독립 holdout으로 부르지 않는다. 576개 방향별 450초 예측 기록에서 수치 검사는 통과했지만 E14의 저속 상태는 seed 17에서도 7/7건 놓쳤다. 속도 RMSE의 일부 감소와 달리 TTT 오차는 커졌다.
- VSL zone head가 실제 셀 10–12에만 작용하도록 맞췄다. 이전에는 셀 14까지 작용했다.
- 10490의 정지선은 272.603559m, 링크 길이는 279.032130m로 정지선 이후 공간은 약 6.43m다. 기존 10초 램프 계산의 점 대기열 문제를 진단하고, 램프 내부만 1초로 계산하도록 했다. 본선 METANET은 10초이며 계수·서비스 표는 재보정하지 않았다.
- no-option/10초 과거 결과의 수치 동일성과 새 1초 계산의 보존·저장·서비스 예산을 검증했다. 관련 24개 검사와 기본 파라미터 검사 PASS를 기록했다.

`native_response_v1`은 10초 램프 계산의 실패 근거로, `native_response_v2`는 수정 후 16개 예측 창과 동결 소스 묶음으로 보존했다. 첫 1350초 시작 450초 history 예측에서 무제어/RM 합류는 109.53/95.43대, 실제는 93/76대였다. 감소량 방향은 맞지만 절대량과 대기 비용을 정확히 설명하지 못한다. 미래 경계를 실제 값으로 준 조건부 진단에서는 92.40/83.66대이며, 이를 온라인 예측 정확도로 보고하면 안 된다.

예측 비용은 본선 셀+8개 진출 connector+10490 램프의 부분 영역이다. Ω 전체 TTT와 직접 섞지 않는다. 그 부분 영역에서도 RM 비용 차이를 모델은 거의 0으로 계산하고 후속 창에서는 부호 오류가 남는다. 10490의 본선 수용량 조회 720개가 모두 1800 veh/h이며 한 번도 결합 제약이 되지 않았다. 기하·수치 검사의 PASS는 제어 응답의 정확도 PASS가 아니다.

**새 물리 기하에서 full GNE local follower kernel의 가변 셀 길이 지원은 미완료다. 코드가 명시적으로 차단한다.** 이번 컴포넌트 실험을 통합 controller의 실행 완료로 표현하지 않는다. 기존 N_UF와 450초 합류량 허용오차를 이 단독 RM 실험의 조건으로 바꾸지 않는다.

주요 구현은 `evaluation/controllers/freeway_geometry.py`, `physical_ramp_boundary.py`, 기존 adapter/accounting/link predictor, `metanet_calibration_v1/canonical_harness.py`, `metanet_terms_implementation_v2/evaluate_native_response.py`에 있다. 실행은 기존 `fast_nc_run.ps1`·`fast_nc_runner.vbs`를 수정해 재사용했다.

## 이어서 할 일

1. 이미 완료된 4조건과 동일 초기 상태를 재사용해 목적지별 램프 도착, 정지선에서 실제 출발 가능한 차량, 본선 합류 수용량을 분리한다. 전체 램프 재고를 곧바로 서비스 가능한 큐로 취급하지 않는다.
2. 10490의 720개 수용량 계산이 모두 상한인 원인과 본선·진출 병목의 공유 여부를 검토한다. 출발지연과 차로 접근을 구분하고, 큐가 길면 서비스가 무조건 낮아진다는 보정은 넣지 않는다.
3. 실제 명령 변화에 따른 합류·재고·부분 영역 TTT 차이를 먼저 맞춘다. 추가 δ/φ 탐색이나 근거 없는 capacity drop으로 RM/VSL의 이득을 강제하지 않는다. 새 계수는 별도 상태/seed에서 검증한다.
4. 방향성과 대기 비용의 재현을 통과한 뒤 전체 follower kernel 이행과 Ω 비용 비교로 진행한다. 후보의 실행 가능성과 선택 문제는 물리 응답 검증 후 별도로 판단한다.

인계 시에는 과거 결과 JSON의 절대 경로를 바꾸지 않고, live harness가 동일한 해시의 geometry profile을 현재 저장소 안에서 찾도록 최소 경로 이식 수정을 했다. 과거 prepared receipt는 원래 실행의 출처이므로 보존한다. 다른 머신의 VISSIM 실행은 복원한 입력으로 새 출력 폴더에 다시 prepare한다.
