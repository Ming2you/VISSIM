# SDMPC 배열 수송·컴파일 실험

판정은 **수치 동등성 PASS / NOT_SELECTED_FOR_SPEED**다. 차로군 수송의
배열·컴파일 전환은 가능했으나 이번 부분 전환으로 실제 예측 시간 개선은
입증하지 못했다. 기본 OFF와 앞선 선택 설정을 유지한다.

이 실험은 차로군 사이의 종방향 차량 수송 블록을 배열과 Numba 커널로
실행한다. 설정은 `adapter.sdmpc_array_transport` 하나이며 기본 OFF다.
기존 선택 설정 `sdmpc_trial_20260922/config_candidate.json`에 이 키만 추가한
후보로 평가한다. 앞선 `flow_update_cache`, `spatial_receiving` 실험은 켜지 않는다.

## 범위와 계산 순서

`physical_lane_groups.PhysicalLaneGroups.advance`에서 인접 셀 사이의 유량을
배분하는 연속된 루프를 대상으로 한다. 송출량에 차로 연결 비율을 곱하고,
하류 차로의 공유 수용량을 적용한 다음 유입·유출, 차량 수로 가중한 속도,
목적지별 재고를 원래 순서대로 갱신한다. 출구 분기와 램프 합류, 횡방향 이동,
METANET 속도식, 도시부 FIFO 및 비용 계산은 기존 경로를 따른다.

컴파일 커널은 수치뿐 아니라 원래 순서의 미분 그래프 간선도 함께 만든다.
커널 경계에서만 Python 객체를 배열로 바꾸고 결과를 복원한다. 원래 Python
sum의 보상 합산과 Dual 등장 이후 덧셈 순서도 유지한다. 구간 간 공유 재고를
한꺼번에 독립 계산한다고 가정하지 않으며, 커널은 단일 수치 스레드로 실행해
기존 최대 8워커 일정에 추가 스레드를 겹치지 않는다. fastmath는 사용하지 않는다.

`sdmpc_tangent_transport`가 배열 포장·컴파일·미분 간선 복원을 맡는다.
기존 `sdmpc_tangent_spatial`의 공통 숫자 연산만 재사용하며, 공간 병렬 옵션은
활성화하지 않는다. 각 예측의 설정 범위 밖에서는 기존 루프를 수행한다.
vendor 및 adapter 복사본은 만들지 않는다. 1초 갱신과 450초 예측, 3개 제어
블록 및 231개 미분 축은 유지한다.

## 검증과 증거

증거 루트는 `diagnostics/sdmpc_array_transport_20260922`다. 수정 전 소스를
`before_sources`에 보존했다. 단위 검사는 보존된 실제 기존 루프를 AST로
추출하여 대조하며 새 커널 수식을 대조군으로 재작성하지 않는다.

- 일반 수치·혼합 미분·전체 미분 입력 18개 사례에서 차량 수, 속도 모멘트,
  목적지 재고, 미분 간선 순서·가중치, 분기/동률/불연속 의존성과 Jacobian을
  비교했다. 빈 차로·차로 수 변화·수용량 포화·분기·합류를 포함한다.
- 일반 수치 합산 및 미분 값이 끼어드는 합산, 혼합 tape/비유한 입력/읽기 전용
  scope의 거부, 설정 기본 OFF와 필수 조건을 검사한다.
- 첫 검사 `tests_v1.log`는 대조 루프 추출기가 생성자의 같은 이름 루프를
  선택하여 실패했다. `advance`로 대상을 한정한 `tests_v2.log`는 4개 PASS다.
  최초 커널 컴파일을 포함하여 28.848초였고, 이를 예측 시간으로 취급하지 않는다.

## 실제 저장 상태 결과

900초 저장 상태에서 450초 예측 및 231축 전체 Jacobian을 계산했다.
`array_h3_v1`의 비용·자원·두 Jacobian 차이는 모두 **0**이다. 총 그래프
노드 수 14,137,087개, 분기 이벤트 수, 동률 및 불연속 의존 축도 같았다.

| 측정 범위 | 기존/OFF | 배열/ON |
|---|---:|---:|
|450초 예측과 전체 Jacobian 검증|143.419초|146.886초|
|미분용 교통 예측|121.252초|124.032초|
|현재 소스의 일반 예측 OFF/ON|59.080초|59.637초|

위 두 행은 과거 기준과 새 단일 실행 비교다. 실행 환경 차이를 제거한 반복
평균은 아니므로 작은 증가를 확정적인 성능 악화로 단정하지 않는다. 마지막
행 `states_v1`은 동일한 현재 소스에서 두 독립 프로세스가 실행한 짝 비교다.
**모든 저장 상태·비용·자원 차이 0**, 실행 중 소스 불변 PASS다. 두 방식 모두
시간 단축을 입증하지 못했다.

커널 경계는 450번 호출됐으며 8번은 일반 수치, 442번은 미분 값이 있었다.
이 구간이 생성한 미분 노드는 63,038개로 전체의 **0.446%**다. 이는 노드 수의
비율이며 전체 실행 시간의 비율로 환산하지 않는다. 구간 전체 시간 1.196초
중 컴파일 함수 호출 안은 0.701초, 배열 포장·입력 확인·그래프 복원 등은
0.495초다. 첫 호출 전체가 0.687초였고 캐시 로드를 포함한다. 최초 호출의
커널 내부 시간은 따로 분리하지 않았으므로 이를 빼서 정확한 warm 커널
시간을 산출하지 않는다.

## 최종 검사와 범위 제한

- SDMPC 회귀 **129개 PASS**, 램프·도시부 연계 **9개 PASS**,
  기존 차로군 물리 검사 **7개를 OFF/ON 각각 PASS**다.
- 파라미터 검사 PASS다. 기존 calibration 우선순위 경고는 남겨 두었으며
  속도 비교를 위해 계수나 실제 교통식을 바꾸지 않았다.
- 차로군 물리 검사의 첫 호출은 이 worktree에 과거 `PROTOCOL.json`이 없어
  import에서 실패했다. 원래 `sdmpc-lane-plant-20260921` 폴더의 해당 JSON/CSV를
  읽기 전용으로 연결했다. v2는 파일 존재 확인 경로를 연결하지 않아 포트 관측을
  읽지 못했으며 OFF/ON에 동일한 두 오류가 있었다. 존재 확인과 읽기를 함께
  연결한 v3에서 실제 관측으로 통과했다. 데이터 보충·추정이나 검사 삭제는 없다.
  사용한 파일 경로·SHA는 `physical_fixture_check_v3.json`에 있다.
- `qualification_summary.json`의 동등성·검사 12개 조건은 모두 PASS지만,
  성능 판정은 별도로 **NOT_SELECTED_FOR_SPEED**로 기록한다.
- 새 전체 SDMPC 결정이나 VISSIM 9000초 런은 하지 않았다. 위 146.886초는
  전체 최적화 완료 시간이 아니며 150초 결정 목표를 달성했다는 뜻이 아니다.

작은 블록을 매초 Python 상태에서 배열로 옮기는 방식은 포장·복원 경계가
남고, 이번에 옮긴 블록의 계산 비중도 작다. 다음 구조 변경의 후보는 차량
재고·유량·미분 정보를 여러 연산 단계에 걸쳐 배열로 유지하는 방식이다.
그 큰 변경의 구현 완료나 예상 단축률은 이 실험만으로 주장할 수 없다.
이 실험은 native 적용이나 RM/VSL 순이득의 보정 완료를 뜻하지 않는다.
