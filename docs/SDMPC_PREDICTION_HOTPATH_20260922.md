# SDMPC 교통 예측 내부의 추가 속도 개선

초기 예측 공유로 결정당 341.574초까지 줄인 뒤 사용자가 추가 단축을 요청했다. 별도 config 키 `adapter.sdmpc_prediction_hotpath=true`를 추가했다. 기존 연속화 후보 평가(`surrogate_reuse`)와 원래 primal 제약 검사가 켜진 격리 worker에서만 적용한다. 키가 없으면 설치하지 않는다. 단일 adapter와 vendor, 물리 방정식, 시간 step, 3개 제어 블록, iteration 상한은 바꾸지 않았다.

## 변경

1. 매 AD 사칙연산에서 같은 객체의 자료형을 여러 번 확인하던 작업을 한 번으로 줄이고, 작은 tape node/result 생성 함수를 호출부에 합쳤다. 계산 순서, float 변환, tape 노드·가중치·support, 서로 다른 tape 혼합 방지, freeze 검사, primal 검사용 분기를 유지한다. 새로운 미분 근사는 없다.
2. 유량 할당과 상태 상한의 원래 검사 함수를 그대로 실행한 후, 통과한 행은 횟수·종류·최대 초과량으로 즉시 집계한다. 매 interval에 모든 성공 행을 저장·압축·복사하고 끝에 다시 풀어 읽는 작업을 없앤다. 위반은 원래 위치에서 원래 예외와 유량 위반 기록으로 중단한다.
3. 차량 이동, Ω 재고·체류시간, 수량 제약용 실제 서비스, coverage 방문 기록, freeway frame와 실제 8램프 합류 기록은 그대로 보존한다. 전체 성공 제약 행은 보존하지 않으므로 `successful_records_retained=false`를 기록한다. 집계 객체를 전체 행 목록처럼 순회하면 명시적으로 실패한다.

별도 독립 primal 대조를 생략하는 기존 연속화 모드의 의미는 유지한다. `primal_audit_performed=false`, `complete_primal_state_match=false`, `execution_model_evaluated=false`다. 성공한 제약 검사를 집계하는 것과 독립 궤적 대조 또는 VISSIM 검증은 다르다.

## 검사와 단일 AD 측정

`diagnostics/sdmpc_stream_summary_20260922/`에 변경 전 소스, 이전 150초 구간 AD 프로파일, 실험 config와 검증 결과를 남겼다. 프로파일은 호출 경로별 비중을 조사하는 용도이며 계측 오버헤드가 있어 일반 계산시간으로 사용하지 않는다.

`tests_v1.log`의 신규 6개 검사와 `regression_v1.log`의 관련 158개 검사가 PASS다. 자료형 dispatch 변경 전후 원시 tape bytes와 미분 행렬 일치, 다른 tape 혼합·freeze 거부, 제약 위반 예외 유지, clone 독립성, interval을 건넌 집계, 누락 coverage의 실패를 확인했다. `parameters_v1.log`는 PASS다.

동일 저장 상태의 450초 단일 AD는 이전 127.984초에서 117.477초로 줄었다. **최적화 iteration 없는 미분 1회**, 최대 8워커이며 각 1회 측정이다. `hotpath_h3_v1/comparison.json`의 비용·수량·비용 Jacobian·수량 Jacobian 최대 차이는 모두 0이다. tape 노드는 14,137,087개로 동일하다.

단일 AD의 960,087개 유량 할당 검사와 178,200개 상태 상한 검사 집계가 이전 전체 기록에서 계산한 값과 정확히 같다. coverage, 종류별 개수, 최대 초과량도 동일하다. 줄인 것은 검사와 교통 연산 자체가 아니라 성공 기록의 저장·재구성과 AD 구현 오버헤드다.

## 전체 결정 측정

900초 저장 상태, 450초 예측, 3×150초 제어 입력, 최대 8워커, 결정 시간제한 없음에서 각 버전 1회 비교했다.

| 항목 | 초기 예측 공유 버전 | 이번 내부 최적화 |
|---|---:|---:|
| 전체 결정 시간 | 341.574초 | 304.255초 |
| 후보별 outer iteration 상한 | 2회 | 2회 |
| 선택 후보 수락 iteration | 2회 | 2회 |
| 수렴 확인 | 없음 | 없음 |
| 전체 rollout | 5회 | 5회 |
| AD / 일반 숫자 예측 | 3회 / 2회 | 3회 / 2회 |
| local QP | 95개 | 95개 |

37.319초(10.926%) 추가 단축이다. **150초 목표에는 아직 미달**이다. 이전 405.153초에서 초기 중복 예측을 없애고 이번 처리를 추가한 누적 결과는 304.255초다. 6 iteration 실행 시간 또는 수렴 완료 시간을 주장하지 않는다.

선택 명령 전체, hold/선택 목적값(402.3185395008343/396.47493233989024 veh·h), 결정에서 사용한 두 미분 행렬의 모든 항목은 이전과 정확히 같다. 두 AD의 제약 방문·검사 횟수·종류별 자원 요약·tape 노드 수 역시 같다. N_P=2400과 743.75 후보는 각각 2회 수락했고, N_P=81.25는 첫 결합 QP 실패로 수락 0회다.

전체 5 rollout은 초기 AD 1회, 첫 iteration 후보 AD 2회, 마지막 iteration 일반 예측 2회다. 후보 두 개는 각각 병렬로 계산하며 선택되지 않은 AD도 계산량에 포함한다. QP 자체의 교통 rollout은 0회다. 측정 중 실행 소스 변경은 없었다.

## 별도 원 실행용 모델 대조

`exact_audit_v1/`에서 **최적화 iteration 0회인 사후 대조**를 수행했다. hold/선택 예측 2회를 병렬 실행한 53.518초이며, 전체 결정 304.255초에 포함하지 않는다. 원 실행용 모델에서도 제약을 만족했고, 실제 출력할 명령과 모델 명령의 차이는 0이었다. 3개 제어 블록의 actuator 범위·변화량 검사를 통과했다. 최대 자원 초과량은 1.11e-15대의 반올림 수준이다.

원 실행용 모델의 hold/선택 Ω TTT는 402.31251168233456/396.57370910204804 veh·h로 이전과 같다. 이는 저장 상태에서의 예측 대조이며 native 개선율이 아니다. 이번 작업에서 VISSIM 또는 9000초 실런은 시작하지 않았다.

최종 검사는 `summary.json`, 재현 스크립트는 `diagnostics/finalize_sdmpc_hotpath.py`, 최종 소스 사본은 `final_sources/`에 남겼다. 기존 실행과 소스 사본은 덮어쓰지 않았고 기능은 새 실험 config에서만 켰다.
