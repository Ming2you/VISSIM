# SDMPC 후보 평가와 미분의 연속화 모델 통합

사용자가 2026-09-22 후보 검증까지 근사하여 중복 예측을 줄이는 방향을 요청했다. 새 키 `adapter.sdmpc_surrogate_reuse=true`를 추가했다. 키가 없으면 기존 경로이며, 기존 최선 설정은 변경하지 않는다. 증거는 `diagnostics/sdmpc_surrogate_reuse_20260922/`에 보존한다.

## 구현 범위

- 후보 비용·제약과 sensitivity가 기존 연속화 모델을 함께 사용한다. 신호 전환의 연속화와 미터 주기 평균 서비스는 기존 `sdmpc_continuous.py` 그대로이며 새 보정 계수를 추가하지 않는다.
- 다음 outer iteration에 사용할 가능성이 있는 후보는 AD rollout 한 번에서 후보 평가용 비용·자원·보존 및 용량 검사와 미분 행렬을 함께 내보낸다. 선택된 후보의 미분을 다음 iteration에서 재사용한다.
- 마지막 iteration의 후보는 같은 연속화 모델의 일반 숫자 예측만 수행한다. AD 기록이 없는 숫자 예측을 미분 결과처럼 재사용하지 않는다.
- 독립적인 AD 대조용 일반 예측을 이 모드에서 실행하지 않는다. `primal_audit_performed=false`, `complete_primal_state_match=false`, `max_primal_state_error=null`로 기록한다. 생략한 검사를 통과로 표시하지 않는다.
- 실제 RED/GREEN 전환을 따르는 원래 실행용 예측은 이 모드의 후보 선택에 사용하지 않는다. `execution_model_evaluated=false`와 연속화 모델 식별자를 결과에 남긴다. 외부 VISSIM 검증을 뜻하지 않는다.
- 기존 원 모델 파라미터, 수요, 1초 물리 step, 450초 horizon, 3×150초 입력과 actuator 범위·변화량·첫 블록 적용 검사를 유지한다. 후보별 모든 제약은 연속화 모델의 새 응답에서 다시 확인한다.
- 결정 내부에서 입력·상태·소스를 고정하고, N_P 상한만 다른 예측을 재사용한다. N_UF나 actuator가 바뀌면 새 예측이다. 초기 N_UF 목표는 연속화 모델의 실제 수용 합류 예측으로 정한다. 기존 실행용 모델로 정한 목표와 다를 수 있다.
- 배치의 전체 계산 슬롯은 최대 8개다. 미사용 후보의 AD도 실제 계산량에 포함한다. 실패한 배치는 부분 결과를 캐시에 공개하지 않으며, 실패 중 실행 횟수가 불확실한 작업은 별도로 기록한다.

## 검증과 측정

`regression_v1.log`: 관련 회귀 145개 PASS. `tests_v2.log`: 최종 재사용/격리/실패/생략 검사 의미 관련 9개 PASS. `parameters_v1.log`: 파라미터 검사 PASS.

단일 AD 검사는 132.273초였다. **최적화 iteration 없는 미분 1회**의 시간이다. 기존 검증된 결과 대비 비용 최대 차이 1.4211e-14, 자원·비용 Jacobian·자원 Jacobian 차이는 0이다. 연속화 모델 자체를 바꾼 것이 아니라, 같은 AD 계산에서 검증용 중복 예측을 뺀 결과다.

전체 결정은 **405.153초**, 후보별 outer iteration 상한 **2회**, 선택 후보 **2회 수락**, **수렴 미확인**이다. N_P=2400과 743.75 후보는 각각 2회 수락 후 상한에 도달했고, N_P=81.25는 첫 iteration의 결합 QP 실패로 수락 0회였다. 수락 0회를 미실행으로 해석하지 않는다.

| 항목 | 기존 최선 | 이번 근사 통합 |
|---|---:|---:|
| 전체 결정 시간 | 386.693초 | 405.153초 |
| 후보별 iteration 상한 | 2회 | 2회 |
| 선택 후보 수락 횟수 | 2회 | 2회 |
| 수렴 확인 | 없음 | 없음 |
| 전체 rollout 수 | 12회 | 6회 |

각 전체 결정은 1회 측정이다. 기존 대비 4.77% 오래 걸렸으며 **속도 개선으로 채택하지 않는다. 150초 목표도 미달**이다. 기존에는 검증 예측과 AD가 병렬로 겹쳐 있었기 때문에, rollout 제거가 그대로 wall time 감소가 되지는 않는다. 이번 전체 결정의 순차 구간은 초기 일반 예측 약 62.2초 → 초기 AD 약 131.3초 → 두 후보 AD 병렬 배치 약 141.4초 → 마지막 두 후보 일반 예측 배치 약 63.5초였다. 이는 동일한 위 2 iteration 실행의 내부 구간이며 별도의 최적화 실행 시간이 아니다.

이번 6회는 초기 일반 예측 1회, 초기 AD 1회, 첫 iteration의 후보 AD 2회, 마지막 iteration의 후보 일반 예측 2회다. AD 3회 중 2회를 미분으로 사용하고 1회는 후보 평가에만 사용했다. 대조용 일반 예측과 실행용 모델 재평가는 최적화 중 각각 0회다. 95개 local QP의 교통 rollout은 0회다.

- `surrogate_h3_v2/`: 기존 검증된 Jacobian과 비용·자원·미분 비교.
- `full_decision_v1/`: 900초 저장 상태의 전체 결정, 후보별 상한 2회, 최대 8워커.
- `exact_audit_v1/`: 최적화 종료 후 별도 수행하는 원 실행용 모델의 hold/선택 명령 대조. 이 추가 진단 시간은 전체 결정 측정에 넣지 않는다. 실제 VISSIM 실행은 아니다.

원 실행용 모델에서 선택 명령은 제약을 만족했다. N_P=562.2458대 ≤ 2400대, N_UF=5142.7570veh/h로 이번 연속화 목표 5144.1629veh/h와 차이는 -1.4059veh/h(허용 ±40veh/h)였다. 최대 자원 초과량은 1.11e-15대의 반올림 수준이었다. 제어 명령의 직렬화 결과와 3개 블록의 actuator/step 제약 검사를 통과했다.

원 실행용 모델의 hold/선택 Ω TTT는 402.312512/396.573709veh·h였다. 근사 모델의 값은 402.318540/396.474932veh·h였다. 원 실행용 모델에서의 예측 감소율은 1.42645%이며 **native 개선율이 아니다**. N_UF 목표 자체도 연속화 모델에서 초기화되어 기존 기준 5144.2144veh/h와 소폭 달라진다.

기존 선택과 명령이 완전히 같은 것은 아니다. 최종 출력 213행 중 18행의 신호/SG 세부값이 달라졌다. 원 실행용 모델의 최종 목적값이 기존 선택과 같았다는 사실을 명령 동일성이나 native 동작 동일성으로 해석하지 않는다.

`default_h3_v1/comparison.json`에서 기본 OFF 경로의 비용·자원·두 Jacobian은 기존 결과와 정확히 일치했다. 최종 구현 검사 및 소스 동결은 `summary.json`과 `final_sources/`에 기록한다. 기능은 명시적으로 켠 실험 config에서만 사용했으며 native VISSIM이나 9000초 런은 시작하지 않았다.
