# SDMPC 교통 예측 공간 분리 실험

이번에는 한 후보의 1초 교통 갱신 안에서 **일반 도시부 링크의 수용량 배분**을
공간적으로 분리했다. 결과 동등성은 확인했지만 시간 이득은 확인하지 못했다.
따라서 **NOT_SELECTED_FOR_SPEED**이며 기본 실행에는 채택하지 않는다.
전체 예측의 공간 분할을 완료했다는 의미는 아니다.

마지막으로 선택한 설정은 `sdmpc_trial_20260922/config_candidate.json`이다.
그 설정의 기존 전체 결정 측정값 **386.693초**는 그대로 이전 측정값이다.
이번에는 전체 결정을 다시 재지 않았고, **150초 목표는 아직 달성하지 못했다.**

## 구현 범위

실험 키는 `adapter.sdmpc_spatial_receiving` 하나다. 키가 없으면 기존 루프를
실행한다. 이 키는 `sdmpc_spatial_20260922/config_candidate.json`에만 추가했으며
선택된 이전 설정은 바꾸지 않았다. reverse AD, 동시 scalar 대조, 8워커가 필요하다.

- 기존 순서대로 공유 신호 자원과 경로별 예산 제한을 먼저 계산한다.
- 링크별 입력을 고정하고 각 수용량 배분의 미분 기록 위치를 예약한다.
- Numba 병렬 커널이 서로 다른 링크의 값과 지역 미분 그래프를 계산한다.
- 원래 순서대로 결과와 경계 미분을 연결한다. 공유 자원 차감과 차량 이동은
  기존 순서를 유지한다. 서로 연결된 링크를 독립된 교통망으로 취급하지 않는다.
- 분기 동률, 세 가지 배분 규칙, Python 부동소수점 합산의 초기 구간을 보존한다.
  `fastmath=False`이고 미분 기록 버퍼 초과는 오류로 처리한다.

미분용 커널은 2개 수치 워커, scalar 대조 커널은 1개를 사용한다.
후보 두 개의 미분과 원 모델 예측이 겹칠 때도 총 수치 워커 상한 8개를 유지한다.
시간축은 직전 상태에 의존하므로 순서대로 진행한다. 1초 적분, 450초 horizon,
150초 제어 3개 및 231개 미분 축을 줄이지 않았다.

## 측정

900초 저장 상태의 450초 예측에서 **Jacobian 한 번**을 비교했다.
전체 SDMPC 최적화 완료 시간과 구분해야 한다.

| 항목 | 기존 `trial_h3_v1` | 공간 분리 `spatial_h3_v1` |
|---|---:|---:|
| 전체 Jacobian 호출 |143.419초|148.879초|
| 일반 연속 예측 |54.967초|58.077초|
| 미분용 교통 예측 |121.252초|126.230초|
| 역전파 |약 0.992초|1.044초|

두 예측은 겹쳐 실행되므로 시간을 단순 합산하면 안 된다. 이 단일 비교에서
공간 분리 쪽이 약 3.8% 더 오래 걸렸다. 반복 측정 평균이나 통계적 성능 판정은
아니지만, 이득이 확인되지 않았으므로 전체 결정에 활성화하지 않는다.

미분 기록은 14,137,087개에서 15,114,736개로 늘었다. 지역 그래프를 원래 순서에
연결하기 위한 예약 공간 중 실제 사용량은 58,534개, 예약량은 1,036,183개였다.
입력 배열화·연결·예약 비용에 비해 분리한 계산량이 작다.

별도 150초 구간의 단계별 측정(`urban_stages_v2`)에서는 미분용 예측 27.596초 중
일반 링크 수용량 배분 전체가 **0.373초(약 1.35%)**였다. 이 구간에는 직렬로
남겨야 하는 공유 자원 제한까지 포함되므로, 실제 병렬화 가능 비중은 더 작다.
도시부 내부에서 더 큰 부분은 실제 차량 이동 적용 2.783초, 유량 요청 구성
2.672초, 경로 선택 구간 갱신 1.838초였다. 이 값은 진단 계측이 들어간
150초 구간의 값이며 450초 전체 결정 성능으로 외삽하지 않는다.

그다음 구조 변경의 대상은 수용량 배분 워커를 더 늘리는 것이 아니라,
유량 요청·이동 갱신·경로별 재고를 큰 배열 단위로 계산하는 부분이다.
공유 재고와 FIFO 순서가 있어 단순히 링크마다 프로세스를 만들 수는 없다.
**이 큰 변경은 이번에 구현하지 않았다.**

## 검증과 한계

- `spatial_h3_v1`: 비용·자원·비용 Jacobian·자원 Jacobian의 기존 대비 차이가
  모두 0이다. scalar/taped 전체 상태 대조도 통과했다.
- `states_v1`: 옵션 OFF/ON의 전체 저장 상태·비용·자원 차이가 모두 0이다.
  실행 중 소스 불변 검사도 통과했다. scalar 예측은 55.800 / 56.910초였다.
- 첫 SDMPC 회귀 122개 PASS, 파라미터 검사 PASS. 기존 calibration 경고는 유지했다.
- 최종 커널 검사 6개 PASS. 값·미분·비영 미분 그래프의 순서·분기 진단 카운터,
  공유 입력, 1/2워커, 비정상 입력 거부와 opt-in 조건을 확인했다.
- 광범위한 물리 검사에서는 **41개 중 36개 통과, 4개 오류, 1개 skip**이었다.
  `test_direct_branch_receiving.GlobalBranchReceiving` 네 검사가 준비 단계에서
  기존 저장 fixture의 `control_interval_sec` 누락으로 실패했다. 새 예측 루프에
  들어가기 전 오류이며 이번 변경에서 그 fixture나 준비 함수를 고치지 않았다.
  이 검사 묶음을 PASS라고 주장하지 않는다.
- 초기 단계별 프로파일 `urban_stages_v1`은 1구간 요청에 3구간 action이 남아
  실패했다. 첫 action으로 맞춘 별도 `urban_stages_v2`에서 다시 측정했다.
  실패 로그도 보존했다.

`states_v1`과 첫 Jacobian 실행 후 미분 동률 진단 카운터 누적 한 줄을 보완했다.
이 보완은 물리값이나 미분값을 바꾸지 않으며 최종 커널 검사에서 카운터까지
동일함을 확인했다. 보완 전 스냅샷은 `sources_v1`, 최종 스냅샷은 `final_sources`에
분리해 보존했다.

최종 소스로 다시 실행한 `spatial_h3_v2`도 비용·자원·두 Jacobian 차이 모두 0이다.
scalar/taped 전체 상태 최대 오차는 기존과 같은 3.638e-12로 기존 허용오차 검사를
통과했다(이 대조는 비트 동일을 의미하지 않는다). 호출 150.297초, scalar 58.471초,
미분용 예측 127.588초, 상태 대조 11.162초, 역전파 1.122초로 시간 이득은 없었다.
최종 소스의 SDMPC 회귀도 **122개 PASS(6.332초)**였다.
단계별 진단 프로파일은 짧은 150초 구간만 사용했으며 전체 Jacobian 검증은
두 번 모두 원래 450초·3구간·231축으로 실행했다.

선택된 이전 설정 파일의 SHA256은 이전 스냅샷과 같은
`5c708fcff3cdda8abc33ee35a65d35613153f49fe233b745b9ba0ddeeb289fe4`다.
마지막 프로세스 확인에서도 이 작업의 Python 계산 및 VISSIM은 없었다.

VISSIM native 적용과 9000초 성능 비교는 실행하지 않았다. RM/VSL 순이득 예측의
기존 NOT_QUALIFIED 상태를 바꾸지 않는다. 이전 최적화의 실패 증거도 그대로 둔다.
이번 실험의 결과·로그·설정은 `diagnostics/sdmpc_spatial_20260922` 아래에 있다.
