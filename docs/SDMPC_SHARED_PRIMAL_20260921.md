# SDMPC common prediction and full-state validation overhead

Worktree: `C:\Users\TRLAB\Documents\ChatGPT\VISSIM\.worktrees\sdmpc-tangent-20260921`.

사용자 문제 제기: 미분 한 번이523초라면 제어150초마다6번 반복할 때 미분만52.35분이다.
정확히 같은 기준점의 캐시 재사용과 조기 종료는 가능하지만,6회 모두 새 기준점이면 이 비용이 반복된다.
QP, 실행 가능한 후보 예측, 제약 복원 시간은 별도다.150초 제어를 달성한 상태가 아니다.

## 변경

`adapter.sdmpc_tangent_shared_primal: true`를 명시한 경우만 다음 경로를 사용한다.
기존8워커,3개150초 입력,450초 예측,route-bins 집계 설정은 유지한다.
후보 설정은`diagnostics/sdmpc_shared_primal_20260921/config_candidate.json`이다.

1. 같은 기준점의 일반 연속 예측을 한 번 계산한다. 전체 상태와 비용/자원 결과를
   부모가 관리하는 임시 파일에 저장한 뒤8개 미분 워커가 공유한다.
2. 모든 워커는 같은 SHA256으로 고정한 원본 요청 바이트를 읽는다. 별도 입력으로
   덮어쓸 수 없으며, 워커별 차이는 미분할 열 번호뿐이다. 저장 상태의 해시, 기준점 해시,
   모델 소스 해시를 검사하고, 각 미분 예측의 전체 상태를 공유한 일반 예측과 비교한다.
3. 전체 상태 검산의 수치형 빠른 경로와 중복 객체 비교 재사용을 도입한다. 모듈/함수 동일성,
   배열 크기, 모든 물리 상태, ledger의 경로/시간별 이동량과 미수집 이벤트 수 검사는 유지한다.
   압축된 ledger는 객체별로 한 번만 풀어 이벤트 수 검사와 내용 대조에서 재사용한다.
4. 일반 예측, 파일 저장/읽기, 미분, 전체 상태 검산 시간을 구분해 기록한다.

새 키가 없거나false이면 기존 경로를 유지한다.1워커에서true는 같은 일반/미분 예측과
빠른 전체 상태 검산을 수행한다.8워커의 최대 동시 계산 수는8이고 일반 예측은 그 전에1개만 실행한다.
이것은 이전 iteration의 미분을 새 기준점에 재사용하는 근사가 아니다.

추가로`adapter.sdmpc_indexed_coverage: true`는제약 검사의 방문 기록을
`(scope, stage, start_sec, end_sec)`별 사전으로 찾아 누적 기록의 반복 선형 검색을 없앤다.
미방문·미완료·중복 방문 판정과 원래 순서의전체 기록은 유지한다. 응답을 내보낼 때
인덱스의 행 수, 키와 원본 행 동일성을검사하므로 누락·변조된 인덱스를 통과시키지 않는다.
후보 설정에는 두 옵션이 명시돼 있으며실행 가능한 후보의 일반 예측에도 이 인덱스를 사용한다.

## 범위와 한계

- 물리 방정식, 제어 입력 수, 예측 길이, 적분 간격, 비용, 제약과 허용 오차는 바꾸지 않았다.
- 원래 검산과 동일하게 sparse transfer는 경로/시계가 같은 이동량을 합산해 비교한다.
  작은 이동량을 버리지 않는다. 객체 참조는 검산이 끝날 때까지 유지해id 재사용으로 인한 누락을 막는다.
- 공통 일반 예측을 없앤 것이 아니라1회로 줄였다. 미분 워커는 여전히 전체450초 동역학을 계산한다.
- 전체 SDMPC 최적화 종료 시간 및150초 달성은 별도 검증 항목이다. VISSIM 실런을 시작하지 않았다.
