# SDMPC 후보 검증과 다음 미분 중첩

실제 작업일 2026-09-21. 기준은 `SDMPC_FLOW_20260922.md`의 전체 결정
423.614초다. 동일한 900초 저장 상태와 450초 horizon/3개 제어 블록,
231개 미분 축, 1초 적분, 후보 수와 반복 수를 사용한다. VISSIM 실행은 없다.

## 구현 범위

`adapter.sdmpc_trial_derivative_overlap: true` 한 키로 켠다. 기존 초기 미분
중첩, NP 응답 캐시와 8워커 설정이 필요하다. 시간 제한 없는 결정에서만 동작한다.

후속 반복이 남았고, line search 후보가 1~2개이며 원 모델의 새 예측이
필요할 때만 각 후보의 다음 Jacobian을 동시에 준비한다. 원 모델 검증에서
선택된 후보의 **전체 미분 요청 해시가 일치할 때만** 해당 결과를 사용한다.
다른 복원 명령이 선택되면 준비한 작업을 join한 뒤 그 명령의 미분을 계산한다.
NP cap만 다른 기존 응답 재사용 상황에서는 추가 미분을 시작하지 않는다.

후보 2개이면 일반 예측 2개 + 각 미분의 scalar/taped 예측 2개씩, 총 6개
수치 실행 흐름으로 시작한다. 각 역전파는 3개 출력 워커로 제한하므로
최대 2+3+3=8개다. 후보 1개이면 일반 예측 1개 + 역전파 최대 7개다.
원 모델 질의·실행 가능성 검사·선택 기준을 생략하지 않는다.

선택되지 않은 후보의 미분도 계산할 수 있으므로 CPU 작업량이 증가한다.
작업은 모두 종료를 기다리고, 사용하지 않은 작업도 실패하면 전체 검증을
실패로 처리한다. 모든 후보가 거부되는 상태에서는 이 선행 계산이 낭비될 수 있다.
따라서 이 옵션의 시간 이득은 해당 저장 상태의 전체 결정으로 검증한다.

## 검증

SDMPC 회귀 **116개 PASS**, 파라미터 검사 PASS다. 기존 calibration 경고는
유지했다. 첫 회귀 검사는 사용하지 않은 작업을 정상 종료에서도 취소하는
cleanup 문제로 2개 실패했다. 정상 종료는 모든 작업 결과를 기다리도록
수정했고, 기존 실패 로그와 수정 후 PASS 로그를 함께 보존했다.
이번 턴의 램프 재고 변경은 앞선 물리·회계 52개 검사도 통과했다.

`trial_h3_v1`의 전체 Jacobian 호출은 143.419초, 일반 연속 예측
54.967초, 미분용 예측 121.252초, 전체 상태 대조 10.482초였다.
비용·자원·두 Jacobian 차이는 모두 0이다. 역전파 자체는 0.992초,
22개 출력 / 231개 축 / 14,137,087개 노드다. 이번 옵션은 호출 간
실행 순서를 바꾸므로 한 번의 미분 호출을 빨라지게 만드는 옵션은 아니다.

`states_v1`의 옵션 OFF/ON 전체 저장 상태·비용·자원 차이도 모두 0이다.
실행 소스 불변 검사 PASS, 두 scalar 예측은 50.894 / 51.075초였다.

## 전체 결정 결과

`full_decision_v1`의 전체 실행 시간은 **386.693초(6분 26.7초)**다.
바로 앞 423.614초 대비 36.921초(8.716%), 이번 턴 시작 기준 474.518초
대비 **87.825초(18.508%)** 단축했다. 모두 동일한 900초 저장 상태의
단일 실행 측정이며 반복 측정의 평균값은 아니다.

| 단계 | 전체 결정 시간 |
|---|---:|
|이번 작업 전 audit 버전|474.518초|
|램프 재고 합산 재사용 + 초기 미분 중첩|423.614초|
|후보 검증과 다음 미분 중첩 추가|386.693초|

- 450초 horizon, 150초 제어 3개, 231개 미분 축, 1초 적분을 유지했다.
  `max_iterations=2`, `line_search_steps=3`와 NP 후보 설정도 같다.
- 초기 미분은 138.587초, 선택된 후보의 다음 미분은 141.587초였다.
  두 번째 미분 완료 시점이 결정 시작 후 370.799초에서 333.663초로 앞당겨졌다.
- 후보 미분 2개를 시작하여 선택된 후보 1개만 소비했다. 다른 미분 1개는
  140.764초에 완료되어 유효성 검사 후 사용하지 않았다. CPU 작업량 증가를
  숨기지 않는다. 준비된 작업은 모두 join했고, 소비한 요청 전체 hash가 같았다.
- 일반 액추에이터 모델의 실제 후보/held 질의는 기존과 같은 **6개**다.
  총 질의 wall time 193.202초 중 일부가 미분과 겹치므로 전체 시간에 단순 합산하지 않는다.
- `qualification_summary.json`의 **23개 조건 모두 PASS**. 최종 원시
  green·offset·8개 RM·VSL 명령, 모델 비용, 제약과 두 Jacobian 차이는 0이다.
  후보별 결과·최종 명령 hash/vector도 같고 source/context provenance만 갱신됐다.
- NP cap 2400 / 743.75는 두 번 수락 후 `iteration_limit`, 81.25는 기존과
  같은 `linear_resource_qp_failed`다. 최종 명령은 feasible이지만 수렴을 주장하지 않는다.
- 전체 결정 중 소스 변화가 없고, 응답 워커와 새로 소유한 미분 작업은 모두 종료했다.
  후속 프로세스 점검에서도 해당 Python 작업과 VISSIM은 없었다.

**150초 목표에는 아직 미달한다.** 남은 큰 비용은 미분 그래프를 만드는 교통
상태 예측과 순차적으로 필요한 원 모델 질의다. 역전파는 이미 약 1초다.
예측 상태의 배열화·컴파일은 더 큰 변경으로 남아 있다.

이 기록은 계산시간과 기존 결과 동등성 검증이다. VISSIM native 적용이나
9000초 제어 성능을 검증한 것은 아니다. RM/VSL 순이득 예측의 기존
NOT_QUALIFIED 상태도 바꾸지 않는다. 이전 566초 → 504초 변경의 원시
녹색 0.001초 차이/FAIL은 그대로 보존하며 이번 PASS로 취소하지 않는다.

실험 설정은 `diagnostics/sdmpc_trial_20260922/config_candidate.json`, 결과는
같은 폴더의 `qualification_summary.json`과 `full_decision_v1`에 있다.
