이번 후속에는 172–173의 소스·프로토콜·실패/완료 로그·요약·정정표와 저장된 20개 예측을 포함한다. 기존 runner의 `--merge173` 진단 모드도 포함하지만 운용 채택을 뜻하지 않는다. 파일별 해시·검증·입력의 저장소 포함 여부는 `diagnostics/handoff_20261004/review173/`에서 확인한다. 이 디렉터리의 목록은 이번 증분에 한정하며, 아래 이전 대용량 로컬 보관 목록을 대체하지 않는다.

소스·시험·누적 보고서·작은 검증 요약·선택망 실행 입력·최근148/158/168/169/170/171의 대표 예측 자료를 포함한다. 전체 로컬 미커밋 산출물은 인계 전 약19.7GB였으며, 모든 전수 탐색 trace/원시 궤적/중복 실행본을 Git에 넣지 않았다.

- [publication_plan.json](../diagnostics/handoff_20261004/publication_plan.json): 이번에 선택한 파일과 이유.
- [LOCAL_ARTIFACTS_NOT_PUSHED.csv](../diagnostics/handoff_20261004/LOCAL_ARTIFACTS_NOT_PUSHED.csv): 작업 worktree 기준으로 남겨 둔 로컬 파일과 크기. 삭제하지 않았다.
- 일부 native 자료는 기존 `D:/VISSIM_runs/`, 이동된 원시 자료는 이전 기록의 E드라이브 위치를 확인한다. 이 목록이 D/E드라이브 전체 목록인 것은 아니다.
- 기록 안의 절대 경로는 실행 당시 컴퓨터의 경로다. 다른 컴퓨터에서는 먼저 같은 저장소 상대경로 자료를 대조하고, 없는 raw/primitive 입력은 로컬 보관 목록에서 옮긴 뒤 해시를 확인해야 한다. **이 커밋만으로 모든 과거 실험이 즉시 재실행되는 완전한 데이터 번들은 아니다.**
- 완료 출력 폴더에는 덮어쓰기 방지 검사가 있다. 과거 실행을 재현할 때 완료 파일을 지우거나 새 계수로 덮어쓰지 않는다.169/170의 수정 전 물리 파일 해시는171의 `physical_ramp_boundary.py.before.txt`, 완료169 runner는 `completed169_run.py.txt`로 확인한다.

이후 파일을 고칠 때도 새 실험의 모델 버전·입력·비용 범위를 명시하고, 기각 후보와 실제 운용 경로를 구분한다.
