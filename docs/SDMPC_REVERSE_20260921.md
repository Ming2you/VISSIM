# SDMPC 계산 경로 단축 — 2026-09-21

후속 가속과 현재 검증 결과는 [SDMPC_SPEED_20260922.md](SDMPC_SPEED_20260922.md)를 따른다.
같은 전체 결정은849.376→566.387초로 추가 단축됐으며,아래는 당시 소스와 실행의 보존 기록이다.

작업 루트는 `.worktrees/sdmpc-tangent-20260921`, 증거는
`diagnostics/sdmpc_reverse_20260921/`이다. VISSIM과 9000초 실행은 시작하지 않는다.
목표는 동일한 저장 상태에서 계산 경로를 줄이고, 미분 호출과 전체 결정 시간을 구분해 측정하는 것이다.

## 보존한 조건

- 실제 관측 900초 상태, 예측 450초, 독립 제어 블록 3개, 총 231축.
- 1초 물리 적분과 150초 제어. 5초 관측 설정을 변경하지 않는다.
- 물리 방정식·비용·NP/실제 합류 NUF·허용오차·QP 및 탐색 설정 유지.
- 일반 예측과 미분 예측의 전체 상태·기록을 매 호출 대조한다.
- 실제 제어 양자화/명령 검증은 원 실행 모델에서 수행하며 첫 블록만 적용 대상으로 삼는다.
- 이번 실험은 오프라인 계산이다. 실제 적용이나 9000초 개선율의 증거가 아니다.

## 구현

`adapter.sdmpc_tangent_backend: "reverse-v1"`는 전체 교통 궤적을 한 번 미분 기록한 뒤
20개 비용 출력과 2개 자원 출력의 adjoint를 역으로 계산한다. 231개 입력 방향을
각 연산마다 sparse dictionary로 전파하거나 8개 예측 궤적으로 중복 실행하지 않는다.
유한차분이 아니며 활성 분기의 정확한 chain rule이다. 이산 분기를 평활화했다는 뜻은 아니다.
기존 연속 신호/미터 예측기와 원 실행 모델의 차이는 기존 anchor correction과 최종 검증을 유지한다.

지역 미분은 연속 배열에 기록한다. 역방향 계산은 Numba의 `nogil=True, fastmath=False`로
8개 출력 작업을 동시에 계산한다. 각 노드와 입력축 누적에 보정 합산을 사용한다.
교통 예측 전체가 컴파일된 행렬 모델로 바뀐 것은 아니다.

`adapter.sdmpc_primal_audit: true`는 자원 배분과 상태 상한의 검증 전용 기록에
불필요한 미분을 전파하지 않는다. 모든 값·개수·용량 초과 검사와 저장 기록은 유지한다.
유량·체류·물리 재고·비용/자원 계산에는 적용하지 않는다.

`adapter.sdmpc_tangent_concurrent_primal: true`는 일반 예측과 미분 예측을 두 격리
프로세스에서 동시에 수행한다. 하나의 해시가 고정된 요청을 사용하며, 일반 예측이
완료된 후에만 그 전체 상태 증거를 받아 대조하고 8개 역방향 작업을 시작한다.
생산자 실패 시 소유한 미분 자식만 종료하고, stdin 종료·불일치·소스 변경은 실패한다.
동시 계산은 일반 예측/미분 예측 2개 또는 역방향 작업 최대 8개다.

누락된 스위치는 기존 경로를 유지한다. 최종 후보 설정은 위 증거 폴더의
`config_candidate.json`에 보관한다. 기존 장기 런 설정을 자동 변경하지 않는다.

## 의존성과 실행

Python 3.12 / NumPy 2.3.5 환경은 유지하고 Numba 0.67.0, llvmlite 0.49.0만
`VISSIM/.review-deps/sdmpc-numba`에 고정 설치했다. 목록과 설치 로그는
`requirements.txt`, `dependency_install.log`에 있다. 실행 시 기존
`.review-deps/sdmpc`와 함께 이 경로를 `PYTHONPATH`에 포함해야 한다.
Numba가 없으면 오류로 종료하며 느린 경로로 조용히 바꾸지 않는다.
호환성 근거: [공식 설치 문서](https://numba.readthedocs.io/en/stable/user/installing.html),
[공식 JIT 문서](https://numba.readthedocs.io/en/stable/user/jit.html).

## 전체 결정에서 발견한 추가 중복

첫 전체 결정 계산은1067.626초(17분47.6초)에 최종 명령 검증까지 완료했다.

`full_decision/` 러너는 최적화 후 JSON 저장에서 tuple dictionary key 오류로 exit1이 됐다.

`recovery.json`은 원본 SHA와 원 러너의 실패를 기록한다. 원 러너를PASS로 바꾸지 않는다.
