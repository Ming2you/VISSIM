# 교통 예측 본체의 중복 연산 제거

후속 추가 단축(전체 결정474.518초)은 [검증 기록 처리 최적화](SDMPC_AUDIT_20260922.md)를 따른다.
아래 수치와 이전 원시 명령 불일치 판정은 당시 증거로 그대로 보존한다.

작업 루트 `.worktrees/sdmpc-tangent-20260921`, 실제 작업일2026-09-21.
기준은 `sdmpc_speed_20260922`: 전체 결정566.387초, 미분용 예측147.044초,
일반 연속 예측53.095초, 전체 미분 호출184.982초다.
저장900초 상태,450초 지평,150초 제어3개,1초 물리 적분,231축,
반복/탐색/QP/제약 허용오차와 워커 최대8개를 유지한다.
현재 작업은 오프라인 계산 최적화이며 VISSIM/9000초 런을 재개하지 않는다.

## 새 설정과 계산 경로

`adapter.sdmpc_prediction_cache:true` 하나로 활성화한다. 없는 설정은 기존 경로다.
후보 설정은 `diagnostics/sdmpc_prediction_20260922/config_candidate.json`.

- 한 물리 예측 안에서 변경되지 않은 FIFO 차량 재고의 원래 `fsum` 값을 재사용한다.
  덧셈/뺄셈으로 누적 합을 근사하지 않는다. append, prefix take, lateral take,
  compact, indexed lateral commit은 캐시를 무효화한다. 큐 사본은 별도 객체다.
  캐시는 상태에 저장하지 않고 예측 종료 시 폐기한다. 중첩 scope도 격리/복원한다.
- 같은 초·현시·동일한 제어 피연산자의 연속 신호 비율을 재사용한다.
  현재 녹색4개,offset,시간 간격,평활 폭 및 native clock 기하를 키에 반영한다.
  AD 피연산자는 primal값이 아닌 객체 정체성을 유지하므로 같은 값의 다른 축이나
  다른 tape를 혼동하지 않는다. 정적 native prehead 카탈로그는 동결된 query cfg 내에서만 재사용한다.
- 램프 snapshot의 이미 계산된 재고를 같은 snapshot의 보존 검사에 전달한다.
  용량·차량 보존·connector/backlog 개별 잔차 검사를 모두 유지한다.
- reverse AD의 차량 합산은 기존과 같은 순서/부모/가중치의 미분 그래프를 직접 만든다.
  중간 Dual 객체만 생략한다. primal은 동일한 `math.fsum`, 역전파는 기존 보상 합산이며
  fastmath=False다. 실제 후보 모델의 신호나 차량 이동식은 바꾸지 않는다.

캐시는 다른 후보나 제어 결정으로 공유하지 않는다. 시간축을 병렬 조각으로 나누지 않는다.
FIFO 직접 변경은 현재 정본의 명시한 mutator/commit 경로에 한정된다. 새 mutator를 추가하면
무효화와 회귀검사도 추가해야 한다. 설정은 기존 query의 동결/사후 불변 검사 대상이다.

## 전체 결정 결과와 명령 차이

`full_decision_v1`은 exit0,feasible로 **504.628초(8분24.6초)**에 완료했다.
이전566.387초 대비 **10.90%,61.759초 단축**이다.
미분2회는154.135/154.540초,기준/후보 질의184.639초였다.
실제 교통 질의6회와 NP-only 재사용은 이전과 같고 반복/탐색을 줄이지 않았다.

기존 결과와 비교:

- 기준/선택 비용402.31251168233456→396.57370910204804veh·h와 모든 상한 후보의 결과,
  최종 NP/NUF 제약 판정은 정확히 같다. 상한2400/743.75는2회 반복 후 iteration_limit,
  81.25는linear_resource_qp_failed이며 수렴을 주장하지 않는다.
- 두 전체 Jacobian의 최대 차이는비용4.00e-15/자원1.71e-13이다. 모든231축,
  전체 상태 대조,제어3블록 검사,블록0만 적용하는 계약을 유지한다.
- **최종 명령 원시값/물리 행의 완전 일치 검사는 FAIL이다.**
  첫 적용 블록SC1003_p2가20.794→20.795초,p4가28.172→28.171초로 바뀌었다.
  미래 블록에도SC101/SC6/SC1001의 일부 녹색이0.001초 바뀌었다.
  offset,미터,VSL은 같다. 실제CSV는millisecond grid로 작성되므로 명령 해시도 달라진다.
  작은 Jacobian 차이와 녹색 투영/반올림 민감도가 있으며,명령 byte 일치를 보장하지 않는다.
  `qualification_summary.json`의 `pass_all:false`와 실패 로그를 수정하지 않고 보존한다.
- 별도 `clocks_v1`에서는 **현재 적용 시간대의 동작 동등성**을 검증했다.
  원 VBS에서시계·GREEN/AMBER/RED 함수6개를 추출해Scripting.Dictionary만으로 실행했다.
  첫 블록900–1049초의122개 신호군,18,300개 상태가 모두 정확히 같았다.
  세 블록의30,600개 원 모델 현시 비율도 같았다. 이는 위 원시값 불일치의 면제가 아니며,
  다른 시작 시간/실제VISSIM응답/9000초 성능까지 보장하지 않는다.
- 실행 중 소스 변화0,소유 워커 모두 종료,VISSIM 적용 없음이다.

증거는 `command_differences.json`, `clocks_v1/comparison.json`, `qualification_summary.json`,
