# 실제 plant에 지속 배열 대기열 연결 — 2026-09-22

도시부·off-ramp 연결부의 실제 FIFO에 숫자 배열 저장을 연결했다.
`adapter.sdmpc_persistent_urban_fifo: true` 하나로 활성화하며, 기본값은 OFF다.
`prediction_cache`와 `reverse-v1`을 요구한다. 실험 설정은
`diagnostics/sdmpc_persistent_plant_20260922/config_candidate.json`이다.
이 설정은 기존 선택 설정에 새 옵션 하나만 추가한다.

이번 범위는 전체 plant를 새로 작성한 것이 아니다. 물리 대기열의 재고,
목적지별 양, 차량 꺼내기, 횡방향 이동, 동일 행동 조각의 재병합이 같은
숫자 배열을 사용한다. 기존 경로 판단·수용량 배분의 Python 제어 흐름과
Ω 회계·제약 검사는 그대로 남아 있다. 전체 plant의 선택적 계산 경로로
연결했으며, 앞선 두 재고 진단 모형을 plant로 대체한 것이 아니다.

## 상태와 미분이 이어지는 방식

- `sdmpc_tangent_fifo.Buffer`가 값/미분 노드 ID/종류 배열을 보유한다.
  `sdmpc_prediction_cache`의 한 예측 범위가 이 버퍼를 소유한다.
  FIFO를 다시 읽거나 갱신할 때 기존 버퍼를 재사용한다.
- 수치 루프는 Numba로 컴파일하고, 행렬과 분기 기록 작업 공간도 재사용한다.
  새 미분 간선은 기존 Trace에 순서대로 추가한다. 값이 바뀌어도 같은
  미분 참조가 유지되는 상수 덧셈 규약을 보존한다.
- 목적지와 초기 차량 라벨, FIFO 선두 순서, 횡방향 이동의 라벨별 순서는
  보존한다. 분수 차량량과 공유 수용량 계산식은 바꾸지 않았다.
- 150/300/450초 상태 복사에서는 기존 deque 형식의 독립 상태를 만든다.
  배열은 모델 상태나 pickle에 추가하지 않는다. 정상적으로 예측 범위를
  벗어날 때 남아 있는 대기열도 기존 형식으로 내보낸다.
- 실패한 예측은 성공 결과로 내보내지 않으며 ContextVar는 예외에서도
  복원한다. 읽기 전용 미분 검사에서 만든 값으로 물리 재고 캐시를
  덮어쓰지 않는다. 혼합 tape와 동결된 tape의 변경은 거부한다.
- 기존 코드가 읽는 `q`는 읽기 전용 배열 view다. 수치는 경계에서 필요한
  만큼 기존 scalar/Dual로 복원된다. 이 복원 비용은 아직 남아 있다.

단일 endpoint 안에서 기존 물리 계산 순서와 1초 갱신을 유지한다.
450초 horizon, 3개 150초 제어, 231개 미분 축, 8워커 상한, 후보 수와
반복 횟수, 실제 명령의 정수화는 변경하지 않았다. VISSIM 데이터 수집이나
기하·수요·FD 계수·METANET 수식에는 손대지 않았다.

## 검증

수정 전 소스는 `before_sources`, 첫 전체 예측 소스는 `sources_v1`에 있다.

- 보존된 실제 FIFO 소스를 대조군으로 쓴 일반 수치/미분 복합 갱신 검사.
  상태값, 부모 간선과 가중치, 분기/동률 의존성, Jacobian을 비교한다.
- 여러 시간 단계에 걸친 분수 차량 이동, 배열 재사용, 독립 스냅샷,
  읽기 전용 검사, 예외 후 범위 정리, 잘못된 방출량 거부를 확인했다.
- SDMPC 회귀 **134개 PASS**: `regression_v2.log`.
- 기존 도시부·램프 연계 **9개를 OFF/ON 각각 PASS**: `coupling_v1.json`.
  하류 폐쇄 시 재고와 대기 비용, 공유 출구 수용량의 중복 사용 방지,
  실제 공유 대기열 방출 영수증 및 과다 방출 거부를 포함한다.
- 정본 파라미터 검사 PASS: `parameters_v1.log`. 기존 calibration override
  경고는 그대로 남겨 두었으며, 이 옵션의 속도를 위해 계수를 바꾸지 않았다.

최초 단위 검사에는 얕은 리스트 복사를 독립 스냅샷으로 취급한 오류와
불완전한 config fixture가 있었다. `tests_v1/v2` 실패를 보존하고 독립 복사와
실제 config로 고친 `tests_v3`가 통과했다. 수명 검사를 추가한 `tests_v4`도
통과했다. 첫 전체 회귀는 진단 코드의 전역 AD 설정 누출과 추출 메서드
fixture의 새 API 누락으로 실패했다. 설정을 원복하고 object 경로 fixture에
비활성 배열 조회를 제공한 `regression_v2`에서 기존 검사를 모두 통과했다.
검사식이나 허용 오차를 느슨하게 바꾸지 않았다.

## 측정 결과와 적용 판단

첫 실제 저장 상태 검증 `persistent_h3_v1`은 900초 상태에서 450초 예측을
수행했다. 비용, 자원량, 비용/자원 Jacobian 차이는 모두 0이다.
그래프 14,137,087개 노드와 분기 이벤트 수, 동률/불연속 의존 축도 같았다.
이 검증의 총 시간은 154.306초, 일반 예측 60.724초, 미분 예측 131.338초다.
일반/미분 예측은 겹쳐 실행되므로 둘을 더하면 전체 시간이 되지 않는다.

첫 검증의 배열 수치 커널은 111,426번 호출되어 약 1.350초를 썼다.
컴파일 경로가 만든 노드는 1,196,885개지만, 노드 비율을 CPU 시간 비율로
해석하지 않는다. 기존 코드에 숫자를 제공하는 경계 조회가 약 131만 번
남았다. 따라서 배열 연결 성공만으로 전체 실행이 빨라졌다고 할 수 없다.

최종 버전에서도 비용·자원·두 Jacobian 차이 0, 그래프 및 분기 의존성
동일을 확인했다. 같은 소스에서 OFF/ON으로 생성한 전체 저장 상태·비용·자원
차이도 모두 0이다. 결과는 `persistent_h3_v2`와 `states_v1`에 있다.

|측정|기존/OFF|배열/ON|
|---|---:|---:|
|450초 전체 Jacobian 검증|143.419초(과거)|153.682초|
|같은 소스의 일반 예측|57.915초|60.973초|
|전체 SDMPC 결정|386.693초(과거)|444.002초|

전체 결정의 최종 action과 실제 명령으로 변환한 행들, 후보별 결과, 제약,
비용 및 모든 사용된 Jacobian이 기존과 일치했다. 23개 전체 결정 대조 조건을
통과했다(`qualification_summary.json`). 실제 원모델 예측 6회와 후보별 반복
횟수도 유지했고, 종료 시 소유 워커가 모두 정리됐다. 선택 결과는 feasible지만
기존과 마찬가지로 2회 반복 상한에서 종료했으므로 **수렴 인증은 아니다**.
81.25 후보의 기존 QP 실패도 그대로 남으며 성공으로 바꾸지 않았다.

이 한 번의 전체 결정은 기존 측정보다 약 14.8% 느렸다. 과거 측정과의 비교는
실행 환경을 통제한 반복 평균이 아니지만, **속도 향상을 입증하지 못했다**.
같은 소스의 일반 예측 비교도 배열 경로가 느렸다. 따라서 판정은
**연결·수치 동등성 PASS / 성능 NOT_SELECTED_FOR_SPEED / 기본 OFF**다.
150초 결정 목표는 미달이다. 기존 선택 config는 바꾸지 않았다.

원인은 연결 경계가 아직 많다는 점이다. 수치 커널을 배열로 옮겨도 경로 판단,
수용량 배분, Ω 회계가 개별 값과 객체를 요구한다. 현재 구조는 그 경계에서
Dual을 복원하고 작은 미분 그래프를 여러 차례 합친다. 다음에 범위를 넓힌다면
그 요청·배분·회계 계산을 같은 커널 묶음 안으로 옮겨야 한다. 이번 결과만으로
그 추가 이식의 단축률을 예측하거나 150초 달성을 약속하지 않는다.

이 검증은 역사적 900초 저장 상태의 오프라인 계산이다. VISSIM native 적용,
9000초 NC/CL 결과, RM/VSL 순이득이나 plant 보정 완료의 증거는 아니다.
