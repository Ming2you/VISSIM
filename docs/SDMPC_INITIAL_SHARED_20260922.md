# 초기 hold와 AD 예측 공유

사용자가 초기 직렬 구간의 추가 병렬화를 요청했다. 기존 연속화 모델의 초기 일반 hold 예측과 초기 AD를 한 AD trajectory로 합쳤다. 새 키는 `adapter.sdmpc_initial_shared_prediction=true`이고, `sdmpc_surrogate_reuse=true`와 `freeway.lane_plant`가 필요하다. 키가 없으면 기존 초기 평가 순서를 유지한다. 기존 vendor와 단일 VISSIM adapter는 수정하지 않았다.

## 공유가 가능한 이유와 제한

기존 흐름은 일반 hold 예측 → 실제 합류량으로 N_UF 목표 초기화 → 같은 물리 명령의 AD였다. 이 경로의 `ObjectiveSpec.box_walk=False`이며, lane plant의 미터 서비스는 여덟 물리 green에서 정해진다. N_UF는 수량 제약의 목표이므로 이 초기 갱신으로 교통 궤적이 바뀌지 않는다. AD의 primal 요약에서 실제 합류량과 hold 비용·제약을 함께 얻고, 같은 궤적의 Jacobian을 첫 outer iteration에 사용한다. 450초 시간 축을 독립 구간으로 나눈 방식은 아니다.

- 최초 실제 reference와 정확히 같은 명령에서 AD가 완료된 경우만 허용한다. 저장 상태, 수요, 소스, 전체 물리 입력은 고정한다.
- 기존 `initialize_decision_nuf`를 사용해 실제 합류량으로 목표를 다시 계산하고, 목표 외의 모든 action 필드가 동일한지 검사한다. 기존 command evidence 검사도 유지한다.
- 원래 action/response token을 보존하고, 초기 목표 연결 증거를 포함한 별도 summary digest를 만든다. 다른 명령을 새로 예측한 것으로 표시하지 않는다.
- 일반 후보의 N_UF 변경과 actuator 변경은 계속 캐시 miss다. 임의 목표, scalar만 계산된 결과, 두 번째 초기 연결, 미래 입력 변경은 허용하지 않는다.
- 초기 AD를 실제로 소비한 것으로 계산량에 기록한다. 후보별 제약·목표량·전체 3개 제어 블록 검사는 그대로 수행한다.
- 연속화 모델과 독립 primal audit 생략은 이전 실험과 같다. `primal_audit_performed=false`, `complete_primal_state_match=false`, `execution_model_evaluated=false`를 유지하며 native 성능을 뜻하지 않는다.

## 증거

`diagnostics/sdmpc_initial_shared_20260922/`에 변경 전 소스, 별도 실험 config, 테스트 및 계측을 보존한다. 첫 전체 결정 시도는 설정 검사에서 `lane_plant`를 잘못된 config section에서 찾는 오류로 계산 시작 전에 실패했다(`decision_v1.log`). 이를 `freeway` section으로 수정하고 실제 실험 config를 읽는 회귀 테스트를 추가했다. 실패 폴더와 당시 단일 AD 증거는 수정하지 않았다.

최종 테스트는 `regression_v2.log`의 152개 PASS, `tests_v2.log`의 초기 공유 및 기존 재사용 검사 16개 PASS다. `parameters_v1.log`에서 실험 config의 파라미터 검사는 PASS다.

## 측정 결과

900초 저장 상태, 450초 horizon, 3×150초 입력, 최대 8워커, 결정 시간제한 없음으로 비교했다. 전체 결정은 각 버전 1회 측정이다.

| 항목 | 직전 연속화 통합 버전 | 초기 공유 적용 |
|---|---:|---:|
| 전체 결정 시간 | 405.153초 | 341.574초 |
| 후보별 outer iteration 상한 | 2회 | 2회 |
| 선택 후보 수락 iteration | 2회 | 2회 |
| 수렴 확인 | 없음 | 없음 |
| 전체 rollout | 6회 | 5회 |
| 일반 숫자 예측 | 3회 | 2회 |
| AD 예측 | 3회 | 3회 |

63.579초(15.693%) 줄었다. 연속화 통합 이전의 최선 386.693초보다도 짧지만, **150초 목표에는 미달**이다. 두 결과 모두 2 iteration 상한에 도달한 것이며, 6회 iteration이나 수렴 완료 시간이 아니다.

선택된 전체 제어 입력과 출력 명령 행은 직전 버전과 정확히 같았다. hold/선택 목적값은 각각 402.3185395008343/396.47493233989024 veh·h로 동일했다. 결정 중 사용된 두 미분 결과의 비용·자원·두 Jacobian 최대 차이도 모두 0이다.

NP=2400과 743.75 후보는 각각 2회 수락 후 iteration 상한에 도달했고, NP=81.25 후보는 첫 결합 QP에서 실패하여 수락 0회였다. 실패한 후보를 통과 또는 미실행으로 바꾸지 않았다. 95개 local QP에서 교통 rollout은 0회였다.

AD 3회는 초기 1회와 첫 iteration 후보 2회다. 후보 2개는 병렬 실행하고 각 AD의 역전파에 4워커씩 할당한다. 이 중 선택되지 않은 AD 1회도 계산량에 포함한다. 마지막 iteration의 일반 숫자 후보 2개도 병렬 실행한다. 전체 결정 내부 초기 AD 배치는 약 132.8초, 다음 두 AD 배치는 약 138.9초였다. 이 수치는 위 **후보별 상한 2회인 전체 결정의 내부 구간**이다.

별도 `shared_h3_v2/` 단일 AD 검사는 127.984초였다. **최적화 iteration 없는 미분 1회**이며, 기존 결과 대비 비용·자원·두 Jacobian 차이는 모두 0이다. 별도 자격 검사 시간은 전체 결정 시간에 포함하지 않았다.

다음 후보는 현재 미분으로 만든 최적화 해에 의존하므로, 다른 outer iteration의 AD를 정확한 입력으로 미리 병렬 실행할 수 없다. 이번 변경은 초기 중복 trajectory를 제거했으며, 교통의 시간 순서를 독립적인 병렬 문제로 바꾸지는 않았다.

## 원 실행용 예측 모델의 사후 대조

`exact_audit_v1/`에서 hold와 선택 명령을 원 실행용 모델로 별도 예측했다. **최적화 iteration 0회인 사후 대조**이며 48.838초, 예측 2회를 병렬 실행했다. 이 진단 시간은 341.574초 결정 시간에 포함하지 않는다.

선택 명령은 원 실행용 모델에서도 제약을 만족했다. N_P=562.245842대 ≤ 2400대이고, N_UF=5142.757016 veh/h와 목표 5144.162909 veh/h의 차이는 -1.405893 veh/h로 허용 ±40 이내였다. 최대 자원 초과량은 1.11e-15대의 반올림 수준이었다. 원 명령과 출력 명령의 차이는 없고, 3개 블록의 actuator 범위·변화량 검사를 통과했다.

원 실행용 모델의 hold/선택 Ω TTT는 402.312512/396.573709 veh·h로 직전 버전과 같았다. 예측 감소율 1.42645%는 VISSIM 실런 개선율이 아니다. 이번에 native 또는 9000초 런은 실행하지 않았다.

전체 결정은 `full_decision_v2/`, 결과·소스 고정 검사는 `summary.json`, 최종 소스 사본은 `final_sources/`에 보존한다. 기능은 별도 실험 config에서만 켜며, 기존 최선 config와 과거 실행 증거는 그대로 둔다.
