## 1. VSL 구속 판정

### 1-0. 먼저 부호 규약을 바로잡는다

`metanet.py:96` 이 유일한 VSL 경로다.

```python
return float(min(no_vsl, (1.0 + alpha_vsl) * vsl))
```

`V_eff = min(V(ρ), VSL)` 이므로 **VSL 이 상태식을 바꾸는 구간은 `V(ρ) > VSL`, 즉 `ρ < ρ_bind(VSL)` 이다.**
밀도가 높아질수록 VSL 은 무효가 된다.

선행 모형비교 표에는 이것이 "구속 시작 밀도(그 아래에서는 VSL 이 무효)"로 **뒤집혀** 적혀 있었다.
`outputs/vsl_sensitivity_20260801.md` §1-1 의 표는 올바른 규약(ρ_bind 가 커질수록 구속 비율 증가)을
쓰고 있으므로, 뒤집힌 쪽이 오기다. 아래는 전부 올바른 규약 기준이다.

관측 최대 링크유량은 8,401 veh/h.

**판정 — 현행 캡은 "꺼져 있는 것처럼 보이지만 실은 절반 이상의 상태를 자르고 있다."**
FD 곡선 위에서는 폭 0.16 veh/km 에서만 걸리므로(자기 최대치와 동일하게 맞춰져 있어서) 설계상
비활성으로 보인다. 그러나 어댑터의 `q_values` 는 **VISSIM 에서 읽은 실제 (ρ, v)** 로 계산되고
그 상태는 내부 FD 곡선 위에 있지 않다 — 내부 FD 가 실측 대비 크게 낮기 때문이다
(모형 용량 1,228/lane vs 관측 자유류 용량 1,962/lane).

결과적으로 **롤아웃은 관측 상태의 52.7% 에서 유량을 평균 837 veh/h(캡의 17%) 잘라낸다.**
방향은 전부 한쪽 — 본선이 실제보다 덜 배출한다고 예측 → 밀도가 덜 빠진다고 예측 →
`density_excess_tts` 가 과대 → 리더/팔로워가 존재하지 않는 정체를 보고 결정한다.
이건 조용한 계통 편향이고, 지금까지 어느 진단에도 잡히지 않았다.

### 3-2. 캡은 롤아웃에만 있는 게 아니다

`freeway_capacity_veh_h` 는 플랜트에서도 광범위하게 소비된다.

| 소비처 | 파일:줄 | 역할 |
|---|---|---|
| 램프 방출 상한 | `metanet.py:278, 301` | `no_meter = min(available, cap, q_cap · receiving_factor)` |
| 본선 진입 상한 | `metanet.py:498` | `entry_realized = min(entry_request, q_cap, receiving[0])` |
| 터미널 배출 상한 | `metanet.py:526-527` | `terminal_cap = q_cap · λ/λ_nom` |
| capacity drop 송출 상한 | `metanet.py:440` | `φ · q_cap · λ/λ_nom` |
| 완충 체인 | `metanet.py:495, 692, 697` | 동일 |

**캡을 4,914 → 6,148 로 올리면 램프 방출 천장과 본선 진입 천장이 동시에 25% 올라간다.**
6,148 → 8,064 이면 64% 다. 이것은 "캡이 꺼진다"가 아니라 **플랜트 거동 자체의 변경**이며,
TTT·큐·spillback 전 지표가 움직인다. 캡 값은 FD 형태와 독립적으로 결정할 수 없다 —
FD 를 바꾸면 캡도 반드시 같이 바꿔야 하고, 그 순간 기존 런과의 비교 가능성이 끊긴다.

### 3-3. 부수 확인 — 현행 캡을 권고 A FD 에 그대로 얹으면

권고 A FD(최대 6,148)에 현행 캡 4,914 를 남기면 FD 곡선상 구속 대역이 **ρ ∈ [12.90, 54.37]** 로
폭 41.5 veh/km 까지 벌어진다. 즉 **캡이 FD 를 대체해 버린다** — 운영 밀도 대부분에서 유량이
FD 가 아니라 상수 캡으로 결정된다. 파라미터를 한 벌로 갈아야지 섞으면 안 된다는 뜻이다.

## 4. two_branch 활성화 여부와 범위

### 4-1. 권고 A 는 필요 없다. 권고 B 는 필요하다

권고 A(S3/Cheng)는 단일값 FD 이므로 `vsl_fd_two_branch` 와 무관하다. 다만 **S3 형태 자체가
`metanet.py` 에 구현되어 있지 않다** — `desired_speed_kmh`(15-17)는 지수형 전용이고 `metanet_a_m`
하나로 형상을 받는다. S3 채택은 `desired_speed_kmh` 에 형태 분기 추가 + 형태 선택 필드 신설이
필요하며, 그 함수는 플랜트/예측/어댑터 전체가 호출하는 최핵심 경로다.

권고 B 는 `NetworkConfig` 정식 필드 신설이 선행되어야 한다.

### 4-2. 필요한 코드 변경의 정확한 범위

**(a) 필드 신설 — `src/models/state.py` `NetworkConfig`(187행~)**

`ExperimentConfig.from_dict`(`state.py:700`)가 `NetworkConfig(**raw.get("network", {}))` 로
생성하므로, dataclass 필드에 없는 키를 overrides 로 넣으면 **TypeError 로 즉사한다.**
따라서 `getattr` 기본값에 기대는 현재 구조로는 켤 수 없다는 사용자 전제는 정확하다.

| 필드 | 기본값 | 비고 |
|---|---|---|
| `vsl_fd_two_branch` | `False` | 마스터 스위치 |
| `rho_crit_two_branch` | `0.0` | 삼각형 공칭 임계(권고 B: 16.45) |
| **`rho_jam_veh_km_lane`** | `0.0` | **신설 필수** |

**(b) `rho_jam` 앵커 교체 — 이게 진짜 작업이다**

현재 two-branch 코드는 전부 `net.rho_max` 를 rho_jam 으로 소비한다.

| 위치 | 현재 |
|---|---|
| `metanet.py:68` | `rho_crit_for_vsl(v, net.v_free, two_branch_nominal_rho_crit(net), float(net.rho_max))` |
| `metanet.py:602-604` | `effective_desired_speed_kmh(..., net.rho_max, ...)` |
| `metanet.py:675-676` | 완충 체인, 동일 |
| `local_freeway_plant.py:298-299` | 예측모델, 동일 |

`rho_max = 95.0196`(`state.py:189`)은 정체밀도가 아니라 **관측 최대밀도**다(신 점군 rho_max=95.24).
실측 정체밀도는 146.7 이다. 이 값으로 앵커하면 삼각형이 w=15.48 과 용량 1,962 를 동시에 만족
못 하고, 강제하면 ρ_crit=10.7 / 용량 1,306(−33%)로 붕괴한다.

그런데 `rho_max` 는 CTM receiving supply(`metanet.py:447-456`)와 밀도 클램프
(`adapter:290`)에서도 쓰이므로 **값을 바꾸면 안 된다.** `rho_jam` 을 별도 필드로 신설하고
two-branch 경로만 그것을 보게 바꾸는 것이 유일하게 안전한 길이다(미설정 시 `rho_max` fallback → 비트 동일).

**(c) 어댑터 배선 불일치 — 미조치 시 예측/플랜트가 갈린다**

`vissim_stackelberg_adapter.py:298-305` 의 VSL 후보 랭킹 롤아웃은
`effective_desired_speed_kmh` 를 **two_branch 인자 없이** 호출한다.

```python
v_eff = metanet_module.effective_desired_speed_kmh(
    rho, float(net.v_free), float(net.rho_crit), float(vsl_kph),
    float(getattr(net, "alpha_vsl", 0.0)), bool(vsl_active),
    float(getattr(net, "metanet_a_m", 1.867)),
)                      # ← two_branch / rho_jam / rho_crit_tb 인자 없음
```

같은 함수의 `density_excess_tts`(293-294)도 `float(net.rho_crit)` 고정,
`select_anticipation_nu(rho, net)`(316)도 vsl 미전달이다. **two_branch 를 켜도 이 함수는 계속
min-cap 으로 VSL 후보를 채점한다** — 플랜트는 two-branch, 어댑터 랭킹은 min-cap 이 되어
`vsl_sensitivity_20260801.md` 가 지적한 "예측-플랜트 배선 불일치"가 재발한다.
`local_freeway_plant.py:296-299` 는 이미 정합하게 고쳐져 있으므로, 남은 곳은 어댑터다.

**(d) 캘리브레이션 배관 — `adapter:975-990` `calibration_to_config_overrides`**
새 키 3개를 `out["network"]` 에 방출하고 캘리브레이션 JSON 스키마에 대응 필드를 추가해야 한다.

### 4-3. flagship 재현성 영향

| 변경 | 재현성 영향 |
|---|---|
| 필드 3개 신설 (기본 False/0.0) | **없다.** `getattr` 경로가 그대로 기본값을 받으므로 비트 동일 |
| `rho_jam` 신설 + fallback `rho_max` | **없다.** two_branch OFF 면 호출 자체가 안 일어남 |
| 어댑터 롤아웃 배선 수정 | two_branch OFF 이고 `capacity_drop_anticipation=False` 이면 `effective_rho_crit` 이 vsl 을 무시하므로 **정의상 no-op** — 비트 동일 |
| **캘리브레이션 값 교체 (v_free/ρ_crit/a/capacity)** | **여기서 깨진다.** 형태와 무관하게 모든 기존 flagship 런과 비교 불가 |

즉 **코드 변경은 재현성을 깨지 않는다. 재현성을 깨는 것은 캘리브레이션 값 교체다.**
두 결정을 분리해서 처리할 수 있다는 뜻이고, 실제로 그렇게 하는 편이 낫다(§6).

### 4-4. VSL 채널이 되살아날 가능성 — 평가

| 채널 | 현행 | 권고 A | 권고 B |
|---|---|---|---|
| 속도식 `V_eff = min(V, VSL)` | 혼잡에서 0 | 혼잡에서 0 | 자유분지 전체에서 활성 |
| 램프 receiving_factor (`metanet.py:289-294`) | VSL 무관 | VSL 무관 | **ρ_c(VSL)↑ → receiving_factor↑** |
| capacity drop 발화 임계 (`metanet.py:135, 437`) | VSL 무관 | VSL 무관 | **ρ_c(VSL)↑ → drop 회피** |
| 리더 density 벌점 (`leader.py:808`) | VSL 무관 | VSL 무관 | **VSL80 이 −31.6/스텝** |
| leader `_feasible_nuf_capacity` headroom (`leader.py:707-708`) | VSL 무관 | VSL 무관 | **headroom↑ → N_UF 예산↑** |

**권고 B 는 죽어 있던 채널 4개를 동시에 켠다.** 다만 `capacity_drop_anticipation=False` 이고
`metanet_nu_cong_km2_h = metanet_nu_km2_h = 65.0` 이라 drop 채널은 **켜도 현재는 무효**이며,
`capacity_drop_discharge_phi=1.0` 이라 φ 채널도 비활성이다. 실측 drop 은 30.3%(φ≈0.70)이므로,
VSL 이 실제로 payoff 를 갖게 하려면 `φ` 와 `ν_cong` 를 함께 열어야 한다.
**`vsl_fd_two_branch` 만 켜는 것은 절반의 조치다.**

그리고 선행 실측 경고를 유지한다 — `vsl_sensitivity_20260801.md` 는 기전을 켠 조건에서도
**최대 이득 −1.1%** 를 보고했다. 채널이 살아나는 것과 이득이 나는 것은 다른 문제다.

## 6. 결론 — 채택 권고안과 대안

**결정은 사용자에게 남긴다.** 아래는 근거와 그 경계다.

### 6-1. 채택 권고안 — 권고 B (two-branch, 물리 앵커)

`v_free = 122.56`, `rho_crit_two_branch = 16.45`, `rho_jam = 146.7`, `w = 15.48`,
`freeway_capacity_veh_h = 8,064`(또는 관측 7,849).

**근거.**

1. **용량이 처음으로 맞는다.** 8,064 /link 는 관측 자유류 용량 7,849 및 원 선언값 7,600 과
   정합한다. 현행 4,914 는 관측 대비 −37% 다. §3-1 이 보여주듯 그 격차가 롤아웃 상태의
   52.7% 를 평균 837 veh/h 잘라내는 계통 편향을 만들고 있다. **이건 v_free=149.7 보다 심각한 결함이고,
   지금까지 아무도 안 봤다.**
2. **v_free 가 물리 상한(122.56) 안에 있다.** 원 문제가 해결된다.
3. **VSL 채널 4개가 동시에 살아난다**(§4-4). 죽은 결정변수를 되살리는 유일한 후보다.
4. `ρ_crit` 공칭 16.45 가 현행 16.354 와 사실상 같아 **리더 벌점 감도가 유지된다**(§2-1).
   권고 A 처럼 공짜 대역을 10.4%p 넓히지 않는다.
5. 혼잡 분지 Newell 적합(w=15.48, rho_jam=146.7)은 런 간 ±2% 로 재현된다 — 신뢰할 수 있는 물리값이다.

**경계 — 이걸 채택하면 감수하는 것.**

- 자유 분지가 **상수속도**라 관측(ρ 3→27 에서 114.5→64.4)을 구조적으로 못 맞춘다.
  bin WRMSE 4.88~5.63 으로 현행 4.005 보다 **나쁘다.** 0–5 대역 −7.1, 20–27 대역 −8.2 로 양끝 동시 실패.
  **적합 품질을 물리 정합성과 맞바꾸는 선택이다.**
- 코드 변경이 가장 크다(§4-2 (a)~(d)). 4곳의 `rho_max`→`rho_jam` 교체와 어댑터 배선 수정이 선행되어야 한다.
- `φ` 와 `ν_cong` 를 함께 열지 않으면 절반의 조치다.

**채택 시 필수 검증 두 가지.**
- (i) §2-4 의 리더 벌점 −31.6/스텝이 **VISSIM 실측 TTT 개선으로 나타나는지.** 안 나타나면
  기준선을 옮겨 스스로를 면책한 것이다. `vsl_sensitivity_20260801.md` 의 "기전을 켜도 최대 −1.1%"
  경고가 살아 있다.
- (ii) 용량 8,064 로 올린 뒤 **램프 방출 천장(+64%)이 spillback 을 만들지 않는지**(§3-2).

### 6-2. 대안 — 권고 A (S3/Cheng, 단일값)

`v_free = 122.56`, `rho_crit = 26.48`, `m = 1.855`, `freeway_capacity_veh_h = 6,148`.

**언제 이걸 고르나.** 코드 변경 범위를 최소로 묶고, 적합 품질(bin WRMSE 3.394, 현행 4.005 대비 −15%)과
v_free 물리성만 확보하고 넘어가고 싶을 때다. 캡 구속도 52.7% → 11.0% 로 크게 개선된다.

**정직하게 적는 한계.**
- **VSL 은 여전히 죽어 있다**(§1-1, 혼잡 분지 구속비 0.000). 메뉴를 50까지 내려도 마찬가지다.
- **리더 가격 신호가 오히려 약해진다**(§2-2, 공짜 대역 10.4%p 확대).
- **용량이 여전히 −22%** 다(1,538 vs 관측 1,962). §3-1 의 계통 편향이 줄지만 사라지지 않는다.
- `desired_speed_kmh` 에 형태 분기를 넣어야 하므로 "코드 무변경"은 아니다.

요약하면 **권고 A 는 v_free 문제만 고치고 용량 문제와 VSL 문제는 그대로 둔다.**

### 6-3. 어느 쪽을 고르든 먼저 해야 하는 것

**용량 등식 제약을 재정의하라.** 현행 적합의 `q_cap_obs = 1,575.8 @ ρ=27` 은 그 bin 안
자유분지 18점(1,739)과 혼잡분지 6점(1,076)의 **혼합 평균**이다. 자유류 용량도 배출률도 아닌 값이다.
`capacity_bin_is_interior_max: true` 는 식별성 확보 신호가 아니라 혼합 경계를 용량으로 오인한 결과다.
**이 제약이 남아 있으면 어떤 형태를 골라도 용량은 1,500대에 묶인다.**

### 6-4. 하지 말아야 할 것

- **FD 값만 갈고 `freeway_capacity_veh_h` 를 그대로 두는 것.** §3-3 — 권고 A FD 에 현행 캡 4,914 를
  남기면 캡 구속 대역이 ρ∈[12.90, 54.37] 로 벌어져 **캡이 FD 를 대체해 버린다.** 한 벌로 갈아야 한다.
- **점 RMSE 로 후보를 서열화하는 것.** regime 을 완벽히 안다고 가정한 상한조차 pt RMSE 10.006 이다.
  후보 간 차이는 세그먼트 이질성 잡음 안에 있다.
- **`vsl_fd_two_branch` 만 켜고 `rho_jam` 앵커를 안 고치는 것.** `rho_max=95.02` 로는 임계가
  12.2→16.3 밖에 안 움직이고 용량 변화 1.7% 라 **레버가 사실상 없다.** 켜도 아무 일이 안 일어난다.
- **§2-4 의 −31.6 을 이득으로 보고하는 것.** VISSIM 검증 전에는 회계 변경일 뿐이다.
