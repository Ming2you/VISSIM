# 컨텍스트 노트 — FD 재적합 (2026-08-02)

## D1. 용량 등식 제약을 버리고 `alt_unconstrained` 를 채택한 이유

`fit_freeway_fd_20260801.py` 는 관측 최대 binned 유량을 용량으로 박는 제약 적합(`primary`)을 기본으로 쓴다.
이번 데이터에서는 그 제약이 **식별되지 않는다**.

- 표본수 ≥ 10 인 bin 중 최대는 bin 19(n=16, 1266.5 veh/h/lane)인데, 위쪽 bin 21/23(n=5/4)의 유량이
  1291.1 / 1431.7 로 **더 높다**. 곡선이 아직 상승 중 → 관측 최대는 용량이 아니라 절단점.
- `capacity_bin_is_interior_max = false` 로 스크립트 자신이 WARN 을 낸다.
- `--cap-min-n` 을 10→4 로 바꾸면 v_free 120.30→127.64, rho_crit 17.44→23.61 로 크게 이동. 비식별 확증.
- `alt_unconstrained` 가 적합도도 낫다(bin 가중 RMSE 1.901 vs 2.011, 점 RMSE 11.597 vs 11.620, bias −0.058 vs +0.135).

두 적합의 차이 자체는 작다(v_free 0.8 km/h, 용량 3 %). **다만 v_free 가 120 을 넘느냐 마느냐가 갈린다** —
이것이 §10-4 정합성 쟁점의 실체다.

## D2. leaf tuning 이 필요한 이유 (기존 진단 재확인)

`real_world_modi_pstack_adapter_v1_response_calibrated_20260721.json` 이
`calibration_override.operational.network = {120, 30, 6900}` 을 박아 두고 있다.
어댑터는 calibration 을 읽은 뒤 tuning 의 `calibration_override` 로 **덮어쓴다**
(`vissim_stackelberg_adapter.py:3824-3826`). 그래서 캘리브레이션 파일만 갈면 도달하지 못한다.

실측 확인(어댑터 경로 그대로 로드)

| tuning | calibration | 컨트롤러가 보는 값 |
|---|---|---|
| segvsl_20260801 | v0_20260719 | 120.0 / 30.0 / 1.867 / 6900 |
| segvsl_20260801 | **v2_fdrefit_20260802** | 120.0 / 30.0 / **2.154** / 6900 |
| **segvsl_fdrefit_20260802** | v0_20260719 | 119.505 / 16.354 / 2.154 / 4914 |
| **segvsl_fdrefit_20260802** | **v2_fdrefit_20260802** | 119.505 / 16.354 / 2.154 / 4914 |

2행이 가장 위험한 상태다 — `adapter_v1` 이 `desired_speed_shape_a` 는 덮지 않으므로 **a 만 새 값**이 되고
v_free/rho_crit 은 구값으로 남는 **부분 적용**이 된다. 캘리브레이션만 갈아치우는 선택지는 없다.

부모 tuning 은 zone4 등 진행 중 작업이 상속하므로 손대지 않았다.

## D3. `frac_points_binding_*` 부호 버그

V(rho) 는 단조감소이므로 `V_eff = min(V(rho), VSL)` 에서 VSL 은 **rho ≤ rho_bind** 에서만 구속한다.
스크립트는 `rho >= rho_bind` 로 세고 있어 정확히 여집합을 보고했다(VSL 80: 3.7 % ← 실제 95.6 %).
`vsl_sensitivity_20260801.md` §1-1 의 92.7 % 와 부호가 반대라 즉시 드러났다. `r <= rb` 로 수정.

구 문서의 수치는 다른 경로로 계산돼 영향 없음 — 재계산 스크립트에 구 파라미터(120/30/1.867)와 구 점군을
넣어 rho_bind 25.84 / 구속 92.7 %, 16.84 / 65.6 %, RMSE 36.44 / bias +35.08 을 그대로 재현해 확인했다.

## D4. 구/신 밀도 비교는 정규화로만

측정격자가 8×1.0048 km(8.04 km) → 8×1.3466 km(10.77 km)로 늘었다. 자유류 구간이 더 많이 포함돼
밀도 절대값이 내려간다. p50 13.95 → 9.09 를 "혼잡이 줄었다"로 읽으면 안 된다.
rho_crit 로 정규화하면 p50/rho_crit 0.465 → 0.556, p95/rho_crit 0.932 → 0.919 로 **레짐은 거의 그대로다**.

## D5. 남은 위험 — 용량 파라미터

채택한 `freeway_capacity_veh_h = 4914`(링크) 는 관측값이 아니라 적합 곡선의 외삽 최대치다.
어댑터는 이 값을 `q = min(q, cap)` 캡으로만 쓰므로(`vissim_stackelberg_adapter.py:257-263`),
캡을 자기 FD 최대치와 같게 두면 **그 FD 위에서는 절대 구속하지 않는다**.
구 조합(FD 최대 8446 vs 캡 6900)은 실제로 구속했으므로 이번 갱신은 내부 모델의 캡 하나를 끈 셈이다.
확정하려면 rho_crit 을 확실히 넘기는 고수요 no-control 런이 추가로 필요하다.

## D6. 결정 보류 항목

v_free = 119.505 < 120 이라 현행 메뉴 [80,100,120] 과 **모순은 없다**(120 이 무제어 앵커로 정합).
그러나 여유가 0.5 km/h 뿐이고, 폐기한 `primary` 적합이었다면 120.300 > 120 이 되어 앵커가 속도 캡으로
성격이 바뀌었다. 방안 A(현행 유지) / B(앵커 상향) / C(코드에서 앵커 명시) / D(메뉴 바닥, P4 연동)를
§10-4 에 적어 두고 결정은 하지 않았다.
