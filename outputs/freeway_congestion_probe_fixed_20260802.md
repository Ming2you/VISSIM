## 3. urban 상태 — lowurban 에서 도시부는 막히지 않았다

도시 링크(`category = urban_or_other`) 기준.

**lowurban arm 은 순수 본선 혼잡 실험으로 성립한다.** 신 lowurban 의 도시부는
재차량 2,011.6 / 정지 비율 40.56 % / 평균속도 34.27 km/h 로,
도시 수요가 사실상 배수 1.00 이던 **구 lowurban(2,256.8 / 42.30 % / 33.90)보다
오히려 가볍고 빠르다.** 본선이 43 km/h 로 붕괴한 상태에서도 도시부가 나빠지지 않았으므로
본선 혼잡이 도시부 병목의 부산물이 아니라는 것이 확인된다.

breakdown 은 urban ×1.20 을 함께 걸어 도시부도 같이 나빠졌다(정지 비율 49.87 %).
**본선만 격리하고 싶으면 lowurban 을 쓰는 것이 맞다.**

주의 — 40 % 대 정지 비율은 이 신호망의 정상 수준이다(적색 대기 포함). 구/신 비교로 읽어야지
절대값으로 "도시부가 막혔다"고 읽으면 안 된다.

### 4-3. ★ 값을 채택하기 전에 반드시 볼 것 (판정만, 채택 결정은 하지 않음)

식별 판정은 통과했지만 **적합값 자체는 그대로 믿기 어려운 신호가 셋 있다.**

1. **v_free 149.7 km/h 는 관측 최대 속도(122.6 km/h)보다 높다.** 물리적으로 불가능한 값이다.
   제약 있는 적합과 없는 적합이 똑같이 ~150 으로 가므로 데이터가 밀어올린 것이고,
   원인은 모형 형태다. 긴 혼잡 꼬리가 `a` 를 2.15 → 0.95 로 끌어내리면
   자유류 고원이 사라져 rho→0 에서 속도가 과대추정된다.
   편향표에서 rho 0~5 구간 관측 115.9 vs 모형 127.7 (−11.8 km/h) 로 드러난다.
   **단일 지수형 METANET 식이 자유류 고원과 혼잡 꼬리를 동시에 못 맞춘다.**

2. **혼잡 분지의 유량이 단조롭지 않다.** bin 평균 차로당 유량이
   rho 27 에서 1,576 → rho 31 에서 1,236 으로 떨어졌다가 rho 49~51 에서 1,493~1,501 로
   다시 오른다. 용량 강하(capacity drop)와 세그먼트 이질성이 섞인 형태다.
   "용량 bin" 이 이 잡음 구간의 국소 최대일 수 있고, 실제로 extreme 단독 적합에서는
   용량 bin 이 중심 **49.0** 에서 잡혔다 — 명백히 혼잡 분지 안이다.

3. **표본 분포가 반대쪽으로 치우쳤다.** 각자의 적합 rho_crit 을 기준으로 보면
   구 데이터는 임계밀도 위 표본이 **1.6 %**(rho_crit 17.44) 뿐이었는데
   신 데이터는 **39.3 %**(rho_crit 30.14)다. 운영 분포로서는 둘 다 대표성이 없다.
   가중 방식(현행은 bin 표본수 가중)에 따라 결과가 크게 달라질 여지가 있다.
   실제로 `alt_equal_bin_weight` 는 rho_crit 32.33 / v_free 140.50 으로 벌어진다.

4. 방향별 적합이 크게 어긋난다 — FW_E v_free 138.6 / rho_crit 31.9,
   FW_W v_free **181.7** / rho_crit 29.1. FW_W 값은 그 자체로 폐기 수준이다.

**따라서 이 문서는 값과 판정만 보고하고 캘리브레이션 교체를 권고하지 않는다.**
교체 전에 최소한 (a) v_free 상한 제약을 건 적합, (b) 자유류/혼잡 분지 분리 적합 또는
용량 강하를 표현할 수 있는 형태, (c) 대표 운영 분포에 가까운 표본 재구성이 필요하다.

## 5. ★ 이 버그가 무효화하는 범위

### 5-1. 무효 — 러너 측 수요 스케일에 의존한 결과 전부

`-DemandScale` / `-DemandProfile` 로 수요를 바꾼 모든 런은 **분석창 수요가 원본이었다.**
분석창에서 스케일 라벨은 의미가 없고, 실제로 달랐던 것은 웜업 적재량뿐이다.

| 대상 | 무효화 내용 |
|---|---|
| FD 재적합 데이터 (`no_control_fd_mfd_20260802_scale135/170_*`) | 두 데이터셋 모두 분석창 수요가 동일한 원본이다. "scale 1.35 / 1.70 두 수요를 풀했다"는 전제가 거짓이고, 사실상 초기조건만 다른 같은 수요 2회 반복이다. rho>20 표본 0.6 % 도 이 때문이다. |
| `outputs/fd_refit_20260802_fit.json` | 위 데이터로 적합한 결과. `capacity_bin_is_interior_max = false` 는 데이터 절단의 결과였고, 절단의 원인이 바로 이 버그다. |
| `evaluation/configs/real_world_modi_pstack_flagship_segvsl_fdrefit_20260802.json` | **현행 배포 캘리브레이션**이 위 적합의 `alt_unconstrained`(v_free 119.505 / rho_crit 16.354 / capacity 4914)를 그대로 쓴다. 용량이 절단점에서 왔으므로 과소일 가능성이 크다(신 관측 6,294~6,303). |
| 기준선 A/B 의 수요 라벨 (`outputs/new_baseline_ab_20260801.md`, `_scale135.json`, `_scale170.json`) | "scale 1.35" / "scale 1.70" 라벨이 분석창에 대해 거짓이다. 두 arm 은 **분석창 수요가 동일**하다. |
| 본 문서 이전의 본선 혼잡 탐침 3종 | 위 §1~2 로 정량화 완료. |
| 혼잡 사다리 (`run_real_world_congestion_ladder.ps1`, scale 1.50/1.70/1.90 및 mixed_critical 프로파일) | 같은 경로. 사다리의 단계 구분이 분석창에서 성립하지 않는다. |

### 5-2. ★ "수요에 따른 부호 전환" 해석 — 근거가 바뀐다

`new_baseline_ab_20260801.md` §8-2 의 핵심 관측은
"scale 1.35 에서 나빠졌던 것이 scale 1.70 에서는 좋아진다" 였고
이것이 "이번 A/B 에서 가장 중요한 관측" 으로 기록돼 있다.

**두 arm 은 분석창 수요가 같았다.** 그러므로 이 현상은 수요 수준의 함수가 아니다.
무제어 기준선 두 런을 직접 대조하면 차이의 정체가 보인다.

| 지표 (분석창 평균) | scale135 | scale170 | 비 |
|---|---|---|---|
| freeway 재차량 | 790.9 | 812.1 | 1.027 |
| freeway 평균속도 | 100.33 | 99.34 | 0.990 |
| urban 재차량 | 2,335.8 | 2,638.0 | **1.129** |
| 정지 차량 | 1,030.4 | 1,308.9 | **1.270** |

600 s bin 총 재차량 비(170/135)는 1.285 → 1.274 → 1.097 → 1.070 → 1.081 → 1.085
→ 1.117 → 1.126 으로 **1.0 으로 수렴하지 않고 7~13 % 오프셋으로 고착된다.**
웜업에서 더 실린 차량이 도시망 큐로 남아 끝까지 빠지지 않기 때문이다.

즉 정확한 재기술은 이렇다. **"수요를 26 % 올렸을 때 부호가 뒤집힌다" 가 아니라
"웜업 적재를 26 % 올려 도시부에 13 % 더 무거운 초기 큐를 남겼을 때 부호가 뒤집힌다" 이다.**
freeway 는 두 arm 모두 자유류(99~100 km/h)로 사실상 동일했으므로,
부호 전환의 무대는 본선이 아니라 **도시부 큐 적재량**이었다.
§8-3 의 "개선은 VSL 이 아니라 램프 미터링과 SC 1 신호에서 나왔다" 는 부속 결론은
이 재해석과 오히려 정합적이지만, **"수요 민감도" 라는 이름으로 일반화한 부분은 폐기해야 한다.**

또한 컨트롤러 arm 은 **예보-실측 불일치**까지 함께 안고 있다.
`LoadInpxDemandSchedule` 은 예전부터 6개 인터벌 전부에 배수를 곱해 예보를 만들었으므로
컨트롤러는 스케일된 수요를 믿고 최적화했는데 시뮬레이션은 900 s 이후 원본으로 돌아갔다.
scale 1.70 arm 에서 컨트롤러는 실제보다 70 % 큰 수요를 예보로 받았다.
**과거 런의 예보-실측 오차 분석은 수요 수준뿐 아니라 이 불일치로도 오염돼 있다.**

### 5-3. 유효 — 영향받지 않는 것

| 대상 | 근거 |
|---|---|
| 강제응답 그리드 (`forced_response_grid_20260802`) | 파생망 `fr_fw100` / `fr_fw125` 가 배수를 **.inpx 전 시간구간에** 미리 구워 넣었고, 러너는 `-DemandScale 1.00` 으로 돌았다. 러너 경로를 타지 않으므로 무영향이다. |
| VSL 세그먼트 계열 러너 (`modi_eval_vsl_segmented.inpx` / `_8seg.inpx`) | 두 망 모두 입력당 시간인터벌이 정확히 1개다(전수 XML 감사). `Volume(1)` 이 전 구간을 의미하므로 버그가 아니다. |
| 배수 없이 돈 모든 no-control 런 (scale 1.00, 프로파일 없음) | 스케일 경로를 타지 않는다. |
| 신호 적합 / 서비스 곡선 계열 | 수요 스케일 비의존. |

### 5-4. 주의 — 이번 재실행이 아직 답하지 않은 것

- 컨트롤러 arm 은 재실행하지 않았다. 기준선 A/B 의 **Δ% 결론은 재실행 전까지 미정**이다.
- 본선 배수 1.90 이 이미 포화라 3종 사다리가 붕괴했다. 강도 구분이 필요한 후속 실험은
  배수를 새로 잡아야 한다(본선 1.2~1.8 구간 탐색 권장).
- seed 13 단일이다. 혼잡 고착 여부의 시드 민감도는 확인하지 않았다.
