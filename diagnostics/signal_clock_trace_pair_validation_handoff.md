`validate_trace_pair(left_folder, right_folder)` is a stdlib-only check of two completed preflight manifests. Pass the original-clock folder first and cached-clock folder second, while the working clock is the reviewed cached version. Success returns a compact dict with `passed=True`; a failed check raises. It does not import the model, spawn processes, or read/recollect raw trace DBs.

The helper requires successful preflight/trace completion, empty errors, unchanged source/input/tracer flags, root PID agreement, complete observed child coverage, equal process/task counts, equal normalized local and v1 hashes, and equal nonlegacy identity contracts. Both sides must pin the same tracer sources, including `evaluation_trace_storage.py` and the launcher. The recorded Python executable, PYTHONPATH, hash seed and environment must agree, with monitor/local enabled and no other diagnostic mode or bootstrap recorded. Only the two trace output environment paths differ; each must resolve to its own execution folder and manifest. Action output command paths are also tied to the corresponding folder.

Source comparison permits exactly `signal_actuation_contract.py` at the reviewed original and cached SHA values, in that order. The current source must match the cached run; all other source, tracer and input bytes are rehashed. The two separately located tuning files must contain identical pinned bytes. The raw snapshot, run and timestamp must match, and selected command inputs must be pinned. Both manifests are rehashed after the check to detect changes during the read.

The helper consumes the preflight's already validated trace hashes and process completion certificate. It does not independently certify raw DB contents again. The existing exact returned action JSON/CSV comparison remains mandatory and separate, as does normal performance measurement. Python version is not present in these manifests; this helper verifies the recorded executable path, not an unrecorded version claim.

Five small synthetic guard tests passed in 0.840 seconds. They include failure/error flags, missing children, local/v1 hash/identity/count mismatches, environment leakage, cross-run output paths, missing storage pin, changed source/input bytes, reversed clock direction and command-state/config mismatches. Source hashes and exact command are in `signal_clock_trace_pair_validation_result.json`. No launcher, driver, storage, production or Git files were changed.
