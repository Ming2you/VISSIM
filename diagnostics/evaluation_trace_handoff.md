# Evaluation trace v1 — initial launcher ready

This diagnostic records ordered leader proxy/full/PFO operations, outer logical follower returns, price batches/tasks/leaves, the outer objective endpoint, and each actually executed control interval inside it. It observes original call/return frames; it does not replace production functions, generate candidates, warm caches, change actions, or invoke extra endpoints. No production/Git/VISSIM/MPC changes or runs were made for this implementation.

**Coverage is deliberately incomplete for user requirement 7-4:** individual urban green/phase/offset local candidates and every freeway VSL sequence score are not yet captured. `valid` means complete within the declared v1 coverage, not proof of full optimizer-candidate equivalence. The first actual baseline trace is still required to test real runtime serialization and installed-callable coverage. Synthetic tests are not a substitute for it.

Use the existing canonical preflight command with `--evaluation-trace` added. For example, retain the actual recorded `--run`, `--time 900`, `--beta 300`, `--config-directory contract_candidate_configs_v4`, `--execute` and explicit timeout chosen by root. No default input source is substituted by this tool. The launcher removes inherited phase/cProfile/evaluation variables and their known bootstrap paths, selects one mode, preserves source/input pins, and requires the returned trace root PID and every observed child PID to have complete valid evidence. The three trace/profile flags are mutually exclusive before any process launch.

Output is under that preflight's `evaluation_trace/`: `evaluation_PID.started.json`, `.jsonl`, and final `.json`. Source locations, OS PID/PPID, perf timestamps, process CPU, thread CPU and peak memory are provenance only. Exact numerical snapshots use `float.hex`, typed dictionary keys and complete control vectors plus physical meter commands/finalization rates. Full state/config/forecast snapshots are taken at logical boundaries, not every physical substep. Selected price, standing-lambda and cache-key context is explicit; this is not a serialization of every hidden controller attribute.

The parent ordered stream preserves candidate order. Worker task streams are matched by task input/context key, and their internal endpoint order is retained; assignment to a particular worker and completion order are excluded. The outer Ω endpoint and nested vendor endpoint count as one logical evaluation. Executed interval controls include changes from box-walk/finalization. Price task counts and endpoint counts are separate units. Unwinds, serialization errors, changed source/input files, unmatched calls, missing sidecars, wrong root PID and observed unrecorded children prevent a valid trace. A readable final preflight result alone does not certify the trace.

Compare two complete trace directories with:

```powershell
& '<same Python executable>' -X utf8 -m diagnostics.evaluation_trace '<baseline evaluation_trace directory>' --compare '<optimized evaluation_trace directory>'
```

The command reports exact comparison hashes, the first differing parent event and whether keyed worker task traces match. Timing fields, source locations and process identity are excluded from this equality. No rounding/tolerance is silently applied to controls or scores.

Timing is **trace-overhead-inclusive**, includes selected-frame serialization/I/O, and is separate from a normal benchmark. `process_time_ns` covers every thread in that process; `thread_time_ns` covers the selected main thread. Nested inclusive times and overlapping worker wall times cannot be added. Peak working set/commit counters reuse root's `decision_profile.memory_counters`; they are also excluded from comparison. Python 3.12.14 cProfile occupies `sys.monitoring` even when `sys.getprofile()` is None, so installation explicitly checks both APIs. The bootstrap exits before the user program if installation conflicts/fails; sitecustomize's default exception swallowing is not accepted.

Files owned by this change: `evaluation_trace.py`, `evaluation_trace_bootstrap/sitecustomize.py`, `evaluation_trace_synthetic.py`, `test_evaluation_trace.py`, this handoff, plus the authorized `run_area_production_preflight.py` integration. The older lifecycle audit's cProfile thread claim was corrected separately without altering historical numerical evidence.

Validation after the memory sidecar addition: 10 tests passed in 1.786 seconds, including fresh parent+two-worker runs twice, original stdout equality, deterministic worker-normalized hashes, nested logical-call collapse, actual interval control variation, PFO score retention, exact float distinctions, exceptions, missing child/root PID gates, environment cleanup and flag exclusivity. These are tiny synthetic functions under explicitly synthetic code addresses; no production body was copied or executed as a substitute. A final rerun after adding the three explicit hinge/protected-queue score fields is recorded in `evaluation_trace_validation.json`.

For the first actual baseline run the implementation retains full cfg snapshots at logical boundaries: no object-ID-only cache can conceal cfg mutations. This costs diagnostic time but preserves context correctness. An eventual once-per-run cfg snapshot optimization requires start/end equality checks and a reviewed treatment of legitimate intermediate configuration changes. A proposed `native_prehead_dispatch_index` is not silently excluded; baseline/optimized context differences must first be reconciled by an explicit cache-only proof/allowlist.
