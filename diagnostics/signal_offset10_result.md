# 고정 녹색 기준 대비 SC1001/SC1004 오프셋 실험

Seed 13에서 SC1001을 10초 앞당기고 SC1004를 10초 늦추자 Ω TTT가 **74.758 veh·h 감소(-1.366%)**하고 관측 출구와 종단 추론을 합한 TTD가 **147회 증가**했다. F 동쪽 진입램프 10639의 대기열이 크게 줄고 FW_E 최초 지속 정체는 90초 늦어졌다. 그러나 상류로 번지는 본선 정체는 남았고 도시 링크 40·420의 대기열과 강제 제거 차량은 증가했다. 이 결과는 실제 오프셋 권한과 공간별 반응을 확인한다. 최종 최적 제어값이나 다른 seed에서의 개선을 입증하지는 않는다.

분석 대상은 `codex_signal_zero_s13_20260910`과 `codex_signal_offset10_s13_20260910`이다. 두 실행 모두 900초부터 같은 고정 녹색 벡터를 쓴다. 이 벡터는 **추가 audit 관측 영향이 있던 첫 n7 런의 t2100 녹색**이다. Native 무제어나 pure n7 성과와 비교하는 실험이 아니다. 이번 변경은 두 SC 간 상대 시차를 20초 바꾼 것이며, 모든 교차로를 일률적으로 +10초 이동한 실험도 아니다.

**비교의 동일 조건과 실제 적용**

두 run의 기록된 network·VBS·adapter·mapping·생성 VBS config·수요 파일 SHA가 일치하고, seed·수요배율·5400초 기간·제어 간격·audit 시점도 일치한다. 900초까지 교통 상태표 31행, 고속도로 셀표 1,302행, 물리 링크표 6,979행이 계산 소요시간 필드를 제외하고 동일하다. 이는 관측된 warmup 상태의 동일성 검사이며 전체 warmup FZP 바이트 동일성 검사는 아니다.

900초 command CSV의 차이는 SC1001/SC1004의 offset 18개 필드뿐이다(교차로 행 2개와 SG 행 16개). SC1001에는 10초, SC1004에는 -10 mod 150 = 140초가 기록됐다. VBS의 `phase = (sim_sec + offset) mod cycle` 관례에서 각각 10초 앞당김과 10초 늦춤이다. 녹색·SG 구간·VSL·미터 설정은 동일하다. 900–5400초 readback으로 적분한 전체 305개 SC/SG 조합의 GREEN 총시간도 두 run이 정확히 같다.

첫 150초의 17 SC, 제어 SG 136개, SG 구간 122개를 별도로 검증했다. 18,632개 제어 SG readback(즉시 9,384, step 후 9,248), 정수 초 SG 전이 366건에서 command·readback·유지·기대 상태·SG 누락·정수 event 누락 오류가 모두 0이다. SC105의 major=p2 현시 순서도 유지된다. 원래 고정 벡터의 SC109 p3 96.5→90초 writer 제한 및 143.5초 주기는 두 비교팔에 공통이다.

전체 run은 SIM_DONE 5400으로 종료했다. SIGNAL_READBACK_OK 288,400, PERSISTENCE_CHECKS/OK 288,240/288,240이며 COM·action format·decision 실패는 0이다. VSL은 120 km/h, 8개 물리 미터는 900–5400초 각각 4,500초 GREEN이다. 따라서 아래 반응을 미터 폐쇄나 녹색시간 증가 효과로 설명할 수 없다.

Offset run은 25,961,573개 FZP 행, 1–5400초의 5,400개 snapshot으로 구성되고 누락 간격은 0이다. 첫 0초는 새 네트워크의 빈 상태라는 가정을 쓰며, 마지막은 5400초 FZP 자체를 사용한다. `--fzp-only`로 state JSON을 섞거나 마지막 꼬리를 외삽하지 않았다. 표본 기반 재고 회계 잔차는 두 run 모두 0이다. 이것이 1초 사이의 모든 실제 이탈 시각을 정확히 복원했다는 뜻은 아니다. 종단 추론·미확정 소멸·고유 차량과 반복 사건을 분리한 이유다.

TTT 감소의 가장 큰 물리 링크 기여는 74의 -38.625, 2의 -34.611, 10639의 -9.950 veh·h이다. 반대로 40은 +5.190, 26은 +4.113, 420은 +3.473 veh·h이다. 모든 Ω 물리 링크 TTT 차이의 합이 Ω 전체 차이와 일치한다(허용오차 1e-7 veh·h).

**본선 정체의 발생과 상류 전파**

30초 관측의 속도 30 km/h 미만, 재고 5대 이상이 90초 지속되는 조건에서 FW_E 셀 8의 최초 정체는 1260→1350초로 90초 늦어졌다. 셀 8의 최대 정지 차량은 171→137대, 최저 속도는 2.571→4.124 km/h로 개선됐다. 그러나 전파는 사라지지 않았다.

일부 상류 셀은 오히려 30초 빨리 기준을 넘는다. 그러므로 오프셋은 합류 부근 차량 도착 시각과 대기 위치를 유리하게 바꾼 후보이지만, 이 설정만으로 지속적인 본선 병목을 제거했다고 볼 수 없다. 차로별 속도 그림은 run의 `analysis/FW_E_lane_speed.png`에 있다.

강제 제거를 완료 차량으로 세지 않는다. Ω 내부 미확정 소멸 326건과 로그상 Ω 내부 제거 170건은 서로 다른 관측·분류이므로 두 수를 일대일 대응시킨 것으로 보고하지 않는다. 제거와 경로 경고가 증가한 상태에서 TTT 감소만으로 최종 정책의 우월성을 선언하면 안 된다. 다른 seed, 특히 별도 holdout에서 대기열과 제거 건수를 함께 재검증해야 한다.

분석 중 production 통합이 진행되어 현재 VBS/adapter 바이트는 기록된 run SHA와 다르다. provenance에 남은 commit `3299040b0b1e384c2858040d0b080e899262193c`의 git blob 및 엄격한 LF→CRLF 복원본도 **기록된 raw SHA와 일치하지 않았다**. 두 run의 기록 SHA가 같다는 사실과, 현재 파일에서 실행 당시 raw 바이트를 복구했다는 주장은 구분한다. 후자는 미해결이다. 고정 config·phase plan hash, 실제 CSV command, 정수 event의 실제 readback은 별도로 확인했으며 위 적용 검사는 이에 근거한다. 원본 raw archive 복원이 완료됐다고 주장하지 않는다.
