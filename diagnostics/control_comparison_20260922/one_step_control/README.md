# 혼잡 상태 한 번의 RM/VSL 선택과 합류 상한 수정

2026-09-22. **최신 결과는 `lane_capacity_v2/`**. 이 폴더 바로 아래의 결과는 수정 전 1800대/h 상한이며, 비교를 위해 보존했다. 새 VISSIM 런 없이 완료된 FW80/urban90, seed23 자료를 사용했다.

## 수정 내용

사용자 지시에 따라 최신 boundary/Hadi/Wang의 `res10_20260922/boundary_literature_v1/*_config.json` 세 파일에 기존 `physical_ramp_capacity_vph` 설정을 명시했다. 2차로 **10482와10681만 총1800→3600대/h**, 나머지 6개 1차로는1800대/h 유지. 기존 1차로1800 기준을 물리 차로 수에 맞춘 명목 상한이다. 실제 방출은 재고·신호 서비스·본선 수용량 중 더 작은 조건에 제한된다. 새로 포화 방출률을 실측 보정했다는 뜻은 아니다.

이전에는 물리8램프로 분리하면서 4그룹의1800대/h 값을 두 차로 램프에도 그대로 상속했다. 실제10482의 직전150초 평균 합류는2568대/h이므로 이 상한은 이미 실측 통과량보다 작았다. 수정 전 원본, 전후SHA, 딱 이 설정만 변경됐다는 검사와 실제 factory 적용값은 `lane_capacity_v2/capacity_change.json`, `config_checks.json`에 있다. 과거 frozen-config pin은 그 파일에 기록된 보관본으로 복원한다. 동결된 보정 계수는 바꾸지 않았다.

추가로 기존 `physical_ramp_boundary.py`가 native2700.1초를 거부하던 정수 시각 제한을 고쳤다. 1초 간격의 소수 위상에서 실제 녹색 구간의 겹치는 시간을 적분하고, 시각을 반올림하지 않는다. 17개 보존/시간 테스트 통과, 기존 정수 시각의780개 전체 receipt JSON은 수정 전과 정확히 같다. 원본은 `physical_ramp_boundary.before.py`.

## 실험 정의

- 공통 관측 시각2700.1초. 동측 셀11/12 속도24.2/29.9km/h,10681 connector 재고57대(신호두 이전38대). 서측 상류에도19–35km/h 셀이 존재한다.
- 450초 예측으로 첫150초 명령을 선택. 현재 무제어에서 RM 계획은 녹색8→6→4초/10초 RG, VSL 계획은100→80→60km/h. 각150초의 변경 한도2초/20km/h를 유지한다. 첫150초만 실제 적용할 명령이며, 후속 계획은 예측용이다.
- 8개 RM 중 하나씩, 8개 VSL zone 중 하나씩, 그리고 그 조합. 유지 포함 RM9개/VSL9개/병행81개. 각 family의 독립적인 두 방향 결과를 재사용하여50회 방향별 rollout으로81개 비용을 계산했다. 이는 한 번에 최대 한 램프와 한 VSL zone을 바꾸는 제한된 후보군이며, 16개 레버의 모든 조합 최적화는 아니다.
- 비용: 본선+8개 on/off connector 체류시간+새로 발생한 상류 램프/본선 경계 대기, 차량·시간의 동일 가중치. **전체 도시 Ω 목적함수나17주체 GNE, N_P/N_UF 제약을 실행한 결과가 아니다.**
- RM이 의미 있게 모델에 들어가도록 기존 PhysicalRampBoundary의 관측 위치별 초기 재고·신호두 서비스·이동 지연·수용량·보존식을 연결했다. 합류량을 외생 고정하지 않았다.
- off-ramp도 기존 conserved travel/storage를 공통 연결하고, 기존 유입 proxy 상한을 유지한 `storage_and_proxy`를 사용했다. 과거150초 배수 proxy와 pre900 통과시간 기반 이동속도를 사용한다. 세 모델의 새 공통 연결이며 최종 운영 채택이나 추가 보정은 아니다.

## 상한 수정이 RM 반응을 바꿨는가

경계 수정 모델,2700.1–3150.1초. 무제어 실제 비교는 같은 초기 상태에서 관측된 이후 런이다. 모델은 과거 기반 도착 예측을 쓰므로 아래 차이를 모두 상한 하나의 오차로 해석하지 않는다.

| 램프 | 무제어 실제 합류450초 | 수정 전 예측 | 수정 후 예측 | 수정 후 RM 계획 적용 |
|---|---:|---:|---:|---:|
|10482|289|223.00|291.94|209.55|
|10681|152|192.24|192.24|185.91|

**10482는 수정 효과가 분명하다.** 무제어 방출과 종료 재고가 실측에 가까워졌다(예측 재고96.00→27.06대, 실제27대). 이제 RM 계획이 합류를82.39대 줄인다. 그러나450초 비용 분해는 본선−2.489, 램프+2.878, off-ramp−0.039차량·시간으로 **총+0.350차량·시간 손해**라 선택되지 않는다. 이것은 명령이 물리량을 못 바꿔서 탈락하는 경우와 다르다. 다만 이 비용 순위가 VISSIM에서도 맞는지는 아직 미검증이다.

**10681에는 다른 문제가 남아 있다.** 첫150초 실제 합류42대인데 예측은75.00→94.24대로 더 과대해졌다. 450초 종료 connector 재고도 실제52대에 비해11.76대를 예측한다. 기존 낮은 명목 상한이 일부 오차를 가리고 있었고, 혼잡에 따른 실제 수용·방출 제약을 충분히 표현하지 못한다. 2차로 명목 상한을 올리는 것만으로 이 램프를 보정했다고 판정하지 않는다.

## 검증과 범위

수정 전·후 각각 세 family150회 방향별 예측(합계300회), 각각243개 결합 후보 비용과9개 결정 완료. 모든 on/off stock 보존, 본선 셀 보존(<1e-6대), 비음성, 잼 밀도 및 projection 검사 통과. 세 source config의 `verify_parameters.py` PASS. 과거 calibration 입력이 parameters에 의해 덮인다는 기존 경고는 남아 있으며, 이번 family coefficient는 harness override로 명시 전달했다.

초기 connector 바깥 재고는 관측 자료에 없어서0으로 두고 이후 발생 대기를 포함했다. 도시 신호/목적지 도착과 spillback의 완전한 피드백은 없다. g별 서비스 곡선도 기존 명목값이고 native의 출발지연을 새로 적합하지 않았다. 그러므로 이 결과는 **최신 모델에 RM/VSL을 넣으면 어떤 후보를 고르는지에 대한 구성요소 진단**이며, 실제 폐루프 성능/최종 controller 완료가 아니다.

다음 물리적 확인 대상은10681의 혼잡 시 실제 수용·합류율이다.10482는 상한 수정 후 방출 정합이 개선됐으므로 두 램프를 같은 방식으로 또 조정하지 않는다. RM이 켜지게 할 목적으로 보상항이나 capacity drop을 추가하지 않는다.

파일: `lane_capacity_v2/summary.json`, `decisions.csv`, `capacity_response_comparison.csv`, `*_candidates.json`, `*_roads.json`. 재현은 `one_step_control.py`의 OUT을 이 결과와 다른 빈 폴더로 지정하고 `main()` 실행(현재 source config는 수정 후). 이전 상한은 보관된 `*_config.before.json`을 명시 사용해야 한다. 새 VISSIM 실행, 수요 변경, push는 하지 않았다.
