# 최신 METANET의 제어 응답과 controller 연결 확인 — 2026-09-22

**판정: VSL 제한의 손실 방향 일부는 예측하지만, 실제 국소 혼잡 완화 이득을 맞추고 그 이득으로 controller가 선택한다는 검증은 아직 없다. 이번 9000초 4조건은 ALINEA·규칙 VSL이며, MPC 선택 결과가 아니다.**

새 VISSIM 런, 계수 재보정, 실행기·물리 모델·수요 변경 없이 기존 자료와 최신 3개 동결 모델을 검사했다. 150개 후보 예측(양방향 300회), 약 98초. 모든 예측에서 음의 밀도·잼 밀도 초과·밀도 투영이 없고 셀 보존 잔차는 1e-6대 미만이었다. 입력 및 모델 코드 pin은 종료 후 동일함을 확인했다.

## 1. 실제 제어를 고른 것은 무엇인가

`D:/VISSIM_runs/20260922_fw080_urban090_controls`의 RM/VSL/both 각 54개 결정, 총 162개에서 `mpc` 선택 기록은 **0개**다. 각 준비 폴더에 `mpc_policy.json`도 없다. 기존 `diagnostics/fast_fixed_profile.py:211`은 이 파일이 있을 때만 `mpc_choice()`를 부른다. 이번 결정은 ALINEA/속도·유량·점유율 규칙으로 생성됐다.

따라서 이번 결과를 “METANET이 비용 이득을 예측해 선택한 결과”로 해석하면 안 된다. 이는 이번 기준 정책 실험의 원래 실행 방식이며, 그 자체가 실행 오류라는 뜻은 아니다.

## 2. 공통 초기 상태에서 실제 반응과 예측 비교

초기 상태는 제어 전 **870.1초**, 지평은 **450초(1320.1초까지)**다. 모든 native 조건의 제어 전 FZP 행은 기존 비교에서 완전히 일치했다. 세 모델에 같은 무제어 초기 상태, 같은 과거 150초 기반 경계 예측을 주고, 120 유지와 실제 VSL 명령 재생을 비교했다. 재생 명령은 기록된 미래 명령을 사용하는 응답 진단이며, 모델이 그 명령을 스스로 예측/선택한 것은 아니다. 계수는 NC100에서 이미 보정된 값을 동결했다.

아래 값은 **VSL − 무제어 본선 TTT**, 단위 차량·시간이다. 양수는 손해다. Ω 전체 TTT와 구분해야 한다.

| 자료/모델 | 동측 | 서측 | 양방향 본선 합 |
|---|---:|---:|---:|
| 실제 VISSIM | +2.232 | +0.488 | **+2.720** |
| 경계 수정 METANET | +1.374 | +0.188 | **+1.562** |
| Hadi 재보정 | +0.750 | +0.022 | **+0.772** |
| Wang 재보정 | +0.751 | +0.013 | **+0.764** |

이 구간에서 손실 부호는 모두 맞고 크기는 모두 과소평가했다. 이것은 “VSL에 반응하지 않는 모델”이라는 결론을 반박하지만, **혼잡 예방·회복의 이득을 맞췄다는 증거는 아니다.** 이번 공통 초기 구간 자체가 본선 순손실 구간이다. 이미 관측된 9000초 전체의 동측 중간 구간 개선을 이 표로 검증했다고 해석하면 안 된다.

## 3. 후보를 비교하면 제한을 선택할 유인이 있는가

무제어 상태 5개(870.1/1800.1/2700.1/4500.1/6300.1초)에서, 각 모델에 9개 후보를 비교했다: 120 유지와 8개 VSL zone 중 하나씩 `100 → 80 → 60`을 150초 간격으로 적용하는 후보다. 이는 기존 소규모 MPC의 단일 zone ±20km/h 후보 형태를 따른다. RM, 도시 신호, 복수 VSL zone 동시 최적화, N_P/N_UF 게임은 포함하지 않았다.

진단 비용은 본선 체류시간과 새로 거부된 본선 경계 유량의 대기시간이다. 도시·램프 전체 비용이 없으므로 **이 표는 후보 응답 점검이며, 실제 controller 호출이나 Ω 최적해가 아니다.**

| 모델 | 5개 상태 중 유지가 최저 | 다른 후보가 더 낮을 때의 최대 예측 절감 |
|---|---:|---:|
| 경계 수정 METANET | 2 | 0.0861 차량·시간, 해당 비용의 약 0.043% |
| Hadi | 2 | 0.00417 차량·시간 |
| Wang | 2 | 0.00138 차량·시간 |

모델이 제어 입력을 무시한 것은 아니다. desired-speed binding이 기록됐고 일부 제한 후보의 손해는 4 차량·시간 이상이다. 하지만 검사한 범위의 유리한 차이는 매우 작다. 이 작은 차이를 실제 개선의 신뢰할 수 있는 선택 근거로 볼 수 없다. 반대로 한 zone씩만 검사했으므로 모든 허용 조합에 이득이 없다고도 할 수 없다.

각 시점의 실제 규칙 VSL 벡터를 그 시점 무제어 상태에 적용한 별도 진단에서도 세 모델 모두 양방향 순손실을 계산했다. 이 벡터는 한 번에 60까지 내려갈 수 있어 MPC trust region 안의 후보 순위에는 넣지 않았다. 870.1 이후 실제 VSL 런과 무제어 런은 이미 상태 이력이 다르므로, 이후 후보의 예측 차이를 두 native 시계열의 같은 시각 차이와 곧바로 정답 비교하지 않았다.

## 4. RM 및 최신 controller 연결에서 남은 구체적인 문제

- 최신 9/22 일반 구성요소 검증은 `boundary_factory.build_window()`에서 과거 실제 램프 방출률을 `ramp_release_vph`로 공급한다. 이번 예측에는 `ramp_dynamics`가 없다. 따라서 RM 녹색 변경 → 신호두 방출 → 합류 → 도시/램프 대기의 연결을 검증하는 모델 구성이 아니다. 내부에는 RM 동역학 기능이 존재하나, 기능 존재와 현재 검증 완료는 별개다.
- 기존 소규모 MPC `evaluate_response.py:540`은 명시된 이전 `config.json`, `selected_parameters.json`, `port_profile.json`을 읽는다. 최신 boundary/Hadi/Wang 보정값이 자동으로 승격되지는 않는다.
- 같은 파일의 window 구성에는 `range(21)` VSL zone 투영이 남아 있다(현재는 방향별 31개 물리 셀). 온라인 자료 읽기는 정수 시각만 허용하지만 현재 native FZP는 5.1, 10.1초 등의 위상이다.
- 비용 계산에는 고정 10초 가중치가 남아 있다. 현재 본선 적분 1초 및 램프 내부 1초 기록과 맞는지 재검증해야 한다. 이번 점검은 이를 고쳐 실행한 controller 검증이 아니다.
- 이 소규모 MPC 자체도 전체 17개 도시 주체와 N_P/N_UF를 포함하는 full GNE/Ω 목적함수는 아니다.

## 5. 다음 검증의 통과 기준

우선 현재 31셀·기록 위상·시간 가중치를 정합한 단일 소규모 선택기에 최신 모델을 명시적으로 연결하고, 실제 명령과 예측 방출·대기 비용을 남겨야 한다. 같은 초기 상태에서 hold/RM/VSL/both의 비용 차이와 선택을 검증하되, 실제 방출이 변하지 않는 RM 후보는 별도로 표시한다.

본격적인 혼잡 직전과 회복기의 같은 상태에서 450초 정도의 짧은 native 분기 비교가 있어야 **국소 이득과 전체 대기 비용을 맞추는지** 판정할 수 있다. 기존 native 런의 서로 다른 후기 상태를 공통 초기 비교인 것처럼 쓰지 않는다. 모델이 유리하다고 예측한 실행 가능한 후보를 실제 선택기가 고르고, 실측 순위도 일치해야 다음 단계로 간다. 이번에는 이 추가 native 실행이나 controller 수정은 수행하지 않았다.
