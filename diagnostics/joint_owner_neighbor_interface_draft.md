# Joint-owner GNE: interface and implementation order

Documentation proposal updated 2026-09-10. No production edits, controller imports, tests, model evaluations or VISSIM execution were performed for this update. The initial dd13e08 source map below is followed by the concrete implementation order. This is not an implemented or certified equilibrium. The performance replay may exchange the original/cached signal-clock module; its public projection interfaces are used here, and no transient clock hash is treated as a new model baseline.

Proposed single canonical module interface: `owner_neighbors(owner, incumbent, decision_context)` → requested owner-local candidates; `realize_owner_candidate(...)` → copied, normalized complete control plus feasibility/resolution evidence; `score_owner_candidate(...)` → canonical physical endpoint result plus the explicitly agreed owner-cost/price quantity. Freeze non-owner physical rows; deduplicate after realization, retaining all requested aliases. Keep incumbent as an evaluated candidate.

After a final simultaneous update, evaluate every owner's feasible unilateral joint neighbor against the same final incumbent. Report the maximum positive improvement in the agreed owner game cost separately from JΩ improvement; JΩ alone does not certify a priced GNE. Physical budget/grid/ownership and strict area conservation are hard checks, not soft penalties. Existing relative coupling convergence is a separate diagnostic. Do not call `_finalize_link_phases` to normalize a trial: it can run another price refinement and mutate follower context. Do not call local FW solve as a pure fixed-candidate scorer: `link_predictor.solve_freeway_agent_local` writes `_wu._last_offramp_flow`.

## First implementation unit: domain and physical realization

Add one canonical helper, `evaluation/controllers/joint_owner_game.py`, containing `owners`, `make_context`, `neighbors`, `realize`, `feasibility`, `evaluate_owner_fixed`, `evaluate_physical`, and `certify_neighbors`. **The first deliverable is only owner-local candidate construction, physical realization and explicit feasibility/result records**, exercised from a new `diagnostics/test_joint_owner_game.py`; it does not yet replace the follower or change its output. Integrate the solver only after fixed-candidate scoring and the final unilateral-gap test work. One proposed config key, `mpc.all_lever_gne`, selects the new algorithm; absent/false delegates to the existing installed solve unchanged. Bounds and tolerances come from the parameter/config contract, not new hard-coded tuning.

Keep the same 19 owners verified in `physical_actuator_ownership_audit.md`: SC1/5/6/7/11/12/16/101/105/107/108/109/1001/1002/1003/1004/1005 each own their entire `green_times[SCx_p1..p4]` and `offsets[SCx]`; FW_E owns free VSL zone heads 0/5/10 plus R_D_E/R_F_E, and FW_W owns free heads 0/5/10 plus R_D_W/R_F_W. Obtain these from the canonical cfg/mapping/selected plan and validate the expected set. Zone15, expanded cell VSL keys, direction fallback values, derived SG windows and eight physical meter SGs are derived values, not extra owners. Require disjoint physical write addresses. Keep plan-active headless phases; this work does not authorize an unrelated service-authority repair.

The source anchors for extraction are vendor `WuFaithfulFollower._solve_urban_agent_joint`, `_solve_offset_local`, `_solve_offset_local_ramp` and `_solve_freeway_agent_metered`; installed `LinkAgentWuFollower._phase_exchange_candidates`; adapter `install_freeway_vsl_sequence_kbest`; and canonical `area_meter_finalization.finalize`. Extract only candidate-list/filter code from the vendor methods into the new helper; do not copy an adapter or invoke a best-response solver just to enumerate. Preserve existing order, trust filters, baseline boxes, release certification and leader/PFO mode distinctions.

Two small domain examples, not recorded model predictions:

- With a four-phase 138 s budget and permissive bounds, `(30,30,48,30)` has the existing 6 s p1→p3 neighbor `(24,30,54,30)`. Pair it with an admitted offset-lattice point, e.g. 0→18.75 s on a 150 s cycle. Normalize through the actual writer and recheck trust; a written value outside the declared trust is excluded, not granted a wider trust radius.
- For a two-ramp equality budget B=1800 and both caps at least 1800, existing seven splits include `(900,900)` and `(1200,600)`. Pair an admitted split with a permitted FW_E zone-head move `(100,100,100)`→`(80,100,100)`, retaining zone15 and FW_W. Values 80/100 belong to the current configured set {80,100,120}. Measured meter realization can merge or reject these requests; enumeration alone does not certify feasibility.

The same incumbent must be present in every owner's candidate set. Copy the complete action, realize it once, and deduplicate by derived physical row identities/values, retaining every requested alias. Recheck that all non-owner physical rows are unchanged. Do not cache by mutable object identity.

## Fixed-candidate evaluation before the game loop

**Urban:** reuse installed `_phase_refine_context(state, snapshot, demand)` → `_phase_refine_signal_setup(signal, state, ctx)` → `_phase_local_cost_phased(signal, full_vector, setup, trial_ctx)`. `trial_ctx['snapshot']` must be the copied trial so the candidate offset is used. The non-ramp path uses the existing phased/platoon rollout; the ramp path dispatches through `local_signal_service.ramp_refinement_setup` / `ramp_refinement_cost`, retaining its explicit ready seed, shared service budget and finite receiving. Context construction clears/writes `_phase_ctx_cache`, and setup fills `ctx['setups']`; these are explicit new solve/round scope effects. Do not reuse setup after its state, incoming coupling, demand, ready seed or relevant control dependency changes.

**FW:** make a narrow fixed-sequence evaluator extraction inside the existing `evaluation/controllers/link_predictor.py`. Keep dynamics, local costs/penalties, landing ledger and validation calls intact; return component costs, accepted off-ramp flows and diagnostics. The existing `solve_freeway_agent_local` must call this evaluator in its old candidate order and retain its old `_wu._last_offramp_flow`, `_has_last_offramp_flow` and `_last_local_landing_diagnostics` commit behavior when the new game is OFF. A new game query receives proposed flow results without writing standing caches. Current `vsl_override` holds VSL but still builds candidate lists and updates caches; it is not yet a pure evaluator.

**Return quantities must match the selected vector.** The dormant vector city oracle chooses a new vector and then returns old scalar `out[1:4]`; do not reuse that tuple. `_agent_net_inflow_veh(signal, green_p1, ...)` redistributes a scalar and uses the legacy cycle-average N_P formula. First extract that declared quantity formula to accept an exact full vector, label it explicitly as the legacy leader quantity, and validate against the same leader constraint definition. Do not call it actual accepted Ω entry/exit or silently replace it with another definition. Accepted flow/coupling outputs come from the corresponding fixed-action rollout. Changing the N_P definition itself requires producer, follower and leader to change together.

## Price and operational-state scope

Within one leader-candidate follower solve, freeze price values, references, weights, trust domains, release certificates, enabled cross terms, λ_P/λ_UF, ω_F and leader quantities. For each round, also snapshot operational dependencies: `_prev_coupling`, Wu off-ramp caches and refinement contexts. Comparable queries share that round's reference and return proposed updates; only an explicit round/solve commit writes them. This changes the game deliberately; it is not a performance-equivalence claim about the old sequential candidate solver. Price dictionaries alone do not make queries order independent.

Use one owner expression everywhere: `L_i(realized action; round context) + fixed external-price terms + declared quantity terms`. Full-vector urban moves use the phase-vector price channel once, plus offset and enabled green–offset cross terms; do not additionally charge the overlapping scalar-green price channel. Keep existing weights, including phase weight 0.25, explicit. FW evaluation holds realized meter and VSL together, charging VSL/meter/cross terms once. Preserve the stated leader/PFO policy distinction: the current equality-split PFO does not automatically inherit the leader's meter price or budget. Making those the same game requires an explicit objective/constraint change.

Price production must use the same fixed-candidate local evaluator and physical realization for `D JΩ − D L_i`. Existing local-meter finite differences reoptimize VSL while the global probe holds it; that is a different function. A quantized duplicate has zero physical displacement and must be marked unidentifiable/deduplicated, not divided by the nominal requested change. Bounds-clipped phase exchanges likewise need their actual feasible direction recorded. Refresh prices only outside a completed fixed-price solve; after changing references, rebuild and rerun the game's final checks. A fixed-price neighborhood certificate is not a price/strategy fixed-point certificate.

Hard feasibility includes the declared N_P/N_UF mode and endpoint stock conservation as well as action bounds. A requested simplex is not a realized simplex. After measured-table finalization, equality mode must find a realized allocation satisfying the declared numerical tolerance or return an empty feasible strategy set to the leader. Do not silently round the leader target or turn equality into a penalty. Whether to change that policy remains an explicit decision; units 1–2 can be implemented without inventing a workaround.

At the final feasible incumbent `u*`, rebuild one final round context. Evaluate `C_i(u*)` and all declared feasible unilateral joint neighbors against the same prices, state, forecast, non-owner action and operational inputs. Report `gap_i = max(0, C_i(u*) − min_v C_i(v_i, u*_{−i}))` for all 19 owners, plus maximum gap, domain counts/rejections, physical fingerprints and shared-constraint residuals. Evaluate admitted probes and incumbent through the same held physical endpoint/horizon. Coupling residual is separate. A capped search or the old hard-coded zero objective residual cannot certify convergence. A passed check covers only the declared finite neighborhood at fixed prices. Do not require JΩ improvement for every unilateral priced move; JΩ remains a separately measured objective and the outer leader's ranking score.
