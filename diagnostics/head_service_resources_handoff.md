# Physical head support → canonical service resource (unapplied)

The proposed correction preserves the actual achieved-discharge evidence and
joins it to the final physical resource. It does not move the old capacity
installer wholesale, copy its seed-max floor into a new resource, or identify
saturation capacity. Production, active configurations and their pinned inputs
were not edited. No endpoint, full MPC or VISSIM was run for this proposal.

## Actual 1050 evidence

The complete native NC v2 windows 150..1050 were replayed through the existing
`signal_head_observation.install` validator. Its existing quality settings are
unchanged: each head requires at least 30 GREEN seconds, and a group requires
at least five qualified crossings. The group rate is the sum over heads of
`3600 * qualified_crossings / green_sec`. Support is the minimum of two
qualified contiguous windows, followed by a verified carry.

| Physical resource | Recorded candidate rates, by window end (veh/h) | Observed-only support at 1050 | Proposed final service |
|---|---|---:|---:|
| 183 / SC107 SG6 / lanes 1–4 →10619 | 300:1015.3846; 450:784.6154; 1050:1061.5385 | 784.6154 | Existing 826.1224 unchanged |
| 52 / SC1004 SG6 / lanes 1–3 →10629 | 450:1840; 600:1040; 750:1520; 1050:2080 | 1040 | One aggregate 1040 budget |

Neither group has a qualified candidate at 900. Therefore neither 1050 rate
forms a new pair. The old 183 floor 1445.7143 was a legacy seed-max value and
is not observed support. It is never used to raise 10619.

52's real post-head connector 10629 maps to the final boundary-out movements
`SC1004_E_SC1005_to_W` and `SC1004_E_SC107_to_W`, both receiving into
`SC1004_W_out`. The old head distributor considers internal movements and
misses these two. It instead allocates to pre-head 10628 movements and phantom
future aliases. 183's pre-head 10600 right turn likewise cannot inherit SG6
service. The proposal restores only those provisional allocations to their
pre-observer values, allows canonical topology to remove the phantoms, then
joins the observed support to the verified final resource. Restoring a
pre-head member's configured seed is not a new measured capacity claim.

## Patch and integration

`head_service_resources.patch` is generated by
`prepare_head_service_resources_patch.py`. It adds one small canonical helper
from `head_service_resources_proposal.py` and surgical hooks in four existing
files. The adapter has only an observer-call wrapper; no adapter or vendor
copy is created. `git apply --check diagnostics/head_service_resources.patch`
passes against the source hashes in `head_service_resources_patch_manifest.json`.
The generator preserves the existing CRLF convention of `local_signal_service.py`.

1. `runtime_setup.configure_runtime` validates the opt-in physical proof before
   the current measured observer. After dynamic/route-corridor topology, and
   before local pool installation, it joins measured support to final members.
2. The observer wrapper retains all original raw, clock, identity, geometry,
   quality and provenance checks. Its separate observed-only metadata key
   includes the run/quality/network identity and the new contract SHA. A
   carried value alone still requires the original action run ID, context=1,
   snapshot time and adjacent window boundary to agree. It never trusts the
   combined legacy floor. Cold installation into an old action history starts
   this namespace at zero; the test's replayed histories are diagnostic copies.
3. 10619 keeps its existing route-owned single service. 10629 registers one
   extra group in the current local pool, containing both boundary-out aliases.
   Their cap-map values are views of that one rate, not two additive capacities.
4. The canonical regular urban substep uses the same existing `register_limit`,
   `limit_batch`, and `accepted` primitives as the local model. The budget is
   local to each 5-second invocation. Existing receiving allocation follows
   the service limit, and only actual accepted vehicles debit it. Existing
   stock, reservation, release, physical transfer and Ω event code is unchanged.
5. Pickled configuration carries the final resource view; the existing worker
   installer consumes it. 10634's three aliases and its 1509.3333 train-only
   offline prior remain unchanged. No extra multiplication by the number of
   heads, source aliases or lanes is performed.

Opt-in (root-owned configuration only after review/application):

```json
{"urban":{"capacity":{"head_resource_contract":"diagnostics/head_service_resource_contract_proposal.json"}}}
```

Existing `urban.capacity.head_observation.enabled=true`, the physical signal
clock, canonical 1128 topology and `urban.shared_local_service_pool=true` are
prerequisites. The module validates exact XML head/lane positions, post-head
connector geometry, competing connector positions, pinned topology proofs and
final movement semantics. No new numerical capacity parameter is introduced.

The **limited activation policy** for 10629 is deliberate: observed support
must exceed the previous independent-member aggregate envelope (826.1224 at
this snapshot) before the new measured shared group is installed. That old
envelope is only a comparison threshold, not an inferred physical seed.
Below it, the proposal records `head_resource_unapplied_10629` and retains the
old regular service behavior. This does not solve unobserved baseline-resource
identification or claim every warmup group already has a measured shared cap.
