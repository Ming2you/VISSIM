# 현재 경로 관측으로 공유 구간의 초기 차량을 보존

공유 도로56의 분기점 이후 차량을 매번8:1:1로 다시 배분하지 않도록 현재 경로 관측을 추가했다. VISSIM2020의 `RoutDecNo`, `RouteNo`, `RoutDecType`을 읽으며 기존 `vehicle_records` v2.1 형식은 그대로다. 새 `vehicle_routes`는 같은 중지 시각의 같은 차량 ID 집합을 별도로 담는다. 기본 실행에는 없는 선택적 관측이고 Ω 비교 런처에서 `RW_VEHICLE_ROUTES=1`로 활성화한다.

실제 COM 검증은 native 수요·신호로1050초를 진행했고75.32초에 끝났다. network/신호/검증 소스 해시는 전후 같았고 전용 cscript/VISSIM만 사용했다. 이는 통제 정책의 성능 비교 팔이 아니다. `vehicle_route_com_probe_20260910_01`의6009개 선택된 관측과 manifest를 보존했다.

| 물리 위치 | 관측 행 | 확인한 현재 경로 |
|---|---:|---|
| 56, native1129 이전 |1113|이전 경로 또는 현재 경로 없음;1129 없음|
| 56, native1129 이후 |830|모두1129:1/2/3|
| 57 |1349|모두1129:2/3|
| 10617 |17|모두1129:2/3|
| 10621 |2266|1129:1 또는 경로 종점 이후 현재 경로 없음; 물리 링크 자체가 bypass를 증명|

이 수치는 차량별 반복 관측을 포함하므로 경로 선택 확률이나 통과 유량이 아니다. `summarize_vehicle_route_com.py`는71개 같은-ID1초 분기점 통과를 확인하고 원래 관측 사례를 JSON에 보존한다. 경로가 있을 때 두 번호는 COM Long(VarType3), 종류는`STATIC` 문자열(8)이었다. 없는 경우 세 값 모두Empty(0)였다. 생산 JSON은 이 부재를 세 개의null로 보존하며0이나−1의 경로 번호를 만들지 않는다.

수집기는 No와 세 경로 속성 표의 크기·행 인덱스 정렬, 실제 차량 번호의 유일성과 물리 관측과의 집합 일치, 전후 Count/SimSec를 확인한다. COM 컨테이너 행 인덱스는 차량 번호와 다르므로 둘을 혼동하지 않는다. 부분적으로만 빠진 경로와 잘못된 값은 관측 실패로 처리한다. Python `complete_vehicle_routes`도 같은 계약을 검증한다. null은 미래 경로결정 자격을 의미하지 않으며, 소비하는 모형이 실제 위치와 경로를 함께 판단해야 한다.

검증: 실제 생산 VBS 함수를 추출해 가짜COM으로 실행한6개 검사 PASS(잘못된 ID/행 정렬/중복/부분 부재/비정수/COM오류/시각/대수/빈 네트워크 포함). 기존 v2.1 수집 경로의 정적12개 검사도PASS다. 실제 COM에서 확인한 속성과 생산 JSON 수집기 자체의 실런 확인은 구별하며, 후자는 다음 제어 런에서 확인한다. 시작 무진행300초 규칙은 전용 probe에도 적용했고 시간 제한에 걸리지 않았다.
