# sdmpc_lp_9000 died at 1050 s: urban stock debit tolerance (2026-09-23)

## What happened

- Native 9000 s run `sdmpc_lp_9000` (launched 11:47). Warmup 1-750 OK. The 900 s
  decision completed (508 s wall, obj 393.916, gain 1.619, meters 0/8, VSL 0) and
  `.applied` was written.
- The 1050 s decision was the **first consecutive SDMPC decision**. It failed 204 s in,
  inside the PFO's second batch (3 taped predictions, not the base prediction).
  The adapter wrote an 89 KB report (`"completed": false`) and **then hung** with no
  child processes and no action JSON. The launcher would only have noticed at
  StallSec (2400 s). Killed at 13:20 (this run's PIDs only).

```
Local urban accepted transfer exceeds its source stock:
stock=0.069276954436243779, amount=0.069276954436244015,
remainder=-2.3592239273284576e-16, tolerance=2.2204460492503131e-16
  lane_urban_runtime._debit_stock <- _debit_movement_transfers <- LaneUrbanRuntime.advance
```

## Cause

`_debit_stock` allowed `16*ulp(stock)`. The overdraw is 17 ULPs of 0.069, so the
check missed by one ULP. The tolerance was scaled to the wrong thing. The residual
comes from **the stock's history**, not its current value: a movement mirror that
once held several vehicles and has drained to 0.07 carries roundoff at those larger
magnitudes. ulp(0.07) is 16 times smaller than ulp(1).

This is not the price-inheritance path (`sdmpc.py:505`) that 1050 was supposed to
test first. That path turned out to work (below).

## Fix (`lane_urban_runtime.py`, commit 5a86363)

`tolerance = max(16*max(ulp(stock), ulp(amount)), 1e-9)`: a floor of 1e-9 veh. That
is a hundredth of the 1e-7 veh that `LaneUrbanRuntime.advance` already treats as an
exact transfer match. A real overdraw is packet-sized and still raises.

- **Decisions that completed before are unchanged.** When the check passes, the
  function still returns `max(0, remainder)`. Only a case that used to raise now clamps.
- **No effect on the tape.** Both operands are floats (`math.ulp` in the tangent
  runtime returns the primal ulp), so `max` goes to the builtin with no node and no
  `branch`. The existing `remainder < -tolerance` comparison changes only its constant;
  an exact tie would need `remainder == -1e-9` to the bit.
- Other users of this function: `lane_offramp_runtime.py:87,145` get the same floor.
