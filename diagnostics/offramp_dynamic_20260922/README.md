# Off-ramp 동적 재고 연결·검증 — 2026-09-22

**구현·비교 완료. 재고가 유입−배수에 따라 바뀌고 유효 차로 차단·회복으로 전달되는 것은 검증했다. 그러나 현재 경계 예측을 그대로 사용하면 재고·회복 예측이 충분히 개선되지 않아 정본에 채택하지 않았다.**

특히 10643 회복 구간에서는 배수보다 진출 유입 과대예측이 핵심이었다. φ를 키우거나 저장용량을 임의로 줄여 해결하지 않았다. METANET 계수는 기존 경계 정합 보정값, φ=3 그대로다. 직전 φ=0 후보를 섞지 않았다.

## 실제 수정

- 기존 `canonical_harness.py::DelayedPort`를 연결했다. 차량의 초기 위치, 이동시간, 배수 가능한 재고, 유한 저장공간을 유지한다. 새 plant/adapter를 만들지 않았다.
- `boundary_factory.py`의 기존 port profile을 사용한다. 실제 본선→off 진입량은 본선 모델이 결정하고, 포트 배수는 도착한 재고와 외부 서비스 입력으로 제한한다. 매 스텝 외부 실측 재고로 덮어쓰지 않는다.
- 원인 분리를 위해 기존 두 파일에 `entry_capacity_mode='storage_and_proxy'`라는 명시적 비교 옵션을 추가했다. 기존 유입 상한과 잔여 저장공간의 작은 값을 쓴다. 옵션이 없으면 기존 동적 포트 동작 그대로다. 기존 일반 예측 기본값도 유지한다.
- 5초 기록 사이 on-ramp→본선→off-ramp를 모두 통과해 본선 표본이 없는 경우를 기존 `extract_observations.py`가 빠뜨리던 문제도 수정했다. 동일 차량, 같은 실제 본선 링크, 순방향 접속 위치가 확인된 경우에만 합류·진출·중간 셀 경계 통과를 함께 센다. 차량 수를 추가 생성하지 않는다.

기존 model/observer 원본은 `*.before.txt`, 해시는 `before_sources.json`에 보존했다. 앞선 lane-drop 실험의 source pin은 이 원본들로 재현한다. production adapter, 물리 네트워크, 수요, 실시간 제어 코드는 수정하지 않았다.

## 관측 및 경계 정합

사용자가 승인한 완료 NC80–90 FZP 한 번만 Idle 우선순위로 읽었다(33.91초). 기존 extractor의 `--port-details`를 사용했다. 출력은 `../demand_sweep/user_native_20260914/metanet_calibration_v1/res10_20260922/fw080_urban090_ports`다.

기존 본선 N/v·유량·경계 CSV 세 개는 다시 추출해도 바이트 동일했다. 추가된 8개 off-ramp의 2,392개 30초 재고 장부에서 미확인 소실 0, 재고 보존 잔차 0이었다.

다만 포트 실제 진입과 기존 본선 진출 집계가 서측 330개 구간에서 달랐다. native 포트 이벤트로 전부 대조했다.

|---|---:|---:|

원본 CSV를 덮어쓰거나 FZP를 다시 읽지 않았다. `study.py::corrected_data()`가 저장된 동일 차량의 포트 출입 이벤트와 실제 기하로 경계를 보완한다. 모든 비교 모델에 같은 보완 경계를 넣었고 본선 N/v는 그대로다. 각 셀의 합류·유출·중간 경계 장부를 함께 바꿔 보존식도 유지한다. `paired_crossing_correction.json`에 차량별 증거가 있다. 이 보정은 이번 자료에만 적용했으며, 다른 과거 수요 조건의 재보정까지 끝냈다는 뜻은 아니다.

FW80·도시90, seed23, 같은 기하·초기 상태·수요·METANET 계수. native 기록5초, .1초 위상 유지, 내부 적분1초, 31개 셀/방향 유지.

포트 이동시간은 같은 자료의 900초 이전 완료 통과시간 중앙값으로 정했다. 따라서 첫 예측은 900.1초부터다. 이는 정지·신호대기를 포함할 수 있는 실효 이동시간 대리값이며, 자유주행시간/포화 방출률 보정으로 부르지 않는다. 이벤트 시각은 5초 구간 내에 있다는 정확도만 가진다.

history 예측은 초기 상태와 과거150초 이력만 사용한다. 미래 교통 데이터를 삭제해도 동일 창이 생성되는 것을 검사했다. 반면 `future_drain_diagnostic`은 실제 미래 출구 통과를 서비스 입력으로 넣은 조건부 진단이다. 실현 통과량은 최대 서비스 능력이 아니므로 이 조건을 ‘완벽한 배수 모델’이나 운영 가능한 예측으로 취급하지 않는다.

## 10643: 회복을 놓친 이유

5400.1초 초기 재고는 42대. 이후 450초:

|항목|VISSIM 실제|동적 재고·유입 상한 유지|동적 재고·저장공간 기준|
|---|---:|---:|---:|
|진입|75|98.351|101.913|
|배수|97|98.959|98.959|
|종료 재고|20|41.392|44.954|

이 구간은 총배수가 약2대 차이인데 진입을 약23~27대 많이 예측했다. 따라서 회복을 놓친 주원인을 배수 부족 하나로 설명할 수 없다.

현재 고정 분기비율 β₀=0.0988024와 실측/예측 셀 총방출 F를 쓰면 진입 오차는 다음처럼 정확하게 분해된다.

`예측진입−실측진입 = (β₀·실측F−실측진입) + β₀·(예측F−실측F) + (예측진입−β₀·예측F)`

저장공간 기준 모델의 **26.913대 = 분기비율 고정 성분16.195대 + 본선 총방출 차이10.718대 + 배분 잔차≈0**다. 이는 장부상 대수 분해이고, 서로 독립적인 인과효과를 식별했다는 뜻은 아니다. `off10643_entry_decomposition.json` 참조.

미래 실제 배수만 알려줘도 이 창의 종료 재고는 약46.94대로 남는다. 유입 예측이 잘못된 채 배수만 맞추는 것으로는 회복하지 않는다. 한편 다른 창·다른 램프에는 과거 배수 평균의 서비스 대리 오차도 있으므로 이 한 사례를 모든 램프로 일반화하지 않는다.

## 검증과 다음 방향

- 16개 단위·회귀 검사 통과. 기존 비활성 일반450초 예측2개 전체 JSON 동일, 기존 동적 포트 기본 동작 동일.
- 합성 대기열에서 배수를 막으면 재고·차로 손실 유지, 배수를 열면 정확히80대가 빠지고 유효 차로가 복원됐다. 이동 완료 전 배수 및 사용하지 않은 서비스 누적은 허용하지 않는다.
- 실제 예측396개에서 밀도·본선 보존 실패0. 본선 최대 보존잔차5.68e-14대, 450초 off 포트 최대1.88e-12대. 모든 평가 포트 재고가 물리 저장 범위에 있었다.
- 이전 native 큐의9개 코드 해시는 동일. 새 VISSIM 실행/중단 없음. 완료 FZP 추출 한 번 이후에는 작은 캐시만 사용했다.

이번에는 동적 저장·배수 연결 자체를 검증했고, 자동으로 예측이 좋아진다는 가정은 기각했다. 정본 채택·RM/VSL 이득 검증 완료를 선언하지 않는다.

다음 우선순위는 10643 등에서 **목적지별 진출 수요/분기비율의 시간 변화와 본선 방출량**을 먼저 분리해 맞추는 것이다. off-ramp 배수는 실현 통과량과 ‘대기열이 있을 때 사용 가능한 서비스 능력’을 구분하고, 그다음 신호·하류 수용·이동시간을 검증해야 한다. 이번에 고친 5초 경계 누락도 기존 학습 자료에 반영한 뒤 계수 재보정을 판단해야 한다. φ나 저장용량 조정으로 이러한 입력 오차를 흡수시키지는 않는다.

재현은 `study.py prepare`, `study.py run`, `study.py rolling` 순서다. 이미 완료된 파일을 보존하기 위해 run/rolling은 덮어쓰기를 거부한다. `preflight.json`, `completion.json`, `summary450.json`, `results450.json.gz`, `rolling150.json.gz`, `final_integrity.json`에 입력·검증·예측 기록이 있다.
