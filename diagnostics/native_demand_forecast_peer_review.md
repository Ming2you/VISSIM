# Native demand forecast review

The reviewed34-input timetable matches the actual900 VBS demand aggregate and gate map. All34 inputs use the same six native interval boundaries (0,900,1800,2700,3600,4500s); the two freeway inputs' role and physical-link classifications agree. Three private150s demand views preserve the current ramp observations and volume field. Evidence is in `native_demand_forecast_peer_review.json`; no model rollout, optimizer or VISSIM was run for this review.

The interval averaging, mapped-gate summation and exclusion of internal/shared generation from external gates are consistent with the current source contract. Asymmetric future freeway inputs are explicitly rejected because the existing scalar-average forecast cannot represent them. This does not validate arbitrary asynchronous input schedules: the actual VBS selects one global schedule key, whereas a generic per-input carry-forward interpretation could differ.

The original review found that a timetable-only ON declaration could silently remain on persistence when `urban.native_internal_inputs` was absent. Root subsequently added a boolean/dependency guard at the start of `runtime_setup.configure_runtime`; the original JSON finding is historical. Root also reported7tests and actual1500→future1800/fresh-worker integration passing (`native_demand_forecast_actual1500.json`). Those latter runs are parent evidence, distinct from this independent read-only source/actual900 check. The six-decimal VBS current rates can differ from unrounded timetable arithmetic below1e-5veh/h; that tolerance is a serialization comparison, not a demand calibration.
