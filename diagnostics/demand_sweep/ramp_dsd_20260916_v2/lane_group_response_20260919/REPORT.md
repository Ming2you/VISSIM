# 차로군 상태를 추가한 RM·VSL 이득 예측 검증

차로군별 재고·수용량·출구행 재고를 구현하고 기존 VISSIM 기록과 비교했다. **수치 보존 검증은 통과했지만, 제어 이득 예측은 통과하지 못했다. 기본 모델로 채택하지 않는다.**

기준은 사용자 수정 기하·램프 DSD120·동측 본선 입력만0.8배인 기존 실험이다. 과거 전역80/50 망이 아니다. 이번에는 VISSIM을 새로 실행하지 않았고, 완료된 동일 초기 상태 4조건의 실제 FZP와 비교했다. 450초 비용 범위는 **동측 본선+진입4개·진출4개 connector**다. Ω 전체 도시 대기를 포함한 성능 개선으로 읽으면 안 된다.

## 구현한 물리

- `evaluation/controllers/physical_lane_groups.py`를 기존 `canonical_harness.py`에 연결했다. 새 adapter나 실행 runner를 복제하지 않았다.
- `freeway.physical_mainline_lane_groups=true`와 명시적인 현재 차로군 관측이 함께 있어야 실행된다. 기본 설정은 변경하지 않았다. 온라인 관측·full GNE 연결은 아직 하지 않았다.
- 동측 cell5–14만 lane1 / lane2 / lanes3+로 분리한다. 나머지 셀과 서측은 기존 집계를 유지한다. 5–9와13–14 사이의10–12도 포함해 실제4→3차로 분기까지 차로 연결을 유지했다.
- connector10613의 실제 연결인 **상류 lane2/3/4→하류 lane1/2/3**을 사용한다. 램프와 출구가 접근하는 차로는 최신 INPX의 from/to lane 및 connector 차로 수로 정했다.
- 현재 재고·속도는 FZP에서 직접 집계한다. 차로군 간 이동률은 직전150초 자료만 사용한다. 망 연결에 따른 차로 번호 변경은 lane change로 세지 않는다.
- 기존 METANET FD·속도식에 차로군 밀도를 넣는다. 임의 capacity bonus, lever 활성화 보상, 수요 조정은 넣지 않았다.
- 램프가 들어가는 차로군의 저장공간을 먼저 예약하고, 본선도 같은 공간을 사용한다. 다른 차로의 빈 공간을 해당 램프가 빌려 쓰지 않는다. 기존 ramp buffer와 head service·이동 시간·대기 비용은 유지한다.
- 출구행 차량은 해당 출구가 실제 받아들일 때까지 목적지 재고로 남는다. 차로 간 이동도 재고와 목적지를 함께 이동시킨다. 출구에서 멀어지는 차로 이동은 그 출구행 재고에 적용하지 않는다.

핵심 보존식은 각 차로군g에 대해 다음과 같다.

`n_g(k+1) = n_g(k) + 본선유입 + 실제합류 − 본선유출 − 실제진출 + 차로군유입 − 차로군유출`

`본선유입_g + 램프합류_g ≤ ρ_jam L λ_g − n_g(k)`

공급·수용량은 실제 차로 연결 행렬을 거쳐 배분한다. 출구에서 막힌 차량을 통과 차량으로 재선택하지 않는다. 본선10초, 램프1초, 진출 event 적분의 기존 component 비용 정의를 유지했다.

## 보정과 결과

처음에는 계수를 그대로 옮겼다. 이후 차로 밀도가 전체 평균 밀도와 다르다는 점을 확인하기 위해, **seed13·23 무제어만** 사용해900/1650/2400/3600초의450초 상태 예측을 보정했다. 11개 후보의 제한된1회 좌표 탐색이며, 제어 이득을 이 보정의 목적값으로 쓰지 않았다.

선택된 변경은 동측 `rho_crit_multiplier:1.0→1.2`다. 나머지 기존 계수는 유지됐다. 새 구조 내부의 훈련 상태 오차는2.87387→2.67231로 줄었으나, 기존 모델보다 악화된 구간이 남았다. 특히 seed13의3600초 회복 창은 기존2.964→후보4.723이다. seed33은 이전에도 살펴본 개발 검증 자료이며 새 독립 holdout으로 주장하지 않는다.

## 실제 차로 반응에서 남은 차이

seed23,2400–2850초의 무제어·VSL FZP를 다시 같은 차로군으로 집계했다. 아래는 차량·시간으로 가중한 평균 속도의 차이다. E7은 코드의0기반 cell7이다.

| 위치 | 실제 VSL 속도 변화[km/h] | 모델 |
|---|---:|---:|
|E7 lane1|+15.10|−0.073|
|E7 lane2|+10.71|−0.090|
|E14 lane1|+7.83|+0.004|
|E14 lane2|+9.69|+0.005|

반면 E5의lane1/2/3+는 실제−9.33/−6.74/−7.58km/h로 느려졌다. **VSL에 따른 상류 감속과 특정 하류 차로의 회복을 동시에 재현해야 한다.** 전 구간 속도를 일괄 높이거나 낮추는 보정으로 대체할 수 없다.

E5–9 평균 재고 변화는 실제−3.751대, 모델+0.168대다. E13–14에서는 실제−5.151대, 모델−0.011대다. 이 수치는 공간 진단용 평균 재고 차이며 Ω TTT가 아니다.

새 모델에서도 VSL이 희망 속도에 실질적으로 작용한 cell×10초 표본은 seed23의 제어대상5개 cell 총225개 중8개뿐이다. **차로군별 평균 밀도·속도까지 나눠도 VSL 반응이 거의 사라지는 문제가 남는다.** 이는 확인된 모델 내부 증상이다. 원인이 속도·차두간격 분포, DSD 통과 차량의 명령 유지, lane change 응답 중 무엇인지 이 비교만으로 확정하지 않는다.

## 검증과 채택 판단

- 단위 검사71개 통과. 현재 snapshot 불일치·미래 snapshot 거부, 접근 불가능한 차로의 공간 차용 방지, 출구 차단 시 목적지·전체 재고 보존 등을 포함한다.
- 기능을 끈12개 예측의 전체 JSON이 기존 기록과 정확히 일치한다. 새 모델을 켜도 서측 cells/flows/ports/ramps는 정확히 일치한다.
- 모든 새 rollout의 셀·차로군·램프 보존, 저장용량, 유한값 검사 통과. 정확한 최대 잔차는 `QUALIFICATION.json`에 있다.
- 계수 검사 `scripts/verify_parameters.py qualification_v4/config.json` PASS. 기존 canonical override 경고는 유지됐다. v6의 config·계수 내용은 v4와 같다.
- 최종 결과는 `qualification_v6/`. v4→v6은 ledger·진단 메타데이터 보완이며 교통 상태·유량·실제 램프 물리 기록은 동일함을 검사했다.
- VISSIM 새 런0개. 동일 명령의 실제 FZP가 이미 있고 오프라인 이득 검증에서 탈락했으므로 같은 실험을 반복하지 않았다.

**판정: NOT_QUALIFIED / 기본 비활성.** 단순히 상태 수를 늘리는 것은 해답이 아니었다. 코드·실측 비교를 보존하되 controller의 기본 plant로 바꾸지 않는다. 기존 `merge_drain_response_20260919/decisions_v1/internal_cost` 설정은 그대로다.

남은 가정은 명확하다. 차로군 이동률은 과거150초 값을 고정했고, 차로군 내부의 희망속도·차두간격 분포와 DSD 통과 cohort를 예측하지 않는다. 출구행 label도 branch cell 진입 시 과거 분기율로 초기화한 것이며 상류에서 관측한 목적지별 재고가 아니다. off connector 자체의 차로별 저장·배수는 이번에 분리하지 않았다. 현재 틀린 지점을 전체 METANET의 불가능성으로 일반화하지 않는다.

다음 수정은 새 상태를 더 늘리기 전에 **명령 변경→그 표지를 통과한 차량의 희망속도/간격 변화→합류·진출 접속 차로 방출 변화**의 연결을 기존 짝 자료에서 따로 식별해야 한다. 단순 frozen 속도분포 보정도 이전 `gain_response_20260919`에서 실패했으므로 그대로 재시도하지 않는다. 그 국소 응답을 재현한 경우에만 이번 conserved lane-group 골격에 연결하고, 아직 보정에 쓰지 않은 seed의 짧은 제어 런으로 확인한다.

## 재현

모든 명령은 저장소 worktree 루트에서 실행한다. 출력 폴더는 새 이름을 사용한다.

```text
python -B -X utf8 diagnostics/demand_sweep/ramp_dsd_20260916_v2/lane_group_response_20260919/run.py --output fresh_validation --state-guards --parameters diagnostics/demand_sweep/ramp_dsd_20260916_v2/lane_group_response_20260919/calibration_v1/selected_parameters.json
python -B -X utf8 diagnostics/demand_sweep/ramp_dsd_20260916_v2/lane_group_response_20260919/validate.py --output fresh_tests.json
```

관측 원천 hash는 `observations_v1/evidence_s*.json`, 추가 실측 비교는 `native_comparison_v1/`, 보정 후보는 `calibration_v1/`에 있다. 실패한 초기FIFO 후보와 출력 저장 실패는 별도 보존했다. stdin에서 시작한 Windows multiprocessing 테스트는 자식 시작 실패로 중단했고, 소유 확인한 그 테스트 PID24624만 종료한 뒤 파일 실행으로 통과했다. 다른 Numerical Simulation 작업과 사용자 VISSIM에는 개입하지 않았다.
