# 2026-09-19 추가: 이득 예측 직접 검증

**아직 RM/VSL의 이득 예측을 통과하지 못했다.** 비용 집계를 수정한 모델에서 실제 제어 전후의 ΔTTT를 직접 보정하고, 합류 입력·시간 간격·속도 분포 가설을 따로 검증했다. 유리하게 보이는 계수나 VSL 반응만으로 새 정본을 선언하지 않았다. 현재 단독 MPC 기준은 이전 `merge_drain_response_20260919/decisions_v1/internal_cost`이며, 이번 후보는 채택하지 않는다.

이 문서의 비용은450초 동안 **동측 본선+동측 진입4개+진출4개 connector**의 차량시간이다. Ω 전체 또는4500초 성능이 아니다. 실측은1초 native 재고, 모델은 내부 체류시간을 사용한다. 다른 seed·다른 제어 시작점은 독립 반복 표본으로 합치지 않는다.

## 1. 실제 합류량을 넣어도 해결되는가

미래 실측 합류를 직접 넣는 진단을 했다. 이는 원인 분리용이고 온라인 예측 성능이 아니다. 처음 본선·램프 상태는 네 조건 간 정확히 같음을 검사했다. 실제로 수용된 합류량을 주므로 이 진단에서는 램프 수용 예측기를 우회했다. 본선 물리식·계수는 그대로다.

|---|---:|---:|---:|---:|
| seed13 RM | −0.4864 | −0.1028 | −0.3403 | −0.3521 |
| seed23 RM | −0.8797 | −0.2623 | −0.3336 | −0.4620 |
| seed23 VSL | −0.8522 | 0.0000 | +0.2581 | −0.0164 |
| seed33 RM | −0.1894 | −0.3035 | −0.0163 | −0.1207 |
| seed33 VSL | +0.1508 | +0.0007 | +0.0544 | +0.1068 |

seed13 RM에는 실제 합류량 예측 오차가 상당히 기여한다. 그러나seed23은 실제 합류량과 미래 source/split/drainage 경계까지 넣어도 본선 효과를 충분히 재현하지 못한다. 특히 VSL은 본선 동역학·공간 해상도의 추가 누락이 남는다. 또seed33에서 기존 RM 본선 예측이 가까웠던 것은 입력 오차와 동역학 오차의 상쇄일 수 있다. 평균 합류량만 잘 맞춰 성공으로 판정하면 안 된다.

근거: `isolation_v2/results.json`,36개 예측,`protocol.json`. `isolation_v1`은 이미 수용된 실측 합류를 넣으면서 기존 램프 수용기의 필수 buffer guard를 남겨 둬 중단된 준비 시도다. v2는 진단 경로에서만 해당 수용 예측을 명시적으로 우회했다. 기본 코드의 guard는 변경하지 않았다.

## 2. 비용 차이를 직접 보정하는 계수 탐색

seed13·23의 실제 ΔTTT와 본선/진입/진출별 ΔTTT 오차로 기존 δ_merge,τ,ν,κ,실제 차로감소 φ를 보정했다. 모델이 허용하던 계수 범위 안에서 두 번의 제한된 좌표 탐색을 했으며 고유 후보는19개다. FD·기하·신호·미터 서비스 곡선·제어 후보·목적함수는 고정했다. 제어 보상을 더한 것이 아니라 관측된 물리 비용 차이에 대한 파라미터 적합이다.

선택 과정에서 각 학습 seed의 무제어 상태 오차가10% 넘게 악화되는 후보는 제외했다. 이후900/1650/2400/3600초의 무제어 예측도 확인했다. 선택된 차이는 실제 차로감소 항 φ=0→1.5뿐이다. 훈련 손실은2.1526→2.0737로 약3.7% 줄었지만 seed23 RM/VSL 부호는 그대로 틀리고, 이번 적합에서 빼 둔seed33의 ΔTTT 오차는 개선되지 않았다. φ 후보를 채택하지 않는다.

seed33은 이전에 이미 검토한 개발 검증 자료이며 새로운 독립 검증 seed가 아니다. 추가 독립 VISSIM 실험으로 승격할 만큼의 개선 후보가 나오지 않았다.

근거: `fit_v2/protocol.json`, `trace.json`, `evaluation.json`. `fit_v1`은 δ 후보2/3이 기존 허용범위0–1 밖이어서 중단됐다. 허용범위를 늘리지 않고 후보 목록을 바로잡았다. 실패 결과를 성공 표본으로 세지 않는다.

## 3. 10초 평균 합류가 미터의 차량군을 지웠는가

진단 실행에서만 본선 계산을1초로 세분했다. 같은1초 계산에서 실제 합류량을10초 평균으로 주는 경우와 실제1초 통과 사건을 주는 경우를 비교해, 적분 간격과 차량군 통과 시각의 효과를 나눴다. native 신호의10초 주기·제어 갱신150초·예측450초는 바꾸지 않았다. 배포 모델의 계산 간격도 변경하지 않았다.

seed23 RM의 본선 ΔTTT는1초 계산/평균 합류−0.3092,실제1초 합류−0.2871로 실제−0.8797과 여전히 다르다. VSL도 각각+0.2624/+0.2541로 실제−0.8522와 방향이 다르다.24개 진단 예측은 보존·수치 검사를 통과했지만 이 가설만으로 이득 오차가 해결되지는 않았다.

근거: `clock_v1/results.json`, `protocol.json`. 이 진단의 기존 `model_residence_10s_veh_h` 필드명은 역사적 이름이며 실제 적분은1초다. 일반 예측과 혼합하지 않는다.

## 4. 평균이 낮아도 빠른 차량은 VSL의 영향을 받는가

현재seed23 모델에서는 VSL100 명령이 동측5–9셀의225개 계산 표본에 들어가지만, 희망속도 상한을 실제로 누르는 표본은0이다. 모델 명령 전달 실패가 아니라 `min(평균 평형속도, VSL)` 형태의 비활성 구간이다.

무제어 FZP 세 개,총59,049,226행에서900/1650/2400/3600초의 셀별 차량 속도 분포를 추출했다. 기존 관측의 차량 수와 평균속도에 정확히 맞는지 검사했다. 예측에는 해당 시작점의 분포만 썼다.

추가 보정 계수 없이 `E[min(V_eq × 현재속도/현재평균속도, 제한속도)]`를 시험했다. 제어하지 않을 때는 기존 결과가 전체 JSON 기준 정확히 같고, VSL이 평균 희망속도를 올리거나 보너스 용량을 주지 않는다. 이 분포는450초 동안 고정된 진단 근사이며 차로 이동·분산·원하는 속도 집단의 이동을 예측하는 완성 모델이 아니다.

이제 VSL에 반응하지만 순비용은seed23에서+0.0838(실제−0.9819),seed33에서+0.1664(실제−0.0628)로 잘못 예측한다. **레버를 모델에서 움직이게 하는 것과 실제 이득을 설명하는 것은 다르다.** 이 후보 역시 설치하지 않는다.

근거: `speed_shapes_v1`, `speed_shape_trial_v1`. 미래 관측으로450초 중간 상태를 덮어쓰지 않았다. 실험 함수 연결은 예측 직후 복원하고 별도 Python 프로세스가 종료됐다.

## 판단과 다음 구조 변경의 범위

지금까지의 근거는 “램프 대기 비용을 낮추면 된다” 또는 “METANET merge 계수를 더 키우면 된다”를 지지하지 않는다. 현재 평균 셀 상태와 단순 속도 상한만으로, VSL이 통과 차량군·차로 점유·합류/진출 병목에 주는 변화를 연결하지 못한다. 단, 어느 누락이 전체 오차 중 몇%인지까지 식별한 것은 아니다.

다음에는 전체 망을 더 복잡하게 만들기보다 다음 두 국소 경계를 보존식으로 연결하는 구조를 설계해야 한다.

- VSL이 작용하는5–9셀과10681/10643 주변: 빠른 통과 차로군과 느린 진출·합류 차로군의 재고/속도, 두 집단 사이 이동 및 하류 수용을 분리한다. VSL은 표지 통과 차량의 희망속도와 도착 시각에 작용하게 하고, 측정 근거 없이 용량을 늘리지 않는다.
- 10490→10484 구간: 실제 합류와 대상 차로의 공간을 같은 수용 예산으로 계산하고,10484 정지선 이후 이동/대기 시간을 그 차로의 회복에 연결한다. 램프 비용 전체와 도시부로의 대기 이전을 함께 유지한다.

이 구조를 구현하기 전에 독립 검증 항목은 고정해야 한다: 무제어/단독/동시의 비용 순위, 실제 합류 시각·차로군 재고·병목 통과량, 자유류·혼잡 전·회복 상태의 제한 해제다. 새 state가 단지 평균 속도 RMSE만 줄이거나 VSL을 항상 유리하게 만들면 기각한다. 기존 자료에 반복 적합한 후보를 새 seed 검증 없이 정본으로 삼지 않는다.

현재 판정은 `QUALIFICATION.json`, 계산·소스 불변 검증은 `verification.json`에 있다. 정본 소스·기준 config·native 수요·기존 결과는 그대로이며 새 VISSIM 런은 시작하지 않았다. 다른 Numerical Simulation 작업 프로세스는 읽기 전용 확인만 하고 건드리지 않았다.
