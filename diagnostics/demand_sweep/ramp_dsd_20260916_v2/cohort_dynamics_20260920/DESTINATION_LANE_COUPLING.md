# 목적지별 차로 수용·진출램프 결합 진단

판정: **구현·보존 검사 통과, RM/VSL 이득 예측 미완료. 정본 채택하지 않음.**

현재 경로 관측을 실제 예측에 연결했다. 사용자 요청의 차로 폐쇄는 혼잡으로 인한 차로별 수용·방출 제한으로 다뤘으며, VISSIM 차로·경로·수요·신호를 변경하지 않았다. 이번 신규 native 런은 0회다.

## 구현한 범위

`urban_route_transport.py`의 작은 실험 모형을 기존 canonical harness에 메모리 내에서 연결했다. 원래 runner/adapter/core 파일은 편집하지 않았다. 프로세스 종료 후에도 정본에 남는 monkeypatch는 없다.

- 10643 두 차로는 기존 CumulativeLane의 동일한 sending/receiving 곡선을 사용한다. 현재 위치순 FIFO에 목적 connector와 초기 차량 ID를 붙였다. 차량·목적지별 질량과 체류 비용을 보존한다.
- 126,10641,71은 차로별 유한 저장 셀로 표현한다. 10643은 실제 접속 위치가 포함된 126의 마지막 셀에 합류한다. 126 상류 차량과 같은 수용 공간을 경쟁한다.
- 71의 목적지별 허용 차로, 10642 중간 분기, native SG2/5 시간을 사용한다. 통과 가능한 옆 차로까지 일괄 폐쇄하지 않는다. 대기·차로 이동 중 차량을 없애지 않는다.
- 현재 알려지지 않은 목적지는 unknown으로 남긴다. 미래 유입의 구성은 과거 관측 기반 예측 가정이며 현재 관측된 목적지라고 표시하지 않는다.
- 도시 외부 유입은 cutoff 이전150초의 도착 패턴을 반복한다. 수용하지 못한 유입은 외부 대기에 남긴다.

공간 근사의 한계: 도시 셀 안의 정확한 차량 간격은 예측하지 않는다. lateral insertion은 목표 셀의 뒤에 붙인다. merge/신호 위치는 셀 경계로 근사한다. 126의 초기 위치 투영 최대 오차는4.114m,71은0.230m다. 도시50km/h는 network mesoSpeed를 빌린 고정 가정이며, 미시 자유속도 보정 완료를 뜻하지 않는다. 파동 속도는 기존 NC13 추정값을 그대로 사용했다.

## 완료한 비교: seed23,2400–2850초

모든 인과적 예측은 같은 현재 상태·과거 이력으로 시작한다. 제어별 미래 관측은 사용하지 않았다.

|10643 2차로 정상 방출[대]|NC|VSL|
|---|---:|---:|
|기존 실제 native 기록|23|30|
|첫 후보: 맨 앞 차량만 lateral 이동|5.982|5.982|
|수정 후보: 뒤 차량도 lateral 이동 가능|24.995|24.995|

첫 후보는 적색에 선 앞차가 뒤 차량의 차로 변경까지 막는 과도한 FIFO 제약이 있었다. longitudinal FIFO를 유지하되 lateral 이동을 별도로 허용했다. 잘못된 과도한 차단은 줄었지만 **VSL에 따른 방출 증가를 아직 설명하지 못했다.** NC 수준이 가까워졌다는 이유로 채택하지 않는다.

수정 후보의 동측 본선+진입/진출 connector ΔTTT는 RM−0.020792, VSL+0.042845, 동시+0.022175veh·h다. 기존 이득 예측 실패가 남는다. 추가 도시 모형의 비용은 별도 기록이며 위 component 비용이나 Ω TTT에 섞지 않았다. Ω 내부 이동인10643 방출은 TTD가 아니다.

## 실제 미래 경계 유입을 준 원인 분리 진단

아래는 **명시적인 미래 관측 실험**으로 운영 예측/성능 검증에 사용할 수 없다. 관측된 실제 진입 차량을 공급으로 제시하되 모델의 수용량이 부족하면 외부 대기에 남겼다. 실제 관측 진입량은 희망 수요의 상한·하한 증명이 아니다.

|모형에 준 입력|NC 2차로 방출|VSL 2차로 방출|차이|
|---|---:|---:|---:|
|실제10643 진입, 도시 유입은 과거 패턴|27.163|27.163|약0|
|실제10643 진입+실제 도시 경계 유입|30.000|30.992|+0.992|
|실제 native 결과|23|30|+7|

실제 도시 경계를 준 경우에도 같은 초기10635행40대의 정상 off 방출은29.000→29.992대로 예측했다. 실측22→28대의 차이를 설명하지 못했다. 따라서 상류 유입 오차만을 원인으로 삼을 수 없다. VSL 실제 진입35대 중0.834대는 이 진단 모델에서 끝까지 수용되지 않았다. 그 차량은 삭제하거나 강제로 넣지 않았고 외부 대기와 대기시간을 따로 기록했다.

## 다음 수정의 구체적인 근거

새로 대조한 실제 차로 이동은 다음과 같다.

|이동,2400–2850초|NC|VSL|이번 모델|
|---|---:|---:|---|
|126의2→1|42|43|누락|
|71의3→4|26|32|예측하지만 제어 반응 미재현|
|10643의2→1 /1→2|3/1|5/2|과거 교환0에 고정되어 누락|

126의2→1 이동 중35대씩은 그 순간71 목적지를 알 수 없는 차량이다. 현재 경로1133–2는126의151.451m에서 끝난다. 이들을 임의로10635행 또는 직진행으로 확정하지 않는다. 이 경로가 왜 그 지점에서 끝나는지, 이후 connector 선택이 어떻게 관측되는지는 별도 확인이 필요하다. 경로가 끝난다는 사실만으로 네트워크 오류나 삭제라고 단정하지 않는다.

우선126의 차로 변경과10643의 소규모 교환을 현재 상태·과거 이력으로 모델링해야 한다. 이동할 때 목적지/차량 재고·순서·공유 수용량을 보존하고, 현재 송출량과 도시 방출량을 동시에 대조한다. 미래 차로 변경을 그대로 입력한 결과는 원인 분석에만 사용한다. 전체 차로를 닫는 계수, 이득 보너스 또는 무근거 처리량 증가를 조정하지 않는다.

실제 native의 도시부 비정상 삭제는 NC10/VSL6대다. 모형에 삭제를 서비스로 넣지 않았다. 제어 이득 해석에는 이 비정상 손실과 후속 영향을 계속 구분해야 한다.

## 검증·재개

- 의미 있는10개 계약 검사 PASS: 목적지/unknown 보존, FIFO, 적색 대기비용, 이웃 차로 차단·해소, 꽉 찬 차로 사이 가상 교환 금지, 수용 공간 공유, 적색 앞차 뒤 lateral 이동, 미래 입력 거부.
- 인과적 후보8개 + 경계 oracle4개 완료. 도시 보존/저장 검사5,412회, 기존 lane interface 검사720회, source pin45개 검증. 과거 소스는 각 결과의 source_before 폴더로 보존했다.
- native SIG의 기존 LDP2,102개 대조와 hash를 재확인했다. parameter checker PASS, 기존 calibration override 경고는 남겼다.
- 결과: `urban_route_transport_v1`, `urban_route_transport_lateral_v1`, `urban_route_boundary_oracle_v1`, `urban_route_transport_verification_v1.json`.
- 새로운12상태 guard/미사용 seed 검증은 하지 않았다. 유망한 이득 후보가 아니므로 정본 승격·대규모 런을 하지 않았다. 모든 이번 계산은 종료, 목표active·NOT_QUALIFIED.
