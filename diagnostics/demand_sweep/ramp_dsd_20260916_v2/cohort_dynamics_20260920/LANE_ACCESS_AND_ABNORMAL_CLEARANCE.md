# 차로별 진출 차단: 현재 틈과 비정상 해제의 구분

판정: **이득 예측 보정 미완료. 새 차단 법칙은 정본에 채택하지 않았다.** 기존 native 기록만 사용했다. 원본 네트워크·수요·정본 plant·실행 프로세스 변경, 새 VISSIM 런, commit/push는 없다.

## 사용자가 요청한 off-ramp 차로 차단

필요한 연결은 `71 목적 차로 접근/신호 방출 → 126·10641 수용 → 10643 차로별 저장·배수 → 접속된 본선 차로 수용`이다. 진출 대기로 막히는 차로와 통과 가능한 나머지 차로를 분리하고, 막힌 차량도 재고와 TTT에 남겨야 한다. 실제 VISSIM 차로를 폐쇄하거나 본선 전체 차로 수를 임의로 줄이는 실험을 의미하지 않는다.

기존 `lane_blocking_audit_v1/result.json`의 seed23,2400–2850초를 다시 확인했다. 10643 2차로와 연결된 저속 대기열 후보는 NC172초/VSL133초다. 해당 관측의 본선 평균 속도는3.81/3.34km/h이고, 다음1초 본선 통과는1/0건, 진출 진입은1/1건이다. 강한 국소 억제는 확인되지만 관측 분류를 곧바로 완전한 유량0 조건으로 쓰지는 않는다. 이 시간 분류는 미래 검증 자료이며450초 예측 입력이 아니다.

## 현재 차체 간격 관측을 수정했다

기존 `route_access_observer.py`에 현재 시점만 받는 `current_access()`와 검증 옵션을 추가했다. 기존 `observe()` 출력은 바꾸지 않았다.

- 목적 차로의 현재 앞차·뒤차 사이에 자기 차체가 들어갈 전체 길이가 있는지 계산한다. 차량 앞 위치를p, 차체 길이를L이라 할 때, 가능한 새 앞 위치의 낙관적 구간은 `[뒤차 앞 위치+L, 앞차 앞 위치−앞차 길이]`이다.
- 현재 위치에서 겹쳐도 앞쪽 틈으로 전진해 들어갈 수 있다. 자기 차로 선행 차량도 전진해야 하는 경우는 별도로 표시한다.
- `LnChg`는 진행 중 차로 변경 방향, `DestLane`은 그 변경의 목적 차로다. 이미 시작한 변경과 새 변경을 구분한다. 설치된 VISSIM2020 `Doc/Eng/attribute.xlsx`에서 확인했다.
- 이 계산은 차체 길이만 사용하는 낙관적 기하 관측이다. 안전 간격·차폭·협조 양보·이후 가속을 추정하지 않는다. 미관측 이웃을 무한한 공간으로 보지 않는다. 현재 전진 여유 부족도 미래 변경 금지가 아니다.

`urban_access_transition_v1`은 두 조건의2400–2850초 전체 현재 상태를 독립적으로 관측했다. 셀 저장량을 만들지 않으므로 기존 nominal6m 초과 snapshot도 제외하지 않는다. 저속(<5km/h) 선두차가 현재 삽입 틈을 갖지 못한 관측은 NC241/VSL226 vehicle-second, 서로 다른 차량은각8대다. 이전 VSL206초와의 차이는 기존 셀 계산에서 제외했던 관측을 포함한 것이다. 같은 표본 정의의 새 모델 성능 개선으로 해석하지 않는다.

이 조건의 다음1초 차로 변경 시작·차로 번호 변경은 모두0이었다. **이것만으로 차단 예측이 검증된 것은 아니다.** 전체 자료에서 다음1초 차로 번호가 바뀐 차량은 모두 이미 변경 중이었다. 즉 단기 적중에는 기록 시점/차로 변경 소요시간 효과도 포함된다. 빈 틈이 있어도 변경하지 않는 경우, 주변 차량이 움직이며 뒤늦게 변경을 시작하는 경우도 남아 있다.

VSL63개 차로/시간 snapshot의14대 재고는 실제 차체 총길이59.233–59.719m다. 차량 사이1.5m를 예시로 더하면78.733–79.219m로 약81.24m 차로에 들어갈 수 있다. 이는 nominal6m 저장량13.54대가 해당 차량 구성을 표현하지 못한다는 근거다. 차로 변경 중인 차량의 중복 계수로 단정하거나 실제14대를 줄여 맞추지 않는다. 1.5m를 모든 상황의 강제 최소간격/새 jam density로 채택한 것도 아니다.

## 핵심: 차단 해제가 정상 방출이 아닌 경우

위8대씩의 전체 native FZP 경로를 끝까지 확인하고 `.err`의 차량별 삭제 사건과 대조했다. 두 파일 전체 hash와11,788,963/11,791,383개 데이터 행 수는 기존 검증값과 동일하다. 로컬 관측에서 사라졌다는 이유만으로 정상 이탈로 처리하지 않았다.

|선정된 저속·틈 부족 선두차의2850초까지 결과|NC|VSL|
|---|---:|---:|
|정상 connector 진출|2|2|
|45초 차로 변경 대기 후 비정상 삭제|5|5|
|2850초에 남아 있음|1|1|

이는 **선정된8대씩의 결과**이며 전체 램프 수요·전체 삭제율·모든 차단 사건의 비율이 아니다. 각 조건3대는 실제10643을 거쳐 왔고, 나머지는 도시 유입과 공유하는 차로에서 관측됐다.5대씩 삭제됐다는 사실만으로 두 조건 총 성능 차이가 전부 삭제 때문이라고 결론 내리지 않는다.

같은 차량13038은 NC에서2682초에 삭제됐지만 VSL에서는2530초에 정상10635로 진출했다. 반면 VSL의 다른 선두차13942는2676초에 삭제됐다. 따라서 총 삭제 대수가 같아도 삭제되는 차량·시점과 이후 수용 공간이 다르다.

차량 삭제로 선두가 사라지며 뒤의 차량이 움직이는 현상을 정상 신호 배수나45초 뒤 자동 회복 법칙으로 학습하면 안 된다. 이 사건은 TTD가 아니며, 보존형 plant에 삭제를 도입해 관측과 맞추지 않는다. 삭제 이후의 주변 차량 흐름에도 영향을 줄 수 있으므로 삭제 차량만 비용표에서 제외하는 것으로 비교 오염이 모두 사라지지 않는다.

## 다음 모델 작업의 범위

1. 정상 진출이 확인된 접근/해제 사건과 비정상 삭제 사건을 분리한다. 현재 관측의 틈·차체 길이·진행 중 변경은 상태로 쓰되, 이후 native 틈/방출은 검증 정답으로만 둔다.
2. 공유 차로의 선두가 목적 connector에 도달하지 못할 때 뒤 차량의 longitudinal 방출을 제한한다. 인접 차로 우회는 그 차로의 실제 수용 공간을 소비하며, 나머지 본선 차로까지 일괄 차단하지 않는다.
3. 정상 도시 배수로 생긴 공간이10643 입구와 본선으로 돌아오는 시간 및 제한 해제를 검증한다.45초 삭제 타이머나 고정된 폐쇄 비율로 대신하지 않는다.
4. 삭제가 교통 회복에 개입한450초 자료는 보존형 예측의 깨끗한 검증 기준이 아니다. 정상 회복 구간에서 국소 법칙을 먼저 확인하고, 제어 이득 qualification에서는 비정상 손실의 영향과 미사용 검증을 별도로 통과해야 한다. 이번 진단을450초 이득 예측 성공으로 보고하지 않는다.

## 재현·검증

- 완료: `route_access_observer.py --access-audit`, `--head-outcomes`.
- `urban_access_head_outcomes_v2/verification.json`: 기하/경로 계약7개, 기존 관측14개 전체 일치, 입력 상태 미변경, 결과·소스 pin 확인.
- `urban_access_head_outcomes_v1`은 삭제 오류문 끝의 마침표를 숫자로 읽은 파서 실패다. 교통 런 실패가 아니며 소스/실패 기록을 보존했다. 최종 결과는v2다.
- 이전 observer 소스는 `route_access_observations_v2/source_before_gap_audit/`에, access audit 당시 소스는 `urban_access_transition_v1/source_before_head_outcomes/`에 보존했다. 과거 hash를 현재 소스 값으로 덮어쓰지 않았다.
- 새 production 예측/계수 채택은 없다. 모든 이번 분석은 종료됐으며 소유 실행은 남아 있지 않다. 목표active·NOT_QUALIFIED.
