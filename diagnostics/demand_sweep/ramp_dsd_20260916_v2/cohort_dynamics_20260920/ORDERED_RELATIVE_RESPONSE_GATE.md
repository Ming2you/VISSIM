# 차량 순서·상대속도 반응식의 무제어 검사

2026-09-21 로컬 후속. **NOT_QUALIFIED, 목표 active.** 앞선 속도 장부에서 확인한 구간 내부 추종 문제를 분리하기 위해 기존 `downstream_restart.py` 안에 선택적 종방향 반응식을 넣고 실제 저장 상태에서 계산했다. 정본 controller나 망을 바꾼 것이 아니며, 이 후보도 채택하지 않았다.

## 기존 시험과의 차이

기존 고정 차로 gap 모델과 이웃 유지율 진단은 이미 존재했다. 문제16셀2550초의 최초 앞차39쌍 중30초 동안 같은 앞차를 유지한 것은7쌍뿐이었다. 따라서 고정한 현재 target을450초 재생하거나 차량 순서만 넣으면 해결된다고 가정하지 않았다.

이번에는 기존 gap 모델의 즉시 간격-속도 관계와, 앞차와의 상대속도를 포함하는 [IDM 반응식 및 정지 시 적분 규칙](https://traffic-simulation.de/info/info_IDM.html)을 같은 초기 차로 집단에서 대조했다. 희망속도는 현재 차량 DESSPEED, 최소 간격·시간간격은 원래 망의 CC0=1.5m·CC1=0.9s에서 가져왔다. 가속·감속은 차종별 native 평균 희망 곡선의0km/h 값, 지수는4, 적분 간격은0.2초다. **Wiedemann 파라미터와 IDM 파라미터가 동등하다는 뜻이 아니라, 보정 전 전달 가설**이다. 계수나 제어 이득을 적합하지 않았다.

원래 함수의 기본값 `interaction=None`과 기존 파라미터 추출은 그대로다. 선택 기능은 `interaction={'law':'idm','delta':4}`일 때만 실행된다. 현재 차량의 위치·속도·희망속도·길이·차로만 초기화하고, 이후 앞차 위치는 모델이 갱신한다. 미래 lane change/target/유입을 재생하지 않는다. 기본 함수 본문의 AST와12개 실제 초기 차로 시험 결과는 수정 전과 정확히 같았다.

## 결과: 부분 개선이지만 채택 불가

무제어 seed23의2280/2400/2550/2700초 ×3차로, 각30초를 시험했다. 두 식 모두10개 차로를 완료했고2550초1·3차로는 초기 차로 투영 겹침 때문에 실패했다. 차량을 옮기거나 삭제해 지원 가능한 상태로 만들지 않았다.

공통 지원 차량의 오차이며, **비교 기준은 기존 작은 gap 모델이지 METANET이 아니다.**

|지평|공통 평가 차량|속도 RMSE 기존→IDM [km/h]|위치 MAE 기존→IDM [m]|
|---|---:|---:|---:|
|5초|493|10.980→11.569|5.509→8.185|
|10초|476|18.338→17.488|16.198→20.198|
|30초|377|19.588→18.116|75.080→72.259|

30초 평가에서137개는 native 선택 링크를 벗어나 완전한 미래 위치가 없어 검열했다. 완료로 간주하거나 차로 변경으로 분류하지 않았다. 공통377개 중199개는 실제 자신의 차로가 바뀌었다. 본인 차로가 그대로여도 앞차 교체와 옆 차로 진입은 있을 수 있다.

문제16셀2550초의 지원2차로13대는 IDM의5초 속도오차21.783,10초39.738km/h로 기존19.842/39.311보다 나빴다.30초는28.839→23.948로 줄었지만 위치오차187.518m가 남았다. 반면2400초16셀22대의30초 속도오차는15.943→13.714로 줄었다. 일관된 무제어 보호를 통과한 결과가 아니다.

IDM은5/10초 평가에서16대,30초 평가에서10대에 대해 native 최대 감속 곡선의 범위를 넘는 반응을 요구했다. 이를 잘라 숨기지 않고 기록했다. 기존 gap 모델의 결과 JSON에 들어간 감속 초과0은 **해당 항목을 계측하지 않았다는 뜻**으로, 기존 식이 감속 범위를 통과했다는 근거가 아니다. `scoring_review.json`에 이를 명시했다.

## 결론과 다음 단계

상대속도 반응은 일부 구간의 과회복을 줄일 수 있지만, 이 단순한 식 전환으로 문제의 혼잡을 자율 예측하지 못했다. IDM으로 정본을 교체하거나 파라미터 sweep을 늘릴 근거가 없다. 종방향 순서를 고정한 두 식 모두 문제 상태의 차로 겹침과 이후 관계 교체를 다루지 못한다. 초기 투영 겹침은 실제 충돌의 증거가 아니라, 현재 1차원 차로 표현의 지원 한계다.

다음에는 **현재 진행 중인 차로 변경의 측방 위치·양 차로 점유와 앞차 교체를 표현할 수 있는지** 먼저 확인한다. FZP의 현재/직전 PosLat·LaneChange·native target에서 얻을 수 있는 정보와 아직 모르는 남은 변경시간을 구분한다. 현재 기하를 임의로 펴거나 전체 차로를 폐쇄하지 않는다. 앞차를 고정한 예측, 미래 차로 변경 재생, 기존 평균 교환률 보정으로 대체하지 않는다. 불확실한 관계 갱신 때문에 이득 부호를 신뢰할 수 없는 영역도 명시해야 한다.

이것은 국소 반응 검사의 다음 입력 문제이며, 미시 VISSIM 복제품을 새로 만드는 결정이 아니다. 향후에는 방출·통과시간·구성 대기 비용으로 검증 범위를 연결해야 한다. RM/VSL/동시450초 순이득·순위, 자유류 보호, 미사용 검증과 정본 통합은 여전히 남아 있다.

## 보존·검증

`ordered_relative_response_v1`에 수정 전 소스, 초기 차로 집단·명시 파라미터, 완료20개 궤적, 실패4개 모드×차로 기록, 점수와 지원 범위를 보존했다. 이전 결과가 `downstream_restart.py`의 옛 해시를 요구하면 이 폴더의 `source_before.py`가 해당 바이트다. 기존 pin을 새 소스로 바꿔 과거 실험을 재해석하지 않는다.

정본 core4파일은`a5dcbd3` 대비 바이트 불변이다. 계산 세션21205는 exit0, 후속 검사도 종료했다. 새 native 실행·사용자 프로세스 개입·기본 활성화·푸시는 없었다.
