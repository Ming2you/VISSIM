# 현재 목적 경로 관측 확보: 같은 차로 재고라도 필요한 출구가 다르다

2026-09-20. **무제어·VSL의 기존 native 실행을 관측 항목만 추가해 재생했고, 교통 궤적이 정확히 유지됨을 확인했다.** 예측 시작 시점에 이미 지정된 목적 경로를 읽을 수 있게 됐다. 이득 보정 완료나 새로운 성능 개선 실험은 아니다. 정본 plant/adapter/runner/writer·기본 config·원본 망·수요는 변경하지 않았으며 목표는 active, 보정은 NOT_QUALIFIED다.

## 실제 실행과 검증

설치된 `PTV Vissim 2020/Doc/Eng/attribute.xlsx`에서 Vehicle 속성 ID와 의미를 확인했다. 기존 `prepare_vehicle_lengths.py`/`analyze_vehicle_lengths.py`에 route-state 모드를 추가하고, 기존 `fast_nc_run.ps1`/fixed-profile 실행을 재사용했다. 별도 adapter나 COM 전수 관측 루프는 만들지 않았다.

추가 native 기록은 LENGTH, ROUTDECNO, ROUTENO, ROUTDECTYPE, NEXTLINK\NO, DESTLANE, LNCHG, INTERACTSTATE, INTERACTTARGTYPE, INTERACTTARGNO다. DestLane은 **현재 차로 변경의 대상 차로**이고, 전체 경로가 요구하는 출구 차로와 같지 않다. 차로 변경 중이 아니면 이 값이 비어 있어도, 경로상 필요한 차로는 존재할 수 있다. [VISSIM 2020 차량 속성 설명](https://cgi.ptvgroup.com/vision-help/VISSIM_2020_ENG/Content/9_SimulationundTest/Simulation_Fz_im_Netz_anz.htm).

|관측 반복|종료|native 실행 전체 경과|원래10개 열 전 행 일치|기존 국소 프레임 일치|
|---|---:|---:|---:|---:|
|seed23 NC|3000초|231.0초|11,788,963행|451개|
|seed23 VSL|3000초|231.7초|11,791,383행|451개|

위 경과시간은 로딩·설정·시뮬레이션·내장 종료 검증을 포함한 실행 전체 시간이다. simulation 단독 속도 개선치가 아니다. 신호 LDP/명령 적용 readback 검증도 각각 통과했다. 원래 1초 FZP·seed·수요·신호·VSL 명령·시뮬레이션 계산 해상도를 유지했다. 준비 시 추가 recording attribute를 제거한 XML은 해당 원본과 정확히 동일하다.

개입 전2400초까지 두 새 기록의 **20개 전체 열**도 8,646,345행, 동일 SHA256이다. 이후 시각의 경로 정보가 시작점에 소급된 것은 아니다. 새 목적 경로 관측은 당시 VISSIM이 기록한 현재 값이다. 처음 NC 시작은 샌드박스의 Windows Script Host 설정 접근 거부로 시뮬레이터 생성 전에 끝났다. 실패 자료를 보존하고 동일 준비본을 권한을 확보해 재시도했다. 두 유효 런은 순차 실행했으며, 소유 실행의300초 무진행 감시를 유지했다. 분석은 두 런 종료 후 수행했다.

## 2400초부터 이미 목적지 구성이 크게 달랐다

10643의 차로별 **현재 지정된** 71 이후 목적 connector다.

|현재10643 차로|차량 수|10634→56|10635→47|10642→67|미지정/미확인|
|---|---:|---:|---:|---:|---:|
|1|16|7|0|9|0|
|2|45|2|40|0|3|

2차로의45대 중40대(88.9%, 목적지가 확인된42대 중95.2%)는71의4·5차로에서 나가는10635가 목적지다. 그러나10643의2차로는126·10641을 통해71의3차로로 연결된다. 현재 차로별 수요를 총량이나 동일한 평균 목적지 비율로 처리하면 이 접근 부담을 잃는다.

또한 현재71의4차로 선두 차량18171은 반대로1·2·3차로에서 나가는10634가 다음 connector였다. 3차로에서4차로로 가려는 차량만 따로 고려해도 충분하지 않다. 인접 차로의 차량이 요구하는 이동과 실제 여유를 함께 보아야 한다. 이것만으로 두 차량의 미래 교착을 확정하거나 해당 차로를 무조건 폐쇄하지 않는다.

앞선 진단의 차량13038과13942도2400초 기록에서 이미 static route1126–1이었다. 뒤늦은 삭제 경고를 초기 경로로 이용할 필요가 없어졌다. 두 조건의 시작 관측은 동일하다. 2644초의 별도 현재 관측에서는 두 차량이71의3차로에서10635를 요구하면서 정지했고,4차로 뒤쪽 차량과의 현재 종방향 여유는 각각−9.13m/−3.18m였다. 음수는 인접 차로 차량과 길이 방향으로 겹쳐 있다는 뜻이며, 동일 차로의 충돌이나 음수 저장 공간이라는 뜻이 아니다. 이 값 하나로 VISSIM 차로 변경 수용 법칙이 검증된 것은 아니다.

관측 함수 `observe(frame, ...)`는 단일 현재 프레임만 받는다. 경로·NextLink 모순은 미확인으로 남기고, 차로 재고를 다른 목적지에 나눠 넣지 않는다. 10643 앞부분에서1126 경로가 아직 지정되지 않은 차량도 unknown 재고로 보존한다. 3개 관측 계약 검사와14개 미래 자료 제거 검사를 통과했다. 현재 상태 해석과 미래 진단용 결과는 별도 파일이다.

미확인3대의 위치는5.86/12.06/18.12m로1126 decision의23.34m 이전이다. 앞의2대에는10643의15.59m에서 끝나는 이전1130–1 경로가 아직 표시되고, 나머지1대의 경로는 비어 있다. **경로 번호가 존재한다는 것과71 이후 목적지가 이미 정해졌다는 것은 다르다.** 최종 검증에서 '미확인은 모두 빈 경로'라는 과도한 검사 조건을 바로잡았으며, 관측 함수는 처음부터 이 세 차량의 질량을unknown으로 유지했다.

## 같은 초기 차량들의 실제 반응도 분리했다

2400초에10643 안에 있던 동일61대를450초 동안 추적했다. 아래 분류는2400초 관측 경로로만 정했다. 방출 시각과 체류시간은 **나중에 확인하는 정답 자료**이며 예측 입력이 아니다.

|초기 지정 connector|초기 대수|NC 정상 진출 / VSL 정상 진출|NC10643 체류[veh·s]|VSL10643 체류[veh·s]|
|---|---:|---:|---:|---:|
|10635|40|22 / 28|11,721|9,693|
|10634|9|8 / 8|1,080|857|
|10642|9|9 / 9|246|246|
|미확인|3|0 / 0|1,350|1,350|

10635행 초기40대의10643 체류는2,028veh·s(0.5633veh·h) 감소했고, 정상 하류 이동은6대 늘었다. 이 차이는 미래에 새로 추출된 차량의 목적지 비율을 초기 상태로 소급해서 만든 결과가 아니다. 다만 후속 교통·차로 이동·도시부 삭제가 미친 간접 영향까지 분리한 것은 아니다.

이 표의 정상 진출은10643→126/연결도로/71로의 이동이다. **Ω 내부 이동이므로 TTD가 아니다.** 이 표에는71의 추가 대기 비용이나 전체 Ω TTT가 포함되지 않는다.10643에서의 정상 이동을 확인했어도 나중의 도시부 비정상 삭제가 정상 완료로 바뀌는 것은 아니다.

## 다음 모델 변경의 범위

현재 관측 가능성의 공백은 해소했다. 다음은 진출램프의 차로별 FIFO 순서와 목적지별 재고를 보존하고,71의 목적 connector에 접근 가능한 차로·인접 차로의 수용·해당 신호 서비스와 연결하는 것이다. 최소 상태 후보는 `n[차로, 목적 connector] + 차로별 선두/대기 순서 + 인접 차로 여유`다. 현재 알려진 목적지는 유지하고 미래 미지정 유입만 실제 route decision의 설정으로 분기해야 한다. 목적지별 합계와 정상 이동·대기 비용은 항상 보존한다.

먼저 현재 자료의 짧은 이동·방출 반응을 검증하고, 그 다음 기존450초 RM/VSL/동시 비용·손익/순위 및 상태 보호를 확인한다.40대가 다른 차로로 가야 한다는 사실을 곧바로 서비스0이나 임의 capacity drop으로 바꾸지 않는다. 새 관측은 같은 seed의 결정적 재생이므로 미사용 seed 검증을 대신하지 않는다. 기존 누적 경계 후보와 합류 타이밍 오차도 해결 완료로 처리하지 않는다.

근거: `route_state_native_v1/{none_s23,vsl_s23}/`의 protocol·run_retry1·analysis, `route_access_observations_v2/`의 현재 상태/초기 코호트 정답/검증 결과. v1 관측 파일과 수정 전 진단 소스도 보존했다. 모든 이번 실행·분석은 종료했으며 commit/push는 하지 않았다.
