# RM 반응 원인 분리 — 추가 체크포인트

**이득 예측은 아직 NOT_QUALIFIED다.** 현재 망의71 경로/차로 접근 문제에 대한 사용자 범위 선택을 기다리는 동안, 완료된 RM 실험으로 독립적인 원인 분석을 계속했다. 망·수요·controller·core 모델은 이 단계에서 변경하지 않았고 새 VISSIM 실행도 시작하지 않았다.

평가는2400–2850초, FW_E 본선과 동측4진입/4진출 connector의 체류시간이다. Ω/full GNE 성능과 다르다. 아래 Δ는RM10490의g8→6→4와 무제어의 차이이며 음수가 체류시간 감소다. 다른 미터는native OFF다.

## 본선 입력 차이로 RM 이득 오차를 설명할 수 없다

`rm_boundary_cohorts_v1/`은1초 native FZP에서 모든 차량의 진입/이탈과 체류시간을 다시 대조했다. 세 쌍의 초기 차량 ID가 같고,6런 모두 미확인 component 경계 사건0, 재고·체류시간 항등식 잔차1e−8 미만이다. 정상 말단 이탈은 실제 끝 위치를 확인한 추론이며 도시부 차량 삭제를 정상 이탈로 센 것이 아니다.

|Δ[veh·h]|seed23|seed33|seed43|
|---|---:|---:|---:|
|실제 component TTT|−0.553333|−0.162222|−0.060278|
|본선 source 진입 시각 항|0|0|+0.000833|

이 표의 각 항은450초 말단에 고정된 잔여시간으로 가중한 회계 분해다. 한 항을 빼서 독립적인 인과 효과라고 부르면 안 된다. seed43의 작은 순이득은 앞선 시드와 같은 배분으로 생기지도 않았다. 외부 도착·진출 반응이 함께 달라졌다.

## 미터 자체와 다른 램프의 대기 반응을 구분했다

`rm_port_attribution_v1/result.json`은 기존 native port 사건으로1초 재고를 복원하고720개30초 실제 재고 표본과 대조했다. 미확인 소실이 있는 경우 실패하도록 했고 모두 통과했다. 총량과 시각을 구분하기 위해 connector별 체류시간도 보존했다.

|항목|23 실제 / 모델|33 실제 / 모델|
|---|---:|---:|
|10490 합류 대수 변화[veh]|−13 / −12.213|−4 / −13.187|
|10490 체류시간 변화[veh·h]|+0.21222 / +0.27048|+0.31139 / +0.29095|

모델은 최신 미채택 `port_origin_split_v1/config.json`과 `port_travel_fit_v1/selected_parameters.json`이다. **seed33의10484 이득은 합류 대수 증가가 아니다.** 합류 시각과 체류가 바뀌었다. 모델은 그 체류 감소를 거의 표현하지 못한다. 반면 seed23에서10484 자체의 대기 비용은 약간 증가했다. 따라서10484에 고정된 RM 보너스를 넣는 방식은 두 시드를 함께 설명하지 못한다.

seed43에는 실런 전 고정한 다른 `port_travel` 후보 예측을 참고용으로 함께 보존했다. 최신 후보와 같은 모델로 세 시드를 검증한 결과로 합치지 않는다. 이 경우10490 실제 합류−13대/모델−16.907대, 체류+0.58556/+0.43936veh·h였다. 실제10490 도착도6대 늘었으므로 그 차이 전부를 미터 서비스율 오차로 볼 수 없다.

## 출구 상한 가설은 이번 시험에서 지지되지 않았다

`terminal_probe_v1/`에서 기존 FW_E 말단 규칙과, 이미 구현된 `terminal_zero_gradient=True` 규칙을 비교했다. 후자는 모델의 예측 sending을 고정 말단 상한으로 자르지 않고 ghost 밀도를 마지막 셀과 같게 둔다. 다른 내부 용량, 입력, 램프 대기, 명령, 계수는 고정했다. 진단 함수에서만 설정했고 core/config에 채택하지 않았다.

## 실측 속도를 줘도 RM 오차가 남는다

`rm_moments_v1/`은 기존RM FZP에서10초 차로별 속도·차량 수를 추출했다. 제어 직전 모든 표본은 같은 시드 무제어와 정확히 같다. DESSPEED가 없는 구기록에서 희망속도를 만들어내지 않았다.

`rm_speed_oracle_v1/`에서는 선택 구간의 **미래 실제 속도만** 매10초 대입했다. 초기 이후 재고 리셋은 없고 도착·합류·진출은 기존 예측으로 유지했다. 미래 관측을 사용하는 원인 분리 실험이며 배포 가능한 예측/보정이 아니다. 모델 최종 출력의7,278개 차로군 속도가 실제 집계와 일치함을 별도로 검증했다.

seed23에서 하류 속도만 주면 총량이 거의 일치하지만, 전체 실제 속도를 주면 다시 어긋난다. **부분 대체의 총량 일치로 보정 성공을 선언하면 안 된다.** 잘못된 다른 상태/유량과의 상쇄 가능성이 있다. seed33은 전체 속도를 주어도10484 대기 감소를 충분히 재현하지 못한다. 현재 셀 안 공간분포·차로 합류 수용·경계 도착과 배수의 결합을 속도 계수 하나의 오차로 취급할 수 없다.

## 다음 작업의 조건

71 망 선택 질문은 아직 답변 전이다. 원본·수요·목적지 비율을 그대로 보존했다. VSL 전체450초 qualification에는 앞선 `BOUNDARY_IDENTIFICATION.md`의 도시 접근/비정상 소실 문제를 먼저 정리해야 한다. 단, RM의 모든 오차가71에서 비롯됐다는 뜻은 아니다.

독립적으로 남은 RM 작업은10490–10484 부근에서 현재 관측으로 예측할 수 있는 합류 수용과 공간 재고/도착 시각을 검증하는 것이다. 기존 평균 유량 gap 모형의 계수를 다시 훑거나, 이번 미래 속도 대체를 controller에 넣지 않는다. 새 구조가 필요하면 해당 국소 상태·보존식부터 검증하고, 전체 순이득/구성 비용과 무제어 상태 보호를 다시 통과시켜야 한다.

`rm_diagnostic_validation_v1.json`은 이 체크포인트의 증거 검사 결과다. 진단 통과와 이득 예측 qualification은 다르며, 목표는 여전히active다. 신규 commit/push는 하지 않았다.
