# 실시간 MPC의 관측 시각 검사

2026-09-21, 로컬 후속. **NOT_QUALIFIED, goal active.** 저장 공간 문제는 두 번째 goal 턴에도 남아 있고 소유 native 프로세스는 없다. 이전 턴은 디스크 실패 분리·1500초 prefix 비교·공간 검사 추가의 진전이었다. 이번에는 실제 관측 코드의 시각 처리 오류를 재현하고 최소 수정했다. 새 VISSIM 실행이나 이득 예측 재보정은 하지 않았다.

## 확인한 오류와 수정

기존 `evaluate_response.online_data()`는 FZP의시각을 `int(float(...))`로 만든 다음 제어시각을 넘는지 검사했다. 제어시각150에서 정수 과거 프레임1–149와150.1초 프레임을 제공하고 동일한 정지 차량 COM 스냅샷을 주면, 기존 함수가 이를 받아들이며 `future_traffic_used=false`, `features_latest_realized_sec=150`이라고 기록하는 것을 재현했다. 원본 코드와 작은 재현 fixture, 잘못된 증거는 `native_time_contract_v1`에 보존했다.

기존 함수에서 원래 float 시각의 유한성·비음수·미래 여부부터 검사하도록 바꿨다. 그 뒤에 정수 초 정렬을 검사하며, 소수 초를 반올림하거나 이전 시각으로 재해석하지 않는다. 현재1.1/2.1초 기록은 명확히 거부하므로, 고해상도 제어 실험 전에 recording phase 또는 정식 관측 시간 규약을 별도로 검증해야 한다. 이를 우회해149.1초 관측을149초나150초로 붙이지 않는다.

기존 오프라인 `native_frames()`와 `downstream_wave_audit.extract()`는 이미 비정수 시각을 거부한다. 오프라인 추출기나 비용 식은 바꾸지 않았다. 이번 오류가 지금까지의 정수 초 VISSIM 실험에서 실제로 발생했거나 RM/VSL 이득 실패를 일으켰다는 증거는 없다. 또한10단계 실험은 현재 무제어 진단만 허용된다. 이번 변경은 향후 관측 연결의 오류를 막는 수정이다.

## 검증 범위

`test_online_native_clock.py`의6개 테스트가 통과했다.

-150.1초의 미래 프레임은 정수변환 전에 거부하고 관측 캐시를 저장하지 않는다.
-과거라도1.1/2.1초 시리즈는 정수 초인 것처럼 기록하지 않는다.
-실제 실패10단계 런에서 추출한 첫1.1초 FZP 행도 거부한다.
-기존 정수 미래 프레임, NaN/무한대/음수 시각은 거부한다.
-정수 입력의150초 및300초 연속 두 주기에서는 수정 전과 반환 상태·증거·pickle 캐시 바이트가 정확히 같다. 합성 관측에 대한 계약 검사이며 실제 폐루프 성능 불변을 검증한 것은 아니다.

python -B -X utf8 -m unittest diagnostics.demand_sweep.ramp_dsd_20260916_v2.cohort_dynamics_20260920.test_online_native_clock

`native_time_contract_v1/verification.json`에 source pin과 검사 범위를 기록했다. `source_before_evaluate_response.py`는 이전 소스의 정확한 보존본이다. 과거 기록이 이 파일의옛 해시를 요구하면 보존본으로 확인하고 옛pin을 새 코드로 바꾸지 않는다. 정본core4파일·기준망·수요·모델 파라미터는 `1f378f3` 대비 불변이다. 기존 `evaluate_response.py`의 운영 관측 검사만 변경했다.
