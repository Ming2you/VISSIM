# 분기 전후 재고 수송 구현과450초 검증

**NOT_QUALIFIED, 목표 active.** 분기 뒤 차량까지 막던 구조는 기존 plant 코드에서 수정했지만, 동일 상태450초의 제어 이득 예측은 여전히 실패했다. 기능은 config로만 켜며 기본 비활성이다. 무제어 전체상태 guard나 미사용 seed를 통과했다고 주장하지 않는다.

## 실제 변경

정본 component가 호출하는 `evaluation/controllers/physical_lane_groups.py`에 분기 전후 재고·속도를 계속 유지하는 선택 기능을 넣었다. 별도 adapter나 물리 엔진 사본을 만들지 않았다. `canonical_harness.py`의 `freeway.physical_branch_partition` 목록이 켜며, 이번 후보는10643만 선택한다. 현재 시각의 `branch_partition_initial`을 반드시 제공해야 한다. 전체 차량 수·차량 가중 속도·분기 전 위치 적격 대수와 일치하지 않으면 실패한다.

- 상류에서 온 차량은 분기 전 재고로 들어오고, 진출행은10643으로만 빠진다. 분기를 통과한 직진 차량은 후방 재고로 이동한 뒤 하류로 나간다. 한10초 계산에서 새로 넘어온 차량을 다시 다음 공간으로 보내지 않는다.
- 해당 셀의10639 합류는 분기 뒤에 있다. 합류는 분기 뒤 여유공간만 사용하며 상류 진출행으로 다시 표지하지 않는다. 본선의 상류 유입은 분기 앞 여유공간만 사용한다.
- 차로 이동에서도 분기 전후 위치 구분과 목적지 표지를 함께 이동한다. 각 영역의 실제 길이·차로 수에서 계산한 저장 상한을 각각 적용한다. 진출 차단은 분기 앞의 공유 차로에 적용하고, 이미 지난 차량의 sending에 다시 곱하지 않는다.
- 전후 공간의METANET 완화·anticipation 및 기존 합류 감속 계수는 그대로 사용한다. 수송한 속도 모멘트는 실제 허용된 차량 이동량으로 옮긴다. 그 뒤 Euler 대류항으로 같은 속도를 다시 운반하지 않는다. 기존 `advected_speed()`를 재사용했다.
- 제어 주기·450초 지평·본선10초 연속방정식·액추에이터·수요·망·비용·FD 계수를 바꾸지 않았다. 완화 시간보다 계산 간격이 긴 경우 속도 ODE만 나누어 완화 가중치가1을 넘지 않게 한다. 차량 방출은 재고·수용량 이내다. 임의 용량 증가, 보상항, 삭제는 없다.

기존 `clear_ending_lane` 옵션은 다른 구간의 실제 차로 종료에 필요하다. 전체 도로에 그 옵션이 있다는 이유로 이번 분리를 거부했던 초기 검사를 좁혔다. 분리 대상 셀의 하류 차로가 모두 이어지는지는 계속 검사한다. 차로 종료·상태별 lane exchange·추가 interruption·전역 momentum 옵션과의 검증되지 않은 조합은 제한한다.

## 반례 → 수정 → 실제 기록 상태 검증

신규 공간 반례 검사는 기능의 자료 구조를 추가한 뒤 기존 수송을 그대로 두었을 때 `0.0 not greater than0.0`으로 실패했다. 구현 후 분기 뒤 방출·상류FIFO·하류 수용·미래 내부 수송·차로 이동·합류 위치 검사를 통과했다.

첫 구현v3에서는 공간 방출은 수정됐지만, 통과 차량이0이어도 느린 상류 속도를 후방 공간으로 대류시키는 문제가 드러났다. 완화·anticipation을 격리한 시험에서100km/h가28.624km/h로 떨어졌다. 실제 허용 유량의 속도 모멘트를 사용한v4에서는 통과0이면 해당 대류 변화도0이고, 통과가 있으면 차량 가중 속도를 한 번만 전달한다. 이 검사는 속도 RMSE를 맞추기 위한 계수 적합이 아니다.

같은2400초 native 초기 상태, 분기 뒤2차로 차량5대:

|---|---:|---:|---:|
|차량 수|0|3.854695|5|

이미 지난 차량을 완전히 막는 오류는 해소됐다. 그러나 두 공간 안의 정확한 차량 위치 순서까지 보존하는 모델은 아니므로5대와 정확히 같지는 않다. 이를 완벽한 초기 궤적 재현으로 보고하지 않는다.

## 검증 영수증과 한계

- `branch_partition_v1/verification_v4.json`: 유효450초 예측16개(두 구현 각4조건, 비활성 재현 두 번각4조건), 비활성 전체JSON8개 exact. 최종 코드에서 비교한 네 조건도 전부 exact다.
- 관련 단위 검사45개 PASS, 이 중 신규 공간/속도 수송 계약9개. 각 정본 실행의 기존 도시 계약27개 PASS. 도시 보존7,216회·본선/램프 인터페이스1,440회·source pin72건 검증. 새 기능의 전후 공간 합계와 canonical 재고도 각 저장 프레임에서 일치한다. 최종 전후 재고 잔차 최대2.14e−14대 수준이다.
- `verify_parameters.py` 후보 config PASS. 기존 선언된 override/버려지는 calibration 값 경고는 그대로이며, 이를 제어 이득 검증으로 사용하지 않는다.
- 최초 비활성 비교는 메모리의 tuple과JSON list를 직접 비교해 실패했다. JSON 정규화 후 전체 내용 일치를 확인했다. 긴 Windows 경로 때문에 소스 보존 경로가 한 번 실패하여 짧은 `branch_partition_v1/off_v1_source.py.txt`로 당시 바이트를 복원했고 원래 protocol SHA와 일치하는지 검증했다. 실패 기록을 덮어쓰지 않았다.
- 이전 소스는 `branch_partition_v1/source_before`, `impl_v2`, `impl_v3`에 보존한다. 이전 실험의 pin을 현재 수정한 파일 hash로 덮어쓰지 않았다.
- 이번에는 새native 실런을 하지 않았다. 원본 망·수요·신호·기본 config·writer/adapter·vendor는 그대로다. 현재 기록과 과거 이력만 예측에 입력했다. 모든 이번 소유 계산은 종료했다. 다른 프로세스를 종료하지 않았다.

## 이어갈 판단

분기 전후를 구분하는 것은 필요한 물리 구조지만, 현재 계수/교환률/하류 경계와 결합한 후보는 채택 조건을 만족하지 않는다. 같은 구조에FD나서비스 상수를 임의로 높이는 sweep을 바로 반복하지 않는다.

다음은 열린3·4차로의 과잉 재고가 **상류 유입·분기 전후 통과·옆 차로 이동** 중 어느 수량에서 생기는지를 현재 분리된 보존식으로 확인하고, 속도 오차와 구분한다. 기존 관측 차로 교환률은 전체 canonical 셀의 값이므로 이를 전후 공간에 그대로 적용한 근사의 타당성도 과거 기록으로 확인할 수 있다. 이후 계수가 필요한 경우 새 공간 정의의 무제어 자료로 식별하고 제어 반응에서 검증한다. 기존 전체셀FD25 시험의 실패를 잊고 같은 변경을 성공으로 재사용하지 않는다.

RM_C10490의 본선 이득 누락은 별도 위치의 합류 반응이므로10643 수정 하나로 해결됐다고 하지 않는다. 해당 합류의 기존 수량/속도/대기 분해와 이번 공간 구분의 적용 범위를 대조한다. 여러 상태 guard·미사용 seed·정본 채택 및 fullΩ/GNE 검증은 여전히 남아 있다.
