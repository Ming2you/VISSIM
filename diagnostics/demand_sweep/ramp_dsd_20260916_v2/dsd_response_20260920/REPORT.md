# 2026-09-20: VSL 표지 반응과 RM/VSL 이득 오차 분리

**표지를 통과한 차량의 희망속도 변경은 구현한 연산으로 재현했다. 그러나 RM/VSL의 순이득 예측 보정은 아직 통과하지 못했다.** 새 실험으로 VSL이 진출부 앞 차로 이동·정체에 주는 변화를 좁혔고, 그 실제 차로 이동률을 넣어도 남는 오차를 확인했다. 기본 controller/config는 바꾸지 않았다.

이번 코드 `evaluation/controllers/desired_speed_transport.py`는 분포 ID·차량별 분포상 순위·표지 통과 사건을 처리하는 작은 액추에이터 연산이다. 차량 이동·차로 선택·METANET의 속도 방정식에 결합한 완성 plant가 아니다. 미래의 실제 궤적이나 차로 이동률을 온라인 입력으로 사용하는 경로도 추가하지 않았다.

## 1. 완료된 native 실행

- 현재 사용자 기하 + 램프 DSD120, 동측 본선 입력1098만0.8배. 과거 전역80/50 조건이 아니다.
- seed23, 제어 시작2400초, DSD51–58을120→100으로 바꾸는 기존 고정 VSL 명령을3000초까지 재현했다. RM은 무제어. 기존4500초 짝 실험의 앞부분을 반복한 것이며 새 독립 성능 표본이 아니다.
- 망의 유일한 편집은 FZP에 `DESSPEED` 3자리 기록을 추가한 것이다. 원래9개 기록 열·수요·경로·신호·물리 설정은 보존했다. 저장된 SimPeriod9001은 유지하고3000초에 중단했다.
- 기존 fast runner/writer, 연속 실행,1초 native FZP, LDP, 명령 적용 시 readback,300초 무진행 watchdog을 사용했다. 매초 차량 COM 조회와 controller 계산은 없다.
- **기존 FZP 원래9열의11,791,383개 데이터 행이 정확히 일치**했다. LDP 및128개 명령 readback 검사를 통과했고, 비대상 설정 before/after hash도 같다.
- 실행 시작→종료/검증 완료는 약172.9초였다. 마지막 native3000초 확인까지는160.9초. 로딩·설정·순수 simulation 각각의 정밀 시간은 이번 기존 runner 기록만으로 분리하지 않았으므로 속도 개선율을 주장하지 않는다.
- 원본 오류 기록, 초기 실패 및 재시도는 보존했다. 성공 실행은 `native_v2/run_retry1/`이며 소유 VISSIM 프로세스도 종료됐다.

`observed_v2/validation.json`은 궤적 일치 및 **정렬 전** 희망속도 오차다. 최종 희망속도 검증은 아래 `clock_v2/summary.json`을 따른다.

## 2. 표지의 실제 의미와 검증

DSD120/100은 정확한120/100km/h 상한이 아니라 분포 ID다. 이 사실 자체는 이전에도 확인했던 내용이며, 이번 진전은 실제 차량의 전환을 검증한 것이다.

| 분포 ID | 망에 저장된 평균 희망속도 [km/h] | 표준편차 [km/h] |
|---|---:|---:|
| 120 | 122.275 | 12.254 |
| 100 | 107.970 | 8.084 |

차량이 가지고 있는 순위 `u`를 유지하며, 표지를 통과할 때 `v_des = F_command^(-1)(u)`로 바뀐다. 이미 지나간 차량을 명령 시점에 소급해서 바꾸지 않으며, 하류120 표지를 통과하면 같은 순위의120 분포로 돌아간다. 평균 비율만으로 FD를 바꾸는 이전 후보는 이미 실패했으므로 다시 채택하지 않았다.

PTV의 [희망속도 변경 설명](https://cgi.ptvgroup.com/vision-help/VISSIM_11_ENG/Content/5_Netzbearbeiten/Strassennetz_Wunschg_aendern.htm)과 일치하며, 이번 설치본 VISSIM2020의 native 기록으로 직접 대조했다. 문헌의 동작 설명을 본 망의 성능 증거로 대신하지 않았다.

실측 정렬 결과:

- 위치로 표지 통과를 판별한 프레임보다 `DESSPEED` 기록이1프레임 늦게 변했다. 실제 `SPEED`는 이미 그 프레임에 변할 수 있다. **이것을1초 운전자 반응 지연으로 모델에 더하지 않는다.** 이번 SimRes는1이다.
- 최초1건의 추가 불일치는 connector에서 다음 link로 들어오는1초 동안 첫 표지를 함께 지나간 사건을 분석기가 놓친 것이었다. 도로 연속 좌표로 그 통과도 잡도록 분석기를 고쳤다. 원래 관측·실패 분석은 보존했다.
- 분포가 바뀐 **1,505건 전부** 다음 프레임에서 재현됐다. 최대 절대오차0.001783km/h, 평균0.000313km/h다. 분포가 안 바뀐 경우까지 포함하면6,519건이 같은 검사를 통과한다. 종료 직전의 미변경 통과9건은 다음 프레임이 없어 검증 대상에서 제외했다.
- 단위 검사5개 PASS: 실측 차량 전환/복원, connector 직후 표지, 소급 적용 방지, 분포 계산, 잘못된 입력 거부.

예를 들어 차량19696은 희망속도154.493→129.662km/h로 바뀐다. 이를100km/h로 잘라 넣으면 액추에이터 입력부터 다른 모델이 된다.

동측5–9셀에서120→100 표지를 지난 차량은 명령 직후0/185대,10초 후30/181대,30초 후104/191대,60초 후160/198대였다.150초 후에도171/192대다. 새로 합류하는120 분포 차량과 첫 표지 상류 부분이 있어 전 차량을 즉시 동일한 제한으로 바꾸는 가정과 다르다. 이 비율은 실제 궤적에서 계산한 사후 관측이며 인과적450초 예측 결과가 아니다.

## 3. VSL이 어디에서 이득·손실을 만들었는가

seed23,2400–2850초, 무제어와 VSL의 동일 초기 상태 비교다. 모든 위치는 본선link2의 좌표다. 표지51–54는48.19m,55–58은1305.39m, 진출10643은1651.81m다. 통과 속도와 공간·시간 평균속도를 혼용하지 않는다.

| 관측 | 무제어 | VSL |
|---|---:|---:|
| 400m 통과 차량 평균속도 [km/h] | 112.44 | 102.57 |
| 1305m 차로1 통과 평균속도 [km/h] | 52.82 | 62.31 |
| 1305m 차로2 통과 평균속도 [km/h] | 46.41 | 63.94 |
| 400–1305m의 차로 변경 횟수 | 366 | 217 |
| 같은 구간의30km/h 미만 차량·초 | 5,068 | 2,402 |

400–1305m에는 중간 진입·진출 포트가 없다. 초기 재고67대가 같고, 무제어는684대 유입−668대 유출로83대가 남는다. VSL은683대 유입−708대 유출로42대가 남는다. **두 경우 모두 보존 잔차0대**다. 이 구간의 재고 감소를 차량 삭제나 수요 차단으로 설명할 수 없다. 전체 망의 비정상 소실이 없다는 뜻으로 확대하지 않는다.

| 구간 [m] | VSL−무제어 TTT [veh·h] |
|---|---:|
| 400–1305 | −0.3142 |
| 1305–진출10643(1651.81) | −0.8975 |
| 1651.81–진입10639(1964.22) | +0.2089 |
| 1964.22–진입10681(2307.38) | +0.2731 |
| 2307.38–120 복원 표지(2652.03) | +0.1275 |

이득은 진출10643 **앞의 대기 감소**에 집중되고, 이후에는 감속 비용이 생긴다. VSL이 전 구간 속도나 용량을 올린 것이 아니다. 짧은 차두간격·속도 분산·차로 이동도 함께 변했지만, 이번 동시 변화만으로 그중 하나를 독립적인 원인이나 capacity 증가율로 확정하지 않는다.

차두간격은1초 궤적의 표지점 통과 시각을 보간했다. 전후 차량 중 차로가 바뀐 모호한 통과를 끼고 있는 간격은 제외했다. 도착이 없는 긴 간격도 포함하므로 포화 차두시간이나 합류 gap 수용 곡선으로 직접 쓰면 안 된다. 근거: `station_v1/`, `local_queue_v1/`.

## 4. 실제 차로 이동률을 알려주면 모델의 이득 예측이 나아지는가

새 용량 보너스나 이득 보상항을 넣지 않았다. 기존 차로군 후보의 나머지 설정을 고정하고, 그450초 동안 실제로 측정된 차로군 이동 횟수/차량·초를 입력했다. **미래 실측을 사용한 원인 분리용 진단**으로, 제어에 따라 이동률이 어떻게 변할지를 예측하는 모델은 아니다. 원래 과거150초 이동률을 쓰는 결과10회(고유8조건)는 이전 전체 예측 JSON과 정확히 같다.

ΔTTT=제어−무제어, 음수가 이득. 범위는 **동측 본선+진입4개+진출4개 connector**이며 Ω 전체가 아니다.

| 조건 | 실측 ΔTTT | 기존 차로군 예측 | 각 조건의 미래 실측 이동률을 입력 |
|---|---:|---:|---:|
| seed13·1650, VSL | +0.7875 | +0.2500 | +0.1920 |
| seed23·2400, VSL | −0.9819 | +0.0106 | −0.1088 |
| seed33·2400, VSL | −0.0628 | +0.0051 | −0.1140 |
| seed23·2400, RM | −0.5533 | +0.0076 | +0.0658 |
| seed23·2400, 동시 제어 | −0.5150 | +0.0183 | −0.1098 |

seed13은 제어 시작점과 VSL 표지 구간도 다르다. 이 세 행을 동일 조건의 독립 반복 표본으로 취급하지 않는다. seed33도 이미 여러 번 검토한 개발 검증 자료다.

seed23 VSL은 무제어의 미래 이동률을 두 조건에 똑같이 쓰면+0.0082veh·h로 여전히 손해다. 각 조건의 다른 이동률을 넣어야−0.1088로 바뀐다. 따라서 이 진단에서는 단순한 미래 평균률 교체보다 **제어에 따라 달라진 차로 교환**이 부호 변화에 기여했다. 하지만 실제−0.9819의 약11%에 불과하고, 미래 평균률은 혼잡 결과까지 포함하므로 인과적 설명력 비율로 읽으면 안 된다.

더 중요한 반례:

- seed33 VSL은 총비용 부호가 맞아도 본선은 실제+0.1508인데 모델−0.0939, 진출 비용은 실제−0.1444인데 모델+0.0864다. 상쇄로 맞는 총합이다.
- seed23 RM의 램프 비용은 실제+0.2564, 진단+0.2630으로 비슷하다. 그러나 본선 이득은 실제−0.8797, 진단−0.1670이라 부족하다. **램프 대기 비용만 깎아서 해결할 근거가 없다.**
- seed23 동시 제어 상호작용도 실제+1.0203veh·h인데 이 진단은 약−0.0667이다. 독립 레버 효과를 합쳐서도 해결되지 않는다.

따라서 미래 실측 이동률을 주어도 이득 예측은 미완료다. 이 후보를 온라인 controller에 넣거나 성공으로 승격하지 않는다.

## 5. 현재 결정과 다음 수정 범위

1. 표지의 분포·순위 보존·차량별 적용 사건은 이번 검증된 연산을 사용한다. 기록1프레임 차이를 물리 지연에 더하지 않는다.
2. 다음 본선 수정의 위치는 진출10643 앞400–1652m다. 통과/진출 차량의 접근 차로 재고, 현재 희망속도 분포와 인접 차로 속도 차이, 사용 가능한 간격으로 **제어 의존적인 차로 교환·막힘**을 설명할 수 있어야 한다. 미래 실측 교환률을 그대로 사용하는 방식은 배제한다.
3. RM10490→10484는 별도로 실제 합류 시각과 접속 차로의 회복/방출을 맞춘다. 이번 결과는 RM 오차까지 차로 교환 하나로 해결된다는 가설을 지지하지 않는다.
4. 평균 속도나 총 ΔTTT만 맞추지 않고 본선·진입·진출 비용, 국소 재고·방출, 동시 제어 상호작용을 함께 통과시킨다. 그 전에는 full GNE 연결·새 폐루프 장기 런·성능 정본 승격을 하지 않는다.

이번 단계는 액추에이터의 실측 검증과 누락 반응의 위치를 확인한 작업이다. 추가 모델 보정 없이 이 결과 자체를 MPC의 이득 예측 개선으로 표현하지 않는다.

## 재현·상태 파일

- `prepare.py`: 동일 명령 native 반복 준비. 기존 출력이 있으면 덮어쓰지 않는다.
- `analyze.py --output <새 폴더>`: 원래9열 일치, 표지 통과/분포 상태 추출.
- `audit_clock.py --observations observed_v2 --output <새 폴더>`: 기록 시점 검증.
- `station_response.py`, `local_queue.py`: 사후 차두간격·재고 보존·구간 TTT.
- `exchange_probe.py --seed <13|23|33> --arm <vsl|rm_ramp|both> --output <새 폴더>`: 미래 입력 원인 분리. `--reuse-extraction`은 같은 seed·시점의 이미 추출한 자료에만 쓴다.
- 최종 gates와 소스 pin: `QUALIFICATION.json`. 모든 실행·실패·원래 `.err`/FZP/LSA/LDP는 유지한다.
- 기본 진단 모델은 계속 `../merge_drain_response_20260919/decisions_v1/internal_cost/`다. 이 문서의 native repeat나 새 유틸리티는 기존 전달 패키지에 아직 포함되지 않았다.
