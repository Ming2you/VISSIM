# 2026-09-19 plant 수정·검증

## 판정

10681 램프의 **차로별 재고와 본선 합류 기회 제한**을 기존 plant 실행 경로에 구현했다. 설정은 `controller_response_4500_v1/model_v5_node`이며, 기존 v4나 기본 설정을 교체하지 않았다. 램프 합류량 예측은 개선됐지만 **RM/VSL 비용 차이의 방향 검증은 실패**했다. 따라서 이를 제어 성능까지 검증된 최종 정본이라고 부르지 않는다.

새 어댑터·새 시뮬레이터는 만들지 않았다. 기존 `physical_ramp_boundary.py`, `canonical_harness.py`, `evaluate_response.py`와 준비 코드의 소스 해시 목록을 수정했다. full GNE의 새 기하 지원은 이번 변경 범위가 아니다.

## 실제 수정

- 10681의 두 차로를 독립된 유한 저장고로 계산한다. 빈 차로의 저장 공간·정지선 서비스·합류 예산을 막힌 차로가 자동으로 빌려 쓰지 않는다.
- 초기 차량은 실제 위치·차로에서 시작한다. 예측 도착의 차로 비율은 직전 150초 진입 기록만 사용한다. 온라인에서는 이미 읽던 native 궤적의 사건을 보존하므로 별도 매초 COM 조회를 추가하지 않았다.
- 본선의 예측 상태에 따라 합류 기회 상한을 갱신한다. 해당 합류점 전에 이미 빠지는 off-ramp 교통량은 충돌 교통류에서 제외했다. 관측된 램프 방출량을 고정 상한으로 복사하지 않는다.
- 실제 합류는 기존 본선 수용량·차로별 합류 가능 재고·새 상한 중 작은 값이다. 미터는 정지선 통과에 작용하고, 이미 정지선을 지난 차량은 적색에도 합류할 수 있다.
- 1초 램프/10초 본선 계산, RG 10초, 기존 서비스 표, 계수, 이동 속도, 수요, 경로, 신호, 목적함수를 유지했다. 차로별 체류시간과 누적량이 상위 진단에도 정확히 합산되도록 했다.
- 스위치는 `freeway.physical_ramp_receiving_nodes` 하나다. 키가 없는 기존 설정은 전 예측 결과를 그대로 재현한다.

추가 상한의 근사식은 다음과 같다. q는 합류점 직전 본선의 차로당 통과 교통류[veh/h]이며 현재 구현은 셀 평균을 사용한다.

```
C_gap(q) = q exp(-q tc / 3600) / (1 - exp(-q tf / 3600))
C_gap(0) = 3600 / tf
q_merge,l <= min(기존 수용 예산/램프 차로 수, C_gap(q), 해당 차로의 합류 가능 재고/dt)
```

gap acceptance를 이용한 램프 모형의 근거는 [Tian·Wu의 연구](https://homepage.rub.de/ning.wu/pdf/Wu_TRB2012_Ramp_Metering_pub_final.pdf)에 있다. 위 구현은 단순 Poisson gap 근사이며 논문의 모든 platoon/차로 분포 동역학을 구현한 것이 아니다. `tc=3초, tf=2초`는 문헌의 정답값을 이식한 것이 아니라 seed13의 대기열 지속 7개 구간에서 적합한 유효 계수다. 실제 운전자의 임계 gap을 직접 측정했다는 뜻이 아니다.

## 같은 초기 상태에서 제어 반응

실제로 명령 적용 전 FZP가 일치했던 기존 두 실험 묶음을 사용했다. 아래는 **42개 본선 셀+8개 on-ramp+8개 off-ramp connector**의 450초 ΔTTT이다. 고속도로+도시 protected network인 Ω 전체 성능이 아니다. 두 묶음의 VSL 구간·명령도 서로 다르다.

| 시작 상태 / 제어 | VISSIM ΔTTT [veh·h] | 수정 plant ΔTTT |
|---|---:|---:|
| seed13, 1650초 / RM 단계 제한 | +0.41667 | −0.00139 |
| seed13, 1650초 / VSL | +0.87083 | +0.05941 |

RM 합류량이 움직이는 것과 RM 순이득을 맞히는 것은 다른 문제다. VSL도 혼잡 상태에서는 평균 속도에 걸리는 제한이 아니어서 기존 METANET의 clipping이 작동하지 않는다. native desired-speed 분포의 평균 비율로 바꾸는 별도 시험도 후기 VSL의 비용 부호를 틀려 채택하지 않았다. 임의의 capacity gain, 제어 활성화 보상, 고정된 혼잡 방출률을 넣지 않았다.

근거: `response_installed_v2/results.json`, `response_v1/results.json`. 기존 MPC 선택 함수를 두 seed×5시점×두 모델로 20회 재실행했다. 신규 모델은 자유류 900초에서 두 seed 모두 hold를 선택했다. 다른 상태에서 RM 후보를 선택하기도 했지만 이득은 최대 약 0.023 veh·h에 불과하고 위 부호 오류가 남는다. 후보 생성·선택 연결은 동작하며, 탐색이 개선안을 놓친 것만으로 현재 문제를 설명할 수 없다. `decisions_v1/summary.json`에 전 후보와 비용을 보존했다.

## 남은 문제와 다음 판단

1. 램프 차로 간 이동과 본선 차로별 혼잡을 아직 동적으로 예측하지 않는다. 독립 차로 근사와 본선 평균 q는 혼잡 해소·차로 재분배에서 한계가 있다. 현재 평균 속도를 450초 내내 고정하는 대안은 회복을 더 늦게 예측해 제외했다.
2. 램프 방출량 변화가 본선의 출발·감속·차로변경·회복으로 연결되는 비용 응답이 부족하다. merge 계수만 크게 만들거나 VSL에 일괄 용량 이득을 주는 것으로 해결됐다고 판정하면 안 된다.
3. 다음 물리 변경의 검증 목표는 더 작은 속도 RMSE가 아니라 위 두 묶음에서 RM/VSL의 **본선 시간 절감과 램프 대기 증가를 따로** 재현하는 것이다. 본선 차로별 재고·통과량과 속도 분산의 필요성을 먼저 구분해야 한다.
4. 부분 영역 바깥의 도시 접근 대기 비용까지 포함하는 full GNE/Ω 비교는 별도 단계다. 컴포넌트 밖 backlog는 보존하며 작은 MPC에서 대기 비용을 더하지만, 그것이 도시 보호망 전체의 실제 대기 위치를 재현한다는 뜻은 아니다.

## 실제 VISSIM 연결 검사

seed23, 새 기하·DSD120·동측 본선 입력0.8 조건을 유지해 1050초까지 실행했다. SimPeriod는9001을 유지하고 SimBreak로 종료했다. 900초에서 실제 관측→새 plant의17개 후보 계산→hold 선택→1050초 정상 종료를 확인했다. 첫 실제 진행까지30.4초, 준비 이후 전체 실행·native검증91.6초였다. 한 결정의 관측4.916초·모델 초기화0.081초·제어 계산4.917초이며, 이를 이전 버전 대비 속도 개선율로 사용하지 않는다.

native LDP462,000개 신호 상태 표본과864개 초기 설정 주소 검증을 통과했다. 이 런은 hold를 선택했으므로 **신규 미터 활성화 명령은 없었으며**, 활성 RM/VSL의 성능 검증이라고 부르지 않는다. 0–1050초 FZP 데이터2,521,969행이 기존4500초 무제어 런의 같은 구간과 정확히 일치했다. 별도4500초 런을 반복하지 않고, 혼잡 성능은 위 기존4500초 자료로 검증했다.

근거: `native_smoke_v1/run_both_retry/run.json`, `fixed_validation.json`, `mpc_candidates_900.json`, `native_prefix.json`. 최초 샌드박스 실행은 Windows Script Host 접근 거부로 simulation 시작 전에 실패했으며 `native_smoke_v1/run_both`에 보존했다. 재시도는 해당 소유 프로세스만 사용했고 정상 종료했다.
