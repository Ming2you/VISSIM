# 2026-09-19 공간별 FD 보정과 진출램프 배수 시계 수정

현재 보정본은 `combined_v3/model/`이다. 실제 기존 plant의 segment parameter 로더와 `canonical_harness.py`를 수정·재사용했다. 속도·밀도·진출램프 재고 예측은 개선됐다. **RM/VSL에 따른 순비용 변화의 재현은 아직 실패했다.** 이 모델을 제어 성능이 검증된 정본이나 full GNE 완성본으로 승격하지 않았다. 기존 기본 config와 과거 결과는 그대로다.

이번에는 새로운 VISSIM 런 없이 완료·실행 검증된 native 기록을 재사용했다. 최적화 손실이나 보상, 실제 신호·미터·VSL 명령, 네트워크·수요를 바꿔 이득을 만들지 않았다.

## 1. 실제 변경

### 위치별 FD

seed13 무제어의 900·1650·2400·3600초 초기 상태에서 각각450초를 예측해 보정했다. 기하 기준으로 미리 정한5개 구간군의 임계밀도를 조정했다. 62개 서로 다른 후보를 계산했으며, 기존 속도·밀도·유량 정규화 RMSE 합을 그대로 보정 지표로 썼다. RM/VSL 제어 결과나 seed23·33은 이 계수 선택에 사용하지 않았다. 두 번의 제한된 좌표 탐색이며 전역 최적해나 매개변수의 유일한 식별을 주장하지 않는다.

| FW_E 셀(0부터) | 구간 | 기존→보정 임계밀도 [veh/km/lane] |
|---|---|---:|
| 0 | 원점 진입부 | 25→15 |
| 1–6,10–12 | 일반4차로 | 25→25 |
| 7–9 | 10643 등을 포함한 진출 복합부 | 25→20 |
| 13–14 | 실제 차로 감소·합류 구간 | 28→28 |
| 15–20 | 하류 일반3차로 | 28→39.2 |

서측 FD, τ·ν·merge δ·lane-drop φ는 기존 값을 유지했다. 동측 자유속도 배율도0.91이 선택됐다. 원점 임계밀도는 탐색 하한에 걸렸다. 위 값은 현재 유한 지평과 경계 모형에서의 유효 보정값이며, 실제 포화용량을 직접 측정한 값이 아니다. 진출 차로의 재고 차이를 이 FD만으로 설명할 수 없다.

파일: `fit_v1/model/segment_params.json`, `fit_v1/fit_trace.json`, `fit_v1/fit_result.json`.

### 진출램프 배수 시계

이전 `DelayedPort.release`는10초 구간 시작에 이미 출구에 도착한 차량만 배수 후보에 넣었다. 구간 중간에 도착한 차량은 다음 계산 시점까지 기다려 추가 수치 지연이 생겼다.

`freeway.physical_offramp_interval_service: true`를 명시하면 구간 안의 도착 사건마다 대기 재고를 갱신하고, 그 이후 남은 시간만큼만 배수 서비스를 쓴다. 먼저 비어 있던 시간의 서비스를 적립하지 않는다. 예를 들어5초에 도착한1대에 서비스360veh/h를 주면10초까지0.5대만 방출한다. 이동 중 재고·대기 재고·방출의 합은 보존된다. 본선과의 교환 주기10초와 신규 진입의 구간 끝 반영 규약은 유지했다.

이 설정은 현재 물리 기하 컴포넌트/진단 MPC의 기존 harness에 연결했다. full GNE 경로에 같은 기능이 지원된다고 주장하지 않는다. 설정이 없으면 과거 계산과 완전히 같다.

## 2. 보정에 사용하지 않은 seed의 예측 결과

각 seed에서 동일한4개 초기 상태·450초·과거150초 관측으로 예측했다. seed23·33은 이전 작업에서도 본 개발 검증 자료이며 새로운 미사용 seed 검증은 아니다.

| 지표 | seed23 기존→보정 | seed33 기존→보정 |
|---|---:|---:|
| 동측 속도 RMSE [km/h] | 24.26→20.40 | 24.80→21.50 |
| 동측 밀도 RMSE [veh/km/lane] | 7.02→5.85 | 7.37→6.42 |
| 동측 셀 유출량 RMSE [veh/h] | 923.13→903.49 | 994.66→911.66 |
| 8개 진출램프 재고 MAE [veh/port] | 6.15→5.26 | 4.98→3.43 |
| 8개 진출램프 합계450초 TTT 오차 MAE [veh·h] | 4.18→2.87 | 4.06→1.82 |
| 동측 본선450초 TTT 오차 MAE [veh·h] | 8.00→8.35 | 7.30→6.07 |

각 초기 상태의 오차 지표를 평균한 값이다. 본선 TTT는 seed23에서 조금 악화됐다. 진출램프 TTT는 양방향8개 connector의 재고를30초 간격 사다리꼴 적분한 값이며 **Ω TTT가 아니다**. 실제 차량의 체류시간을 줄였다는 뜻이 아니라 예측 오차가 줄었다는 뜻이다.

배수 시계만 바꾼 대조도 실시했다. 기존 FD·공간 FD 각각3seed×4초기 상태에서 본선 상태·유량은 모두 정확히 같았다. 배수 시계 수정은 이 표본에서 진출램프 체류량을 개선했으며, 본선 혼잡 개선을 입증하지 않는다. 공간 FD에 배수 시계를 더할 때 seed13의 진출 TTT 오차는0.885→1.108veh·h로 증가했지만, 각 port 재고 MAE는 개선됐다. 오차 상쇄를 성공으로 취급하지 않았다.

근거: `combined_v3/evaluation.json`, `timing_v2/results.json`.

## 3. 제어 반응은 여전히 통과하지 못함

공통 초기 상태에서 실제 실행된 단일10490 RM, 지정 동측 VSL, 동시 명령을 그대로 재생했다. seed13은1650초, seed23·33은2400초 시작이다. 이는 고정 명령 실험이며 새로운 ALINEA/폐루프 MPC 실험이 아니다.

| seed·명령 | 실측 ΔTTT | 보정 모델 ΔTTT |
|---|---:|---:|
| 23·RM | −0.6167 | +0.0288 |
| 23·VSL | −1.0083 | 0.0000 |
| 23·동시 | −0.6083 | +0.0288 |
| 33·RM | −0.2667 | +0.0105 |
| 33·VSL | −0.1958 | +0.0003 |
| 33·동시 | −0.0167 | +0.0107 |

단위veh·h. 평가 영역은 **동측 본선+동측 on/off connector**이며, 각 제어의 첫450초에서 무제어 대비 차이다. Ω 전체와 혼합하지 않는다.0은 이득으로 세지 않았고 작은 부호의 통계적 유의성도 주장하지 않는다. seed23·33 모두 순비용 방향0/3이다. 해당 ΔTTT MAE는 seed23에서0.7534→0.7636, seed33에서0.1646→0.1669로 약간 악화됐다. 따라서 평균 속도 개선만으로 controller를 승인하지 않는다.

세부 분해에는 유용한 진전도 있다. seed33 RM의 동측 **본선** ΔTTT는 실측−0.2917에 대해 보정−0.2881로 가까워졌지만, on-ramp 증가량은 실측+0.1250에 대해+0.3011로 과대 예측했다. off-ramp 감소도 실측−0.1000에 대해−0.0026만 예측했다. 이를 보면 본선 RM 효과가 언제나0이라는 해석도 부정확하며, 대기·경계 응답을 함께 맞춰야 한다.

## 4. 남은 원인과 다음 수정 범위

`lane_audit.json`의 실제10643 재고에서, seed23의2400초에는1차로16대·2차로45대이며 정지 차량은 각각6대·40대다. 명목 저장은 차로당53.17대다. 전체 저장106.33대 대비61대라는 평균만으로는 이 편중을 표현하지 못한다. 명목 저장량은 차량 간격 가정으로 계산한 값이며 실제 포화 판정의 절대 기준이 아니다.

현재 모델은 진출램프 전체 저장과 과거150초의 실제 배수량을 사용한다. 따라서 한 차로의 정체, 빈 차로로의 서비스 전용 불가능, 도시부71번 등 하류 신호 접근부와의 상호작용을 충분히 표현하지 못한다. 다만 **차로 편중이 실제 제어 차이의 전부를 설명한다고 검증한 것은 아니다**.

다음 구조 변경은10643부터 차로별 재고·목적 방향·도시부 수용을 연결해야 한다. 단순히 두 차로를 독립 큐로 고정하면 안 된다. seed13 전체 관측의 완결 통과 중10643은 약6%가 입·출구 차로를 바꿨고,10481은 약41%여서 차로 이동을 무시할 수 없다. 관측 통과 비율을 혼잡으로 억제되지 않은 희망 경로 비율로 오인해서도 안 된다.

본선 차로 전체를 동시에 막는 FIFO나, 진출만 막히고 본선에는 영향이 없는 가정 사이에서 실제 차로 공유 범위를 반영하는 제한이 필요하다. 기하와 회전별 차로 사용을 이용하는 partial FIFO는 검토할 수 있는 접근이다. [Wright 외, On node models for high-dimensional road networks](https://escholarship.org/uc/item/59x2m66n). 이번 보정에서는 이 구조를 아직 구현하지 않았고 임의 capacity drop도 넣지 않았다.

새 adapter, 새 VISSIM 실행 경로, 새 native 런은 만들지 않았다. combined_v1/v2의 실패 검사에서 남은 이번 작업 소유 Python PID15664·18872만 명령행·부모 PID·실패 로그를 다시 확인해 종료했다. 사용자의 기존 프로세스에는 개입하지 않았고 commit/push도 하지 않았다. 세부 채택 판정은 `QUALIFICATION.json`을 따른다.
