# FW-owner held-action finite neighbors — unapplied proposal

This adds only an inactive candidate helper. It copies one full action and returns FW_E or FW_W's complete 21-cell VSL vector, direction alias, and two model-meter rates. Head coordinates 0/5/10 are independent; recovery head15/cells15–20 are fixed. No scalar speed overwrites the nonuniform vector. All other owner addresses and native rows stay fixed. No controller, optimizer, endpoint, VISSIM, runtime config, vendor or Git mutation is part of this work.

The new query holds one action throughout its explicitly supplied horizon. **This is a new algorithm domain, not preservation of the old temporal VSL sequence search.** The old installed sequence generator distinguishes complete future sequences even when their first action agrees. The new helper must not receive those sequences or deduplicate them by first action. Later replacement of scalar/offset/post-phase refinement with a joint game is also an algorithm change, separate from the already tested performance-preserving work.

`generate(ownership, cfg, owner, incumbent, domain, *, requested_admissible, realize, realized_admissible, physical_rows)` returns full controls, physical row hashes, full-modeled-control hashes, request aliases, explicit rejection evidence and `feasible_neighbors` or `empty_infeasible`. The explicit `Domain` has no numeric defaults:

Request order is incumbent → head0,5,10 values in caller order → meter points → explicit joint pairs. Physical duplicates retain all original requests and rejection/realization evidence. Deduplication is local to this call; no visited-state set prevents revisiting a prior value in later rounds. Rebuild the caller domain from a fixed decision anchor/declared round policy, rather than accidentally reapplying the old downward temporal rule to each new incumbent.

The input incumbent must already be realized. It is always **requested**, and re-realizing it must preserve all four lever vectors and every native command exactly. If any value or own/foreign physical schedule changes, generation raises instead of replacing the base; diagnostics-only bookkeeping is allowed when the action/commands agree. If the caller's requested/realized admissibility or budget rejects the unchanged incumbent, it remains in rejected records with `incumbent_feasible=false`. A nonempty alternative set may still be returned. If no realized allocation satisfies equality, all requests are rejected and status is `empty_infeasible`; never round the target, scalar-clip rates, or convert equality to a penalty here.

## Canonical realization and score boundary

The caller must bind `realize` to canonical `area_meter_finalization.finalize` with an immutable decision-time context, on the private copy supplied by the helper. That module invalidates stale request/context markers, applies current spill guard and the measured table, then stores realized rates and physical schedule commands. Do not manually write its marker or populate allocation-cache diagnostics. Equivalent metering rate is a command representation, not measured throughput.

Use the actual CSV row projection for `physical_rows`, excluding file paths, progress and diagnostic-only columns; require all213 owned physical identities and complete command payloads (including each of eight meter schedules, DSD values and selected SG/SC timing). The callback gets another private action copy, so writer bookkeeping cannot change the scored action. Compare the score action's meter marker using `assert_writer(..., require_scored=True)` and require VSL serialization to agree with the model vector. The helper rejects foreign/fixed native-row changes. One physical fingerprint with differing full four-lever modeled values is an error, not a safe duplicate. Context/state/forecast/price immutability and callback output completeness still need the actual integration guard.

`owner_physical_fingerprints(ownership, physical_rows)` adapts the same exact catalog/complete row payloads to Flow's core `physical_fingerprint(control, context)` contract: all19 owners map to nonempty SHA256 strings. The bound caller supplies canonical rows and separately fingerprints the full context, including source/plan/mapping and held horizon. Each generated candidate exports this mapping as `owner_physical_sha256`; the core must recompute it from the candidate rather than trust cached tokens after a mutation. Model-lever values are compared separately in both helpers. Equal group rates with a changed individual meter schedule change that owner's token. The hash proves equality of supplied rows; it does not prove the callback included every physical attribute. Source-verified canonical row extraction is still required.

Both admissibility callbacks run on private controls and reject lever mutation. The realizer may change only owned permitted lever values and diagnostics; fixed/dead/recovery/foreign addresses and all non-lever action fields remain unchanged. Post-realization checks include full zone aliases, allowed VSL set, nonnegative model rates, caller's realized budget and all frozen physical rows. Receiving, shared service, stock conservation and priced game feasibility require the future fixed-candidate scorer; this address/command helper does not prove them. No reserved previous accepted flow for other owners is introduced.
