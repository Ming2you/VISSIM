# 선택 명령 주변의 작은 VSL·RM 비교

seed47의2700초 동일 초기 상태, 과거 head/도시/VSL 이력과 현 candidate_config를 사용했다. 앞서 완료된 실제 SDMPC 선택의 도시 녹색·offset, 뒤150초 두 블록, N_P·N_UF cap을 고정했다. 첫150초의 S13/S14 VSL 또는 RM_C10484 녹색만 바꿨다. 미래 실측 입력과 추가 보정은 없다.

|후보|실행모델 Ω TTT, veh·h|선택명령 대비 ΔTTT|10484 실제 합류 예측, veh|N_UF, veh/h|
|---|---:|---:|---:|---:|
|실제 SDMPC 선택: VSL100, g2|485.553917|0|45|5731.396|
|첫 VSL만110 유지|485.508690|−0.045227|45|5731.390|
|첫 RM만g3|485.566091|+0.012174|52.5|5791.375|
|첫 RM만g4|485.668903|+0.114986|60|5851.354|

모두 N_P cap506.531veh, N_UF cap5890.358veh/h를 만족한다. N_P는409.038–409.319veh다. 적용 명령 범위와 주기간 제한, 모델 자원 제약·차량 보존을 통과했다. 자원 최대 초과는4.5e−16 이하,10484 재고 잔차는4.2e−13 이하. 이는 구현된 모델 내 제약 검사이며 VISSIM 실행 증명이 아니다.

- RM g3/g4는 합류량을 실제로 늘리는 모델 후보지만, 대기 절감보다 본선 등 비용 증가가 커 Ω 목적값이 나빠진다. 이 작은 두 후보가 제약 때문에 배제된 것은 아니다. 더 큰3블록 완화(4/6/8)는 앞선 검사에서 N_UF cap을 넘고 비용도 증가했다.
- VSL110이100보다0.045veh·h 좋다. 2회 반복에서 멈춘 현재 solver가 이 작은 유한 후보 차이까지 최적으로 고른 것은 아니다. 이를 큰 VSL 이득 또는 미세 차이를 맞출 추가 보정의 근거로 삼지 않는다. 선택을 바꾸거나 보상항을 넣지 않고, 실제 선택 전체의 검증을 진행한다.
- 실행모델/미분용 모델은 위4후보 순위가 같다. 선택명령의 두 모델 결과는 이전 저장 결과와 재현됐다. 현재 선택 전체의 기준명령 대비 개선 예측9.738veh·h를 VSL·RM 개별 이득으로 보고하지 않는다.

예산은 미분용4회+실행용4회=450초 예측8회, optimizer0회이며 모두 완료됐다. `comparison.json`, `protocol.json`, `forecast.log` 및 원본4후보 결과를 보존했다. 대규모 탐색이나 계수 재적합을 하지 않았다.

후속: 기존 완료된 seed47 RM 유지 런을 비교 기준으로 재사용하고, 검증된 SDMPC3블록을3150초까지 한 번 재생한다. 기존 정본 runner/writer를 사용한다. 새 native 결과가 나오기 전에는 실제 이득을 확인했다고 하지 않는다. 기존9000 STOP을 유지하며 push하지 않는다.
