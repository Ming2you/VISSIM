# S-DMPC quadratic terminal cost — 2026-09-30

## 원문과 적용 범위

사용자가 제공한 Scheu & Marquardt (2011), *Sensitivity-based coordination in distributed model predictive control*, Journal of Process Control 21, 715–728을 확인했다. PDF 9쪽/학술지 723쪽, §4 식 (12)는 `sum Phi_i + x(tf)^T P x(tf)`이다. 식 (13)의 말단 상태 등식은 대안이며 이번에는 넣지 않았다. 원문은 전체 시스템 정보를 사용해 P를 설계해야 한다고 설명하며, 해당 정식화의 폐루프 안정성 보장은 후속 연구로 남긴다. 교통용 P나 수치를 제공하는 논문은 아니다.

기존 450초 Ω TTT에 말단 비용을 추가하는 **옵션을 구현**했다. 원래 실행 중인 frozen SDMPC9000 런과 원본 expanded036 설정에는 적용하지 않았다. 시험용 활성 설정은 이 폴더의 `candidate_config.json`이다. 원래 파일에 키가 없으면 이전 경로를 유지한다.

## 구현

`adapter.sdmpc_terminal_cost`가 명시한 비음수 대각행렬 P를 사용한다.

```text
x_g = sum(terminal ledger's inside vehicles in group g)
V_f = sum_g P_g * x_g^2
J_selection = TTT_Omega(0:450 s) + V_f
```

- 그룹: 도시 주체 17개, 동·서측 본선, 8개 독립 램프, 기존 PASSIVE_OMEGA. 램프를 본선 재고에 중복 합산하지 않는다.
- 계수 단위는 h/veh, 각 항의 단위는 veh·h다. 외부 cohort는 제외한다. 말단 재고를 종료 차량으로 취급하지 않는다.
- `evaluation/controllers/sdmpc_terminal.py`가 동일한 식을 공통 endpoint에서 계산한다. 각 주체 비용과 이웃 비용의 미분은 같은 말단 비용 분할을 사용한다. PASSIVE 비용도 전체 비용/외부 효과에서 유지한다.
- 최종 명령 검증에서 P fingerprint·그룹별 비용·주체별 합·총점을 재검사한다. 임의의 추가 비용을 허용하지 않는다.
- 보고용 `ttt_veh_h`는 기존 Ω TTT다. `additional_cost_veh_h`와 `selection_score_veh_h`를 별도로 기록한다. `prediction_ttt_reduction`에도 말단 비용을 섞지 않는다.
- P fingerprint를 SDMPC policy에 포함한다. 다른 P로 계산한 과거 가격을 같은 정책이라고 재사용할 수 없다.
- 동역학, 수요, 경로, 제어 주기, VSL/RM 실행 규약, N_P/N_UF 정의는 변경하지 않았다.

## 초기 P는 시험값이다

우선 독립적인 유체 대기열을 일정률 q로 비운다는 근사에서 `P_g=1/(2*q_ref_g)`를 사용했다. q_ref는 저장된 3600초 상태의 **고정 기준 명령 450초 모델 예측**에서 계산한 그룹 간 방출률이다. 이 P를 모든 후보에 공통으로 동결했다. 실제 미래 궤적, 특정 seed/명령의 보너스, 이득의 정답 부호를 입력하지 않았다. 28개 그룹 모두 양의 기준 방출이 있어 0 계수로 빠진 그룹은 없다.

이 방출률은 **처리용량의 추정치나 불가능 판정용 상한이 아니다**. 외부/내부 차량이 섞인 물리 reservoir의 전체 통과량이 사용될 수 있고, 특히 PASSIVE의 통과량을 Ω 탈출률로 읽으면 안 된다. P는 말단 Ω 재고만 평가한다. `design.json`에 모든 기준률과 계수를 기록했다.

이 근사는 다음 수요, 하류로 옮겨진 차량의 추가 주행·대기, 병목 공유, 속도 상태, 혼잡 회복을 완전히 평가하지 않는다. 따라서 **논문의 말단 항 형태를 구현한 것이며, 적절한 최적 cost-to-go 또는 안정화 P를 재현했다는 뜻은 아니다**. 아직 운영 설정으로 채택하지 않았다.

## 저장 상태에서 비교

동일한 seed29, 3600초 초기 상태·수요 예측·도시 신호, 450초 지평. 기준 VSL은 동측 zone13의 90 km/h, RM은 10초다. VSL 80/100은 해당 구간만 변경했고 양측 입구 110을 유지했다. RM은 10681에 8/6/4초를 적용했다. 다음 값은 기준 대비 변화이며 음수가 낮은 비용이다.

| 후보 | Δ450초 Ω TTT [veh·h] | Δ말단 비용 [veh·h] | Δ선택 비용 [veh·h] |
|---|---:|---:|---:|
| RM10681 8/6/4 | -0.005133 | -0.048601 | -0.053734 |
| VSL 80 | +0.275735 | +1.467993 | +1.743728 |
| VSL 100 | -0.030176 | -0.028692 | -0.058868 |

P의 크기를 0·0.5·1배로 사후 재채점해도 순위는 `VSL100 → RM8/6/4 → 기준 → VSL80`로 같았다. 이는 비용 순위이며, 네 후보에서 전체 SDMPC 최적화나 운용 제약 검증을 새로 완료했다는 뜻은 아니다. 고정 명령 비교이며 native 실현 이득은 시험하지 않았다.

RM 합류량은 156.793665 → 156.508808대로 0.284857대만 달라졌다. 말단 비용을 더해도 이 물리적 작은 반응 자체는 변하지 않았다. 말단 비용을 크게 만들어 RM을 강제로 고르는 것을 성공 기준으로 삼지 않는다.

## 검증

- 실제 물리 예측 5회: 옵션 OFF 기준 1회, ON 동일 명령 1회, 대안 3회. 원래 저장 기준 비용 517.5983935981086 veh·h와 일치했다.
- ON/OFF의 **전체 예측 상태, 차량 보존 장부, 실제 유량 기록, Ω TTT가 정확히 일치**했다. 추가한 것은 채점뿐이다.
- 모든 후보에서 기존 구현의 물리 제약 기록이 완결됐고 램프 보존 오차는 1e-7대 미만이다. 이것을 전체 native/운용 제약 인증으로 확대하지 않는다.
- 단위·회귀검사 126개 통과: 외부 대기 제외, 중복 방지, P 누락/음수/비정상값 거부, 변조된 말단 기록 거부, 순·역방향 자동미분, PFO·공통 응답·최종 명령 검증.
- `verify_parameters.py candidate_config.json` PASS. 상속된 예전 calibration 무시 경고는 그대로이며 이번 변경은 해당 파라미터를 수정하지 않는다.
- 별도의 옛 `test_area_leader_objective`는 fixture에 `control_interval_sec`가 없어 setup에서 실패했다. 검사를 우회하거나 오래된 fixture를 고치지 않았다.
- 최초 미분 테스트 fixture 작성 오류와 sandbox 의존성 오류는 이후 수정/허용된 의존성 접근으로 해결했다. 운영 코드의 실패로 숨기거나 성공 결과에 합치지 않았다.

실제 S-DMPC worker도 **완료/PASS**했다(`worker_summary.json`). 독립 스칼라 450초 예측 1회와 237개 좌표의 전체 역방향 자동미분 예측 1회에서 비용/제약 오차는 5.684e-14, 중앙 제약에 사용되는 5,106개 상태값의 오차는 4.843e-14였다. 스칼라 23.24초, AD 47.44초였으며 최적화 반복은 0회다. 모든 내부 상태 객체까지 비교한 증명은 아니며, 전체 상태 비교는 앞의 물리 ON/OFF 시험에 해당한다. 연속 제어 예측기의 Ω TTT=517.513110, 말단 비용=225.304068, 총점=742.817178이었다. 실제 신호 전환을 그대로 쓰는 물리 예측기의 값과 혼동하지 않는다.

첫 worker 진입 검사는 진단 callback의 closure 접근 오류로 예측 전에 실패했다. 로그 `worker.log`와 `check_worker.failed1.txt`를 보존했고, `worker_v2.log`는 수정 후 완료 결과다. 전체 작업은 물리 예측 5회 + 연속 스칼라 1회 + AD 1회이며, 새 VISSIM 런·최적화·push는 수행하지 않았다. 초기 물리 시험 후 수정한 것은 말단 비용 활성 표기와 비유한 비용 거부 검사뿐이며, 수치 식은 같고 이후 실제 worker 검증은 최종 소스로 실행됐다.
