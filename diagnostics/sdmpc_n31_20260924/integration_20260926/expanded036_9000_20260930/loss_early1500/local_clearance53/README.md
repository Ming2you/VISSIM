# 국소 차로 상태 + 저속 합류 공간 해소 시간: 예비 통과, 통합 후보 미채택

2026-10-01. 미래 실측 차로 속도·유량 대신 **과거 관측으로 초기화한 국소 셀22·23의 예측 상태**에 기존 저속 합류 보정을 연결했다. 새 계수 적합은 없었다. 예비 검사는 개선됐지만, 현재 expanded036에서 본선 피드백까지 재계산하면 RM 손해 크기와 유지 상태의 회복이 악화해 채택하지 않았다.

## 시험 범위

- 보존된 `LocalMergeLaneState` 구현과 과거2520.1–2670.1초만으로 추정했던 공통 차로 이동 계수를 재사용했다. 독립 셀별 계수나 새로운 차로 모형을 만들지 않았다.
- 10484 수용 간격에 기존 차량 간격6m와 posthead 정상 이동속도67.97km/h로 구한 추가 공간 해소 시간을 더했다: `extra = max(0, 6×3.6×(1/v_lane − 1/67.97))`. 기존 critical2초/follow-up1.5초에 같은 extra를 더하며, v_lane=0이면 수용0이다. 임의 용량 보너스는 없다.
- 먼저 이전 국소 모델의 저장된 자율 예측을 고정하고, 유지/완화/각VSL90의 네 조건×두 방법으로8회 램프 buffer를 재생했다. 기존 수용 재생1,800개1초 결과가 저장 궤적과 일치했다.
- 이후 **현재 expanded036 component**에서 aggregate / local gap / local clearance 각각 유지·완화, 유효6회450초 예측을 비교했다. 실제 합류가 본선 재고·속도에 반영되고 바뀐 본선 상태가 다음 수용을 바꾼다.
- 도시·외부 피드백을 포함한 full Ω 예측은 아니다. 평가 범위는 동측31셀+그 방향의8개 진입/진출 커넥터이며 같은30초 적분을 사용했다. 17개 신호 SDMPC 연결을 주장하지 않는다.
- 현재 코어에 과거 패치의 국소 hook만 메모리에서 적용했다. 바뀐 top-level 정의와 harness의 rollout만인지 AST 검사했고 최신 off-ramp 코드와 보호 조건을 유지했다. 파일과 운영 설정은 변경하지 않았다. route-inventory 상태가 주어진 경우 이 국소 구현을 사용할 수 없다는 기존 guard도 유지했다.

## 예비 검사와 현재 모델 검사는 다르다

예비 검사는 예전 국소 모델의 고정된 본선 예측에 clearance만 넣었다. RM 완화−유지 posthead 체류는0.123→0.497대·시간, 실제1.040으로 오차가40.8% 줄었다. 유지 합류45.329→45.248, 완화92.933→91.370대로 나타났다. 실제 head/미래 차로 관측은 입력하지 않았다. 다만 본선은 재계산하지 않아 이 단계만으로 채택할 수 없다.

다음 표는 별도로 **현재 expanded036의 동일 초기 상태·같은 명령·같은 경계 예측**으로 계산한 결과다. 예비 검사와 reference 계수도 다르므로 두 단계의 차이 전부를 피드백 효과로 해석하지 않는다.

## 현재 expanded036의 본선 피드백 포함 결과

Δ는 RM 완화−유지, 단위는대·시간이다.

| 지표 | 실제 | Aggregate | 국소 차로+기존 gap | 국소 차로+clearance |
|---|---:|---:|---:|---:|
| 10484 신호등 뒤 ΔTTT | **1.0396** | 0.1306 | 0.1221 | **0.9528** |
| 동측 본선+8커넥터 ΔTTT | **5.9292** | 2.5763 | 2.1668 | **1.8659** |
| 유지 셀24 평균속도[km/h] | **79.70** | 56.20 | 49.80 | **49.89** |
| 완화 합류[대] | **91** | 92.91 | 92.96 | **79.68** |
| 완화 최종posthead[대] | **16** | 1.31 | 1.26 | **14.54** |

신호등 뒤 대기 개선은 자율로 계산된 차로 상태를 사용해도 나타났다. 그러나 다음 두 문제가 남았다.

1. **국소 차로 동역학이 RM 유지 때 회복을 더 느리게 만든다.** 셀24는 aggregate보다 약6.3km/h 더 느리며 실제와 차이가 커졌다. 주된 악화는 국소 차로+기존 gap 단계부터 있었고, clearance가 전부 만든 것은 아니다.
2. **최종 재고가 맞아지는 것만으로 성공이라고 할 수 없다.** 완화 실제 도착은88대인데 예측은75대, 실제head106대인데 예측93.217대다. clearance를 넣은 모델은 합류도79.68대로 실제91보다 작다. posthead14.54대가 실제16대에 가까워진 데에는 들어온 차량과 나간 차량을 모두 적게 예측한 상쇄가 포함된다.

유지 도착은 실제73/예측75대, 합류는실제45/후보45.214대다. 따라서 모든 상황에서 clearance가 지나치게 제한한다고 일반화하지 않는다. 완화에 따른 도착 변화는 이 component의 고정 경계 예측으로 표현되지 않는다.

사전 기준 중 posthead 반응 개선·큰 RM 손해 방향·재고/유량 RMSE 한계는 통과했다. **전체 component 반응 오차와 유지 회복 기준은 실패**했다. 해당 모델을 full Ω/SDMPC에 포팅하거나 VSL 후속을 확대하지 않는다. 계수를 다시 탐색해 이 작은 시험에 맞추지도 않는다.

## 검증과 실패 보존

- 예비8회 buffer 재생, 본선450초 예측8회가 실제 수행됐다. 후자 중4개 기준 결과와2개 실제 활성 후보가 유효하다. 처음2개의 clearance 표기 결과는 함수 hook이 적용되지 않아 무효다.
- 첫 preflight는 변경 대상 함수명을 잘못 지정해 예측 전에 종료했다. 다음 시도는 사후 활성 호출 검사가0회를 검출해 실패 처리했다. 실패 로그·소스·결과를 보존하고 import된 함수 참조만 고쳤다. 유효한4개 기준 예측을 재사용하고 후보2개만 다시 계산했다.
- 수정 후900번의10484 수용 계산에 보정이 실제 호출됐다.8개 포트·본선·국소 차로 보존 잔차는1e−7 이하이며 활성 후보 국소 잔차는약1e−12대다. 생산 소스·선택망·설정·STOP의 해시를 유지했다.
- 출력: `assessment.json`(예비), `coupled_active/assessment.json`(유효 통합), `coupled/failure.json`(무효 실행), 각 실행 로그·소스·예측파일. 현재런 조회/새VISSIM/FZP재스캔/push는0회다.

## 다음 판단

저속·접속 차로 상태가 posthead 대기 설명에 필요하다는 근거는 강화됐다. 그러나 이전 국소 차로 METANET을 통째로 되살리는 방식은 회복을 악화하므로 채택하지 않는다. **본선 aggregate 회복 동역학과 접속 차로의 수용 상태 추정을 분리**하는 최소 표현을 검토해야 한다. 이때 도착/합류 시점과 실제 유량을 함께 검사하고, 최종 잔여나 대기만 가까워지는 후보는 거부한다. 아직 큰 RM 손익 방향은 구별하지만 크기·VSL 순위·full Ω 선택 검증은 미완료다.
