# 램프 입구 대기와 제한된 도착을 희망 수요로 연장하는 문제

2026-10-01. 이전 턴은 셀21·24의 독립 반응 검증으로 본선 오차와 램프 비용을 분리한 PROGRESS였다. 이번 턴은 실제 램프 입구 대기와 모델 수용식의 차이를 확인하고, 새 계수 없이 한 가지 수용 가설을4회450초 예측으로 시험한 PROGRESS다. 새 VISSIM·FZP 스캔·현재 CTG 조회·fit·push는 없다. 생산 모델은 변경하지 않았다. 목표는 ACTIVE/NOT_QUALIFIED다.

## 저장 위치 자료가 보여 준 것

seed53의2670.1–3120.1초16개30초 표본을 사용했다. 실제 port_cohorts의 위치와 속도로 신호등 전후를 구분했고, 입구20m 이내 저속 차량도 확인했다.

- 10639 RM 유지: 입구20m 안 속도10km/h 미만 차량이16/16표본,5km/h 미만도15/16표본이다. 전체 재고가45–48대에서 유지되고30초 도착도 대체로3대다. 완화 조건에서는 저속 입구 표본이7/16으로 줄고 재고가17대까지 감소하며,450초 도착은46→72대로 증가한다.
- 10484 RM 유지: 후반에 입구까지 대기열이 닿아8/16표본에서 입구20m·속도10km/h 미만을 관측한다. 완화 조건에서는0/16이다. 도착73→88대, 최종 재고53→22대다.
- 단순히 입구 가까운 차량이 있다는 기준만 쓰면, 정상 속도로 막 들어온 차량도 대기열로 오인한다. 위치와 속도를 함께 사용했고5/10/15km/h 기준을 모두 보존했다. 두 조건의 모든 차이를 이 하나의 원인에 귀속한 것은 아니다.

현재 PhysicalRampBoundary의 finish_interval/current_admission_space는 connector 전체 빈 공간으로 진입을 허용한다. 10639의 전체 정지 저장공간은68.08대지만 신호등 앞은52.47대,10484는 각각90.32/62.85대다. 신호등 앞 공간만 하드 한계로 바꾸더라도, 혼잡 중 차량 간 간격 때문에 절대 정지 저장량보다 먼저 입구 수용량이 낮아지는 현상은 표현하지 못한다.

## 보정계수 없는 단일 수용 가설

각각 기존의 물리 용량1800대/h, 설정 이동속도40.36/41.96km/h, 간격6m, 실제 신호등 위치를 사용했다. 이 값들을 새 자료에 적합하지 않았다.

`Q=기존 용량/3600`, `k_j=차로 수/간격`, `v=기존 이동속도/3.6`, `w=Q/(k_j−Q/v)`로 혼잡파 속도를 유도한다. 10639는4.096m/s,10484는4.040m/s다. 예측 중 현재 신호등 앞 재고를N, 앞쪽 길이를L이라 할 때:

`다음Δt 진입 한계=min(connector 전체 여유, 앞쪽 정지 저장 여유, QΔt, w(k_jL−N)Δt/L)`.

이것은 제한된 물리 가설이며 보편적으로 검증된 VISSIM 수용식이라고 주장하지 않는다. 예상 도착량은 기존의 과거 관측 기반 입력을 그대로 쓰고, 진입하지 못한 차량은 외부 대기에 남겼다. 본선 merge/속도식·head 서비스·off-ramp 동역학·명령은 바꾸지 않았다. 앞선 셀21·24 후보도 합치지 않았다.

기존 클래스의 두 진입 메서드에만 이 과정을 메모리에서 추가했다. 원본 파일·생산 설정은 그대로이며 실행 소스를 보존했다. 실제로 시험한 것은 component의 finish_interval 경로이고, 전체 도시 결합의 current_admission_space 경로는 아직 실행 검증하지 않았다.

## 비용이 줄었다고 판정하지 않은 이유

RM 유지의 component TTT는151.5041→151.1313대·시간으로 줄어 보이지만, 같은30초 사다리꼴 집계의 상류 대기0.3727을 합치면151.5041로 정확히 같다. 네 조건 모두 합산 비용 차이는6e−14대·시간 이내, 본선 상태 차이는4e−13 이하이다. **대기 위치를 옮긴 것이며 순이득 개선이 아니다.**

원래 assessment.json의 component_plus_added_backlog_ttt는 component30초+backlog1초의 혼합 간격 보조값이다. 최종 비교에는 verification.json의 동일30초 집계만 사용한다. 1초 대기 기록은 그대로 보존한다.

## 다음 단계

1. 전체 모델에서 도시→10639/10484의 희망 도착과 실제 수용을 분리한다. 이미 상류에 있는 목적지별 차량과 앞으로 도착할 차량을 공급으로 쓰고, 막혀서 통과한 적은 차량 수만 연장하지 않는다.
2. 지금 수용 가설을 전체 도시 결합에 옮길 경우, 각 시간 구간의 수용 예산을 여러 urban movement가 중복 소비하지 않도록 검증한다. 현재 component 시험은 이 부분을 증명하지 않는다. 거부된 차량은 기존 도시 재고 소유자에게 남겨야 한다.
3. 기존 전체 모델의 seed47/43 입력·도착 이력을 우선 재사용한다. 희망 수요 원인 검증 없이 full model 수요를 임의로 올리거나, 본선 FD/merge 계수로 이 차이를 상쇄하지 않는다.
4. 전체 대기를 포함한 RM/VSL 비용·순위와 독립 상태를 확인한 뒤 채택을 판단한다. 이번 후보는 물리 대기 형상 개선 후보로만 보존한다.
