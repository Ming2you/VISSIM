# 1500–1650초 10484: 신호등 이후 이동·합류 대기 오차

완료된 seed29 expanded036 9000초 SDMPC 런의 첫 VSL 명령 이전 구간이다. 새 VISSIM이나 plant 전체 예측은 실행하지 않았다. 이전 4조건 예측의 저장 자원과 native MER·차량 관측만 재사용했다.

**신호등 통과의 총량·시각 오차만으로 과대 합류를 설명할 수 없다.** 실제 통과 시각을 그대로 주어도, 고정된 기존 이동·수용 계산은 실제보다 약9.90대를 더 합류시키고 그만큼 신호등 뒤 잔여 재고를 적게 남긴다.

| 150초 결과 [대] | 기존 자율 예측 재현 | 실제 head 시각으로 조건부 계산 | VISSIM 관측/보존 재구성 |
|---|---:|---:|---:|
| 신호등 뒤 초기 재고 | 3 | 3 | 3 |
| 신호등 통과 | 43.614 | 45 | 45 |
| 본선 합류 | 45.759 | 43.899 | 34 |
| 신호등 뒤 종료 재고 | 0.855 | 4.101 | 14 |

합류 실측 열은 `초기 posthead 재고 + head 통과 − 종료 posthead 재고`이며 직접 합류 검지 계수가 아니다. 이전 진단에서 해당 커넥터의 native 삭제 없음과 전체 램프 보존을 확인했다. 이번 결과도 3+45−34=14를 보존한다. 전체 커넥터 재고는 13→22대다.

## 고정한 것과 바꾼 것

- 초기 차량 위치, 신호등 이후 명목 이동시간8.7286초(67.97km/h), 저장된 매초 canonical/physical 수용 예산의 작은 값을 그대로 사용했다.
- 기존 모델 head를 넣었을 때 저장된 합류45.7591652274와 잔여0.8545402237을 1e-7대 이내로 재현했다.
- 이후 head 입력만 native MER의 실제45개 진입 사건으로 교체했다. 실제 시각과 다음 정수초로 올림한 시각 두 경우의 결과는 1e-12대 이내로 같았다.
- 미래 MER를 썼으므로 **조건부 buffer 회계 진단**이다. 바뀐 합류가 본선 상태·수용 예산을 다시 바꾸도록 계산하지 않았다. 자율 예측 성능이나 제어 이득 검증으로 사용하면 안 된다.

## 실제로 무엇이 남았나

1650초 신호등 뒤 차량14대 전부가 명목 이동시간8.7286초보다 오래 전에 신호등을 통과했다. 경과시간 중앙값은21.015초이고, 현재속도5km/h 미만은5대다. 마지막30초 head는 실제10대/모델5.344대로 입력 시각 차이도 있으나, 실제 입력을 주어도 잔여가4.101대뿐이어서 이를 유일한 원인으로 삼을 수 없다.

이 자료는 **posthead의 이동시간·가속/추종·합류 수용을 묶은 계산이 차량을 너무 빨리 비우는 상태**를 보여 준다. 그중 어느 항을 얼마나 고쳐야 하는지, 또는 10484가9000초 손실의 얼마를 만들었는지는 아직 식별하지 못했다. 임의로 합류 상한을34/150으로 맞추거나 모든 상태에서 속도를 낮추는 보정은 하지 않았다. 회복 상태와 실제 RM 반응이 큰 상태에서도 확인해야 한다.

## 재현·검증

기존 `../assess.py --posthead-timing` 선택 모드로 수행했다. 완료 결과가 있으면 덮어쓰지 않는다. 과거10490 진단 스크립트의 순수 `close`·`fluid_replay` 함수만 AST로 읽어 재사용했고, 과거 진단 자체는 실행하지 않았다. 기존 assess의4개 함수는 수정 전과 AST가 같다.
