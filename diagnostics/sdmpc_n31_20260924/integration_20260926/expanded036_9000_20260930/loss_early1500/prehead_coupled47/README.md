`Q=capacity/3600`, `k_j=lanes/spacing`, `w=Q/(k_j-Q/v)`.

매1초 head/merge 갱신 직후 `S=min(전체 여유, prehead 여유, QΔt, w×prehead 여유/L×Δt)`를 한 번 고정한다. 여러 도시 movement가 같은 수용량을 중복 소비하지 않도록 이미 받은 pending/committed 양을 뺀다. 기존 도시 재고가 거부된 차량을 계속 소유하고 ramp 외부에 두 번째 대기열을 만들지 않는다.

## 추가 실측 근거: 부족한 도착은 새 차량 생성 차이만이 아니다

저장된150초 관측8개와 native MER6개를 읽고 각 chunk SHA를 검증했다. 미래 자료는 사후 평가에만 사용했다. 두 런2700초의 차량 ID·위치·속도 기록은 완전히 같다.

- 10484 진입72/83대 중 공통 차량67대, 유지에만5대, 완화에만16대다.
- 완화에만 들어간16대 중10대는 두 런의2700초 초기 상태에 모두 있었다.
- 이10대는3150초 유지 런에서 전부31번 링크1차로에 남아 있다. 완화 런에서는3112.11–3144.12초에 램프에 진입했고3150초에 전부10484에 있다.
- 나머지 완화 전용6대와 유지 전용5대는 초기 망에 없었던 차량이다. 따라서 net+11 중10대는 기존 공통 차량의 진입 지연 차이이며, 새 차량 그룹의 순차이는1대다. 이를 차량별 총 TTT나 본선 이득의 인과 기여로 환산하지 않는다.
- 3150초 link31은 유지18대(10km/h 미만13대), 완화5대(저속0대)다. 이 링크 전체를 램프행이라고 가정하지 않았으며, 모델의 SC1001_W_out은 더 넓은 물리 소유 범위라 link31 대수와 직접 동일시하지 않는다.

이 근거는 램프가 막혔을 때 도시 상류에 남는 목적지별 대기와 풀렸을 때 진입하는 차량을 함께 다뤄야 함을 뒷받침한다. 미래83대를 수요로 넣거나 희망 수요를 임의 증액하는 수정은 하지 않았다.
