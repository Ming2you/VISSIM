# SC1002→SC1001 도착·방출 경로 진단과 이동속도 집계 수정

이전 목표 턴은 progress(램프 속도 연결 수정과 실제 방출 오차 확인)였다. 이번에도 완료 자료의 원인을 분리하고 정본 어댑터의 집계 결함을 수정했다. 목표는 **ACTIVE / NOT_QUALIFIED**다. 현재 CTG를 조회·변경하지 않았고 새 VISSIM, FZP 재읽기, 계수 탐색, push는 없다.

## 1. 실제 차량은 지나갔는데 모델은 녹색을 놓쳤다

seed29 완료 런의2250초 동일 관측·명령에서150초 동안:

| 물리량 | 실제 | 기존 | 속도 집계 수정 |
|---|---:|---:|---:|
| 329 직진 head 통과 | 35 | 14.060 | 14.060 |
| 29 직진 head 통과 | 31 | 2.542 | 10.534 |
| 10484 입구 도착 | 27 | 23.904 | 27.900 |
| 10484 본선 합류 | 36 | 43.189 | 45.765 |

기존 모델은 SC1002→SC1001 이동을101–104초로 잡았다. SC1002 직진 녹색은2266–2332초, SC1001 직진 녹색은2296–2351초였다(적용 기록; 기존 native LDP 실행 검증을 재사용). 상류 모델 방출은2267초부터 시작하지만 약104초 뒤에 도착해 하류 녹색을 놓친다. 첫 하류 방출2.542대는 초기 직진 큐0.667대와 초기 이동 재고3대의 직진 분할1.875대다. 이후 도착분은2400초에 직진 큐9.204대로 남았다.

실제29 통과31대 중27대는 상류329 head 통과와 차량 번호로 연결된다. 두 head 사이 경과시간 중앙값54.72초, 범위50.21–164.62초다. **주행+신호·대기 시간을 포함한 조건부 통과 코호트**이며 자유류 시간의 직접 보정치가 아니다. 나머지4대는329를 거치지 않는 유입 등을 포함할 수 있어 모두 누락/오류로 취급하지 않는다. 미래 통과 시각은 사후 진단에만 사용했다.

## 2. 수정한 코드 원인

`vissim_stackelberg_adapter.build_local_observation_summary`는 `urban.tau.moving_only=True`에서 각 링크 속도를 이동 차량 기준으로 환산한다. 하지만 링크들을 같은 모델 storage로 합칠 때 다시 전체 차량 대수로 가중했다. 전 차량이 정지한 링크도0km/h 표본으로 섞였다.

2250초에는29의 정지2대와10690의 이동3대가 같은 storage에 대응한다. 이동3대 평균40.7805km/h가 전체5대로 나뉘어24.4683km/h가 됐다. 선언된 기존 차로 보정을 곱한 유효속도와 대수 기반 거리로 계산하므로, 잘못 낮아진 속도가 이동시간104초로 이어졌다.

수정은 **같은 시각의 이동 차량 대수**로 가중치를 일치시키는 것이다. 이동 표본이 없는 링크는 이동속도 표본에 기여하지 않는다. 전체 storage에 이동 표본이 없으면 기존 모델의 명시된 nominal speed 경로를 사용한다. 정지 재고·수용·서비스 제약은 유지하므로 정체 자체를 삭제하는 처리가 아니다. `moving_only=False` 경로는 유지했다. 새 속도계수나 fitted travel time을 넣지 않았다.

실제2250초 초기화의 집계 회귀 검사는 수정 전 실패, 수정 후40.7804644368km/h로 통과했다. 기존 거리·차로 산식은 유지해 이동시간이61–63초가 됐다. 이 결과를 실제54.72초와 완벽히 같다고 주장하지 않는다. 병렬 연결로를 합친 storage의 이동거리 근사도 남아 있다.

## 3. 별도 상태에서는 개선되지 않는 항도 있다

| 3600초, 첫150초 | 실제 | 수정 전 | 수정 후 |
|---|---:|---:|---:|
| 329 직진 head 통과 | 27 | 13.139 | 13.139 |
| 29 직진 head 통과 | 8 | 3.049 | 3.049 |
| 10484 도착 | 23 | 16.900 | 16.900 |
| 10484 합류 | 23 | 16.976 | 16.976 |

이 상태의 이동속도 집계는22.584→31.561km/h, 지연은109–113→78–81초다. 그러나 SC1001 녹색3605–3655초가 SC1002의3630초 이후 방출 차량 도착보다 먼저 끝난다. 따라서 첫150초 방출이 같다는 것이 수정 미반영을 뜻하지 않는다. 실제29 통과8대 중7대는 시작 시 이미29에 있던 차량이다. 연결된329→29 실제 코호트6대의 경과시간 중앙값110.64초는 적색 대기를 포함하므로2250초의54.72초와 다른 속도계수로 바로 해석하지 않는다.

450초 Ω 예측 TTT는2250상태485.1621→485.2185,3600상태517.5937→516.9855다. **예측 모델 변경에 따른 값 변화이며 실제 제어 이득이 아니다.** 실제 다음 도시 명령은 바뀌므로450초 전체를 같은 명령의 native 검증으로 사용하지 않는다. 두 상태는 같은 seed여서 독립 seed 검증도 아니다.

## 4. 남은 두 오류를 구분한다

1. **상류 직진 큐 배정 부족.** 2250초329의2·3차로에31대(정지25대),4차로에6대(정지5대)가 있었다. 저장 모델은 정지30대를 세 movement에10대씩 배정한다. 실제로2·3차로31대는 다음150초 안에 직진 head를 통과했다. 미래 통과 사실은 검증 근거이며 초기 상태 생성에 넣지 않았다. 다음은 이미 구현된 `head_phase_queue_weights`/`queue_attribution=head_phase`가 관측된 차로 큐와 실제 SG를 정확히 사용하는지 제한적으로 검사한다. 새 도착/차로 프레임워크를 만들거나 모든 링크의 계수를 풀지 않는다.
2. **램프 방출 과대.** 도착이27.90대로 실제27대에 가까워졌지만 합류는45.76대로 실제36대보다 더 크다. 초기 재고22대에서 계산한 종료 재고도4.136대로 실제13대보다 작다. 도착 총량만 맞춰서 RM 응답 검증을 통과시키면 안 된다. 미터 신호 전후 이동·수용과 초기 차량 위치를 다시 분리해야 한다.

두 직진 movement의 수용 단계 이후 허용량 손실은 저장된 모든 첫150초 substep에서0이었다. 이는 의도량 생성 이후의 receiving/공유 head 제약이 이 두 방출을 깎은 원인이 아니라는 뜻이다. 모든 네트워크 제약이 항상 비활성이라는 의미는 아니다.

## 검증·예산·재현

- 정본 함수 변경은 `build_local_observation_summary` 한 개(AST 비교). 기존 램프 속도 연결 수정, 모델계수·SDMPC·RM 물리 코드·STOP의 해시는 유지됐다.
- 두 상태 각각 수정 전/후450초: **4회 예측 모두 정상 종료**. 추가2250초 초기화1회. 관측·green/offset/VSL/RM 명령 동일, 검사한 초기 도시 재고·도착/배수 예약과 본선 배열 동일,8개 램프 보존 잔차<1e-8.
- 기존 관측속도 검사4개+새 혼합/무표본/비활성 보존 회귀 검사4개: **8개 통과**. 처음에는 오래된 테스트 대역에 simulation/mpc/cycle 필드가 없어1개 오류가 났고, 현 초기화 계약에 맞게 대역을 보완한 뒤 통과했다.
- 예비 분석에서 기본 detector mapping만 읽으면10690 지원 링크가 빠지는 것을 확인했다. 최종 회귀 근거는 실제 vehicle_records와 물리 투영 출처를 사용했다. 이전 protocol의 lane runtime 해시는 수정 전 기준이어서 최종 검증은 보존된 `lane_plant_runtime_after.txt`와 비교했다.
- N_P/N_UF, 미분, 후보 순위, 새 SDMPC/native 성능은 이번 검증 범위가 아니다. 보정 완료를 선언하지 않는다.
- `verification.json`: 실제 전후 결과·불변식·해시. `native.json`: head 코호트·초기 차로·신호 기록 및 원본 핀. `2250*/`, `3600*/`: 초기화·1초 transfer/resource trace. `adapter_before.txt`, `adapter_after.txt`: 소스 보존.
- `../audit_city_arrival.py`: 기존 초기화·probe를 호출하는 진단 instrumentation. `../city_native.py`, `../summarize_city_path.py`: 저장 결과 후처리. 별도 runner/adapter는 만들지 않았다.
