# 10490: 예측 합류 셀 속도를 반영한 posthead 이동 후보

2026-10-01. **혼잡 때 과대합류와 과소대기는 일부 줄었지만, 회복 상태는 소폭 악화했고 전체 제어 이득 보정은 미완료다.** 후보는 정본 설정에 채택하지 않았다. 현재9000 런을 조회하거나 수정하지 않았다.

앞선 [점유·수용 진단](../posthead10490_receiving/README.md)에서 실제 head 통과를 주어도 과대합류가 남았다. 이번에는 새로운 수용량 계수를 맞추지 않고 고정 posthead 이동 가정을 하나만 변경했다.

## 계산 변경

10490의 신호등 이후95.776m는 명목57.67km/h, 약5.979초의 이동 buffer를 쓴다. 후보는 매1초 현재 예측된 합류 셀 속도와 명목 속도 중 작은 값으로 이동 중 차량의 진행을 제한한다.

`v_move = min(v_nominal, current_predicted_merge_cell_speed)`

남은 거리를 명목 속도의 시간으로 보관한 기존 ETA에는 매초 `dt * (1 − v_move/v_nominal)`을 더한다. 속도가0이면 남은 거리를 유지하며, 회복하면 이동을 재개한다. 이미 합류점에 도달한 차량의 receiving queue와 수용 예산은 그대로다. 새 head 통과 차량은 해당 초 끝에 들어가므로 같은 초에 즉시 합류하지 않는다.

기존 `physical_ramp_boundary.py`, `lane_ramp_runtime.py`, `canonical_harness.py`만 수정했다. 공통 함수를 두 예측 경로에 연결했고, reference의10490 노드에 `posthead_speed=merge_cell_cap`을 명시한 경우에만 사용한다. 기본 설정·vendor·다른 램프의 직접 이동 규칙·명령·수요·목적함수·내부1초 적분은 유지했다.

이는 **합류 셀 평균속도가 램프 이동도 제한한다는 검증 후보**다. 실제 차로별 공간과 양보 동역학을 복원한 모형은 아니다. 미래 실측 속도/유량을 입력하지 않았고 seed·시간·RM/VSL별 보너스나 새 계수 fit도 없다.
