# SC1001 물리 경로의 속도 단위 수정과 두 상태 검증

이전 목표 턴은 속도 용도 혼용을 확인한 progress였다. 이번 턴은 정본 코드에 선택 가능한 수정과 회귀 검사를 넣고 **동일 상태450초 예측2회**를 완료했다. 전체 목표는 **ACTIVE / NOT_QUALIFIED**다. 기본 설정·현재 동결 CTG·망·수요·목적함수·제약은 바꾸지 않았다. 새 VISSIM, FZP 재읽기, 실시간 조회, 계수 fitting, push는 없다.

## 변경

`route_choice_corridor`의 기존SC1001 목적지별 이동 모델에 `urban.sc1001_destination_travel.speed_source="physical_observation"` 선택을 추가했다. 기존 `initial_unknown="reachable_native_prior"`와 함께 쓰며, 옵션이 없으면 기존 경로다.

- 실제 connector·link 길이로 계산하는 SC1001 유입 movement와10483 direct 진출 경로는 `state.local_observation_summary.urban_link_speed_kph`의 **차로 배율 적용 전 관측값**을 사용한다.
- 기존 대수 기반 저장고 지연에 필요한 `state.urban_link_speed_kph`의 유효속도는 변경하지 않는다.
- 물리 관측 표가 아예 없으면 실패한다. 표는 있지만 해당 링크 표본이 없으면 기존 nominal speed를 사용하고, 기존 속도 하한도 유지한다.
- 초기 차량의 실제 위치·속도·경로 기대 할당, 목적지 태그, 초기 ETA, 저장·배수·spillback, 램프 buffer/receiving/head 계산과 차량 보존은 유지한다.
- 다른 물리 경로 모듈에 전역 적용하지 않았다. 이번에 진단한 SC1001 계약만 대상으로 한다.

2250초의29→10484 약540.683m는139.098km/h 유효속도/14초 대신40.780km/h 물리 관측값/48초가 됐다.37→10484는23→61초,40→10484는17→65초다.3600초에는 각각19→62초,15→39초,24→90초다. 이전9000 동결 모델이 아닌 직전`service329` 후보와 비교한다.

## 검증

- 수정 전4개 새 회귀 검사가 모두 의도한 속도 계약에서 실패했고, 수정 후 기존 포함16개 검사가 통과했다.
- 기존 첫 시도에서 오래된 fixture에 distance observer가 요구하는 connector 필드가 없어3개 KeyError가 났다. fixture에 실제 구조의 connector를 넣은 뒤 위4개 물리 회귀 실패를 다시 확인했다. 모델 실패로 세지 않는다.
- forward AD의 고정속도 경로 배분·부분 수용4개 출력은 scalar 및 유한차분과 일치했다. 전체 rollout237축이나 SDMPC 미분 검증을 대체하지 않는다. 최초 AD 시도는 느려진 장거리 차량까지100초에 모두 도착한다고 가정한 fixture 검사에서 실패했다. 새 옵션에서 실제 마지막 예약시각을 사용하도록 고쳤고, 원래 옵션의100초 검사는 유지했다. 실패 로그도 보존했다.
- 두 actual initialized 상태에서 옵션 적용, 관측 물리속도, 경로 기하와 초기 cohort를 저장했다. 기존 `runtime.json` 요약은 이 새 metadata 항목을 내보내지 않아 첫 후처리 검사가 실패했으며, **실제 예측에 전달한 cfg와 상태를 저장한 `physical_speed.json`**을 근거로 수정했다. native 실행이나 모델 재실행은 하지 않았다.
- 초기 상태·큐·저장·이동예약·유효속도·관측 투영·서비스상한·수요예측·도시/VSL/RM 명령·초기31셀 상태가 직전 후보와 정확히 같았다. 바뀐 설정은 speed_source 한 개다.
- 8개 램프450초 보존 잔차 최대4.16e-13/2.24e-13대.10484 buffer의 모든450초 stock/head/merge/eligible 계산을 저장 trace로 재생해1e-8 이내 일치했다. 미래 native 도착·유량·속도는 예측 입력에 사용하지 않았다.
- parameter checker는 기존 global calibration override 경고와 함께PASS. 경고를 새 파라미터 보정 성공으로 해석하지 않는다.
- 정본 함수는 `configure_direct_exit_legsplit`, `direct_exit_receive`, `direct_exit_movement_receive`와 새 `_direct_travel_speed`만 변경했고, 같은 파일의 기존53개 함수 AST는 동일했다. adapter, lane plant, SDMPC, urban accounting, ramp buffer, 기준 설정, selected network, 기존 STOP의 핀을 검증했다.
