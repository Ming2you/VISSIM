# SC101 3600초 방출 과대예측: 준비 큐·도착 시각 진단

완료한 seed29 SDMPC 기록과 직전 서비스 후보 예측을 재사용했다. **실제 좌회전11대에 예측19.800대였던 차이를 출발지연 하나로 보정하지 않는다.** 상류의 다른 신호 앞 큐와, 이동 중 차량의 일괄 도착·목적지 배분을 먼저 고쳐야 한다. 이번 작업은 원인 분리이며 보정 채택·이득 검증 완료가 아니다. 현재 목표는 ACTIVE / NOT_QUALIFIED다.

## 실제 통과와 모델의 차이

평가 구간은3600–3750초, SC101 남쪽 좌회전 SG3, DCP960084/960085다. 다음150초는 기록된 도시 명령과 예측 명령이 같으며 이후300초까지 동일한 native 비교로 확대하지 않는다.

|항목|완료 native 기록|서비스 후보 모델|
|---|---:|---:|
|방출 차량|11|19.800|
|초기 SC101 접근로의 좌회전 차로 정지 차량|5|5|
|SC15 앞 차량을 SC101의 즉시 서비스 큐로 계산|해당 차량은 약580m 이상 상류|3|
|녹색 이전 일괄 도착|차량별 도착 시각·목적지는 서로 다름|3615초에 좌회전11.800대|
|녹색 길이|26초|기존 명령 시각 규약 유지|

11대의 차량ID를 초기 상태와 결합했다.8대는 처음부터 SC101 접근로1220011503에 있었다(정지5+이동3). 나머지3대는 SC15 접근로1210008501의 정지 차량이었고, SC101 좌회전을3660.81/3663.21/3665.19초에 통과했다. 앞의8대는3645.07–3653.47초에 통과했으므로 두 묶음 사이 최대7.34초 공백이 있다. 녹색 명령은3643초, 최초 통과는2.07초 뒤다. 이 시차를 모든 상황에 적용할 고정 출발손실로 보정하지 않는다.

초기1220011503의4차로 이동 차량 중8대는 이후 직진 검지기를 통과했다. 따라서 '현재 좌회전 가능 차로에 있으므로 모든 이동 차량이 좌회전한다'고 바꿀 수도 없다. 이 목적지 식별에는 미래 MER를 사용했으며 **사후 진단 전용**이다. 자율 예측 입력에 차량의 미래 목적지·도착·방출을 넣지 않았다.

## 어떤 가정이 과대예측에 연결됐는가

모델의 SC1_to_SC101 초기 저류55대 중50.581대를15초 뒤,4.419대를105초 뒤 도착으로 예약한다.15초 예약에 현재 좌회전 비율0.233289를 곱한11.800대가3615초에 준비 큐로 들어간다. 이 예약은 `seed_urban_arrival_buffer`의 기존 이동/정지 잔차 기본 지연이며, 공간별 거리나 중간 SC15 신호 시각을 계산한 결과가 아니다. SC1001에서 고친 물리 속도와 차로 환산 속도 문제를 이 위치에 다시 적용할 사안도 아니다.

초기 준비 큐8대는 실제 SC101 앞5대와 SC15 앞3대의 합이다. SC15 앞 도로의15대가 SC101 세 movement에3/9/3대로 바로 배정된다. native는 SC15에 별도 신호가 있고, 연결10550을 지나1220008502와10544/10545를 거쳐 SC101로 접근한다.10551/10552로 갈라지는 다른 목적지도 있으므로 이 도로를 검증 없이 하나의 결정적 transit 경로로 치환하면 안 된다.

모델은19.800대가 준비된 상태에서1대/초로 방출해 모두 통과시킨다. 녹색 중 모델 하류 여유는500대 이상이어서 모델의 수용 상한은 묶이지 않았다. 이는 **모델 내부 자원 검사**이며 실제 하류의 순간 차로 막힘이 없었다는 증거는 아니다.

같은 준비 재고·상한에서 단순히 녹색 앞2초 또는5초를 빼도 방출은 모두19.800대다. 실제11대로 제한하려면 이 계산에서는15초의 손실이 필요하다. 이는 연성 전체 예측이나 출발지연 적합이 아닌 `min(준비 재고, 서비스율×유효 녹색)` 산술 진단이다. 관측된 약2초 시차만으로 오차가 해결된다고 볼 수 없다.

2250초 저장 상태에서는 같은 상류1210008501의4대가 이미 저류로 분류되고 준비 큐에는 없었다. 따라서 모든 시점에 일정 대수를 차감하거나 하나의 전역 방출률을 낮추는 수정은 피한다. 앞선2250초 서비스 보완의 개선과3600초 악화를 함께 보존한다.

## 중간 고정신호는 확인 가능한 경계 조건

완료된9000초 런의 SC15 LDP 약199KB를 읽었다. 선택망의 FIXEDTIME/program1/offset0과 실제 실행에 사용한 `.sig` SHA256을 대조했고, 기존 정본 parser로 SG3·SG8의1–9000초 **18,000개 상태가 모두 일치**했다. 추가 신호 파서나 실시간 COM 조회는 만들지 않았다.

SC15 SG8의 녹색은3605–3700초이고, SC101 SG3은3643–3669초였다. 원래 SC15 앞에 있던3대가 후반에 도착하는 현상과 일관된 이동 시간·신호 조건이지만, 이것만으로 각 차량의 방출·여행시간 모형이 검증된 것은 아니다. 기존 obs150의 신호 목록에는 SC15가 빠져 있었지만 native LDP에서는 검증 가능했다.

다음 수정은 기존 관측/도시 이동 계산에서 **다른 신호 앞 재고를 downstream 준비 큐와 분리하고, native 고정신호·연속 경로·현재 위치로 도착을 예약하는 것**이다. 중간 신호의 분기 확률과 공유 재고 보존을 함께 검증해야 한다. SC15를 새 제어 레버로 만들거나, 미래 실측 도착을 사용하는 보정으로 대체하지 않는다. 우선 이 한 접근의 범위로 제한하며 불확실한 이동 차량 목적지를 임의 확정하지 않는다. freeway 계수나 합류 감속을 바꿔 도시 도착 오차를 덮지 않는다.

## 실행 범위와 증거

- `arrival_readiness3600.json`:11대 초기 위치·통과 시각,8대 차로/직진 반례,모델 transfer/resource와 질량보존,기하·분기·입력 SHA256.
- `arrival_native_clock15.json`:native 신호18,000상태 검사,실행 provenance/프로그램/LDP 해시.
- 기존 `audit_sc101_source.py`에 위 두 사후 진단만 추가했다. 다른 기존 함수는 변경하지 않았다.
- 새 전체 예측0,계수 적합0,새 VISSIM0,FZP 스캔0,현재 런 조회0,push0. 운영 소스·설정·망·기존STOP은 그대로다.

원래 ALINEA·VSL90 네 정책 및 공통 초기 상태 반응을 이득 검증의 기준으로 유지한다. 이번 도시부 진단의 완료를 RM/VSL 예방 이득이나 SDMPC9000 목표의 완료로 해석하지 않는다.
