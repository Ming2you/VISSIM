수정·예측 완료: [중간 신호 앞 재고의 준비 큐 배정](readiness_candidate/README.md). 기존 두 함수만 수정,4회 예측·28개 검사 완료.3600초 좌회전19.800→16.800대(실제11),2250 전체 trace 동일,독립47 RM 방향과8램프 결과 동일.105초 잔차 지연은 남아 있어 일부 오차 상쇄 가능성을 명시했고 운영 채택은 보류했다.

후속 진단 완료: [3600초 준비 큐·도착 시각](ARRIVAL_READINESS_3600.md). 실제11대/예측19.800대 차이는2–5초 출발지연만으로 해소되지 않았다. SC15 앞 재고3대의 즉시 큐 배정과15초 일괄 도착11.800대를 확인했다. 완료 native LDP에서 SC15 고정신호18,000상태가 정본 parser와 일치했다. 이 진단은 서비스 후보 채택이나 새로운 이득 검증이 아니다.

## 확인한 원인과 수정

10484의 상류29·329번 도로 방출 부족을 추적했다.2250초 SC101 동쪽 접근1220014201의 정지16대는 기존 직진4/좌회전8/우회전4대로 배분됐다. 실제 차로·신호두·connector에 맞춘 기존 queue 계약을 이 접근로까지 확장하면 직진12/좌회전2/우회전2대다.1차로는 직진과 우회전의 공유 가능성이 있어 기존 가중치를 유지했고, 개별 목적지를 확정하지 않았다. 남쪽 접근1220011503의 좌회전 차로 정지11대도 기존3.667대 대신 해당 좌회전 큐에11대가 배정된다. 총 차량 수와 다른 도로의 배분은 같았다.

남쪽 좌회전 서비스 관측에는 별도의 문제가 있었다.1800/1950/2100/2250초 과거 관측의 녹색은25/27/27/29초다. 기존 최소 녹색30초 검사에서 모두 제외돼, 두 차로의 실제 통과가 기록돼도 모델 상한은413.061대/h였다. 초기화 시 membership 추적으로 실제 movement 연결은 존재함을 확인했다. 원인은 movement 누락이 아니라 짧은 녹색에 대한 관측 채택 조건이다.

기존 `head_service_resources.configure`에 선택망의10539 connector 증거를 검증하는v8을 추가했다. 기존4구간 green-exposure pool을 이 두 좌회전 차로에만 적용한다. 과거 관측으로2250초의 상한은2353.846대/h가 됐다. 미래 기록·관측 구간 내 차량 수를 계수로 입력하지 않았으며 METANET·램프 합류·신호 명령·수요·목적함수는 그대로다. 다른 movement의 서비스 상한은 바뀌지 않았다. 기존v7 및 그 이하 설정은 유지된다.

## 독립 상태의 RM 방향 보존

seed47 공통2700초에서10484 녹색2초 유지와4→6→8초 완화를 각각450초 예측했다. 도시 신호·VSL·기준 명령·본선/램프 초기 상태가 기존 비교와 일치했다. 이미 검토했던 seed이며 처음 보는 holdout이라는 뜻은 아니다.

완화−유지 Ω ΔTTT는 실제+2.053833, 기존+1.644970, 수정+1.644970대·시간이다. 실제와 같은 ‘유지가 유리하다’는 방향을 보존했지만 정확도를 더 높이지는 않았다. 동측 본선 ΔTTT는 실제+4.869944/모델+4.807361, 램프는−2.679722/−3.070293이었다. 수정 전후8개 램프 도착·합류·최종 재고는 같았다. 외부 체류 Δ는 실제−0.498611/모델−0.000434로 오차가 남는다. 이는 고정 명령 반응이며 새로운 SDMPC 선택·미분·N_P/N_UF 검증이 아니다.

## 검증과 다음 작업

- 실제 선택망의 head/connector/경로 출처, 새 자원에 대한 미검증 movement 추가 거부, 기존v7 호환을 포함한10개 검사와 queue 투영17개 검사 통과.
- 여섯 예측의8개 램프 질량보존·동일 명령·미래 관측 미사용 통과. 기존 서비스 보완 전후 첫 상태는 정확히 같다. 큐 수정은 검증된 두 접근로 배분만 바꿨다.
- 코어 변경은 `head_service_resources.configure` 한 함수다. 같은 파일의 나머지8개 함수 AST와105개 보호 파일 중 의도한 코어 외 파일, 선택망·기준 설정·기존STOP을 확인했다. parameter checker PASS이며 기존 calibration override 경고는 남는다.
- 네 개발 예측의 계산시간183.102초, 독립 두 예측68.933초, 합계252.035초다. 최적화 iteration은0이고 전체 작업 경과시간/단축률은 측정하지 않았다.
- 최종 파일 검사 첫 시도는 상대·절대 경로 비교로 의도한 코어 변경을 잘못 분류해 실패했다. 경로를 resolve한 뒤 검사만 재실행했고 예측 재실행은0회다. 실패 이유와 실행 소스도 보존했다.
