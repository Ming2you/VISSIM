# 10490 도착·head 통과: 현재 위치를 이용한 초기 이동시간

후속: [독립seed 제어 반응6회](response/README.md)를 완료했다. Seed47의 RM 유지 우선 순위는 유지하지만 손해 크기 오차는 커졌다. Seed43에서는 RM 최선/VSL 단독 손해는 맞추고, 병행 이득은 여전히 놓친다. 초기화 개선을 전체 이득 보정 성공으로 해석하지 않는다.

2026-10-01. **도착·head 과대예측의 큰 부분이 램프 서비스율이 아니라 초기 상류 차량의 이동시간 표현에서 발생했다.** 기존 자료만 읽은 timing 진단 후, 기존 정본 초기화에 선택적으로 위치별 남은 이동시간을 적용했다. 계수 보정 없이 450초 예측3회(기본 일치1,후보2)를 수행했다. 후보는 아직 정본 채택/이득 검증 완료가 아니다.

## 실제 마지막6대는 대기열이 아니라 이동 중이었다

native MER의 entry/head 사건을 차량 ID로 연결하고2250/2400,3600/3750초의 완전한 차량 관측과 대조했다. arrival plane은 ramp 시작1m다. 두 구간 모두 초기 prehead 집합 + 진입 − head 통과 집합이 종료 prehead 차량 ID와 정확히 일치했다. 모델에는 미래 MER를 넣지 않았다.

|10490|2250–2400초|3600–3750초|
|---|---:|---:|
|실측 도착/head 통과|38 / 38|32 / 30|
|종료 prehead 차량|6|6|
|그 중 마지막23.62초 진입 차량|6|6|
|기존 모델 같은 시간대 도착|0|0|
|완료된 entry→head 여행시간 중앙값|27.28초|26.95초|
|기존 모델 entry plane→head 이동시간|23.62초|23.62초|

종료6대는 모두 해당 구간 안에서 진입했고, 약32–43km/h로 이동 중이었다. 오래 정지해 있던 head queue로 해석하면 안 된다. 완료 여행시간 표본은150초 창에 의해 검열되므로 평균 포화 headway/서비스율 추정으로 사용하지 않았다.

오차는 보존식으로 분해된다.

- 2250: head 과대예측12.897대 = 도착 과대6.897대 + 누락한 종료 prehead6대.
- 3600: head 과대예측13.392대 = 도착 과대7.392대 + 누락한 종료 prehead6대.

현재 head 서비스 가능량은150초63대지만 실제 모델 통과는50.90/43.39대다. 가능량이 남는다는 사실과 위 시간분해를 볼 때, 이 두 오차를 포화 서비스율만 낮춰 맞출 근거가 부족하다.

## 원인: 서로 다른 초기 차량/새 차량 시간 표현

상류 source `in_SC1001_W`에는2250초177대가 있는데170.84대를15초 뒤,6.16대를105초 뒤 도착 buffer에서 일괄 해제했다. 미래 새 차량의10490 도착시간은 실제 경로32→10778→129 길이와 현재 링크 평균속도로176초를 적용했다. 따라서 이미 길 위에 퍼져 있는 차량은 먼저 뭉쳐 나오고, 미래 차량이 도달하기 전에는 도착 공백이 생겼다.

3600초도170대 중159.95대가15초 뒤 일괄 해제되는 같은 구조였다.10490으로 향하는 모델 도착은 서비스 상한0.5대/초로 평탄하게 나왔다가 끝부분에0으로 끊겼다. source movement 이름은SC1001이지만10490 방향은 이 망에서 `unsignalized` 접근이다. 이름만 보고 도시 녹색 부족으로 진단하지 않았다.

## 기존 코드에서 바꾼 부분

`physical_ramp_branches.initialize_gate_routes`의 기존 city-lock 초기화에 `urban.ramp.initial_gate_geometry_timing=true` 후보를 추가했다.

1. 정확히 물리 차량에 귀속되는32/10778/129의 기존 재고만 현재 위치로 나눈다.
2. 기존 검증된 경로 기하와 미래 gate travel에 쓰던 **동일한 현재 링크별 속도**로 남은 이동시간을 계산한다. 차량별 정지 속도를 미래 내내 고정하지 않는다.
3. 기존 목적지 비율을 그대로 쓰되 이미 지난 분기로 돌아갈 수 없게 한다. 현재 경로 ID는 기록에 없으므로 실제 확정 목적지를 복원했다고 주장하지 않는다.
4.127 등 이미 도시 방향인 재고와 부분 귀속 재고는 기존 도시 timing을 유지한다. arrival/release buffer를 같은 양으로 바꾸며, 현재 전체 재고·queue·수요·새 차량 timing·서비스율·제어명령을 바꾸지 않는다.

2250초 retime한 차량은163대, 도시 timing을 그대로 둔 차량은14대다.10490행 예상 초기 재고 총44.8965대는 유지되며, due는2251–2425초로 분산됐다.2376–2400초의 예정 도착6.816대가 생겼다. 이는 현재 위치와 고정된 확률 비율에서 나온 기대량이며 실측 미래6대를 넣은 값이 아니다.

이 후보는 직전 origin-capacity 수용 후보에 초기 timing 변경만 추가한 것이다. 생산 설정은 바꾸지 않았다.

## 검증 범위와 다음 단계

- 이전턴=progress,이번턴=progress. 기본 옵션을 끈450초의 전체trace·상태·명령·비용이 직전 후보와 정확히 일치했다.
- 기존 초기 gate 테스트와 위치·보존·지나간 분기·모호한 부분귀속 실패 검사를 포함해28개 통과. pytest의 sandbox 의존성 읽기 실패 후 기존 의존성을 승인된 로컬 읽기로 실행했다. 설치 없음.
- 후보 두 상태 모두 실제 첫150초 green/offset/VSL/RM 명령을 유지했다.450초 전체는 이후 명령 유지 예측이므로 실제 이후 정책의450초 검증으로 과장하지 않는다.
- 8램프 보존식,초기 물리 상태,새 차량 demand/여행시간,이동용량·서비스 설정 불변 확인. 미래 관측은 사후 채점에만 사용했다.
- 계산은 기본32.41초,2250후보32.67초,3600후보29.14초. 초기화·분석은 별도다. 추가 VISSIM/FZP 재스캔/현재 CTG 조회/optimizer/계수 fit/push는0회.
- 독립seed와 RM/VSL 비용 순위 및 전체 SDMPC AD는 이 timing 후보에서 **아직 검증하지 않았다**. 이전 receiving 후보의seed47 순위 통과를 이번 후보의 검증으로 대체하지 않는다.

다음은 준비된seed47 RM 유지/완화 두 조건에 이 초기화를 적용해,도착·head 개선이 손익 순위도 유지하는지 확인하는 것이다. 그 뒤 혼잡 상태에서 남는10490 posthead 과소재고를 실제 차로 수용·혼잡 지속과 연결해 검토한다. head 곡선을 다시 낮춰 상쇄시키거나 도착량을 임의 보정하지 않는다. 현재 두 후보는 정본/9000에 자동 적용하지 않는다.
