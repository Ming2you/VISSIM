# 10484 합류 오차의 출처: 도착 시점과 물리 이동속도

완료된 seed29 SDMPC9000의 손실 시작 구간을 진단했다. 이전 목표 턴과 이번 턴은 모두 progress이며, 전체 이득 예측 목표는 **ACTIVE / NOT_QUALIFIED**다. 이번에는 새 coupled forecast나 VISSIM을 실행하지 않고 저장된 모델 경로와 관측을 재사용했다. 실시간 CTG는 조회·변경하지 않았다.

## 완료9000의 손실 위치와 이 진단의 범위

전체 결과는 `../../loss_diagnosis/README.md`를 재사용한다. Ω TTT는 무제어7263.267→SDMPC7589.973대·시간, **+326.706(+4.498%)**였다. 동측 본선에서+401.888대·시간이 발생했다. 동측 추가 재고는1800초부터 드러났고, 누적 전체 이득은2265.1초에 가장 컸다가3325.1초에 손해로 돌아섰다. 뒤쪽 램프군 상류 셀18→16→9→6→4로 저속 영역이 확대됐다(31셀,0기준).

2250–3300초에는10484의 실제 합류 재구성값이NC161→제어236대인 동시에,10481분기 이후 본선 통과는1907→1630대로 줄었다. 도시 신호·VSL·차량 이력이 함께 달라져 두 차이를 단독 인과관계로 해석하지 않는다. 이 진단은 **그 상태에서 plant가10484 도착·head·합류를 어떻게 잘못 예측하는지**를 좁히는 작업이며,9000초 손실 전체를 한 램프 문제로 설명하는 보고서가 아니다.

## 1. 합류 과대는 주로 신호등 전 단계에서 전달됐다

기존 `city_path/2250_svc`, `3600_svc`의450초 trace를 사용했다. 이 모델은 앞선 관측속도·head 차로/서비스 진단 수정이 포함된 후보이며, 원래9000초 런의 동결 모델과 동일하지 않다. 첫150초만 실제 실행 명령이 모두 같은 비교다. 이후300초는 held-command 모델 trace의 내부 검증이며 실제 후속 명령과 같다고 주장하지 않는다.

실제 합류는 `초기 재고+도착−종료 재고` 및 `초기 posthead+head 통과−종료 posthead`의 동일한 보존식 재구성값이다. 직접 합류 검지값은 아니다. 기존 삭제 기록 검증에서 이 램프의 삭제는 없었다.

2250초의 합류 오차10.935대는 head 오차11.093대에서 종료 posthead 오차0.158대를 뺀 값이다. 모델의 종료 head-ready queue는0이고, 신호등 전2.232대는 이동 중 차량이다. **종료 시점 순차이를 크게 만드는 것은 head 이전의 차량 통과 시점**이다. 이 계산만으로 posthead의 순간 속도·수용·차로 접근이 정확하다고 판정하지 않는다.

기존 물리 램프 버퍼를 같은 예측 도착·head 서비스·수용 예산으로 다시 계산해 두 상태 각각450초의 시작재고·head 통과·합류·eligible·보존·종료재고를 전부1e-8 이내로 일치시켰다. 이는 저장된 계산의 귀속 검증이며 새로운 독립 예측 성공이 아니다.

램프 내 기존 이동시간32.355초를 기준으로 head에 도달할 만큼 오래된 도착을 회계적으로 세면, 모델27.093대/실제18대다. 실제 새 도착 중 head를 통과한 것은16대다. 초기 prehead13대는 양쪽 모두 통과했다. 따라서 head 오차11.093대는 `도착 시점·양의 차이9.093 + 실제 나이 조건 충족18대 중 아직 통과하지 않은2대`로 정확히 분해된다. **고정 이동시간 한 개에 대한 사후 회계**이지, 실제18대 모두 반드시 방출 가능했다는 물리 증명이나 서비스 상한 보정은 아니다.

3600초에서는 모델 head−5.178대, 합류−5.358대로 부호가 반대다. 이 경우에도 도착 시점별 대수 부족이 head 오차와 일치한다. 합류 상한을 전 상태에서 낮추는 처방은 지지되지 않는다.

## 3. 상류 경로의 속도 용도 혼용을 확인했다

기존 `_apply_lane_delay_correction`는 전 차로 여유대수로 계산하는 가상의 종방향 거리를 보정하기 위해 관측속도에 유효 차로 수를 곱한다. 코드 설명도 이 값을 **관측 물리속도가 아닌 유효속도**라고 정의한다. 기존 vendor 지연식에는 이 보정이 필요하다.

그런데 `route_choice_corridor.direct_exit_movement_receive`는 실제 connector 길이와1137 분기 위치로 거리를 계산하면서 같은 `state.urban_link_speed_kph[origin]`을 그대로 사용한다. 실제 거리에는 이미 차로 수가 곱해져 있지 않으므로 이 경로에서는 이동시간이 그 배수만큼 줄어든다.

|2250 현재 진단 후보의 경로|실제 경로 길이[m]|보정 전 속도[km/h]|유효 차로 수|현재 지연[s]|보정 전 속도를 쓴 산술 시간[s]|
|---|---:|---:|---:|---:|---:|
|29 직진→31→10484|540.68|40.78|3.411|14|47.73|
|37 우회전→31→10484|470.93|27.88|2.693|23|60.81|
|40 좌회전→31→10484|497.49|27.63|3.877|17|64.81|

29의40.78km/h가139.10km/h로 들어간 것이14초의 직접적인 계산 근거다. 같은 창에서 실제 head→10484 입구를 통과한 차량 코호트의 시간은29 출발9대가46.30–64.32초,40 출발3대가45.52–47.67초였다. detector는29/40의 native head와10484의1m 위치이며, 모델 경로에는 head 이후 접근 링크의 수m가 생략돼 있으므로 완전히 같은 두 평면이라고도 주장하지 않는다. 그 수m 차이는 수십 초의 차로 배율을 설명하지 않는다.

보정 전 속도로 바꿔 계산한 마지막 열은 **산술 진단**이다. 실제 관측 미래 시간으로 맞춘 값이 아니며, coupled rollout을 다시 수행하지 않았다. 40번은64.81초로 실제 조건부 코호트보다 길어지므로 단순히 배율을 제거하면 모든 경로가 맞는다는 결론도 불가하다. 정지선 전 origin 속도가 정지선 이후 가속 구간을 대표하는지도 별도 문제다. 작은 종료창 안에 도착한 코호트만 포함하므로 긴 이동시간은 우측 절단된다.

이 속도 혼용은 기존 거리 보정 방식과 이후 물리 경로 계산의 계약 충돌이다. 도시 관측속도 집계 버그와는 별개다. 관측속도 집계를 올바르게 고친 뒤 물리 경로에서 시간 과소가 더 커질 수 있는 이유를 설명한다. **139.10 및14초는 현재 진단 후보의 값이며 원래 동결9000의 수치로 인용하면 안 된다.**

## 4. 초기 목적지의 확률적 차이도 분리했다

SC1001 출처를 초기 차량과 세 유입 movement별로 복원했다. 기존 `direct_exit_requests/commit`의 목적지별 비례 인출을 재현해 두 상태450초 전체 request와 accepted를1e-8 이내로 일치시켰다. 이 계산도 이미 저장된 모델 입력을 이용한 회계다.

2250초 모델의 초기31번 차량 중10484 기대 할당은6.5대이고, 실제 해당 초기 차량이10484에 진입한 것은4대다. 미래 차량 목적지는 아직 관측되지 않은 native 정적경로 비율에 따른 기대값이다. 이2.5대 차이를 모두 모델 버그 또는 제어 효과로 보정하면 안 된다.2280–2310초의 모델 도착9.424대에는40번 방출분5.6대,SC2001 경유2.963대 등이 들어간다. 경로별 시간·방출량을 함께 확인해야 한다.

124번에 이미 내려간 차량과10483 direct 차량이10484를 다시 선택한다는 이전 가설은 여전히 기각 상태다(`../routing_correction/REJECTED.md`). 기존 경로 태그·도달 가능 목적지 계산을 유지했고, 초기10698 connector 차량도 원래의 남은 거리를 보존해 처리했다.

## 다음 작업과 채택 기준

1. 기존 유효속도와 물리 경로용 속도의 계약을 분리한다. 기존 vendor의 대수 기반 지연을 전역으로 되돌리지 않고, 실제 미터 단위 거리 경로에 차로 배율을 이중 적용하지 않도록 제한적으로 수정한다.
2. 동일2250/3600 상태에서 현재 후보와 수정 후보를 각1회 비교한다. 먼저 두 경로의 도착 시간대·head·merge·pre/post 재고가 맞는지 확인한다. 한 상태에서 오류 부호가 바뀌었으므로2250 하나만 개선했다고 채택하지 않는다.
3. 효과가 확인되면 이미 완료된 다른 상태/seed 및 의미 있는 RM 유지/완화 쌍을 재사용해 ΔTTT·실제 합류·램프/도시 비용·후보 순위를 확인한다. 외부 비용은 진단으로, Ω TTT 목적함수는 유지한다.
4. 전체9000 손실의 VSL·도시 신호·RM 기여는 아직 분리되지 않았다. 이번 발견을 전체 손실 원인 확정이나 SDMPC 선택 성공으로 대체하지 않는다.

이번 턴에서 정본 소스·설정·망·목적함수·제약은 변경하지 않았다. 후보는 채택하지 않았고 새 계수 탐색, FZP 재스캔, 새 native, live poll, push는0이다.
