# 10490 posthead 수용·점유 진단

2026-10-01. **혼잡 때의 posthead 과소재고는 도착·head 시각 오류만으로 설명되지 않는다.** 실제 head 통과를 그대로 넣어도 저장된 예측 수용 예산은 너무 빨리 합류시킨다. 교통량이나 단일 검지점 점유율에 계수를 붙이는 것만으로 해결된다는 근거도 없다.

완료된 seed29 SDMPC9000의2250–2400초와3600–3750초, MER chunk6개와 저장 상태·차량 frame·기존 예측 trace만 재사용했다. 새 VISSIM/FZP재스캔/현재 런 조회/완전한 plant rollout/계수 fit/push는0회다. 제어 코드·설정·STOP은 바꾸지 않았다.

## 실제 head를 넣어도 혼잡 때 대기가 너무 빨리 사라진다

위치 timing+origin receiving 후보의 저장된1초 수용 예산과 기존 posthead 자유 이동시간5.97875초를 고정했다. 예측 head 입력으로 원래 trace의 합류·잔여 재고가 정확히 재현되는지 먼저 확인했다. 이후 **미래 실제 head만 대입한 조건부 회계 진단**을 했다. 바뀐 합류를 본선 상태에 다시 전파하지 않았으므로 자율 예측이나 제어 효과 검증이 아니다.

|10490 [대]|혼잡2250–2400|회복3600–3750|
|---|---:|---:|
|초기 posthead 재고|9|3|
|실제 head 통과|38|30|
|실제 합류: 보존식 재구성|37|32|
|실제 종료 posthead|10|1|
|저장된 자율 예측 합류 / posthead|43.404 / 1.400|30.424 / 1.114|
|실제 head + 저장 수용 예산: 합류 / posthead|44.704 / 2.296|32.000 / 1.000|
|실제 head + 검지점 빈 시간 기회: 합류 / posthead|42 / 5|32 / 1|

혼잡 상태의 합류7.704대 과대·posthead7.704대 과소는 실제 head 시각으로도 남았다. 회복 상태에서는 합류32대·잔여1대가 맞는다. head 시각을 다음 정수초로 올림해도 두 결과는 같아1초 위상으로 설명되지 않는다.

이는 **고정 이동시간+예측 receiving 조합이 혼잡 때 합류 지연을 충분히 만들지 못한다**는 제한된 증거다. 이동시간·수용·본선 상태 오차 중 독립 원인을 확정한 것은 아니다. 실제 합류는 head 통과 + 초기 posthead − 종료 posthead이며 이전 삭제·보존 검증을 재사용했다.

## 적은 통과량이 많은 합류 공간을 뜻하지 않는다

10490은119번1차로395.105427m에 합류한다. through10483 검지기960238은 같은 차로393.698300m, 합류점 **1.407127m 앞**이다. 동일 단면2·3차로도 집계했다.

Poisson 행은 기존 tc=tf=1.5초 식에 **실제 해당 차로 교통량만** 대입한 진단이다. 실제 수용량이나 저장된 plant의 실효 예산이 아니다. 빈 구간 계산은 구간 시작1.5초 이후 첫 기회, 이후1.5초 간격이며 평가창 밖의 시간을 포함하지 않는다. 저속 혼잡의 낮은 통과량은 Poisson 식에서 오히려 많은 기회를 만든다. 실제 점유를 반영하면 방향이 바뀌지만 그대로 receiving 식에 채택할 근거는 부족하다.

## 이 검지기는 합류 차량 차체를 놓치는 사례가 있다

최초 MER 점유 ID와 현재 차량 frame의 차체 중첩 ID를 비교하는 검사는 **실패**했다. 코드·원인은 `attempt1_source.py`, `attempt1_failure.json`에 보존했다.

차량30735는10490 head를3590.41초에 지났다.3600초119 1차로에서 차체 앞397.489975m / 뒤393.278975m, 속도1.093km/h였다. 차체 뒤가393.698300m 검지점을 덮지만 차량 앞은 검지점 하류의 합류점으로 들어와 이 검지기의 entry/exit 기록이 없다.

따라서 계산한 빈 시간은 **기록된 본선 통과 차량 사이의 빈 시간**이다. 합류 차량 차체, 하류 저장 공간, 상대속도, 양보·차로 변경까지 고려한 실제 사용 가능한 틈이 아니다. 한 frame을 연장해 누락 점유시간을 임의 복원하지 않았다. 경계 예외1개를 명시적으로 분류했다.

이 빈 시간 기회와 실제 head를 쓴 조건부 검사도 혼잡 종료 재고5대로 실제10대를 놓쳤다. 이를 자율 예측 개선이나 용량 보정 성공으로 판정하지 않는다.

## 판단과 검증 범위

도착·head만 고쳐 해결됐다고 보면 안 된다. 다음에는 현재 차로 상태·하류 공간·본선과 램프가 같은 공간을 사용하는 관계가 수용 계산에서 누락되는지 확인해야 한다. 교통량 단독 gap 식이나 측정 점유율 하나를 바로 붙이는 후보는 채택하지 않는다. 향후 자율 검증에서는 현재 관측/예측 상태만 사용하고 RM 유지·완화의 실제 방출, 전체 대기 비용, Ω 손익 순위를 함께 확인해야 한다.

10490 국소 오차를9000 손실 전체의 원인으로 일반화하지 않는다. [이전9000 보고서](../../loss_diagnosis/README.md)의 손실 시작·전파 진단을 유지한다.

`verification.json`:28개 입력 hash 불변,6개 검지 계수·누적계수 일치, 기록 점유 구간 entry/exit 짝·비중첩, 명시적 경계 예외1개, 기존 trace 재현·조건부 보존 확인. `lane_point_summary.csv`, `point_entry_exit_pairs.csv`에 근거를 남겼다. 현재 후보는 여전히 정본 미채택, 전체 이득 **NOT_QUALIFIED**다.
