# 10490 합류 수용 상한: 이전9000 손실 후속 진단

후속 주의: [초기 위치 timing 검사](../head10490_timing/README.md)에서 도착/head 과대예측을 줄이자2250초 posthead 예측이9.175→1.400대(실측10)로 바뀌었다. 아래 receiving 후보의 queue 개선 일부는 과다한 head 유입과의 상쇄였다. 이 문서만으로 수용 동역학 검증 완료로 해석하지 않는다.

2026-10-01. **혼잡 상태의 합류 과대예측 일부를 줄인 후보이며, 정본 채택·전체 이득 보정 완료가 아니다.** 완료 자료와 고정 명령 오프라인450초 예측5회만 사용했다. 현재 CTG 런은 조회하지 않았고 새 VISSIM·FZP 재스캔·계수 탐색·optimizer·push는 없다.

## 이전9000에서 손실이 시작된 곳

[원래 손실 보고서](../../loss_diagnosis/README.md)의 결과는 유지한다. 동측 본선 추가 재고는1800초부터 드러났고, Ω 누적 TTT는2265.1초 최대이득−21.3694대·시간 이후3325.1초 손해로 바뀌었다. 최종Ω 손해+326.706대·시간(+4.498%) 중 동측 본선+401.888, 나머지Ω−85.375가 핵심이다. RM은54결정 모두 완전개방이었다.

2250–3300 실제10484합류는NC161→SDMPC236대, 뒤쪽 분기 이후 본선 통과는1907→1630대였다. 도시 신호·VSL 이력도 달라서 이를 단일 원인의 인과 효과로 해석하지 않는다. 이번10490 검토는 **모델의 수용·대기 예측 오류를 분리하는 후속 작업**이다.10490이 원래9000 손실 전체의 원인이라는 뜻이 아니다.

## 확인한 수식과 제한된 변경

기존 canonical 공급은 현재 예측 합류 셀 밀도로

`f = clip((rho_jam-rho)/(rho_jam-rho_crit),0,1)`

`min(램프용량, 본선전체용량×f, 기타제약)`

를 사용한다. 이후 물리 램프 runtime이 gap 기회·합류 가능 재고·실제 head 방출을 교차 제한한다. 본선 전체 용량이 큰 경우 밀도가 올라가도 램프용량보다 높은 공급이 남아 밀도 제한이 약할 수 있다.

Hegyi 학위논문의 origin 수용식은 origin 용량을 밀도계수에 곱한다([공식 원문, 식3.6](https://web.dcsc.tudelft.nl/~bdeschutter/research/phd_theses/phd_hegyi_2004.pdf)). 이를 근거로10490에만 `램프용량×f`를 추가 상한으로 시험했다. 기존1800대/h, 현재 predicted density와 effective rho_crit를 그대로 썼다. 새로운 배율을 적합하지 않았다. 기존 incident/본선/gap/차로 공급 제약은 계속 교차 적용한다.

- 정본 vendor는 수정하지 않았다. 공유 함수는 `physical_ramp_boundary.py`에 두고 기존 coupled runtime과 component harness가 함께 호출한다.
- receiving-node에 명시된 `density_supply: origin_capacity`일 때만 적용한다. 기본 설정은 그대로이며, 기존2250초 예측의 명령·모든 상태·비용·전체 ledger가 **정확히 일치**했다.
- 변경한 것은 candidate의 reference_config와 그 manifest pin이다. production tuning, 망·수요·신호·VSL·RM 서비스곡선·여행시간·목적함수·STOP은 바꾸지 않았다.
- 차로 평균 밀도를 사용한다. 별도의 동적 차로 수용/공유 모델을 검증한 결과는 아니다.10490의 상류 진입 차로와 평균 밀도의 차이는 이전8램프 보고서에 남아 있다.

과거10484의 단순lane1 gap/잔여용량 후보가 실패한 기록과, origin scale이 실제 상태 조건부 검사에서 비구속이었던 기록을 재사용했다. 그 접근을 새로 반복하거나10484에 이번 후보를 확대하지 않았다.

## 검증·남은 작업

- 고정 예측 총5회: 기본 일치1,혼잡 후보1,회복 후보1,독립seed47 두 조건2. 계산 약169.08초(초기화/보고서 제외). 세 exec 세션과 마지막 독립 세션 모두 종료코드0.
- receiving 식의 자유류/혼잡/밀도상한 밖/잘못된 입력 검사, forward/reverse AD와 수치미분 일치. **전체 SDMPC237축 AD 검증은 수행하지 않았다.**
- 기존 portable ramp 보존·순서 테스트7개 통과.8번째 과거 실제기하 fixture는 로컬 `port_profile.json` 부재로 실행 실패했으며 PASS로 세지 않는다. 대신 본작업 실제 초기cohort/8램프 ledger 보존과 기본 전체trace 일치를 별도로 검증했다.
- reverse AD 첫 시도는 누락된 의존경로, 다음은 sandbox 읽기 제한으로 실패했다. 기존 pinned dependency에 대한 승인된 로컬 읽기로 통과했다. 설치·ACL 변경 없음.
- production 기준과 STOP의 SHA는 보존한다. 계수 적합/새 native/VSL후보/자동 선택은0회다.

다음 우선순위는10490에 새 배율을 더 주는 것이 아니라, 남은 **도착→head 통과 과대예측**의 발생 시각과 서비스 이용을 분리하는 것이다.10482/10681의 다른 head/대기 오차를 같은 receiving 문제로 묶지 않는다. 이후 실제 손실과 더 가까운10484 유입 및 본선 방출·상류 재고 오차와 연결하고, 동일 초기상태의 명령 순위를 확인해야 한다. 현재 후보는 실험 설정에만 남기며9000·정본에 자동 적용하지 않는다.
