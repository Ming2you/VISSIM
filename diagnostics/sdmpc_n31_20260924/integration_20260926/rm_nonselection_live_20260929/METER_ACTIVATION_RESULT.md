# RM 유한 단계 연결: 실제 한 주기 검증

2026-09-29. **탐색 연결은 동작하지만 이번3600초 상태의 최종 명령은 바뀌지 않았다.** 물리적 RM 이득 보정이나 운용 기본값 채택을 의미하지 않는다.

## 무엇을 바꿨나

기존 `sdmpc.py`, `sdmpc_sequence.py`에 기본 비활성인 `adapter.sdmpc_meter_activation_secant`만 추가했다. 완전 개방에서 비용과 두 자원 미분이 모두0인 RM 축은 기존 유한차분 후보를 계산한다. 시퀀스의 실제 직전/다음 명령 변경 제한, 기존 비용·제약·최종 writer 검사는 유지한다. 서비스표·수용량·목적함수·지평·수요는 바꾸지 않았다.

실제 기록의 RM 유한차분 설정은**2초**였다. 앞선 `rm_activation_stencil_probe.json`은1초 설정의 합성 재현이며 실제 설정값의 증거로 사용할 수 없다. AD의 g9→g10 서비스표 기울기가0이라는 진단은 그대로지만, 기존2초 후보 생성기는 호출되면 g8을 만들 수 있다. 최종 수정에서는 임시로 넣었던 ‘가장 먼 끝점’ 규칙을 제거하고 기존 후보 생성기를 재사용했다. 실제 측정44개 끝점이 최종 코드에서도 동일함을 재검사했다.

동측에서 수치 잡음 이상 반응은10490의 첫 블록g10→g8이었다. 각 탐색 초기 명령 대비 Ω 비용이0.007876/0.008258대·시간 감소했고 N_UF는0.5161/0.5275대/h 감소했다(450초 합류량 약0.065대 감소). 이들은 원래 유지 명령이나 실제 무제어 대비 이득이 아니다. 다른 동측 RM 후보의 이 비교에서의 반응은 수치 정밀도 수준이었다. 따라서 g9/g10 평탄 구간을 넘기는 것만으로 큰 RM 반응이 생기지는 않았다.

현재 연결은 secant를 QP에 공급하며 모든 유한 끝점을 독립적인 최종 후보로 강제 수락하는 방식은 아니다. 그러므로 전수 이웃 최적성이나 ‘유리한 RM 조합이 전혀 없음’을 증명하지 않는다. 다음에는 원래 유지 명령 기준의 최소 후보를 우선 사용하고, 실제 합류가 변하지 않는 반복의 비싼 재평가는 줄여야 한다. 이번44회 추가 평가가 선택을 개선하지 않았으므로 운용 기본값에는 켜지 않았다.

## 검증·실패 보존

- RM/VSL 단위 검사8개 통과. 기존 순차 명령/상한 검사27개+24 subtests 통과. 별도5개 SavedCoordinateTests는 존재하지 않는 다른 컴퓨터의 TRLAB 망 경로 때문에 초기화 실패했으며 통과로 세지 않았다.
- 최초 오프라인 시도는 정책 해시가 달라 기존 가격 검사에서 중단됐다. 실패 폴더와 로그를 보존했다. 후속의 `--meter-activation-ablation`은 원래 정책 전체 해시/적용 CSV 영수증을 검증하고 그 가격을 유지한다. production `load_prices` 검사를 약화하거나 기존 action/영수증을 수정하지 않았다.
- 샌드박스의 pytest 파일 접근 제한도 별도 최초 로그에 남아 있다. 같은 기존 라이브러리로 실행 권한 범위를 바꿔 검사를 완료했으며 패키지 설치는 하지 않았다.
- `meter_activation_comparison.json`, `summarize_meter_activation.py`, `config_meter_activation.json`, `meter_activation_protocol.json`과 원래/새 정책 해시로 재현할 수 있다. 최종 간소화 후에는44개 끝점 일치와8개 회귀 검사를 다시 확인했고, 동일 후보의 비싼 전체 최적화를 중복 실행하지 않았다.
