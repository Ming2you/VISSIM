# 사용자 중단 후 공통8100초 검증

**현재 SDMPC는 무제어 대비 개선되지 않았다.** Ω TTT는 +0.7781%, 망에
삽입된 차량의 전체 체류시간은 +300.0159대·시간이다.9000초 완주나 이득
보정 완료로 선언하지 않는다. 추가 native 실행·재보정·push는 하지 않았다.

사용자 요청에 따라8400초 관측 지점에서 소유 runner와 계산 자식을 종료했다.
VISSIM에는 먼저 정상 창 닫기를 요청했고, 남아 있던 동일 생성시각의 PID만
강제 종료했다. 모든 소유 PID 종료를 확인했다. 이 종료 처리 후 일부 native
LDP/ERR의 마지막 버퍼가 잘린 사실을 확인했다. 원본은 보존하고 모든 대상의
신호 기록이 완전한0–8100초를 공통 분석 구간으로 사용했다.
STOP 파일과 중단 이력을 유지하며 원래9000 자동 후처리를 재개하지 않는다.

## 실제 교통 결과

동일 seed29·네트워크·수요·기준 설정이다. 제어 전431,233개 FZP 데이터 행이
정확히 일치한다(SHA f1a0b040b711e5974615873f334d28395e7aa037de356caeda101fafcc8fbcda).
5초 FZP 기록을 적분했으며 마지막8095.1–8100초는 마지막 재고를 유지하여
체류시간만 보간했다. 이 구간에 유출 사건을 만들어 넣지 않았다.

TTD는 실제 안→밖 관측과 물리적 말단 도달 가능성을 검사한 소실 추론의 합이다.
내부 이동·종료 잔여·명시적 삭제와 원인 미확정 소실은 TTD에 더하지 않았다.
5초 사이 모든 경계 통과가 포착됐다는 의미는 아니다. 미삽입 대기 적분과
최종 native 완료 카운터는 중단으로 수집되지 않아 **미측정**이다.0으로 대체하거나
무제어9000초 값을8100초 결과에 섞지 않았다.

앞서 보고한7800초 +1.70%는150초 관측 사다리꼴 근사였다. 같은7800초까지
5초 FZP로 다시 적분하면 무제어6581.7170, SDMPC6624.5458대·시간으로
**+0.6507%**다.150초 샘플링 근사가 상대 차이를 과대평가했다. 신호주기와
관측 시점의 정렬이 원인일 가능성은 있으나 이를 따로 입증하지는 않았다.
8100초 +0.7781%와 혼동하지 않는다. 원래 잠정치도 삭제하지 않았다.

## 실행과 손실 위치

완전한 prefix 원본 바이트만 잘라 기존 명령 시계·readback·LDP 검사기에
입력했다. 정상 완료 로그를 합성하지 않았고 원본 파일도 수정하지 않았다.
NC의 미터8SG, SDMPC의 도시+미터144SG 및 각264개 VSL 차종 주소를 검증했다.
해당 구간의 실제 신호 상태와 VSL 적용 readback이 명령과 일치했다.
LSA의 COM 기록 문제를 성공으로 바꾸지 않았다.

- 적용된48개 제어 결정에서8개 RM은 모두 g10으로 유지됐다.
- VSL은22개 결정에서 동측S13 또는S5/S7에100km/h를 적용했고 그 외에는110을 유지했다.
- 48개 모두 기록된 N_P/N_UF 공유 수량 제약을 만족했다. 이것은 물리 예측 검증이 아니다.
- 기존 짧은 반복 예산에서 수렴을 확인한 결정은0개다. 이 사실만으로 성능 악화 원인을 탐색으로 확정할 수 없다.
- 동측 미터의 기록된 국소 비용·자원 미분은 모든 결정에서0이었다. 유한한 g10→g8 변경도 효과가 없다는 증거는 아니다.

TTT 차이를 위치로 분해하면 동측 본선 **+131.8083대·시간(+6.2041%)**,
서측 본선 +10.9773, 나머지 Ω 내부 −90.2294, Ω 밖 +247.4598이다.
Ω 내부 일부 비용 감소가 본선과 외부 체류 증가를 상쇄하지 못했다.
동측 히트맵에서도 중후반 상류 방향으로 더 넓은 저속 구간이 보인다.
이는 신호·VSL을 함께 바꾼 폐루프 비교이므로 VSL 단독 원인으로 단정하지 않는다.

다음 진단은 새9000초 런이나 광범위한 계수 탐색보다 두 가지를 우선한다.
첫째, 저장된 혼잡 상태에서 나머지 명령을 고정하고 합법적인 g10→g8의
실제 합류 변화와 전체 대기 포함 비용을 따로 검사하여 국소 미분0과 유한
변경 효과를 구분한다. 둘째, 도시 신호가 줄인 Ω 내부 비용과 늘어난 외부
대기를 동일 후보·초기 상태에서 대조한다. 현재 자료만으로 어느 레버가
손실을 일으켰는지 또는 최적화 반복을 늘리면 해결되는지 확정하지 않는다.

- 상위 `user_stop_receipt.json`, `user_stop_owned_tree.json`: 중단·소유 프로세스 근거.
- 상위 `analyze_stopped.py`: 기존 검증·집계 함수 재사용. 최초 분포 키 표기,
  부분 구간 입력 필터, 로그 인코딩 오류와 그림 의존성 권한 실패 로그는 보존했다.
  완료된 검증·NC 집계는 재사용했고 계수나 실행 코드는 변경하지 않았다.
