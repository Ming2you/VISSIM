# 중단된 SDMPC 런: 목적함수 유지·기록 기반 진단

2026-09-28. 사용자 결정: **Ω 내부 TTT 목적함수 유지, 외부 비용은 진단에만 사용.** 목적함수·외부 비용 제약·계수·수요·controller를 변경하지 않았다. 새 VISSIM 런과 최적화 반복은 없다. 원래 런의 STOP을 유지한다.

## 판단

현재 증거는 “외부 비용을 목적함수에 넣으면 해결된다”는 결론을 지지하지 않는다. Ω 내부에서도 실제 성능 개선에 실패했다. 우선 구분할 문제는 **램프별 도착 배분·합류와 본선 회복의 예측 오차**, 그리고 **작은 예측 차이의 실제 선택 유효성**이다.

완전 검증 구간 0–8100초의 Ω TTT는 NC 6,754.400 → SDMPC 6,806.956대·시간(+52.556, **+0.7781%**)이다. 동측 본선은 +131.808대·시간(+6.2041%), 기타 Ω 내부는 −90.229대·시간이다. 이는 도시 신호와 VSL을 함께 바꾼 정책 간 결과이며 개별 lever의 인과 효과가 아니다. 외부 삽입 차량 체류 +247.460대·시간은 별도 진단이고, 미삽입 대기는 측정되지 않았다. [기존 실행·집계 검증](stopped_prefix8100/README.md).

## 1. 선택 계산과 실제 명령을 사용하는 모델의 비용 방향

현재 SDMPC 런의 4500·6000초 저장 상태에서 이전 실제 명령 유지와 기록된 선택 명령의 **계획된 3×150초 시퀀스**를 비교했다. 과거 head·VSL 이력은 복원했고 미래 관측을 예측 입력에 넣지 않았다.

선택−유지, 단위 대·시간:

|초기 시각|SDMPC 연속 근사 Ω TTT|실행 명령 모델 Ω TTT|추적 외부 체류 변화|Ω+추적 외부 변화|
|---|---:|---:|---:|---:|
|4500초|−2.0942|−2.2176|+2.5002|+0.2826|
|6000초|−1.1182|−1.0757|+0.9790|−0.0967|

두 계산 경로는 Ω 이득의 부호와 크기가 비슷하다. 이 두 상태에서 근사 계산만 이득으로 보고 실행 명령 모델은 손해로 보는 현상은 확인되지 않았다. **두 시퀀스 모두 유지 대비 RM·VSL은 세 블록에서 같고, green·offset만 다르다.** 따라서 위 숫자는 RM/VSL의 추가 이득이 아니다.

450초 시퀀스의 첫 150초만 적용된 뒤 재최적화되었으므로 이 표를 실제 450초 이득으로 취급하지 않는다. 시간이 진행된 NC와 SDMPC는 초기 상태도 다르므로 이 표와 정책 간 실제 차이를 직접 인과 비교하지 않는다. 외부 비용을 합치면 4500초의 부호가 바뀌지만, 사용자 결정에 따라 선택 기준 변경의 근거로 쓰지 않는다.

## 2. 실제 적용 명령으로 다음 150초를 예측한 결과

예측 완료 후에만 다음 관측을 열어 검증했다. 실제 적용된 joint 명령, 현재 상태, 과거 head·VSL 이력을 사용한 **명령 조건부 반응 검증**이며, 동일 초기 상태의 무제어 반사실 비교는 아니다.

|4500–4650초|151.2952|152.9226|+1.6274|

주요 동측 램프에서 서로 다른 오차가 보인다. 아래는 실제/예측 차량 수다.

## 3. 동측 회복 오판을 경계 유량으로 분해

6000초 동측 본선 재고는 1,102대다. 6150초 실제는 **1,069대(−33)**, 모델은 **1,109.81대(+7.81)**다. 실제 재고가 감소하는 구간에서 모델은 증가를 예측한다. 같은 공간 경계에서 아래 보존식이 관측·예측 모두 닫힌다.

`종료−초기 = 본선 입구 유입 + 램프 합류 − off-ramp 진출 − 본선 말단 방출 − 삭제`

|6000–6150초 동측|관측|예측|종료 재고 오차 기여|
|---|---:|---:|---:|
|본선 입구 유입|291|304.00|+13.00|
|4개 램프 합류|81|87.45|+6.45|
|4개 off-ramp 진출|138|137.45|+0.55|
|본선 말단 방출|267|246.19|+20.81|
|본선 삭제|0|0|0|
|합계|||**+40.81대**|

이 구간의 회복 오차는 off-ramp 진출 총량보다 **말단 방출 과소예측과 본선 유입 과대예측**이 크다. 이는 장부 분해이며, 말단 물리 capacity 자체가 원인이라는 증명은 아니다. 상류 전달·속도·수송 시간·예측 유입 차이도 말단 방출에 영향을 준다. 과거 150초 유입을 미래로 연장한 오차를 미래 실측값으로 바꿔 넣어 해결됐다고 할 수 없다.

4500–4650초 동측 재고는 실제 +40대, 예측 +52.14대다. 오차 +12.14대는 본선 유입 −5.00, 합류 +8.67, 진출 +5.16, 말단 +3.31대로 분해된다. 두 상태만으로 전체 혼잡·회복 구간의 보편적 오차를 단정하지 않는다.

진단 구현에서 `density × 고정 lane-km`를 차량 수로 환산하자 저장된 보존 재고와 불일치해 검사가 중단됐다. 이 trace에는 동적 유효 차로 수가 없으므로 그 환산을 버리고 **보존 장부의 본선 총 재고**를 사용했다. 셀별 예측 속도·재고 오차를 새로 검증했다고 주장하지 않는다. 최초 집계 JSON과 후속 경계 분해 JSON을 모두 보존했다.

## 4. RM 미선택: 확인한 것과 남은 것

실제 48회 결정에서 8RM 모두 g10이었다. 동측 미터의 비용·자원 미분도 모두 0이었다. 그러나 SDMPC는 녹색을 정수로 반올림해 미분하는 구조가 아니다. `sdmpc_continuous.meter_rate`가 측정 service 표를 연속 보간하고, 예측 근사에서는 연속 서비스 상한을 사용한다. 실제 실행 모델은 RED/GREEN 시간을 적용한다. 따라서 “정수 미분 때문에 무조건 0”이라는 설명은 근거가 없다.

4500초 상태에서 각 동측 램프만 **8/8/8 또는 8/6/4초 녹색**으로 바꾼 기존 8개 유한 비교도 확인했다. green/offset/VSL은 유지했으며 각 블록의 writer·±2초 변경 제한과 재고 보존은 통과했다. 가장 큰 Ω TTT 변화의 절댓값도 **0.00323대·시간**이었다. 큰 예측 이득을 가진 미터 후보를 국소 미분이 놓쳤다는 증거는 이 상태에서 나오지 않았다.

이 유한 비교는 NP/NUF 제약까지 판정한 feasible 후보 탐색이 아니다. 그 이전 물리 효과가 작았다는 진단이다. 또한 다른 시각·다중 미터 조합·강한 제한·VISSIM의 RM 효과까지 무효라는 결론도 아니다. 과거 seed53 강한 미터 해제에서 개선된 손해 방향 검증과 현재 g10 근방 민감도를 구분해야 한다.

근거: `../closedloop_recorded4500_lever450_stop_rm4/summary.json`, `comparison.json`.

## 다음 판단 순서

1. 목적함수는 유지한다. 외부 체류·삭제·미삽입은 별도 품질·영향 진단으로 남긴다.
2. 우선 10490 도착 과대예측과 10681의 head 통과 이후 합류·재고를 구분한다. 본선은 말단 방출·회복과 유입 예측을 구분한다. 일괄적인 merge/anticipation 증대의 근거는 아직 없다.
3. 지금 확인한 것은 실제 명령의 절대 반응이다. 모델의 **후보 순위 오판**을 확인하려면 동일 초기 상태의 후보별 native 결과가 필요하다. 현재 저장 자료만으로 없는 반사실을 만들지 않는다.
4. 최적화 반복은 PFO·SDMPC 각 최대 2회였고 수렴은 증명되지 않았다. 다만 이번 두 상태의 선택·실행 모델 부호는 일치하며, 4500초 유한 미터 비교에서도 큰 이득이 없었다. 반복 횟수만 늘리면 해결된다고 단정하지 않는다.

이번 진단에서 새로 실행한 예측은 실제 명령 조건부 150초 2회뿐이다(각 순수 rollout 약 6–7초; 초기화·이력 복원 제외, optimizer 0회). 앞서 완료된 450초 유지/선택 4개 예측 및 미터 비교 9개 예측을 재사용했다. 추가 native·재보정·push 없이 여기서 결과를 정리한다. **이득 보정 완료 상태가 아니다.**

### A. 이미 도시행으로 분기한 초기 차량을 램프행으로 다시 배정

현재 설정에서 `urban.ramp.initial_native_gate_routes`와 `native_gate_travel`은 켜져 있지 않다. 이전 수정안은 900/1050초 다른 상태에서 경로 미확정·소유 재고 문제로 초기화에 실패해 비활성으로 보존된 것이다. 새 문제를 처음 발견했다고 표현하지 않는다. 기존 [초기 목적지 진단](../GATE_ROUTES_AND_ARRIVAL_TIMING.md), [미래 이동 검증 및 실패](../GATE_FUTURE_TRANSPORT.md)를 현재 혼잡 구간에서 재확인했다.

`in_SC1001_W` 저장소에는 32·129번 램프 접근 도로뿐 아니라 분기를 이미 지난 도시행 127번 도로도 섞인다. 10695는 127→38의 신호 이후 connector다. 동일 network SHA의 접속점을 읽어 확인했다. 이 저장소는 현재 목적지 구분 없이 관측 통과율에서 얻은 β로 도시/10482/10490을 다시 나눈다.

|초기 시각|저장소 총 초기 재고|이미 분기를 지난 도시 재고|모델 도시 배정|모델 램프 배정|최소 잘못 재배정된 양|
|---|---:|---:|---:|---:|---:|
|4500초|164|41|24.6|139.4|**16.4**|
|6000초|66|15|9.9|56.1|**5.1**|

이 지평에서 해당 초기 저장소로 추가 유입은 0이고 초기 재고는 전량 배정됐다. 따라서 `max(0, 확실한 도시 초기 재고−모델 도시 배정)`은 초기 차량의 잘못된 **램프 방향 재배정**에 대한 하한이다. 차량 수 보존은 통과하지만 목적지 보존은 맞지 않는다. 이는 10482/10490 합계의 하한으로, 어느 차량 몇 대가 10490에 잘못 배정됐는지까지 식별한 것은 아니다. 현재 저장된 state에는 완전한 `vehicle_routes` 묶음도 없으므로 알려지지 않은 차량의 목적지를 지어내지 않는다.

4500초 10490 도착 예측66.71대는 초기 저장소 출신49.28대+미래 gate 이동 재고 출신17.44대다. 6000초31.42대는 각각16.72대+14.70대다. 초기 목적지 문제와 미래 이동 시간 문제는 별개이며, 위 하한을 전체 도착 오차에서 기계적으로 빼서 보정값으로 사용할 수 없다.

**진단 우선순위:** 이미 지나간 분기는 재선택하지 않는 초기 상태 표현이 먼저다. 현재 위치만으로 확정되는 도시행은 보존할 수 있지만, 나머지는 관측 가능한 경로 정보와 불확실성을 구분해야 한다. β나 METANET merge 계수 조정으로 이 오류를 덮는 것은 적절하지 않다. 이 검토에서는 초기화·설정을 고치거나 실패한 기능을 켜지 않았다.

|본선 합류 합계|37|26.530|
|정지선 이후 재고 변화|−2|+7.775|

정지선 통과 합계는 약0.7대 차이지만 합류는10.47대 적게 예측한다. 관측의 정지선 이후 재고는 `17+35−37=15`로 정확히 닫힌다. 이 구간의 큰 오차를 녹색 출발지연만으로 설명하기 어렵다.

현재 component 설정은10681 gap 수용 모델(`critical_gap=3.5s`, `followup=1.5s`)과 차로별 ramp buffer를 사용한다. mainline lane-group 기능과 ramp 차로 교환은 비활성이다. `LaneResolvedRampBoundary`는 계산된 수용량을 차로 수로 균등 배정하며, 빈 차로의 몫을 대기 차량이 있는 차로로 넘기지 않는다.

현재 예측150초의 합류 수용량 합은46.816대지만 각 차로에23.408대씩이다. 현재 예측 head 통과량과 이 수용량을 고정하면, 이동 지연을 낙관적으로0으로 만들어도:

`합류 상한 ≤ min(23.408, 초기 posthead 0 + head 3.431) + min(23.408, 초기 posthead 17 + head 30.874) = 26.839대`

이는 모델26.530대에 가깝고 실제37대보다10.161대 작다. **주어진 예측 head·수용량·차로 교환 없음이라는 조건에서만 유효한 상한**이다. 전체 제어 공간의 불가능 판정이나 물리적 실제 capacity가 아니다. 지평 중 실제 차로 변경을 이번 자료로 추적하지 않았으며, 주행 차로별 실제 합류량도 분리하지 않았다.

4500초에는 같은 조건부 상한47.299대가 실제48대와 가깝다. 따라서 고정 배분/충돌류 근사가 특정 차로 편중 상태에서 더 문제일 수 있다. **무조건 수용량을 늘리거나 두 차로 용량을 합치는 수정의 근거는 아직 아니다.** 실제 합류 차로·충돌류·차로 교환 가능성과 조건부 배분을 먼저 구분해야 한다.

이번 결과는 이 망의 RM/VSL 이득을 증명하거나 선택 순위를 확정하지 않는다. 다만 추가 보정 전에 바로잡을 구조적 후보가 구체화됐다: **① 초기 도시행 재고의 램프 재분류, ② 차로 편중 상태의 합류 수용 배분/충돌류 근사.** Ω 목적함수와 STOP은 유지하며 새 런·보정·push를 하지 않았다.

## 후속: native 궤적으로 확인한 10681 차로별 합류와 경쟁 교통류

앞선 추정의 한계를 좁히기 위해 중단 런의 기존 FZP를 **한 번만 읽었다**. 4495.1–4655.1·5995.1–6155.1초의 두 짧은 구간을3.70MB gzip 캐시에 저장했다. 원본 크기·mtime 불변을 확인했고, 읽은 바이트 범위의 SHA를 기록했다(전체 파일 SHA로 표현하지 않는다). 새 native·예측·재보정은 없다.

5초 FZP와 시작/종료 시각의 완전한 COM 차량 snapshot을 연결했다. 4500–4650초 진입50·head51·합류48대, 6000–6150초 진입34·head35·합류37대 모두 독립 native 경계 기록과 정확히 일치한다. 미분류 소실0, 램프 재고 보존 통과다.

|구간|실제 합류 마지막 램프 1차로|실제 합류 마지막 램프 2차로|관측된 램프 내 차로 변경|
|---|---:|---:|---|
|4500–4650|16|32|1→2차로 1건|
|6000–6150|2|35|0건|

각 차량의 첫 본선 관측 차로도 마지막 램프 차로와 같았다. **5초 사이 모든 차로 변경이나 정확한 합류 순간 차로를 확인한 것은 아니다.** 다만 6000초 구간의35대가 2차로를 사용한 합류로 관측되어, 모델의 차로당23.408대 수용 예측이 이 반응을 충분히 설명하지 못함을 뒷받침한다. 단순 총합 비교에만 의존한 결론이 아니다.

같은 native network에서10681은 본선 link2의1·2차로에 연결된다. 합류부 앞 본선 교통량은3·4차로에 훨씬 많았다. 다음 표의 교통량은150초 관측을 시간당으로 환산한 값이다.

|구간|모델 상류 셀 끝의 본선 2차로|같은 위치 4개 차로 평균|합류점 직전 2차로 관측 범위|예측 gap식의 등가 경쟁 교통량 평균|
|---|---:|---:|---:|---:|
|4500–4650|864|1,344|888–912|1,460.5|
|6000–6150|912|1,524|912–1,032|1,871.4|

단위는 대/h/차로다. 합류점 직전 범위는5초 관측 양 끝의 차로가 다른 통과 차량을 시작/종료 차로 중 어디에 배정하는지에 따른 범위이며, 관측 사이 숨은 왕복 차로 변경까지 보장하는 통계적 신뢰구간은 아니다. 모델 상류 셀 끝은 link2 위치2159.868m, 실제 합류점은2307.379m다. 두 위치를 같은 지점이라고 취급하지 않았다.

마지막 열은 새 보정값이 아니다. 저장된 매초 `physical_receiving` 한계를 **기존 gap식과 동일한3.5초/1.5초 계수로 역산**한 등가 입력이며, 매초 canonical receiving 한계가 비활성임을 확인했다. 이를 실측 교통량으로 표현하지 않는다. 현재 model branch는 상류 셀의 평균 `density × speed`로 경쟁류를 계산하고 해당 수용량을 두 램프 차로에 균등 배정한다. 특히6000초 구간에는 실제 합류 대상 차로의 통과량과4차로 평균 자체가 크게 다르며, 모델의 등가 경쟁류는 그 평균보다도 높다.

이 결과는 **어느 본선 차로가 실제 합류를 방해하는지에 대한 구분 없이 평균 경쟁류를 쓰는 근사**를 우선 검토할 근거다. 표의 실제2차로 유량을 예측 입력으로 넣어 성공했다고 하지 않았고, 임계 gap을 임의로 줄이거나 빈 차로 수용량을 모두 옮겨 쓰지도 않았다. 실제 gap·양보·platoon·차로 교환의 기여까지 분리한 결과는 아니다.

수정 검토 시에는 우선 해당 합류부의 차로 대응과 경쟁류 표현을 제한적으로 확인하고, 기존 동일 초기 상태 자료에서 미터 유지/변경의 실제 합류 차이와 대기 비용을 함께 검증하는 것이 타당하다. 31셀 전체를 세부 차로 모델로 바꾸거나 METANET 감속 계수만 크게 바꿔야 한다는 결론은 아니다. 이번 진단만으로 제어 이득·후보 순위·9000초 완료를 선언하지 않는다.

## 다음 수정의 구체적 범위 — 아직 실행하지 않음

사용자의 최신 지시는 **“목적함수는 유지하고 진단만 계속”**이다. 아래는 진단에서 도출한 다음 작업 제안이며, 수정·보정·새 native 실행의 완료 기록이 아니다. 현재 STOP은 그대로다.

### 1. 기존 초기 목적지 보존 기능의 막힌 부분부터 해결

대상은 기존 `physical_ramp_branches.initialize_gate_routes`와 `runtime_setup.configure_runtime`의 연결이다. 새 adapter는 필요 없다.

-127·10777처럼 이미 도시행 분기를 지난 위치는 램프로 다시 배정하지 않는다.10695처럼 도시 신호 이후 connector는 올바른 기존 도시 재고 소유자에 귀속한다. 차량 수뿐 아니라 목적지 계열과 Ω 소유가 보존되어야 한다.
-현재 목적지가 확정된 차량과 아직 선택 전인 차량을 구분한다. 현재 state의 완전한 route envelope 부재를 확인 없이 기본 β로 덮지 않는다. 알려지지 않은 목적지는 별도 불확실성으로 유지하고 미래 궤적의 route를 초기 입력으로 사용하지 않는다.
-과거 900/1050초 초기화 실패 상태와 이번4500/6000초를 함께 검사한다.1200초만 통과한 기능을 일반 제어에 켜지 않는다.
-첫 검증은 목적지 보존이다. 다음150초 램프 도착 오차의 개선 여부와 도시 재고·TTT 변화는 별도로 확인한다. 목적지 수정과 미래 이동시간/서비스율 보정을 동시에 섞지 않는다.

### 2. 10681의 경쟁류·차로 수용 배분을 제한적으로 검토

대상은 기존 `lane_ramp_runtime.LaneRampRuntime.advance`와 `physical_ramp_boundary.LaneResolvedRampBoundary`다. 현재의 기본 `lane_groups=False` 계약은 `lane_plant_runtime._load_sources_v2`에서 차로 모델 기능 활성화를 명시적으로 거절한다. 기존 차로 기능을 켜는 것만으로31셀 모델과 호환된다고 가정해서는 안 된다.

-합류 대상 본선1·2차로와3·4차로의 교통량을 구분할 수 있는 현재/과거 관측을 검토한다. 최소 수정은10681 합류부의 경쟁류·수용 배분 범위로 한정하고,31셀 전체를 다른 차로 모델로 바꾸지 않는다.
-Poisson gap 근사의 계수 변경보다, 어떤 경쟁 교통류를 입력했는지와 균등 배분이 물리적 차로 대응을 반영하는지 먼저 확인한다. 빈 차로 용량을 근거 없이 대기 차로에 더해주지 않는다.
-어떤 후보도 기존 본선 총 수용량·램프 재고·정지선 서비스·유한 저장공간·실제 RG 시간을 동시에 지켜야 한다. 진입/본선 합류/정지선 통과를 같은 양으로 간주하지 않는다.
-우선 기존4500/6000초의 관측 명령으로 반응을 확인한다.6000초 오차를 줄여도4500초의 이미 가까운 합류48/47.16대를 악화시키는지 본다. 특정 상태에 대한 미래 실측 경쟁류 대입이나 capacity 보너스로 통과시키지 않는다.

### 3. 기존 독립 결과를 회귀 검증으로 재사용

seed53의2670.1초 공통 초기450초 미터 유지/점진 해제/VSL/both 자료는 완료되어 있다. 실제 미터 해제는 합류+94대, 동측 비용+5.929대·시간의 손해였다. 후보δ4/E2는 그 손해 방향을 맞췄지만 방출 감소 크기는 부족했다. 향후 수용 계산을 수정하면 이 **강한 미터 효과의 방향을 망가뜨리지 않는지** 우선 검사해야 한다.

그 자료의 작은 VSL 효과−0.150대·시간을 정밀하게 맞추는 추가 계수 탐색은 우선순위가 아니다. 미래 검증은 자유류 불필요 제한, 혼잡시 합류 억제 효과, 회복시 해제, 램프·도시 대기를 함께 본다. 실제와 모델의 평가 공간·기간은 동일하게 맞추며, 외부 비용은 사용자 결정에 따라 선택 목적에 더하지 않고 따로 보고한다.

### 4. 이후 SDMPC와 새 native

위 검증이 통과한 후보에 대해서만 같은 저장 상태의 SDMPC 한 주기에서 선택·미분·수량 제약·writer를 확인한다. PFO/SDMPC 반복 상한2회와 수렴 미증명을 명시한다. 최적화 반복 수만 늘리는 작업은 이번 수정 범위로 묶지 않는다.

현재9000초는8400초에서 사용자 지시로 중단됐고 완전 검증 범위는8100초다. 실제 재실행은 이 진단의 허용 범위에 포함되지 않는다. 오프라인 수정·검증을 허용받더라도 새 VISSIM을 자동으로 재개하거나 STOP을 지우지 않는다. 전체 목표의 이득 검증과9000초 완료는 아직 충족되지 않았다.
