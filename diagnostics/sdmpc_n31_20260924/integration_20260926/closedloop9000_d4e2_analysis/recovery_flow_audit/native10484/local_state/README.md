# 셀22·23 국소 차로 상태와 보존 장부

**합류 차로의 재고를 따로 두는 것에 더해, 차로 사이 이동도 상태에 따라 달라져야 한다.** 같은 공통 초기 상태에서 RM 유지와 완화의 후속 차로 이동이 다르며, 예측 시작 전150초의 고정 이동률은 이를 설명하지 못했다. 아직 이 장부를 자율 METANET450초 예측이나 SDMPC에 연결한 것은 아니다.

## 이번에 준비·검증한 것

- 셀22·23을 합류 차로1과 나머지2개 차로로 나눈 **현재 재고·속도 초기값**을 만들었다. 기존31셀의 차량 수와 속도 모멘트(차량별 속도의 합)를 보존한다. 초기값은 `initial_state.json`이다.
- 2520.1–2670.1초 과거 자료만으로 두 셀에 공통인 양방향 이동률2개를 산출했다. 미래 기록은 학습에 넣지 않았다.
- 과거30구간과 유지·완화90구간씩, 셀21–25의 두 차로그룹 및10484 신호 이후 재고에 대해5초별 차량 수와 속도 모멘트 장부2,310행을 검증했다. 차량 수 오차0, 속도 모멘트 항등식 최대오차4.55e−13이다.
- 기존 helper `audit_stopped_predictions.py --ramp10484-local-state`에만 기능을 추가했다. 정본 물리식·설정, 망, STOP, 열린 사용자 VISSIM은 변경하지 않았다.

장부는 관측 양끝 사이의 집단 이동이다. 차량이 같은5초에 셀 경계와 차로를 모두 바꾸면 정확한 차로변경 위치·시각은 모른다. 차로 번호가 같아도 중간 왕복 변경은 관측하지 못한다. 따라서 이것을 개별 boundary flow나 정확한 lane-change hazard로 바꾸어 주장하지 않는다. 속도 모멘트의 잔차가0이라는 것은 회계가 닫힌다는 뜻이며, 가속 동역학이 보정됐다는 뜻은 아니다.

## 같은 초기 상태

0기준 셀22:1차로11대·41.84km/h, 나머지2개 차로20대·38.13km/h.

셀23:1차로9대·31.59km/h, 나머지14대·57.96km/h.

RM 유지와 완화의2670.1초 원래 캐시는 동일하다. 준비된 국소 상태는 이 공통 시점에서만 읽으며, 미래 실측 초기화나 특정 제어에 붙는 보너스는 없다.

## 고정 이동률의 한계

두 셀 내부에 관측 양끝이 모두 있는 차로 집단 변경을 세었다. 과거150초에는 합류 차로→나머지9대, 반대3대다. 출발 집단의 차량·초로 나눈 공통 이동률은 각각0.0035928/s와0.0006309/s다. 새 망의 실제 차로변경 모수를 식별한 값으로 채택하지 않는다.

|---|---:|---:|---:|
|유지2670.1–2820.1|12|9|7.71 /2.28|
|유지2820.1–2970.1|13|10|5.21 /1.76|
|유지2970.1–3120.1|11|15|5.14 /1.80|

|완화2820.1–2970.1|19|0|12.29 /3.24|

오른쪽 열은 **미래의 현재 실측 재고를 조건부 입력으로 한 이동량 검사**다. 예측 재고를 스스로 갱신한 자율 예측 결과가 아니다. 실제로 관측되는 방향성 변화에 비해 고정률은 유지의 복귀를 크게 누락하고, 완화의 복귀를 계속 허용한다.

위 표에는 같은5초에 셀도 바꾼 사례가 포함된다. 마지막150초에는 유지의1→나머지11대 중6대, 복귀15대 중11대가 그런 사례다. 완화21대 중1대만 셀도 바꿨다. 구간 경계를 드나들며 차로도 바꾼 사례는 별도 열로 보존했다. 이 측정 차이를 무시하고 표의 횟수에 맞춰 새로운 임의 계수를 넣지 않는다.

같은 셀 안에서 관측된2820.1–3120.1초 이동도 차이를 뒷받침한다. 셀23의1차로에서 다른 차로로 바뀐 차량은 유지5대·완화25대, 반대는 유지2대·완화0대다. 합류부 배수와 이 측방 이동을 분리해서 검토해야 한다.

완화의 셀23 이탈25대 중, 해당 차로 이동 전에 이번 구간10484 합류가 이미 관측된 차량은1대뿐이다(`cohort_departures.json`). 따라서 관측된 증가를 모두 방금10484에서 합류한 차량의 차로 정리로 설명할 수는 없다. 나머지 차량은 출처 미확인으로 남겼으며10490·기존 본선 차량 등의 구성까지 분리한 결과는 아니다. 이 분류도 사후 관련성 검사이지, 특정 원인의 독립 효과나 새 이동률 학습 결과가 아니다.

## 캐시 범위 오류를 발견하고 보존한 과정

첫 장부 검사는 유지3030.1→3035.1초 차량26036이 갑자기 셀22에 나타나는 것처럼 보여 실패했다. 실패 source와 `attempt1_failure.json`을 보존했다. 기존 작은 캐시는10484와 관련 본선 링크만 담고 있어, 같은5초 안에 **10490에서 합류해 셀22까지 도달한 차량**의 이전 행을 빠뜨렸다.

원본 완료 FZP의 해당 ID를 다시 찾아3030.1초10490,위치364.18m,속도57.03km/h인 것을 확인했다. 파일 전체 SHA가 기존 완료 기록과 같았다. 보충 행은 `hold_endpoint_additions.json`에 따로 저장했고 원래 캐시·이전 집계는 덮어쓰지 않았다. 미설명 생성·삭제로 처리하거나 해당 차량을 제외하지 않았다. 램프10484 자체의 기존 event 집계와 이 이웃 행 보완은 다른 문제다.

완료 파일 읽기는 과거 캐시 생성1회와 누락된 이웃 행 확인1회, 총2회다. 재시도에서는 과거 캐시를 재사용했다. 새 VISSIM이나 controller 실행은 없다.

## 채택 여부와 다음 단계

국소 초기 상태와 보존 장부는 준비됐다. **고정 차로 비율, 고정 차로변경률, 앞서 기각한 단순 gap 대입과 본선 우선 잔여식을 생산 모델에 넣지 않았다.** 소수의 상태 의존 이동 계수를 검토하더라도, 속도차·수용 공간에 대한 의존성을 과거 자료에서 확인하고 독립 상태에서 먼저 시험해야 한다.

다음 실제 예측 후보는 기존 보존 계산 안에서 국소 재고·측방 이동·램프 공동 수용을 연결해야 한다. 정본 VSL 이력, 램프 대기, 동적 진출부,31셀 집계와 나머지 셀 계산을 보존하는 대조가 필요하다. 이 연결 및450초 이득·강한 합류 상태의 SDMPC 선택 검증은 미완료다. 새 수치 grid나 전역 lane-group 경로 전환은 시작하지 않았다.

원자료와 계산: `past_frames.json.gz`, `initial_state.json`, `mass_moment_5s.csv`, `exchange_5s.csv`, `summary.json`, `coverage_repair.json`. 현재 결과는 seed53 구조 진단이며 미사용 seed 검증이라고 부르지 않는다.
