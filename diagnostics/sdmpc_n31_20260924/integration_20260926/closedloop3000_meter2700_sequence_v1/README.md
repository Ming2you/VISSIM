# 실제2700초 상태의 한정된 RM 응답 검사

완료된 SDMPC3000의2700초 관측과 실제2550초 명령으로 초기화했다. 도시 green/offset 및 VSL은 그 직전 실제 명령으로 고정하고, 동측 미터만 하나씩 바꿨다. 계수 변경·최적화·새 VISSIM 실행은 없다.9개450초 예측이 모두 종료했다(session42535 exit0).

완전 개방을 유지한450초 Ω TTT는496.985854차량·시간이다. 아래 Δ는 해당 예측에서의 변경−유지이며 실측 이득이 아니다.

| 미터 | 8/8/8초 Ω ΔTTT | 8/6/4초 Ω ΔTTT | 8/6/4초 대상 램프 합류 Δ[대] |
|---|---:|---:|---:|
| 10639 | +0.000091 | +0.000231 | −0.810 |
| 10681 | +0.000003 | +0.000009 | −0.079 |
| 10490 | +0.010946 | +0.011947 | −0.414 |
| 10484 | +0.001773 | +0.003319 | −4.168 |

관측한 모델 재고의 Ω 밖 체류를 더해도 유리한 후보는 나타나지 않았다. 변화가 작으므로 ‘실제로 확실히 손해’라고 해석하지 않는다. 이 상태·단독 명령·450초에서는 모델상 실질적 이득이 발견되지 않은 것이다. 모델이 거의 같은 합류량을 내는 경우가 많아, 단순히0 기울기를 유한차분으로 바꾸면 RM이 켜질 것이라는 근거도 없다.

8/6/4는 실제 녹색 기준 주기별 최대2초 변경을 지킨다. writer·물리·블록 간 변경 한도는 검증했지만 이 고정 응답 검사는 NP/NUF의 최적화 후보 선택 검증이 아니다.2700–3150초 예측 중 실제3000초 이후 결과는 존재하지 않으며 미래 실측을 입력하지 않았다. 이 결과를 이전 ALINEA의 다른 초기 상태나 더 강한 개입 전체에 일반화하지 않는다.

## 보조 코드 오류와 수정

첫 진단 `../closedloop3000_meter2700` 및 과거 `../select1200v3_check`의 고정 endpoint 호출에는 `sdmpc_sequence.prediction_scope`가 빠져 있었다. 미래 두 블록이 무시되어 첫 블록을450초 유지했다. 기존 파일은 보존하고 `SEQUENCE_VALIDITY_NOTICE.json`으로 세 블록 예측 자격을 취소했다.

기존 `probe_levers`에 실제 SDMPC evaluator가 사용하는 같은 scope를 연결했다. 이번9개 예측 모두 실제 방문 블록 `[0,1,2]`를 결과에 기록·검증했다.8초 유지와8/6/4 결과가 이제 구분된다. 생산 SDMPC의 `area_follower_objective.py`와 `sdmpc_tangent_worker.py`에는 이미 이 scope가 있었으므로, 완료된 native3000 실행 및 실제 TTT 비교는 이 오류의 영향 대상이 아니다.

기존 `diagnostics/test_sdmpc_sequence.py SequenceTimingTests`의 시간·인과성·불완전 실행 검사4개 PASS. 전체 테스트 파일의 SavedCoordinateTests는 다른 컴퓨터의 오래된 TRLAB 망 경로가 없어 setup 실패했다. 이를 통과로 숨기거나 해당 망을 임의로 대체하지 않았다.

## 다음 판단

METANET의 절대 속도를 더 맞추기 전에, 실제로 이득을 보였던 기존 공통 상태에서 **허용된 미터 명령 → 실제 합류 감소 → 본선 비용 감소와 램프·도시 대기 증가**를 같은 비용 범위로 대조한다. 운용 한도 내 개입이 실제 유량을 바꾸는지 먼저 확인하고, 바뀌는 경우에만 그 이득 방향을 놓치는 물리 항을 수정한다. 여기서 이득을 강제하는 보상·수용량 보너스는 추가하지 않는다.
