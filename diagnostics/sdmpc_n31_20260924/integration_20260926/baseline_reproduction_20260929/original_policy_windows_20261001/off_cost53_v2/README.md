# RM 순이득 오차: 본선 단독 경계 가정과 결합 모델의 구분

2026-10-01. 직전 목표 턴은 10681 가설의 독립 상태 시험을 완료한 progress였고, 이번 턴도 기존 예측의 240개 off-ramp 시간창과 실제 SDMPC 결합 모델 8개 off-ramp를 대조해 다음 보정 범위를 바꾼 progress다. 목표는 ACTIVE/NOT_QUALIFIED다.

## seed53 단독 플랜트의 비용 오차

기존 expanded036의 4조건×4개 동측 off-ramp×15개30초 창을 재집계했다. 각 창의 실제·모델 재고 보존, 누적 유량 차분, 시간 가중 입출량과 사다리꼴 TTT 항등식을 검사했다. 새 예측·VISSIM·FZP 재읽기 없이 저장 결과만 사용했다. 미래 관측은 채점에만 썼다.

RM 완화−유지의 off-ramp 합계 ΔTTT는 실측 +0.420833, 예측 −0.322003veh·h다. 오차 −0.742837 중 10643이 −0.455218(절대 오차 합계의 약61.3%), 10481이 −0.204961이다.

입력 파일을 확인하면 10643 배수 서비스는 네 명령 모두 **576대/h**, 10481은 **336대/h**로 고정돼 있다. 실제로 초기 상태 이전2520.1–2670.1초 5개 창의 배수량×24와 정확히 같다. 직접 연결 출구10483/10682는2250대/h이므로 모든 off-ramp가 같은 과거 평균 처리라고 일반화하지 않는다.

10643의 실제 배수 변화 −6대가 모델에서0인 것은 본선 단독 시험이 도시 신호·하류 저장공간을 자율 예측하지 않는다는 가정과 함께 해석해야 한다. 10643 TTT 반응 오차 중 시간 가중 진입 오차는 −0.03855, 배수 변화 오차 기여는 −0.41667veh·h다. 이는 회계분해이며 각각을 독립적인 인과효과로 해석하지 않는다. 진입량 자체의 약19~20대 과대예측은 별도의 본선·경로 반응 문제로 남는다.

**이 부분영역 합계에 맞추려고 METANET 계수를 더 조정하면, 고정된 도시 경계 가정의 오차를 본선에 떠넘길 수 있다.** 반대로 본선 상태와 합류·진출 유량 검증까지 면제되는 것도 아니다.

## 실제 SDMPC 결합 경로와 대조

운영 `lane_plant_runtime.initialize`는10643을 차로별 CumulativeLane와 CoupledPort에 연결하고, 다른7개는 LaneOfframpRuntime에 연결한다. 배수는 실제 예측 도시 신호, 도착 준비, 하류 가용 저장공간으로 결정된다. 본선 단독의576대/h 상수를 가져오는 실행 경로가 아니다. 동적 재고·배수·spillback은 이미 연결돼 있다.

완료된 seed47 공통2700초 RM 유지/완화의 현재 expanded036 결합 결과를 재사용했다. 양쪽 native의 정확한 공통 prefix와 기존 대조 유효성 검사를 확인했다. native 파일의 **전체 런 비용은 공통 prefix가 차분에서 소거되므로 Δ만 비교**했다. 450초 모델과 native 전체 런의 절대 비용을 직접 비교하지 않았다.

## 다음 보정·선택 검증의 기준

1. seed53 본선 단독 시험의 큰 RM 본선 반응은 유지한다. 고정 도시 경계를 포함한 부분영역 순이득 차이를 운영 플랜트 전체의 미통과 수치로 그대로 사용하지 않는다.
2. 기본 물리 보정은 기존 단순 네 정책 및 공통 초기 상태에서 본선 합류·방출·재고·회복을 확인한다. 특히 초기 RM의 약한 방출 반응과 VSL 반응의 미해결 부분은 그대로 남는다.
3. 램프·도시 대기를 포함한 비용과 SDMPC 선택은 도시부까지 연결한 동일 상태·명령 결과로 검증한다. seed47의8램프 대기 오차와 완료된9000의 초기1500–2250 유입/합류 시각 오차가 다음 연결 진단의 대상이다. 작은 off-ramp 차이에 대한 계수 탐색은 하지 않는다.

추가 계수·코어·목적함수·제약 변경, native 실행, 진행 중 CTG 조회, STOP 변경, push는 없다. 수정은 분석 코드와 근거 문서뿐이다. 초기 v1 출력에서 `off_capacity_vph`를 service라고 표기한 명칭 오류는 v2에서 진입 proxy와 실제 `off_drain_vph`로 분리했다. 원래v1 결과와 실행 소스는 보존했고 수치·실패를 덮어쓰지 않았다. 근거는 summary.json, bins.json, source_executed.py.txt다.
