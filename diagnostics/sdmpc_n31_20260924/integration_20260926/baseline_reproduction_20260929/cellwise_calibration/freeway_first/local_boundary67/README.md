# 합류부에서 전달된 오차와 회복부 자체 오차의 분리

2026-09-30. **정확한 유입량과 주변 공간 평균상태만 주어도 셀24·25의 저속 편향이 남았다. 통과 차량의 속도를 경계에 사용하면 셀24가 상당히 개선됐지만, 셀25 오차는 남았다.** 회복 계수만 키우기 전에 공간 평균속도와 경계 통과속도의 차이를 다룰 근거다. 미래 경계 조건부 진단이며 자율 예측 보정 완료가 아니다.

## 실행한 비교

완료된 seed67 RM 완화 기록의2670.1초 공통 초기 상태부터450초를 사용했다. 모두 VSL110이며, 새 VISSIM·FZP 읽기·계수 적합은 없다. 기존 route036 계수와 물리 셀 주소를 유지하고 정본 `_freeway_substep_events`를 호출했다. 새로운 교통 방정식이나 adapter를 만들지 않았다.

예측 영역을①셀24–25,②셀23–25,③셀21–25로 바꾸었다. 영역 내부 N/v는 초기값 이후 덮어쓰지 않고1초씩 전진한다. 영역 앞의 실제5초 통과량과 영역 안의 실제 램프 합류량은5초 안에 균등 배분했다. 외부 셀은 관측5초 N/속도모멘트를 선형 보간한 경계 저장소이며, 다음 step에 다시 관측값을 공급한다. 이 외부 상태를 전체 망 차량 보존 예측으로 주장하지 않는다.

21–25에는 진출 분기가 없다. 상류 off-ramp 영향은 관측 경계에 포함되므로, 이 열린 국소 영역에는 경로 재배정·off-ramp 모델이 필요하지 않다. 이것은 정본의 동적 진출 재고를 제거하는 변경이 아니다. 램프 대기 비용도 이번에는 예측하지 않는다. 입력량을 모두 수용했고 국소 jam 초과나 최소속도 도달은 없었다.

## 2. 경계 통과 차량의 표본속도로 바꾼 민감도

첫 결과를 보존한 뒤 별도의 사전 기록 `crossing_protocol.json`으로 두 계산만 추가했다. 영역은24–25로 고정했다. 같은 유입 차량을 대상으로, 상류 셀 평균 대신 각5초 구간에 통과한 차량들의①직전 표본속도 평균,②직후 표본속도 평균을 주었다. 나머지 조건·계수·경계량은 같다.

**5초 양끝 표본은 정확한 경계 순간속도가 아니고 엄밀한 상·하한도 아니다.** 특히 직후 값에는 경계 통과 뒤 가속이 포함된다. 미래 관측이므로 controller 입력이나 자율 모델의 새 계수로 사용하지 않는다.

셀24 실제 누적 통과는820대다. 공간 평균 경계는810.95대,직전 표본은814.50대,직후 표본은817.70대로 예측했다. 셀25는 실측823대에 대해800.72/807.33/812.60대다. 마지막 셀24 재고도22.05→18.50→15.30대로 실제13대에 가까워진다.

셀23 하류 통과819대의 차량 가중 직전/직후 속도는56.88/72.33km/h다. 셀23의15시점 공간 평균속도39.84와는 집단·시간 연산자가 다르지만, 동일한 상류 평균을 통과 차량 속도로 쓰는 근사에 주목할 근거가 된다. 이는 단순히 ‘가속도를 더 주면 된다’는 식별 결과가 아니다.

## 검증과 실패 보존

- 세 공간 평균 경계 계산과 두 통과 차량 속도 계산,합계5개 국소450초 궤적. 전체망 자율 예측0회.
- 관측 ID 이동에서 재구성한20/22/23/25 경계의5초 통과량이60개 기존30초 기록과 일치했다. 같은5초에 램프에서 합류해 해당 셀까지 통과한 차량도 기존 ramp event로 포함했다.
- 6,300개 cell-step의 차량 보존 최대오차1.49e−14대. 입력 거부0,국소 최소속도 도달0. 실제 입력을 억지로 받기 위해 재고를 삭제하지 않았다.
- 초기1초 식은 기존 실측 상태 스칼라 계산과 일치한다. 통과 속도 변경에서는 원래 convection 항의 정확한 차이를 더한 식과 최대1.16e−14km/h 오차다.
- 과거 실행 helper 사본을 사용해80개 출처 pin을 검증했다. 기존81개 helper 함수 AST는 그대로이며 core·설정·STOP은 변경하지 않았다.
- 최초 시도는 진단 설정의 빈 route inventory 사전을 ‘비활성’으로 잘못 사용해 첫 영역을 완료하기 전에 실패했다. 실제 `inventory_enabled`는 `None`만 비활성으로 판정하므로 진단 설정만 수정했다. `failure.json`,초기 helper·로그와 재시도 원문을 모두 남겼다. 실패한 계산을 완료에 포함하지 않았다.

## 다음 적용 범위

본선의 **셀 평균→경계 통과 차량 속도** 근사를 우선 확인한다. 기존 전역 accepted-flow 이류 변경과 셀22·23 차로 분리 실패를 반복하지 않는다. 실제 통과 속도나 미래 분산을 주입하거나 특정 셀에 상수 속도 보너스를 붙이지 않는다. 현재 예측 상태만으로 통과 속도·가속 구간을 표현할 수 있는지 검증해야 하며, 이전 셀15–20용 분산/minmod closure가 셀23 회복 문제까지 통과한 것은 아니다.

셀25의 남은 저속 편향과 RM 유지/완화·VSL에서의 반응도 함께 확인해야 한다. 지금 개선된 조건부 셀24 속도를 ΔTTT·후보 순위의 자율 검증으로 대체하지 않는다. 전체 Ω 비용·SDMPC 및9000초 목표는 ACTIVE / NOT_QUALIFIED다.

원자료: `summary.json`, `crossing_summary.json`, `domain*.json`, `audit*.json.gz`, `verification.json`. 재현 entry는 기존 helper의 `diagnose-local-recovery-boundary`, 초기 진단 설정 수정 후 `resume-local-recovery-boundary`, 두 추가 민감도는 `diagnose-local-crossing-speeds`다. 기존 결과가 있으면 중복 실행을 막는다.
