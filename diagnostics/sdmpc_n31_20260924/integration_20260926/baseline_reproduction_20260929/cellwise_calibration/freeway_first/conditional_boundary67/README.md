# seed67 실제 진입·합류 경계의 조건부 본선 진단

2026-09-30. 기존 `diagnose_expanded_merge_boundary`를 새 후기 상태에 사용할 수 있게 확장했다. 모델 식·계수·수요 설정·기하·VISSIM 실행기는 바꾸지 않았다. 새 VISSIM 및 재보정은0회다.

## 무엇을 고정하고 무엇을 대입했나

기존 route036의 같은2670.1초 초기 상태, 현재 목적 경로 재고, VSL 이력, 동적 off-ramp 저장·배수를 유지했다. 예측 모델의 램프 도착/head/대기/gap 선택 대신 실제5초 connector 방출량을 같은 구간에 균등 배분하여 본선 합류 경계로 주었다. 본선 source admission은 실제30초 수량을 각30초에 균등 배분했다. 미래 off-ramp 배수·재고는 대입하지 않았다.

미래 실측을 사용하는 **조건부 원인 분리**다. 자율 예측 검증·실행 가능한 명령·램프 대기 포함 순이득이 아니다. 예측 상태의 gap/수용 예산보다 강제 합류량이 큰 구간도 숨기거나 clip하지 않고 `receiving_envelope_exceedance`에 기록했다. 특히10681은 조건별16.2–19.6대,10490은4.4–12.5대의 초과분이 합산된다. 이 값을 VISSIM의 위반이나 실효 capacity라고 해석하면 안 된다.

## 재현 확인과 실행

먼저 RM 유지/VSL110 및RM 완화/VSL90의 저장된1초 실제 모델 합류량을 외부 경계로 재생했다. 원래 자율 예측과 `cells`, `flows`, `ports` 배열이 모두 정확히 같았다. 그 후 네 조건에 실측 source·merge를 적용했다. 총 예측6회=재현2회+조건부4회다.

두 번째 재현의 결과 JSON 이름은262자로 Windows 경로 제한에 걸렸다. 예측 gzip 및 동일성 검사는 이미 완료돼 있었다. `failure.json`과 첫 실행 소스를 보존하고 짧은 파일명으로 수정했다. 두 완료 예측을 재사용해 조건부4회만 실행했다. 실패를 이유로 native 또는 재현 계산을 반복하지 않았다.

모든 조건의 source30초 오차는최대4.97e−14대, merge30초 오차는최대1.07e−14대다. 따라서 아래 차이를 합류 총량/30초 source 총량을 제대로 대입하지 못한 결과로 설명할 수 없다. 다만 구간 안의 상세 시각·차로별 도착·미래 목적지 선택까지 실측과 같게 만든 것은 아니다.
