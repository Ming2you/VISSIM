# 차로 평균 때문에 VSL 작용이 가려지는가

2026-09-30. **기존 계수를 차로별 밀도에 대입하는 것만으로 미설명 VSL 이득이나 회복 오차가 해결된다는 근거는 얻지 못했다.** 실제 본선 동역학 검증을 우선하며, 이 결과로 전역 차로 모델이나 전체 망 보정을 시작하지 않는다. 목표는 ACTIVE / NOT_QUALIFIED다.

## 범위와 계산

seed67의 완료된 RM 완화 / RM 완화+VSL90 기록에서2670.1–3120.1초,5초 간격,동측 셀14–26을 재사용했다. 기존 검증 캐시만 읽었다. 새 FZP 스캔·VISSIM·자율 예측·계수 fitting은 없다.

같은 현재 차량을①기존 셀 전체,②1차로/나머지 차로,③각 차로로 나누었다. 각 그룹의 실제 N과 물리 차로 폭으로 밀도를 계산하고, 현재 route036의 **동일한 셀별 nominal FD 및 Carlson(A=.5,E=2)**를 호출했다. 그룹별 목표속도를 차량 수로 가중해 합쳤다. 식 사본을 만들지 않았다.

110/90은 **현재 차량 모두가 해당 명령을 이미 본 경우의 가상 목표속도**다. 실제 VSL 코호트·통과 지연을 재현한 출력이 아니며, 실제 nominal 기록과 제어 기록 간의 인과 효과도 아니다. 예측속도, 가속도, 처리용량 또는 TTT 이득으로 해석하면 안 된다. 셀26도 물리 복원 뒤에 있는 민감도 대조이며 실제90 적용구간이라는 뜻이 아니다.

Carlson 법칙은 단순 속도 상한만이 아니므로 양의 목표 변화도 가능하다. 이를 코드 오류 또는 자동 capacity 이득으로 처리하지 않았다. 현재 계수는 aggregate 상태에 보정된 값이므로, 본 검사는 차로별 재보정의 가능성을 배제하지 않는다. 특히5초의 짧은 셀·차로 재고는 표본 변동이 크다.

## 기존 구현을 재사용하기 전에 확인한 점

`physical_lane_groups.PhysicalLaneGroups`는 진출 목적 재고를 과거 분기비율로 배정한다. `offramp_routing`은 현재 관측 경로와 미래 native 선택 확률의 차량 재고를 accepted flow로 이송한다. 두 구현은 현재 명시적으로 동시 사용을 거부한다. guard만 제거하면 동일한 목적지 재고를 공유하게 되는 것이 아니다.

기존 `local_lane_candidate`에서는 이미 셀22·23의 상태 의존 차로 이동을450초 예측에 연결했으나 회복·유량 오차가 악화해 원복했다. `flux_convection`에서는 전31셀의 accepted-flow 속도 전달도 이득 반응을 개선하지 못했다. 이 시험들을 반복하거나 실패 후보를 복원하지 않았다.

이번 결과는 차로/경로 재고 결합의 큰 구현에 앞서 수행한 범위 제한 검사다. 기존 경로 재고·동적 진출 저장을 유지하고, 본선의 제어→방출/회복 반응을 먼저 해결한다. 모든 셀을 독립적으로 재보정하거나, 관측된 희망속도 변화 자체를 TTT 보상으로 넣지 않는다.

## 검증과 남은 범위

총2366개 cell/time 상태에서 세 분할을 계산했다. native30초 N/v416개, 제어 분기 전 공통 snapshot78개가 일치했다. 모든 분할은 현재 차량 수·속도 모멘트를 보존했다. 동일 차로 밀도130개 대조도 기존 FD와 일치했다. 출처37개 SHA가 계산 전후 같다. helper 구문 검사 통과, 정본 코어·설정·STOP 변경 없음.

실행은 기존 `replay_congested_component.py audit-lane-fd-sensitivity`다. `helper_executed.txt`, `protocol.json`, `rows.json.gz`, `summary.json`, `verification.json`에 원문·결과·검증을 보존했다. 실행 로그는 상위 integration의 `lane_fd67_run.log`다.

이번에는 물리 모델을 채택하거나 자율 예측의 개선을 확인하지 않았다. 램프·도시부 전체 Ω, SDMPC 선택,9000초 목표도 미완료다. 후속 원인 분리는 기존 본선의 속도/방출 전이를 대상으로 하며, 실측 미래 경계를 쓰는 경우 반드시 조건부 진단으로 남긴다.
