# 셀19–21 차로×목적지 동역학 시험 — 채택하지 않음

2026-09-30. 고속도로를 먼저 검증한다는 우선순위에 따라 기존31셀 플랜트의 셀19–21에만 차로별 유량·속도 갱신을 연결했다. **차량·목적지 보존은 통과했지만 VSL 이득을 설명하지 못했고, RM 손익 예측도 일부 악화했다. 후보는 정본에 채택하지 않았고 변경한 core4개를 작업 직전 바이트로 복원했다.**

## 실제로 구현하고 실행한 범위

- 기존 `physical_lane_groups.py` 안에 지역 차로 상태를 구현하고, 기존 `offramp_routing.py`의 목적지 재고를 동일한 실제 수락 유량으로 이동시켰다. 별도 차량 집단이나 어댑터를 만들지 않았다.
- 셀19–21의3개 차로는 현재 COM 차량의 경로·차로·속도로 초기화했다. 접근 가능한 차로에서만10483 진출이 가능하고,10490 합류는1차로 수용공간을 사용한다. 진출하지 못한 차량을 통과행으로 재분류하지 않았다.
- 나머지 셀의 기존 계산, 계수, 수요·명령, 램프 이동/대기, 동적 off-ramp 저장·배수, VSL 적용 이력을 유지했다. 지역 내에서는 기존 METANET식을 차로별로 계산했다. 같은 셀의 VSL 명령 이력 비율은 차로 사이에 공유하는 근사다.
- 상류 셀18에서 지역으로 들어오는 목적지별 차로 비율은 현재 관측으로 초기화한 뒤 고정했다. 관측되지 않은 목적지는 균등 비율이다. 이 경계 근사는 추가 검증 대상이며 정확한 차로 선택 모델이 아니다.
- 차로 간 이동률은 seed29 초기 NC의2220.1–2670.1초 기존5초 기록에서만 추정했다. 같은 지역에서 양 끝이 관측된6,784개 차량·구간의 순 차로변경82건을 사용했다. 해당450초의 TTT나 후기 제어효과를 fitting 목표로 쓰지 않았다.
- 대응하는6개 이동률은 차로1→2 `0.0019893/s`,2→1 `0.0015138/s`,2→3 `0.0024599/s`,3→2 `0.0013896/s`,1↔3은0이다. 이는5초 endpoint 기반 근사이며 전체 실제 차로변경 횟수나 상태별 gap acceptance를 식별한 계수가 아니다.

## 비교 결과

공통 초기2670.1초에서450초 자율 예측. seed29·67 각각 RM 유지/완화 × VSL110/90의4조건을 사용했다. ALINEA 명령 이력을 거친 후기 상태의 재생 시험이며 처음부터 무제어와 비교한 실험은 아니다. 미래 실측은 예측 입력에 넣지 않았다. 두 seed 모두 앞선 진단에서 이미 보았으므로 완전히 미공개인 검증자료라고 주장하지 않는다.

아래 TTT는 **동측 본선31셀**, 단위 차량·시간이다. 음수는 기준 명령 대비 감소다.

seed29의 작은 VSL 차이는 성공/실패의 주된 근거로 쓰지 않는다. seed67의 의미 있는 VSL 이득은 후보에서도 사라졌다. 네 후보 중 RM 유지/VSL110을 고르는 순위는 기존·후보 모두 맞았지만, 그것만으로 물리적 이득 예측을 통과시키지 않았다.

동측 본선+4진입/4진출 connector 비용에서도 seed67 RM 완화의 실측 손실은+4.946인데 기존+2.325, 후보+1.890으로 손실을 더 작게 보았다. 이 영역은 전체 Ω나 도시부·외부 대기를 포함한 비용이 아니다.

본선 TTT 절대오차의4조건 평균은 seed29 `2.282→2.776`, seed67 `0.986→1.708`로 악화했다. 전체 속도·유량 등을 합친 기존 점수는 seed67에서 조금 나아졌지만, 손익 반응 개선을 대신하는 근거로 쓰지 않는다.

## 무엇을 놓치는지 더 좁혀짐

seed67의 RM 완화±VSL 비교에서 셀19 1차로를 같은5초 시각30개 `(2970.1,3120.1]`로 맞췄다. 앞 보고서의 시작 포함 표본 창과 경계 표본이 하나 다르므로 수치가 조금 다르다.

| 셀19 1차로 | VSL 없음 실측 | VSL90 실측 | VSL 없음 후보 | VSL90 후보 |
|---|---:|---:|---:|---:|
|평균 재고 대|16.77|10.87|9.79|9.67|
|차량 가중 평균속도 km/h|16.34|37.13|33.51|35.46|

VSL90의 속도만 보면 가까워 보이나, 후보는 **VSL이 없는 조건의 재정체와 차로별 재고 축적을 놓친다.** 두 조건을 모두 비교해야 하는 이유다. 실측 셀19 하류 통과 증가38대에 대해 기존은10.92대, 후보는7.08대 증가로 보았다.

이는 재정체 오차가 고정된 경계 차로 분배 때문인지, 평균 이동률의 상태 반응 부족 때문인지, 차로별 METANET 속도식 때문인지를 확정하지는 않는다. 차로 상태를 나누고 기존 계수를 그대로 적용하는 것만으로 해결된다는 가설은 지지되지 않았다. 실패한 후보에서 계수 탐색을 바로 늘리지 않는다. 다음 작업은 이 후보의 기존 기록으로 차로별 유입·차로 이동·방출의 재고 축적 차이를 먼저 분리하는 것이다. 전체 망이나 도시부를 조정해 이 차이를 상쇄하지 않는다.

## 구현 오류와 보존 검증

- 최초 초기화는 길이 가중 차로 수가 `3.0000000000000004`로 표현되어 정확한 정수 비교에서 중단됐다.1e−9 비교 허용오차만 고쳤다. 기하·수요·계수 변경 없음.
- 첫8개 예측에서는 접근 불가능한 차로에도 진출 FIFO 속도 제한이 적용되는 오류가 있었다. 출구 접근 차로에만 적용한다는 계약과 모순됐으며, 회귀 테스트에서80km/h여야 할 비접근 차로가48km/h로 내려가는 것을 재현했다. 해당 조건을 고친 뒤 동일 계수·동일8조건을 다시 실행했다. 첫 결과는 형제 `joint_lane_region`에 보존했다.
- 수정본의5개 단위검사 통과: 접근 불가능한 진출행 보존, 동시 합류/진출/차로 이동과 목적지 보존, 과도한 수락 합류의 명시적 실패, origin 이중계상 방지, 접근 차로에 한정된 FIFO 속도 제한.
- 수정본8개450초 예측의 차로 합산 N·Nv와 기존 셀 관측360개가 일치했다. 전체 물리 보존 잔차 최대 약1.28e−12대다. 경로별 잔차는 각 결과의 `joint_route_marginal_max_error`에 저장했다.
- 후보를 끈 기존 경로는 `cells/flows/ports/ramps` 데이터가 저장된 기준과 정확히 같았다. 초기 실패 전 확인까지 포함하면 이번 작업의 완료 계산은 후보16회+기준 재현3회=19회다. 초기화 실패1회 및 경로 길이 제한에 따른 파일 저장 실패도 보존했다.
- Windows 경로 길이 제한으로 중첩 폴더의 소스 복사에 실패한 준비 시도가 있다. 예측 전에 종료됐고, 짧은 형제 폴더인 여기서 실행했다.

`summary.json`, `decision_checks.json`, `lane_comparison.json`은 결과, `protocol.json`은 사전 범위·계수·입력 해시다. `executed_sources/`, `helper_executed.txt`, `test_candidate.txt`, `rejected_candidate.patch`는 실행된 후보를 보존한다. `restoration.json`은 core4개 복원 증거다. 후보 소스는 실행 코드에서 제거했으므로 보존된 소스를 복원하지 않은 상태에서 새 helper의 후보 명령을 재실행하지 않는다.

새 VISSIM 실행·FZP 재읽기·전체 망 보정·SDMPC 실행·push 없음. 기존9000초 STOP 유지. 목표 ACTIVE / NOT_QUALIFIED이며 이 시험의 완료를 전체 이득 보정 완료로 취급하지 않는다.
