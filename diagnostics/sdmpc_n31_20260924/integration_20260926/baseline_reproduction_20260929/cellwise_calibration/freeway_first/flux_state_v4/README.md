# 本선 방출 계산과 상태 예측의 분리

2026-09-30. 동결 expanded036, seed29 초기 NC/RM 두 조건에 대해 기존 450초 예측을 그대로 재실행하면서, 매5초 시점의 canonical1초 유량 배분을 별도로 계산했다. VSL은110으로 같다. 새 계수·VISSIM은 이 진단에 사용하지 않았다.

## 완료 결과

두 자율 예측의 cells/flows/ports/ramps 전체를 같은 JSON 표현으로 비교해 저장 기준과 정확히 일치했다. 각 관측 시점에는 예측 상태 그대로, 실측N만, 실측v만, 실측N+v, 실측N+v+off재고의5개 조건을 계산했다. 유효 조건부900회, 자율450초2회다. 복제한 무변경 상태의 실제1초 유량 차이는0, 셀 보존 최대잔차2.13e−14대였다.

다음은 RM−NC의 하류 통과 변화다. 실측은 실제 경계 누적 통과량, 조건부 값은 매5초 순간1초 유량에5를 곱해 합한 표본 근사다. 따라서 서로 동일한 관측 연산은 아니며 용량의 직접 측정도 아니다.

## 판단

- 셀19·22·23에서는 **현재 방출식도 적절한 차량 수와 속도를 받으면 방출 증가를 표현할 여지가 있다**. 즉시 용량 보너스를 추가할 근거로 보지 않는다.
- 본선의 자율N/v 변화와 그 결합을 먼저 보정할 방향을 지지한다. 다만 순간 상태 치환은 미래 정보를 사용하는 조건부 진단이며, 제어 이득의 자율 예측 검증은 아니다.
- 지난 실측 합류 경계 진단과 함께 보면, 합류 예측만으로 해결되지 않고 본선 상태의 전파·회복 반응이 중요하다.
- 기존 큰 후기RM 손해 예측은 보존한다. 같은 계수 격자를 자동 반복하거나 속도만 맞추는 보정은 하지 않는다.

## 실패 기록과 재현

첫 시도는 중첩 진단 호출이 원래 VSL 감사의 desired-speed 기록 수를 늘려 첫1초에서 중단됐다. 다음 두 시도는 실제 수치 변화가 아니라 저장JSON의list와 메모리tuple 직접 비교 때문에 ramp 동일성 검사에서 실패했다. 세 번째 실패 파일을 JSON으로 대조했을 때 네 배열 모두 기존과 정확히 같았다. 실제 교통값이 변했다는 해석은 철회한다.

최종 시도는 중첩 호출의 감사·문맥·설정을 분리하고 같은 직렬화로 값을 대조했다. 실패 로그/실행 소스는 ../flux_state_source에 보존했다. 최종 유효900조건부 외에 준비 과정에서905조건부 계산, 완결NC450초2회와 첫1초 실패1회가 추가됐다. 중간 실패를 유효 결과 수로 합치지 않았다.

summary.json과 none.json/rm.json은 최종 결과다. 이후 seed61 준비 옵션 추가로 진단 helper의 live SHA는 바뀌었으며, 실행 원문은 ../flux_state_source/replay_v4.py.txt가 그 원래 pin을 충족한다. 정본 물리식·계수·망·기존9000 STOP은 변경하지 않았다.

새 독립 seed61의 네 조건은 별도 heldout61_freeway_20260930에 고정된 모델로 준비했다. 그 결과를 보고 본선의 큰 손익 방향과 선택 순위를 확인한다. 전체망 보정이나9000초 실행의 통과 선언은 아니다.
