**PROGRESS / 이득 검증 미완료.** 이전 목적지별 이동 시간 수정에 이어 저장공간 가설을 검증했다. 단순 앞쪽 저장량 제한은 비활성이라 채택하지 않았다. 대신 기하로 확인된 SC1001의 잘못된 신호 제한 하나를 수정하고 동일 상태 450초 예측 6회를 완료했다. 새 VISSIM·계수 fitting·SDMPC 최적화·push는 없다. 기존9000 STOP과 native 준비 HOLD 유지.

## 1. 앞쪽 저장공간만 줄이면 해결되는가: 이번 자료에서는 아니다

10484 전체 길이는541.911m, head 위치377.111m, 기존 간격은6m다. 전체 저장량90.318대 중 미터 앞의 명목 저장량은62.852대다.

기존 완료된6개 예측의 실제 수용·head 통과·합류 ledger에서 미터 앞뒤 재고를 매초 다시 구성했다. 최대 재구성 오차3.27e−13대. seed47 유지의 최대 앞쪽 재고는53.439대이고 제한까지 최소9.413대가 남는다. seed47 완화는29.046대, seed43 네 조건은14대다. 따라서 이6개 궤적에 단순 앞쪽 용량 제한을 추가해도 걸리는 step은0개다. 이 판정은 현재 저장량 제한 하나의 활성 여부이며 모든 공간적 수용 모델의 무효 판정이 아니다.

제어 이전2250·2400·2550·2700초 자료에서 양쪽 차량 모두1km/h 미만인 인접 간격은8쌍뿐이다. 중앙값6.209m(명목60.741대)을 적용한 민감도도 비활성이다. 평균은7.364m이고5.249–11.733m로 흩어져 있다. 반복 차량과 소수 표본이므로 대표 jam density를 식별했다고 주장하지 않는다. 미래3150초의56대 queue에 맞춰 상한을 정하지 않았다.

실측 유지 조건은3000초에 앞쪽48대, 마지막 차량 위치3.16m이고3150초에는56대·1.31m다. 움직이는 queue의 간격과 출발 파동 때문에 단순 차량 수와 꼬리 위치가 같지 않다. 그 공간적 동역학은 아직 수정·검증하지 않았다.

## 3. 코드에서 확인한 별도 오류: 10121은 정지선 이전 분기

10121은37번 도로1차로의501.320m에서31로 분기한다.37번의 세 신호 head는534.047–534.408m에 있으며10121과31에는 head가 없다. native route1116:3이37→10121→31을 사용한다. 그런데 `SC1001_N_SC2002_to_W_RAMP`는 신호가 있는 다른 이동과 같이 SC1001_p1 녹색으로 제한되고 있었다.

기존 `physical_movement_routes.configure_phase_authority`의 검증된 정지선 이전 분기 처리에 이 경로를 추가했다. 네트워크·route·lane·분기 위치·모든 source head·선택 신호계획을 검사한 경우에만 `unsignalized=True`를 설정한다. 식별용 phase는 유지한다. 전용 runner/adapter나 새 모델을 만들지 않았다.

수용량·이동별 용량206.531대/h·beta·초기 queue·도착 이력은 바꾸지 않았다. 무신호라는 사실은 무제한 방출이나 우선권이 있다는 뜻이 아니다. 기존 접근 대기·service·하류 수용 제약은 남는다.
