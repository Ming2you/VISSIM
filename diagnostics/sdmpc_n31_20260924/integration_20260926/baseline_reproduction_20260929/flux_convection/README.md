# 실제 유량을 사용하는 이류 비교: 이득 개선 없음, 원복

2026-09-29. 기존 정본 모델의1회 기본450초 확인, 대안4조건450초 예측 완료. 추가 fitting/native/push0. 학습 단계의 반응 오차 기준을 통과하지 못해 준비한 seed43/후기 상태8회는 실행하지 않았다.

## 가설과 수정

기존 이류 변화는 `dt_h * v_i/L_i * (v_up-v_i)`다. density/flow가 서로 다른 인접 셀에서 이 가중치가 속도 모멘트 전달을 왜곡하는지 확인하려고, 동일 차량보존 계산의 실제 accepted mainline inflow와 다음 재고를 사용했다.

`delta_v = dt_h * q_mainline_in * (v_up-v_i) / N_after`

출발 재고가 well-mixed이고 램프 차량은 별도 merge 감속 전 현재 recipient 속도를 가진다는 조건에서 속도 모멘트 전달과 맞는 식이다. 합류차 속도를 실제로 관측했다는 뜻은 아니다. 상류 평균보다 빠른 차량의 선택적 이탈도 해결하지 않는다.

전 FW_E31셀에 동일하게 적용했고, 계수·기하·FD·이완·anticipation·lane-drop·merge·수요·VSL 노출 및 ramp/off-ramp 동역학은 유지했다. 기존 최소속도 clipping 및 lane-drop 감속 **앞**에서 이류를 대체했다. 별도의 capacity나 제어 보상은 없다.

진단 run.py에서 기존 CanonicalFreewayModel._config의 런타임 표식만 활성화했다. 정본 설정/runner에 새 실행 경로를 추가하지 않았다. 실행 소스는 executed_sources의 평탄 파일명으로 보존되어 있다. 현재 정본에는 이 표식의 처리 코드가 남아 있지 않다.

## 확인과 복원

기본450초의 cells/flows/ports/ramps 배열은 이전 저장 결과와 정확히 일치했다. 대안4회 최대 포트 보존잔차8.95e-13대. 계수 없이 한 대안만 비교했고 결과를 본 뒤 기준이나 후보 수를 바꾸지 않았다.

최초 준비는 Windows 긴 경로 때문에 helper 실행 소스 복사에서 실패했다. 예측 전 실패였고 run.log를 보존했다. 복사 대상 이름을 평탄화하여 재실행한 세션5671은exit0으로 끝났다. prediction 실패나 미완료 실행을 성공으로 세지 않는다.

area_freeway_accounting.py와 vissim_stackelberg_adapter.py를 저장한 원래 SHA로 정확히 복원했다. 이류항 관측용 helper의 임시2줄도 제거했다. 계산 당시 helper/코어 전체 원문과 해시는 executed_sources.json에 있다. 원복 후 시험 결과를 재현하려면 보존 원문이 필요하며 run.py 단독으로 현재 정본에서 같은 후보가 활성화된다고 가정하면 안 된다.

정본 미채택 / 전체 이득 미검증. 기존9000 STOP 및 native 준비 HOLD 유지. 동일 이류 후보의 계수 세분화는 하지 않는다.
