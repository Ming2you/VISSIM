## 무엇을 재현해야 하는가

기존 성공 사례는 ALINEA와 Carlson-inspired **고정 병목 DSD90**의 결합이다. Carlson MTFC 전체 알고리즘과 같다고 부르지 않는다. 같은 선택망64cf의 seed29 9000초 결과는 동측 본선 TTT−9.39%, 전체Ω−1.17%, 전체도로+미삽입 대기+1.70%였다. VSL 단독의 Ω 개선은−2.32%였다. 범위를 섞지 않는다.

이번 짧은 진단은 그 전체 정책을 다시 실행한 것이 아니다. 기존 공통2220.1초 상태에서2250초부터 VSL90을 적용한450초 분기 실험의 원인 분리다. 동일 초기 상태·현재 모델·실제 명령을 유지했다. seed29/43은 이미 검토된 자료이며 독립 미사용 holdout이 아니다.

## 검증과 실패 기록

- 네 고유150초 관측 사례, 11,400개 실제 속도식 기록. 각 기록의 relaxation/convection/anticipation/lane-drop 재구성과 정본 함수 결과가 일치했다.
- prefix 비교 과정에서 최초1회 재생은 Python 정수 lane-key와 저장JSON 문자열 lane-key를 그대로 비교해 실패했다. 진단 출력을 보존하기 위해 해당1회만 재실행했다. JSON 표현을 양쪽에 동일하게 맞춘 후 수치 변경 없이 정확한 비교가 통과했다. 총 실행은150초5회이며 네 고유 사례다. 실패 자료는 `speed_terms/s29_none_prefix_failure.json`에 남겼다.
- 그 전의 수식 직접 대입 진단은 셀18을 off-ramp 없는 셀로 가정한 사전 검사에서 멈췄다. 실제10481이 셀18에 있어 그 방법을 폐기하고 정본 실행 관측으로 전환했다. 계산 결과는 없으며 `speed_terms/failure.json`, `failed_source.py.txt`에 보존했다.
- 최초 공간 집계는 seed43 무제어 추출manifest에 per-file SHA가 있다는 가정에서 멈췄다. 해당manifest는 원본FZP SHA만 포함한다. flows CSV는 앞선 조건부 진단의SHA와 대조했고, cells CSV는 현재SHA·같은 초기상태·이전 본선TTT 합계 일치로 확인했다. 이전 cells CSV의 per-file SHA까지 검증했다고 주장하지 않는다. `summary.json.source_verification`에 한계를 명시했다.
- 계수와 선택망을 바꾸지 않았다. 실행 중인 다른 작업에 개입하지 않았다. 유효 결과와 실패 자료를 보존했다.
