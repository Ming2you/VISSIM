# SC1001 목적지별 이동 시간 검증 — 2026-09-29

**부분 개선, 제어 이득 검증 미통과.** 기존 완료 VISSIM 자료를 재사용해 450초 후보 예측 6회와 기본 동작 회귀 확인 2회를 완료했다. 새 VISSIM 런, 계수 보정, optimizer 실행, push는 하지 않았다. 변경은 명시적 옵션에서만 활성화되며 정본 기본 설정으로 채택하지 않았다.

## 세그먼트별 보정과의 관계

앞선 [31셀 공동 보정](../cellwise_calibration/RESULT.md)은 31개 셀에 각각 rhoCrit·shape·tau·nuGE·nuLT, 합류 셀 4개에 delta를 허용한 159변수 시험이다. 모든 수집 자료를 사용한 것은 아니다. seed29의 두 초기 상태·8개 학습 궤적과 이미 열람한 seed43의 4개 확인 궤적을 사용했다. 상태만 보정하면 학습 상태 손실은 17.1% 줄었지만 제어 반응 오차는 36.2% 증가했다. 반응을 포함한 보정도 seed43에서 반응 오차가 6.4% 증가했다. 이어진 공동 Jacobian 보정은 학습 반응 오차를 17.9% 줄였으나 seed43 오차는 1.8% 증가했고 RM+VSL 이득 부호를 틀렸다. 이 결과는 개별 셀 보정이 불가능하다는 증명이 아니다.

따라서 추가 계수 탐색 전에, 실제 합류량과 대기 비용의 입력이 잘못 전달되는지 확인했다. 이번 변경은 METANET 계수가 도시 접근 경로 오류를 대신 설명하지 않도록 하는 작업이다.

## 확인한 원인과 변경

SC1001_W_out의 기존 보내기 계산은 1.9595km 전체 길이를 사용했다. 그러나 동측 10484 분기는 링크31의 약412.087m 지점에 있다. 길이 전체를 짧게 바꾸면 서측 램프와 망 밖 목적지까지 너무 빨리 보내므로 목적지별 경로를 보존했다.

- 정본 INPX의 decision1137에서 동측10484 / 서측10480 / 망 밖 비율 1/2, 1/3, 1/6과 각 분기까지의 거리를 읽는다. 기존 집계표는 1/2, 1/4, 1/4였다.
- 기존 단일 도시 재고 안에서 목적지·도착 가능 시각을 추적한다. 수용량에 막힌 차량의 목적지를 다시 뽑거나 별도 재고로 중복 계상하지 않는다.
- 목적지까지 이동 시간을 지난 뒤 기존 지수형 이동 지연을 다시 부과하지 않는다. 기존 램프 수용량과 유출 상한은 유지한다.
- 10483에서 들어오는 차량은 원래의 망 밖 목적지를 유지하고, 링크124 진입 위치부터 남은 거리만 사용한다.
- 초기 관측에 과거 route ID가 없어 현재 위치에서 도달 가능한 목적지의 native 비율로 기대값을 배정한다. **실제 개별 차량 목적지를 복원한 것이 아니며**, 이미 분기를 지난 차량을 그 램프에 재배정하지 않는다. 링크124의 초기 차량에는 직접 진출 차량이 섞였을 수 있어 불확실성이 남는다.
- 별도 SC2001 접근 경로는 기존 모델을 유지한다. 새 경로에 흡수하지 않았다.

옵션: `urban.sc1001_destination_travel = {"initial_unknown":"reachable_native_prior"}`. 기존 `preserve_direct_offramp_destinations=true`가 필요하다. 미래 실측 도착량·방출량은 예측에 주입하지 않았다.

완화−유지의 **전체 Ω ΔTTT**는 실측 +2.054veh·h, 기존 +0.473, 변경 후 +0.776이다. 큰 손해 방향은 유지하고 차이는 줄었지만 아직 과소 예측한다. 본선 비용 증가는 변경 후 +4.045, 10484 램프 대기 비용 감소는 −3.179veh·h다. 외부 비용은 목적함수에 넣지 않고 별도로 보존했다. 실측 외부 체류 차이 −0.499veh·h도 아직 재현하지 못한다.

실제 완화 시 도착이 11대 늘었는데 예측은 늘지 않는다. 앞선 차량 식별 진단에서는 그중 공통 초기 차량 10대가 유지 조건에서 링크31의 저속 대기 상태로 남았다. 이번 변경은 기본 도착량을 개선했지만, 램프 입구 대기열이 접근 차량을 막았다가 풀어주는 반응까지 해결하지 않았다.

## 다른 상태 확인: seed43, 2250–2700초

모든 숫자는 전체 Ω의 NC 대비 ΔTTT[veh·h]이며, 음수가 개선이다. 위 31셀 구성요소 보정 표의 평가 영역과 다르므로 직접 혼용하지 않는다.

| 조건 | 실측 | 기존 예측 | 변경 후 |
|---|---:|---:|---:|
| RM | −1.547 | −0.016 | −0.035 |
| VSL | +0.777 | +0.202 | +0.144 |
| RM+VSL | −1.453 | +0.188 | +0.112 |

8개 램프·모든 조건의 평균 절대 오차는 도착 9.52→8.58대, 합류 9.03→7.92대, 종료 재고 5.38→5.36대로 변했다. 10484 NC 합류는 68.41→73.62대(실측81대)로 개선했다. 그러나 RM+VSL 이득 부호가 틀리고 RM 이득 크기도 여전히 너무 작다. VSL 손해 방향은 유지했지만 손해 크기는 오히려 더 과소 예측한다. **다른 상태에서도 이득 예측이 개선됐다고 판정하지 않는다.**

## 검증과 범위

- 후보 6회와 옵션 OFF 2회, 총 8회 예측 완료. 옵션 OFF는 이전 실행의 모든 case 결과가 wall_sec를 제외하고 정확히 일치한다.
- 같은 초기 상태·명령표·450초·150초 제어 블록 3개를 사용했다. 실행값과 step 제약 검사를 통과했다. 이번에 N_P/N_UF 후보 선택이나 SDMPC 최적화를 새로 검증한 것은 아니다.
- 8개 램프 차량 보존 잔차 최대 5.76e−13대. 목적지 추적은 기존 물리 재고의 별칭이며 추가 차량이 아니다.
- 관련 19개 테스트 통과. 이동 완료 시각, 분기 도달 가능성, 목적지 보존, 수용량 차단, 직접 진출, 설정 의존성을 검사한다.
- 실제 instrumented AD에서 buffer 수량의 forward/reverse 미분과 유한차분 비교 통과. reverse 최대 오차 약1.1e−11. **전체 SDMPC rollout AD 또는 이산 도착 시각의 미분 검증은 아니다.**
- 초기 테스트·환경 import 실패 로그도 보존했다. 기존 설치 의존성을 읽어 최종 확인했으며 새 설치는 없다.
- 최종 설정 의존성 guard는 예측 완료 후 추가했다. 해당 guard가 통과하는 enabled/disabled 설정으로 이미 8회 실행했으므로 수치 경로 변경은 없다. `source_after/`는 예측 시점의 자동 snapshot이 아닌, guard와 최종 테스트를 포함한 최종 소스 보관본이다.
- 원시 VISSIM 오류·삭제와 TTD의 기존 제한은 그대로다. 새 정상 종료 차량 수나 성능 향상률을 주장하지 않는다.

다음 원인 후보는 미터 head 이전의 대기 공간과 head 이후 빈 공간을 합쳐 램프 입구 수용량으로 사용하는 문제다. 현재 전체 길이 기반 저장량은 약90.3대지만 head 이전 길이 기준은 약62.9대(기존6m 간격 가정)다. 실측 미래 재고에 맞춰 임의 상한을 넣지 않고, 과거 관측·기하로 입구 차단 및 완화 시 추가 도착을 설명하는지 먼저 확인해야 한다. 이후에만 필요한 셀 계수의 제한적 재보정을 판단한다.
