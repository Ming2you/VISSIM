# 최종 선택에서 유지 명령이 빠진 사례 — 2026-09-28

## 확인된 원인

완료된 수정 SDMPC9000은 Ω TTT가 무제어보다 98.45 차량·시간(+1.36%) 크다. 이 전체 차이를 설명했다고 주장하지 않는다. 그중 2700/3750/8400초에서 **모델 자체가 더 좋게 예측했고 제약도 만족하는 유지 명령이 최종 비교에서 빠진 것**을 확인했다.

현재 PFO는 19개 제어 주체의 소유 비용 합을 줄여 초기값을 만든다. Ω 안에 있지만 직접 소유자가 없는 재고의 비용 `PASSIVE_OMEGA`는 이 초기 탐색의 merit에서 제외된다. 이후 SDMPC는 전체 Ω 비용을 쓰지만, 실제 실행 가능한 탐색 개선안이 없으면 PFO 초기값만 유지했다. 원래의 실제 명령 유지안은 후보로 복구되지 않았다. PFO 자체의 목적을 변경할 필요와 이 최종 후보 누락은 별개다.

|기록 시각|선택−유지 Ω 예측 TTT|소유 비용 변화|PASSIVE_OMEGA 변화|유지안 제약 적합|
|---|---:|---:|---:|---|
|2700초|+0.507335|−2.389619|+2.896954|통과|
|3750초|+2.330708|−1.538107|+3.868815|통과|
|8400초|+0.173546|−0.872489|+1.046035|통과|

단위는 차량·시간이다. `PASSIVE_OMEGA`는 Ω 밖 대기와 다르다. 위 변화는 같은 초기 상태의 450초 예측이며 실현된 이득이 아니다. 겹치는 지평의 수치를 합쳐 실제 개선량으로 쓰지 않는다.

## 최소 재현

기존 `probe_selected_arrival_path.py`에 `--held-budget-check`를 추가했다. 실제 adapter의 상태·예측 초기화와 SDMPC의 원래 PFO 진입점을 그대로 사용하고, 원래 명령을 한 번 예측한 뒤 최적화 전에 종료한다. 기존 결정의 최종 N_P/N_UF cap과 비교하며 과거·미래 명령을 변경하지 않는다.

- 3개 예측 모두 원래 기록의 유지 비용을 0~1.14e−13 오차로 재현했다. 모델·writer·물리 제약을 통과했다.
- 3750초의 유지안은 N_P 467.907917 ≤ cap 544.986602대, N_UF 5638.199702 ≤ cap 5807.912080대/h였다. 제약 때문에 더 나쁜 안을 선택해야 했던 상황이 아니다.

- 소스 변경 전 archive: `executed_sources/sdmpc_before_feasible_held_930f42398e08.py.txt`, `executed_sources/probe_selected_arrival_path_before_held_budget_ce2496e4f89d.py.txt`.

## 좁은 수정과 검증 상태

`evaluation/controllers/sdmpc.py`의 최종 cap-mode 선택에서만, 원래 유지 비용이 현재 최선보다 낮으면 그 명령을 **현재 최종 cap으로 다시 예측**한다. 동일한 물리·수량 제약을 만족하고 전체 Ω 비용도 더 낮을 때 최종 후보로 남긴다. 선택된 명령은 원래의 writer·3블록 검증을 다시 거친다. 탈락한 명령의 가격 갱신 신호는 가져오지 않는다.

PFO merit, N_P/N_UF 정의와 cap 생성, 제어 범위·주기, METANET 계수와 목적함수는 바꾸지 않았다. 유지안보다 이미 좋은 후보가 있으면 추가 예측은 없다. 유리한 유지안을 확인할 때만 최대 1개 예측이 추가된다. cap-mode 외 경로는 그대로다.

- 새 회귀 검사 4개 및 기존 PFO·중앙 제약·surrogate 재사용 검사 합계 **46개 통과**: `held_candidate_tests.log`.
- 수정 전 검사 실패 기록을 보존했다. 최초 검사 fixture 오류는 `held_candidate_before_test.log`, 실제 ControlAction으로 바로잡은 뒤 누락을 확인한 기록은 `held_candidate_before_test_valid_fixture.log`다.
- 실제 3750초 상태의 SDMPC 한 주기 재계산·최종 제약·writer 검증도 **완료**했다(exec21970 exit0). 기존 선택 476.339856 대신 유지 474.009149를 선택했다. 물리 명령 CSV의 213개 행은 실제 직전 명령과 정확히 같다(설명용 metadata 제외). `closedloop_recorded3750_select_heldguard/unused_action.joint_written.json`, `held_writer_comparison.json` 참조.
- 해당 한 주기 계산은 adapter 기준 190.95초였다. PFO는 상한2회/실행2회/수락1회, SDMPC는 상한2회/실행1회/수락0회이며 수렴을 주장하지 않는다. 마지막 유지안 확인에 scalar 예측 1개(17.29초)가 추가됐다. 전후 실행 환경이 달라 전체 계산시간의 개선율을 주장하지 않는다.
- 이 수정으로 새 VISSIM은 실행하지 않았다. 완료된 9000초 결과와 동결 runtime은 변경하지 않았다. 새 순이득이나 플랜트 보정 완료를 주장하지 않는다.

다음에는 별도의 공통 초기 상태에서 VSL 유지/해제의 짧은 native 반응 순위를 확인한다. 이번 후보 누락 수정만으로 VSL/RM 이득 예측 문제가 모두 해결됐다고 보지 않는다. 현재 소유 계산은 모두 종료됐으며 native 런은 새로 시작하지 않았다. 목표는 ACTIVE다.
