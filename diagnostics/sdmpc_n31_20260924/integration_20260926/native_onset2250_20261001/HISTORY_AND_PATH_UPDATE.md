# 과거 입력 동등성 확인과 기존 물리 경로 후보의 네 조건 대조

2026-10-01. 이전 목표 턴과 이번 턴 모두 **progress**, 전체 목표는 **ACTIVE / NOT_QUALIFIED**다. 별도 CTG 런은 조회하거나 변경하지 않았다. 새 VISSIM/FZP 읽기/계수 fitting/최적화/push는 없다.

## 1. 모델이 사용한 과거 입력 차이는 배제했다

원래9000과 새 onset2250 기준 런의 현재 물리 관측은 같다. 하지만 과거1950초 차량1대 위치와2100초 큐 검지기의 소수점 값이 달라, 이전 보고서에서는 예측 비교를 조건부로 남겼다.

이번에는 기존 정본 head observer와 VSL cohort observer를 **각각150–2250초의15개 창에 실제로 실행**했다. 원래/새 런의 실제 provenance·각 native tuning SHA를 따로 검증하고 각 이력을 처음부터 누적했다. 예측/최적화 endpoint는 호출되면 실패하도록 막았다.

- Head의 수치 metadata, movement별 용량, 물리 head resource가15개 창 모두 정확히 같다. 비교 때만 run/config identity에서 유도된 hash 이름을 정규화했으며 key 충돌이 없음을 검사했다. 실행 입력의 provenance를 바꾸지는 않았다.
- VSL 과거 readback, 셀별 차량 구성(cohort), 보존·노출 감사값도15개 창 모두 정확히 같다. 명령을110으로 재설정하거나 다른 런의 cohort를 복사하지 않았다.
- 물리적으로 파생된 head/경계/차로 관측의 차이는 실제 native replay tuning을 가리키는 `head_window.config_sha256`뿐이었다. 각 hash가 자신의 원본 파일과 일치함을 따로 확인했다.
- 따라서 **2250 현재 상태와 해당 예측이 소비하는 head/VSL 이력의 동등성은 통과**했다. 앞선 사전 예측과 새 네 native 조건의 비교에서 과거 입력 차이를 미해결 원인으로 남길 필요는 없다.
- 원래9000 raw FZP prefix의 완전 재현 실패는 별개이며 그대로다. `analysis/summary.json`과 실패 로그는 수정하지 않았다. 전체9000의 동일 궤적 재현이나 seed 간 일반화가 통과했다는 뜻도 아니다.

근거: `history_qualification.json`, `observer_replay_v3/summary.json`. 최초 파생 관측 비교의 config hash 차이, 진단 wrapper의 시각 필드 처리 오류2건은 로그·이전 소스로 보존했다. 마지막 실행은 정상 종료했고 native 원자료에 쓰지 않았다.

## 3. 다음 작업의 판단

강한 seed47 RM 유지/완화 상태의 SDMPC 연결은 이미 수행됐고, RM 명령도 선택된 기록이 있어 같은 선택 계산은 반복하지 않았다. 그 증거와 이번 결과를 합치면 “RM 연결이 전부 끊어져서 안 켜진다”는 설명은 맞지 않는다. 원래 seed29의 g9=g10 평탄 구간과 실제 작은 합류 변화는 별도로 남는다.

**생산 설정에는 이번 후보를 채택하지 않았다.** 도시 도착·물리 이동시간 수정만으로는 VSL의 본선 방출·회복 응답을 설명하지 못한다. 다음은 저장된 본선 반응에서 VSL 해제가 바꾼 도착·통과·회복을 예측과 시간별로 나누어, 현재 FD/속도식 또는 실제 수용 상한 중 어디에서 민감도가 사라지는지 확인하는 것이다. 이미 실패한 전역 merge/anticipation 계수 탐색이나 작은 onset 손익 fitting을 다시 시작하지 않는다. 이전에 별도로 기각된24–25 FD 후보를 자동 채택하지도 않는다.

이 실험은 native 결과를 이미 본 뒤의 제한된 후보 검증이며 blind holdout이 아니다. 기존 독립 RM 결과·삭제/미삽입/외부 비용 한계를 유지한다. 아직 새9000을 성공 검증으로 실행할 단계는 아니다.
