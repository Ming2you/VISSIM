## 정본 코드에 구현한 선택적 수정

`route_choice_corridor.py`의 기존 known-W_out 경로 보존기에 두 옵션을 추가했다.
선택 설정의 기본값은 여전히 OFF이고, 아래 검증은 진단 드라이버가 해당 옵션을 켠 경우다.
새 adapter/실행기를 만들거나 vendor를 수정하지 않았다.

1. `urban.known_wout_native_choice_prior`: 미래1135 선택만 현재 망의1/1/3 가중치로 나눈다.
   현재 이미 선택된 목적지, 선택 지점 이후 unknown,1130:3 직접 통과 차량은 재배분하지 않는다.
   단일 시간 구간·all vehicle types·static·경로·목적지·formula 부재를 확인한다.
2. `urban.known_wout_physical_travel`: 실제 connector/링크 위치로 목적지별 이동 지연을 계산한다.
   관측 초기 차량은 현재 위치·속도·현재 route를 사용하고, 미래 차량은 현재 모델의 속도
   정보와 실제 이동 경로를 사용한다. 기존 속도 하한 규약을 유지한다. 미래 실측 속도나
   도착 시각을 넣지 않는다.1135 도달 후 한 번 선택하며 수용 거절 시 그 목적지와 재고를 유지한다.

기존 SC1004_W_out 배수율에 쓰인1.9902km는123 통과 꼬리까지 포함한다. 현재10681 분기는
68 진입 후 약118m 지점이다.123은 실제 초기화에서도 별도 SC1004_W_tail 재고다.
기존 모델은 도착 예약이 끝난 차량에도 긴 거리를 사용하는1/τ를 다시 곱했다.
수정에서는 신호 방출→1135→각 램프 진입/기존 통과 경계의 이동 예약을 한 번씩 적용한다.
그 뒤 기존 connector 서비스 상한·램프 수용 공간·미터·본선 수용 계산을 그대로 거친다.
새 신호등이 이 이동 경로 안에 생기면 미모델 신호를 우회하지 않도록 실패 처리한다.

`urban_flow_accounting.py`와 `lane_offramp_runtime.py`는 이 옵션이 예약을 소유할 때
기존 집계 이동 예약을 중복 생성하지 않는다. 실제 source stock 및 Ω ledger의 소유권은 유지한다.
선택적 이동 예약·경로 선택·수용 거절·초기 관측 보존과 기존 도시 유량 회귀 **25 tests 통과**.
[로그](transport_regression_tests.log). `git diff --check` 통과. 새 옵션의 SDMPC 미분/worker 검증은 아직 별도다.
