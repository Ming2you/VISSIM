## 확인한 원인

SC1002 동측 접근로는 정적 결정1113의 경로1/2/3으로 29/73/420번 도로에 분기한다. 현재 선택망의 상대유량은 **5:1:1**이다. 실제 초기화는 기본 `routing` 출처의 2026-08-24 표를 읽어 **1:1:5**를 적용했다. 따라서 29번 도로→SC1001→램프로 가야 할 희망 수요 상당량을 다른 도시 도로로 예측했다.

이는 이번 관측 통과량으로 비율을 추정한 것이 아니다. 선택망의 이미 설정된 입력을 잘못 연결한 문제다. v3b 표에는 같은 접근로의 올바른 값이 있지만, 별도 망 전체 표를 가져오면 다른 접근로도 바뀌므로 그대로 교체하지 않았다.

## 수정과 검증 범위

- 기존 `physical_movement_routes.py`와 `runtime_setup.py`에서, 초기화 시 검증된 native 경로 비율을 서비스율 계산·상태 투영 전에 적용한다. 이번 계약은 SC1002 동측 세 이동만 포함한다. 새 adapter는 없다.
- 설정한 native 경로 전체, 연속성, 원점/수신 권역, 양의 상대유량, 추가 입력·하류 재선택 부재를 확인한다. 현재 망에서329에 도달하는 static route는1113:1/2/3뿐이다. 원점 총수요를 바꾸거나 기존 차량을 삭제하지 않는다.
- 경로 중간10518은322→325의 병렬 connector이며 독립 유입이 아니다. 첫 검사에서 이를 별도 입력으로 잘못 거부했다. 실제 양끝이 같은 접근로 안에 있음을 확인하는 검사로 보완했다. 실패 이력은 `native_choice_audit.json`에 남겼다.
- 기존 설정에 이 계약이 없을 때, 동일2250초 초기화의 전체 audit(출력 경로가 다른 source_hashes 제외)이 수정 전과 정확히 같다.
- 6개 단위검사와2개 subtest 통과. 누락 경로·다른 목적지·잘못된 망·새로운 중간 입력/경로 결정은 거부한다. 실제 저장 상태 초기화도 망 SHA와 관측 이력을 검증한다.
- seed43 공통2250초의 NC/RM/VSL/both4회, seed47 공통2700초의 유지/기존 도시 포함 선택 명령2회, 각각450초를 계산했다. 명령은 전후 동일하고 미래 관측은 예측에 넣지 않았다. seed47은 새 학습에는 쓰지 않았지만 과거 진단에서 이미 본 상태이므로 완전히 새로운 독립 holdout은 아니다.
