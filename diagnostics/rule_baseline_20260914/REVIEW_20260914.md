# 100km/h 기준 무제어·VSL·RM·병용 검토

이번 네 조건에서는 실제 TTT 개선이 나오지 않았다. 그렇다고 모든 결과를 “plant가 제어 이득을 놓친 탓”으로 설명할 수도 없다. **RM10639의 합류량 변화 없음은 실제와 모델이 일치했고, VSL의 하류 속도 반응에서는 모델이 방향까지 틀린 사례가 확인됐다.** 다음 수정은 이 둘을 구분해서 해야 한다.

## 실험과 실행 검증

고속도로80%·도시50%, seed13, 각0–3000초. 처음부터100km/h·미터 개방·기존 도시 신호를 사용했고, 규칙 제어는900초부터150초마다 갱신했다. 네 런은 다음과 같다.

- 무제어: `rule100_none3000_s13_v1`
- VSL: `rule100_vsl3000_s13_v2`
- RM: `rule100_rm3000_s13_v2`
- 병용: `rule100_both3000_s13_v3`

모두 완료 확인서와 실제 LDP·VSL readback 검증을 통과했다. 각 조건144개 SG의432,000개 native 상태 표본, 23,992개 미터 명령 시계 대조에서 불일치0이다. VSL은66개 DSD×4개 차량종류×21회 적용 readback을 확인했다. 도시136개 SG의 상태는 네 런에서1–3000초 내내 같았다. LSA의 COM 기록 누락은 독립 실패로 유지하며, 사용자 승인에 따라 LDP를 대체 증거로 사용했다.

처음900초의970,296개 차량 표본은 시간·ID·link·lane·position·speed를 canonical parser로 읽은 값의 해시가 네 런에서 정확히 같다. 원시 FZP의 모든 열이 바이트 동일하다는 뜻은 아니다. 저장된 관측과 head 이력도 같다. 수정된 VSL60 지원 목록 외 물리 모델·수요·신호 설정은 바꾸지 않았다. 실패했던 런은 비교에서 제외하고 원본을 보존했다.

## 실제 교통 결과

TTT는 Ω=고속도로+도시 protected network 내부 체류시간이다. TTD는 살아서 Ω 밖으로 나간 관측 사건과 검증 가능한 말단 유출이며, 내부 이동·비정상 삭제·미확인 소실·종료 잔여를 포함하지 않는다.

| 조건 | TTT0–3000 [차량·시간] | 무제어 대비 변화 | TTD [사건] | 종료 Ω 차량 수 |
|---|---:|---:|---:|---:|
| 무제어 | 1,391.645 | 기준 | 10,663 | 2,712 |
| VSL | 1,436.905 | +3.252% | 10,538 | 2,790 |
| RM | 1,395.601 | +0.284% | 10,667 | 2,720 |
| 병용 | 1,439.189 | +3.416% | 10,520 | 2,810 |

양수는 TTT 악화다. 제어가 실제 노출된900–3000초만 비교하면 각각+3.793%, +0.332%, +3.984%다. 아직 수요 감소·회복까지 평가한9000초 결과는 아니며, 단일 seed의 작은 차이에 통계적 유의성을 주장하지 않는다.

VSL의 TTT 증가45.260차량·시간 중 본선 증가가49.203이고, 도시·기타와 램프 connector 비용은 합쳐 약3.942 감소했다. 제한속도로 인한 본선 체류 증가를 상쇄하는 처리량 이득은 이번 기간에 관측되지 않았다.

VSL과 병용에서는 입력1099에 각각54대의 미삽입 잔여가 있었다. 경고1건을 차량1대로 세지 않았다. Ω 밖의 이 입력 대기시간은 정의상 ΩTTT에 포함되지 않는다. 따라서 수요 설정이 같아도 실제 망에 들어온 차량 조건까지 완전히 같다고 할 수 없고, 이 결과를 미삽입 없는 동일 총수요 처리 성능으로 확대하면 안 된다.

네 런의 native 차량 삭제는46/41/40/43대, Ω 미확인 소실은98/90/89/93건이다. 두 수치는 영역과 의미가 달라 중복 가능하며 합산하지 않는다. 말단 삭제 충돌과 램프 connector 건너뜀 후보는 모두0이다. 도시 경로 오류도 남아 있다. DLL 원본에는 네 조건 공통으로 COM 미터8개의 native signal program 부재가 기록돼 있으며, 실제 미터 전환은 별도 LDP로 확인했다. 자세한 근거는 [품질 요약](native_quality_summary.json)에 있다.

## 실제로 무엇이 움직였나

VSL 단독과 병용의 VSL 일정은 같았다. 서측 seg0은1050초부터60km/h, seg5는1350–1500초와1650초 이후60km/h였다. 실제80km/h 명령은 발생하지 않았다. 동측 seg5의 첫60 명령은3000초이므로 이번 교통 결과에 노출된 시간이0초다. 따라서 이번 VSL 실험은 사실상 **서측 두 구역 제한**의 결과다.

RM 단독은10639가1650초 g9에서 시작해2400초 g7,2550초 g5,2700초 g3,2850초 g2로 줄었다. 다른7개는 검지점 점유율이15% 미만이어서 g10이었다. 병용에서는10639가 g8→g7→g8 등의 변화를 거쳐2850초 g5,10480은2700초부터 g8이었다. 나머지6개는 g10이다. 미터는10초 RG 주기이며 실제 직전 녹색 대비±2초 제약을 유지했다.

그런데10639의 **900–3000초 실제 본선 합류량은 네 조건 모두66대**였다. NC와 RM의150초 표본 최대 connector 재고도4대로 작았다. RM은 신호를 바꾸고 차량을 잠시 지연시켰으나, 이 기간의 누적 합류량을 줄이지 못했다. 이66대를 램프행 희망 수요라고 해석해서는 안 된다. 상류 경로·신호·차로 접근 때문에 도착하지 못한 램프행 차량은 별도 추적해야 한다.

- 무제어 동측은 E8에서1800초, 상류 E7에서2040초, E6에서2250초, E5에서2730초로 저속 구간이 확장됐다. RM 조건도 E8·E7의 시작 시점이 같아 뚜렷한 예방 효과를 보이지 않았다.

E8의 차로별 저장 관측도 확인했다.1650초에는1차로32대 중12대가 정지했고 평균33.9km/h였지만, 다른 차로는82–100km/h였다.1800초에는1차로44대 중19대 정지·평균12.3km/h, 다른 차로는약75–97km/h였다.2400초에는1차로가5.4km/h,2차로21.5km/h로 악화됐지만3·4차로는90–101km/h였다. **차로 한쪽에 집중된 병목을 구간 평균만으로 표현하기 어려운 상태가 실제로 존재한다.** 이 관측만으로 출구행 차량이 유일한 원인이라고 확정하지는 않았다. ## plant는 제어 반응을 맞췄나

기존 plant에서450초 예측16개를 실행했다. 최초 상태·그때의 수요 예측을 유지하고, 해당 기간 실제 적용된150초 명령3개를 사후 재생했다. 미래 관측으로 상태를 다시 맞추지 않았다. 이는 실제 명령에 대한 조건부 반응 비교이며, 미래 명령을 모르는 온라인 MPC의 성능 증명은 아니다.

900초는 네 조건 모두 같은 초기 상태다.1650초에는 NC↔RM, VSL↔병용의 초기 관측·head 이력·그 이전 실제 명령이 정확히 같다.1650–2100초의 각 쌍에서는10639 미터만 달랐다. 이 두 시점의 비교는 제어 반응을 분리해 볼 수 있다.1800/2400초의 각 정책은 이미 다른 상태에서 시작하므로 그 사이 비용 차이를 같은 초기 상태의 후보 순위라고 부르지 않았다.

**VSL:** 초기450초 TTT의 손해 방향은 맞았지만 크기는 과소평가했다. W5의 같은 시각 속도 표본 평균 변화는 실제−10.65km/h, 예측+3.44km/h로 방향도 반대였다. W4는 실제−24.51, 예측−9.43km/h였다. 따라서 속도제한이 차량에 적용되는 위치, 이동 지연, 하류 도착·밀도 반응의 연결을 검토할 구체적인 반례가 생겼다.

**RM:**1650–2100초10639의 실제150초 합류량은 NC=RM `[7,8,6]`, VSL=병용 `[6,9,6]`이며 각 쌍의 말단 재고도 같다. 모델도 합류량과 상태가 같았다. 모델의10초별 가용 재고는 최대2대인데, OPEN 요청 상한4.2대를 g9의3.69대 또는 g8/g7의3.24/2.79대로 낮춰도 실제 방출을 제한하지 못했다. 이번 “합류량 변화 없음”은 일부 실제 현상과 일치한다. 이를 억지로 이득으로 바꾸는 보상항이나 capacity drop을 넣을 근거는 없다. 다만 초 단위 지연과 후속 궤적 차이까지0이라는 뜻은 아니다.

**절대 예측:** 기본12개 창의 초기 Ω 재고 차이는0–2대에 불과했지만450초 TTT는4.3–12.7% 과대, TTD는414–527대 과소였다. 무제어1800–2250초 E8 속도는 실제28.9 / 예측97.0km/h였고, W7은 실제81.4 / 예측35.5km/h로 반대 방향의 오차가 났다. 램프별로도2400–2850초10482 합류는 실제61 / 예측117.0대,10646은 실제99 / 예측48.2대였다. 합계를 맞추는 보정만으로는 이런 오차가 상쇄될 수 있다. 수요 예측·도시 방출·경계·시간 지연 기여는 아직 분리하지 않았으므로 특정 FD 식 하나의 오류로 단정하지 않는다.

## 권장 방향

1. **현재 게임·탐색기 확장보다 물리 반응 검증을 먼저 한다.** 이번 단순 제어에서 실제 이득이 확인되지 않았으므로 “유리한 후보를 게임이 놓쳤다”는 결론부터 내리지 않는다.
2. **VSL은 공통900초 W4→W5 반응을 우선 진단한다.** 실제 명령의 공간 적용과 도달 시간을 고정하고, 감소한 속도가 하류 도착·재고에 전달되는 과정을 비교한다. TTT 부호뿐 아니라 W5 반응 부호를 검증 기준으로 삼는다.
3. **E8은 차로 집중 대기와 분기·합류의 수용량을 표현하는 최소 상태를 검토한다.** 전체 속도식을 복잡하게 만들기 전에, 정체 차로와 통과 차로를 구분한 재고·방출·spillback이 필요한지 확인한다. 차량 보존과 도시·램프 대기 비용은 유지한다.
4. **RM은 램프별 희망 수요→실제 도착→서비스→합류를 구분한다.**10639의66대는 도착한 결과다. 다른 램프의 과대·과소 예측도 따로 확인하고, 실제 합류량이 달라지는 상태에서만 제한의 이득을 평가한다. 이번 비제약 구간에서는 모델도 변화 없음으로 남아 있어야 한다.
5. 이 반응 검증을 통과한 뒤 작은 중앙집중 후보 비교와 기존 다중 주체 선택을 비교한다. 지금은 임계점유율을 무작정 낮추거나 모든 미터를 강제로 움직여 개선이라고 판정할 단계가 아니다.

이번 검토에서는 새로운 VISSIM 런, plant 물리식 수정, 파라미터 재적합을 하지 않았다. 분석 코드·요약·그림만 추가했다. 상세 재생 근거는 [plant 검토](PLANT_REPLAY_FINDINGS.md), [수치 표](plant_replay_windows.csv), [실행 감사](actuation_review.md), [native 품질](native_quality_summary.json), [성능 분해](review_v1/performance.csv)에 보존했다.
