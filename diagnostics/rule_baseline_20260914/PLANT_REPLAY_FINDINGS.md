# 완료된 100 km/h 기준 네 조건: plant 재생 검토

2026-09-14. 새 VISSIM 런이나 물리 모델 수정 없이 완료된 실제 명령을 기존 plant에 재생했다.

## 비교의 성격과 검증

- 조건: 무제어 `rule100_none3000_s13_v1`, VSL `rule100_vsl3000_s13_v2`, RM `rule100_rm3000_s13_v2`, 결합 `rule100_both3000_s13_v3`.
- 각 조건의 900, 1800, 2400초에서 시작하는 450초 예측 12개와, 첫 RM 개입인 1650초의 짝 비교 4개를 완료했다. 각 재생은 초기 관측 한 번과 그때 만든 수요 예측을 사용한 기존 450초 endpoint 한 번이다. 미래의 실제 명령 세 개는 사후 입력하지만 미래 관측으로 상태나 수요를 갱신하지 않는다. 실제 MPC의 온라인 예측 성능을 그대로 뜻하지 않는다.
- 900초 네 조건은 network/provenance 경로, run id, signal-window config SHA 네 metadata 항목을 제외한 모든 관측·head 이력이 같다. 1650초에는 무제어↔RM, VSL↔결합이 같은 조건을 만족하며 1–1500초의 모든 직전 물리 JSON·CSV 명령도 같다.
- 1650–2100초의 두 짝에서 VSL·도시 green·offset은 계속 같고, RM10639 녹색만 다르다. 무제어↔RM은 10→9초, VSL↔결합은 10→8/7/8초다. 따라서 이 구간은 metering 반응을 별도로 검토할 수 있다.
- 900초와 1650초의 공통 분석 설정은 NC 설정의 `vsl_set`에 실제 실행한 60 km/h를 추가한 사본이다. 이것 외 변경은 없다. 실행 당시 원본 설정은 보존했다. 설정 차이와 SHA는 `common_config_proof.json`에 있다.
- 16회 모두 실제 JSON의 VSL·meter rate·green·offset과 model 적용값이 정확히 일치한다. CSV VSL 값 및 meter 녹색도 JSON과 일치한다. 실제 native 실행 성공 여부는 별도의 LDP·VSL readback 검증을 따른다.
- 새 `compare.py` 변경은 1650초 공통 초기 상태를 허용하고 직전 물리 JSON/CSV 동일성을 강제하는 진단 부분에 한정했다. native 집계나 물리 모델은 바꾸지 않았다. 기존 held-command 450초 endpoint와 재생 endpoint의 완전 일치 증명은 `replay_existing2400_smoke_v2/summary.json`에 있어 반복하지 않았다.

## 제어 변경에 대한 예측 차이

TTT는 Ω 내부 체류시간[veh·h]이다. 아래 차이는 제어 조건−대조 조건이므로 양수는 비용 증가다.

| 같은 초기 상태 비교 | 실제 ΔTTT | plant ΔTTT | 실제 ΔTTD | plant ΔTTD |
|---|---:|---:|---:|---:|
| 900–1350: VSL−무제어 | +0.770278 | +0.191420 | −18 | −2.759983 |
| 1650–2100: RM−무제어 | +0.233611 | 0 | −15 | 0 |
| 1650–2100: 결합−VSL | +0.197639 | 0 | −6 | 0 |

900–1350초 RM은 실제로 계속 열려 있어 RM=무제어, 결합=VSL이다. 이 창을 metering 작동 검증으로 쓰지 않았다.

VSL에서는 해당 초기 구간의 비용 방향은 맞았지만 크기와 공간 반응은 맞지 않았다. 1050초부터 서측 첫 VSL 구역을 100→60 km/h로 바꾼 후, 900–1350초의 동일 시각 30초 표본 평균에서 W4 속도 변화는 실제 −24.51 km/h, 예측 −9.43 km/h였다. 바로 하류 W5에서는 실제 −10.65 km/h인데 예측 +3.44 km/h로 방향도 반대였다. 이는 속도제한의 공간 적용·이동 지연·하류 밀도 응답을 구분해 확인할 지점이다. 이 자료만으로 원인을 하나로 확정하거나 VSL의 일반적 이득/손해를 결론내리지 않는다.

1650초 RM 비교에서는 **모형의 합류 변화 없음이 실제와도 일치하는 부분이 확인됐다.** RM10639의 세 150초 구간 실제 합류 대수는 무제어=RM `[7, 8, 6]`, VSL=결합 `[6, 9, 6]`이다. 각 짝의 450초 합류량은 모두 21대이며 150초 말단 connector 재고도 같다. 모형의 두 짝은 150초 ΩTTT, 30초 cell 상태, 10초 8개 합류, 전체 transfer CSV가 각각 byte 단위로 같다.

그 이유는 이번 모형 초기 상태에서 RM10639의 10초별 가용 재고가 최대 2대인데 평균 요청 상한은 OPEN 4.2대에서 g9 3.69대, g8 3.24대, g7 2.79대로만 줄어 상한이 실제 방출을 묶지 않기 때문이다. 물리 capacity 항은 그대로 4.2대이고 request 항만 달라진다. 실측도 150초 합류가 같다는 점을 고려하면, 이 사례에서 metering 효과를 만들도록 임의 보상이나 capacity drop을 넣는 것은 근거가 없다. 초 단위 통과 시각과 후속 궤적의 작은 차이는 남을 수 있으며 실제 ΔTTT가 정확히 0이라는 주장도 아니다.

## 절대 예측 오차는 별도로 남아 있다

처음 계획한 900/1800/2400초 12개 창에서 초기 Ω 재고 투영 차이는 0∼−2대다. 그런데 450초 TTT는 실제보다 약 4.3∼12.7% 높고, TTD는 약 414∼527대 낮다. 이는 초기 총 재고 두 대 차이로 설명할 수 있는 수준이 아니다. 다만 현재 결과에는 목적지별 유입 예측, 도시 신호 방출, 시간 지연과 경계 모델의 오차가 함께 있어, 이 합계만으로 특정 FD 식이 원인이라고 단정할 수 없다. TTD에서 빠지는 내부 발생량을 잘못 보존 오차로 분류하지 않는다.

무제어 1800–2250초의 같은 시각 속도 표본 평균:

| Cell | 실제 [km/h] | plant [km/h] | 판단 |
|---|---:|---:|---|
| E8 | 28.9 | 97.0 | 실제 혼잡을 거의 놓침 |
| E7 | 41.5 | 98.1 | 실제 상류 전파를 놓침 |
| W7 | 81.4 | 35.5 | 반대 방향으로 과도한 저속 예측 |

무제어 2400–2850초의 450초 합류는 RM10482가 실제 61대 / 예측 117.0대, RM10646이 실제 99대 / 예측 48.2대다. 램프마다 오차 방향이 다르므로 총 합류 하나만 보정하면 서로 상쇄할 수 있다. 다음에는 각 램프의 예상 도착·가용 재고·실제 합류의 연결을 확인하는 편이 낫다. 이 수치를 특정 미터의 포화 서비스율 오차라고 바로 해석하지 않는다.

1800/2400초는 정책마다 이미 달라진 자기 초기 상태에서의 조건부 예측 정확도다. 두 정책의 그 창 TTT 차이를 같은 상태의 제어 후보 순위로 해석하지 않는다. 실제 미래 수요로 재계산한 별도 대조는 수행하지 않았으므로, 예측 오차 중 수요 예측과 물리 응답의 기여를 완전히 분리한 결과는 아니다.

## 다음 판단에 쓸 결과

1. 이번 RM10639 사례는 실제 150초 합류량이 안 바뀌는 비교다. 이를 plant의 일반적 metering 무효 판정이나 예방 이득 누락 증명으로 쓰지 않는다.
2. VSL의 공간적 속도 변화, 특히 W4→W5 방향 오류는 같은 초기 상태의 실제 제어 응답에서 확인됐다. 이 부분을 먼저 좁혀 검토할 수 있다.
3. E8/E7의 혼잡 누락, W7의 과도한 저속, 램프별 도착/합류 편차는 제어 후보 평가 이전의 예측 기반을 왜곡한다. 도시 출구 TTD의 공통 과소도 따로 검토해야 한다.
4. 다음 작업은 이미 완료된 기록에서 해당 연결의 오차를 분해한 뒤 결정한다. 이번 검토에서 FD·capacity·목적함수나 탐색기를 조정하지 않았다.
