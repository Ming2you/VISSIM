# Off-ramp 진출량부터 정합한 뒤 셀 재보정 — 2026-10-02

사용자의 최신 우선순위를 반영한다. **8개 off-ramp 본선 진출량 → 커넥터 배수·재고 정합 → 셀별 동역학 재보정 → 같은 초기 상태 NC/RM/VSL/both 손익 검증** 순서다. 본선 총 진출량만 맞았다고 다음 단계로 넘어가지 않는다. 현재 목표는 ACTIVE/NOT_QUALIFIED다.

## 확인·수정한 설정 연결

선택망 manifest가 pin한 `port_profile.json`은 10682·10483에 각각 총2,250veh/h의 배수 서비스를 선언한다. 그러나 결합 모델의 direct branch는 그 값을 읽지 않고 도시부 공통1,400veh/h/lane을 사용했다. `lane_plant_runtime.initialize`가 선언값과 출처를 각 포트에 설치하고, `LaneOfframpRuntime.drain`이 이를 쓰도록 수정했다. 선언 없는 direct branch는 기존 도시부 차로당 값을 유지한다. 잘못된 포트·신호 branch·비양수/비유한 값은 거부한다.

이 수정은 선언된 설정 연결의 복구다. **2,250이 실제 포화 배수능력이라는 새 추정이나 이득 보너스가 아니다.** 유한 저장, 코호트 이동 지연, 하류의 동적 가용 공간, 본선 보존·속도식은 유지했다. 도시부 공통 서비스율·FD·merge/gap 계수는 바꾸지 않았다. 현재 설정 전체가 이득 검증을 통과했다는 뜻도 아니다.

실제 drain의 서비스 자원, 하류 공간 제한, 재고 보존, 기존 default와 오류 거부를 검사한5시험 통과. 수정 전 실제 drain 시험은0.388889veh 대신0.625veh를 기대해 실패했고, 새 설치 함수 시험도 실패했다. 실패 로그는 보존했다.

## 조건부 원인 분리

기존 seed47@2700의 두 native 조건에서 10682 MER 진입 시각을 넣어 커넥터만 재생했다. 미래 실측을 사용하는 **조건부 진단**이며 자율 예측·MPC 입력이 아니다. 하류 receiving은 무제한으로 둔 분리 시험이다. 초기·종료 0–1m 검지기 앞 차량이 없고 해당 커넥터 삭제가 없음을 확인했다. 실제 도시 배수는 재고보존으로 추론했으며 독립 출구 검지 측정이 아니다.

|조건|실측450초 진입/배수 [veh]|재고 MAE:1400→2250 [veh]|
|---|---:|---:|
|RM 유지|147 /148|1.651→1.030|

두 조건 모두 재고 오차가 줄지만, 비포화 표본이므로 이 결과만으로 포화능력을 식별하지 않는다. 실측 커넥터 속도도 시점별63–108km/h로 달라 고정 이동속도 근사가 남는다. 근거는 `../ramp10681_mainline/drain_audit.json`이다.

## 자율 예측8회 결과

기존 runner로 static SC105 두 조건과 기존 routed SC1001의 seed43 네 조건·seed47 RM 유지/완화 두 조건을450초씩 실행했다. 총208.412초, 세션77249/43810/23142 모두exit0. 계수 fitting/optimizer/native/FZP 재읽기0회. 같은 명령·초기 물리 상태 및 목적지 재고를 유지했고, 보존·자원·writer 검증을 통과했다. routed와 static은 SC105 보정 포함 여부도 다르므로 둘 사이 차이를 오직 route 옵션의 효과로 단정하지 않는다.

static 10682의 모델 진출량은 기존206.60대에서228.18/228.88대로 증가했다(실측 각147대). 잘못 생기던 커넥터 적체는 줄었지만 과도한 진출 수요가 더 드러났다. 3150초 셀11 속도는 아래와 같다.

선택 조건은 개선되지만 유지 조건은 과도하게 회복한다. 같은 RM·VSL이며 도시 명령만 다른 비교다. 이것을 RM·VSL 인과효과나 공통 회복 성공으로 부르지 않는다.

## 8개 출구에서 드러난 배분 오차

사용자 지시 직후 기존 native MER·완전한 차량 snapshot·삭제 기록과 이번 예측을 추가 대조했다. 아래는 RM 유지2700–3150초이고 도시 선택 조건도 `eight_offramps.json`에 포함한다.

|방향 / 출구|실측 본선 진출|모델 본선 진출|실측 램프→도시 배수 [veh]|

**동측 총 진출량은 실측434대 대 예측432.97대로 거의 같지만, 출구별 배분이 크게 틀린다.** 이 상태에서 셀별 계수를 맞추면 잘못된 공간별 재고를 보상할 위험이 크다. 서측 합계는487 대437.95대다. 한 커넥터만의 문제가 아니다.

native 진출량은 검지기 위치 보정, 배수는 초기재고+진입−잔여−삭제로 계산했다. 모델의 신호 branch3개는 총 flow key가 경로명으로 합쳐져 이 집계 파일만으로 물리 배수를 분리할 수 없었다. 이를0이나 임의값으로 채우지 않고 null로 남겼다. 다음 실제 예측 비교에서는 이미 존재하는 port state의 admitted/departed/stock으로 해당3개를 확인한다.

다음은 각 출구의 현재 목적지 재고와 연속 route decision, 본선 도착 유량을 먼저 정합한다. 이후 동일 경계 조건에서 남는 셀별 혼잡·회복 오차를 재보정하고, 마지막에 전체 대기 비용을 포함한 제어 순위를 확인한다. 현재 계수로 잘못된 출구 배분을 보상하거나 과거 관측 방출을 미래에 그대로 입력하지 않는다.

`assessment.json`에8회 예측과 소스 범위를, `eight_offramps.json`에8개 물리 출구를 기록했다. 첫 보고 검사에서 held와 selected의 validation schema 차이를 누락한 KeyError는 보고 코드만 고쳤으며 예측을 재실행하지 않았다. 기존9000 STOP·실패 자료 보존, push 없음.
