## 왜 총 이동량을 맞춰도 실패했는가

verify.py는 같은5초 시각에서 동결 식에 관측 상태와 각 후보의 예측 상태를 각각 넣었다. 이 비교는5×현재 재고×이동률의 동일한 선형 강도 계산이다. 실제 운용의 이동은 종방향 수송 후 재고, 지수 hazard, 목적 차로 저장 상한을 추가로 적용한다. 다음 표의 마지막 열만 그 실제 운용 수용량이다.

|---|---:|---:|---:|---:|---:|
|셀20·1차로, 가운데150초|+3|+3|+3.222|−0.135|−0.150|
|셀25·3차로, 마지막150초|−16|−14|−0.875|−0.123|−0.125|

- **셀20:** 관측 상태에서는 차로 순이동 반응이 가까웠지만 예측 상태에서는 사라졌다. 이 구간은 상태 갱신 오차가 반응을 훼손한다는 근거다.
- **셀25:** 관측 상태를 넣어도 반응을 놓쳤다. 인접 이동만 보아도 실제−14대 대 식−0.875대다. 비인접 표본 누락2대만으로 설명되지 않는다. 전체 이동 건수의 적합이 필요한 차로·시점의 순이동 적합을 보장하지 않았다.
- 위 분해는 관측 부분 이동에 대한 대수 비교이며 VISSIM 원인의 기여율이 아니다. 특정 속도·밀도 특징을 더 넣으면 해결된다거나 추가 캘리브레이션이 불가능하다는 결론도 아니다.

168의 초기30초 셀20·1차로는 실측 재고12대/속도43.176km/h에 대해19.969대/13.825km/h였다. 셀21은 실측2대/55.370km/h, 모델5.161대/23.641km/h다. 기존148의 초기 상태 갱신 오차를 차로 이동률 변경만으로 고치지 못했다. state_recurrence.json에5·30·150·300·450초,19–25 모든 차로의630개 비교를 보존했다.
