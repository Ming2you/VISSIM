# REVIEW108 — 출구 차로 접근과 목적지별 차로 이동

2026-10-03. 진단 및3회 오프라인 예측 완료. **후보 미채택, 목표 ACTIVE / NOT QUALIFIED.** 새 VISSIM·FZP 읽기·fitting·push는0회다. 실행 중인9000초 런과 정본 물리 코드는 유지했다.

앞선 REVIEW107은 차로별 수용 상한을 추가해도 VSL 이득을 재현하지 못했다. 이번에는 사용자의 “VSL이 차로 변경 시간을 늘려 정지를 줄일 수 있다”는 가설을 출구행 차량의 실제 차로 접근과 나눠 확인했다. Claude의 보관된 REVIEW_CHECK·K1K6 기록도 다시 확인했다. 별도의 FWE 문서는 현재 worklog 사본에 없어, 그 내용을 확인했다고 가정하지 않았다.

## 기하와 관측

선택64cf 망의10613 연결은 **link2의2차로→link119의1차로**이며3차로가 연결된다.10483은119의1차로에서 진출한다. 따라서 상류2차로에서 하류1차로로 번호가 바뀌는 것은 차로 변경으로 세지 않았다. 상류1차로에는10481 진출도 있으므로, 그 차로의 모든 차량이 옆 차로로 합류한다고 가정하지 않는다.

seed67의 완료된 RM 완화/VSL110과 같은 RM/VSL90,2670.1–3120.1초의5초 캐시 및 기존 native port 사건을 재사용했다. 초기6개 프레임은 정확히 일치한다.

나머지22대는 관측 시작 시 이미 하류에 있었다.5초 사이 변경 후 원래 차로로 돌아오는 행위는 이 데이터로 배제하지 못한다. **이 진출 집단은 결과를 보고 분류했으므로 서로 다른136대와150대의 평균 진출시각을 제어의 인과 효과로 비교하지 않는다.**

현재2670.1초 경로 정보만으로10483행임을 알 수 있던65대도 따로 고정해 추적했다. 두 조건 모두65대가 진출했고 순 차로 변경0건, 정지 표본 수도123개로 같았다. 두 조건의 평균 진출시각 차이는+0.154초로 작았다. 이 집단은 주로 앞부분을 통과하므로, 후반 VSL 이득 전체의 대표 집단으로 사용하지 않는다. 앞선 REVIEW90의 다른 사후84대 집단과 섞지 않는다.

주변 차량의 변화는 남아 있다. 상류 접근에서 관측된1→2 순 변경은5건/2건,119에서 관측된2→1 변경은34건/41건이었다. 노출시간·차량 구성이 달라 이 숫자만으로 합류 마찰이나 capacity 계수를 추정하지 않는다. 이번 자료는 **출구행 차량 자체가 마지막 순간에 차로를 못 바꾸는 문제**를 주된 설명으로 삼는 데는 지지력이 약하다.

## 코드에서 찾은 근사와 최소 수정

기존 시험용 `RouteLaneRegion`은 모든 목적지 재고에 같은 시간당 차로 교환율을 적용했다. 따라서 이미 출구 차로에 정렬된10483행 차량도 옆 차로로 흩어진다. 이번 관측과 맞지 않는 근사다. 이것은 정본 aggregate 모델 전체의 새 버그라고 부르는 것이 아니라, 채택되지 않았던 차로 모델의 동작을 확인한 것이다.

최소 후보에서는 셀19·20의10483행 재고가 이미 물리적 출구 차로에 있으면 일반적인 확률 차로 교환에서 제외했다. 아직 정렬되지 않은 차량과 통과 차량의 기존 교환율은 유지했다. 어떤 차량이 나중에 실제로 진출했는지는 입력으로 사용하지 않았고, 기존 현재 경로 재고와 미래 선택 기대 비율을 그대로 사용했다. 새로운 녹색·VSL 보상이나 capacity 보너스는 없다. REVIEW107의 추가 수용 상한은 켜지 않았다.

실행 전에 최대3회 예산을 정했다: 수정 비활성1회와 수정 활성 VSL110/90 각1회. 기존107의 차로 모델 결과를 비교 기준으로 재사용했다. 정본 함수 연결은 이 진단 프로세스 안에서만 적용·복구했다.

## 검증 및 남은 방향

- 비활성 실행의 cells/flows/ports/ramps가 이전107 결과와 정확히 일치했다.
-3회 모두 기존 상태 유효성·연속방정식·경로/차로 재고 보존을 통과했다. 최대 오차는 연속방정식5.69e−14대, 경로/차로5.05e−14대다.
- 기존helper12개 AST, 정본9개 파일, 입력8개, 기존STOP을 보존했다. 프로세스 내부 연결도 복구했다.
-3회 예측과 평가9.16초. VISSIM 실행 단축률과 관계없는 오프라인 시간이다.
- 후처리 초안에서 port의 누적 admitted/departed를 시각별로 더한 오류를 발견했다. 해당 초안을 `invalid_cumulative_sum*`로 보존하고 마지막 누적값으로 고쳤다. 각449개 재고 차분 및 셀20의 실제 accepted flow 합과 일치를 확인했다. 예측·TTT·채택 실패 판정은 바뀌지 않았으며 예측은 다시 돌리지 않았다.

목적 차로 접근을 일관되게 처리하는 것과 VSL 이득을 재현하는 것은 별개였다. 다음 조사는 **이미 같은 차로에 정렬된 차량의 정지·재출발과, 가까운 합류부에서 방출되는 차량의 도착 시각이 그 대기열에 미치는 영향**으로 좁힌다. 기존 merge/queue 진단에 같은 검사가 있는지 먼저 확인하고 재사용한다. 미래 실측을 넣는 검사는 원인 분리용으로만 표시하며 자율 예측 통과로 대신하지 않는다.
