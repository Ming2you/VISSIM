## 실측 대열은 끝50m에만 머물지 않는다

seed67 RM 완화110/90의 기존5초 현재 차량 상태를 사용했다. 길이199.968m인 셀20·1차로를 같은 길이의4구간으로 나눠 비교했다. 미래 실제로 진출한 차량을 거슬러 분류하지 않고 현재 NEXTLINK=10483만 진출행으로 셌다. 정지는 속도5km/h 미만이다.

중간150초(2820.1–2970.1)의 평균 정지 차량 수는110에서6.433대,90에서1.867대다. 마지막50m의 정지 차량 비중은26.9%/25.0%이고 해당 구간의 전체 차량 비중25.8%/26.9%와 비슷하다. 110의4구간 평균 정지 대수는1.40/1.37/1.93/1.73대,90은0.17/0.43/0.80/0.47대다. 따라서 **이 구간의 오차를 출구 앞 짧은 대열만 셀 전체로 확대했기 때문이라고 단정할 근거는 약하다.** 새 셀20 공간 분할을 바로 추가하지 않는다.

이는 정지 발생 원인을 합류·진출로 확정한 검사가 아니다. 진출행 차량이 정지했다는 사실과 진출 때문에 정지했다는 인과 주장은 다르다. 실제 VSL의 정지 감소가 단일 메커니즘에 의한 것이라는 뜻도 아니다.

## 현재 모델에서 상태 보정이 바로 잘리는 조건

## 다음 한 후보의 의미

상한의 역할을 없애거나 용량을 늘리지 않고, 현재 허용 이동률에서 얻은 속도를 **METANET 목표속도의 상한**에 반영하는 후보를 검사한다. 평균속도는 기존 이완시간·대류·anticipation으로 갱신하고 실제 유량의 수용/저장/FIFO 제약은 그대로 둔다. 새 시간계수나 VSL 명령 보너스를 넣지 않는다. 이 후보가 옳다는 증거는 아직 없고, 새로운 유량·대기·손익 비교가 필요하다. 같은 순간에 셀 전체 평균속도를 경계 유량으로 치환하는 근사를 완화하는 시험이며 미시적 queue front 모형을 완성하는 변경은 아니다.

검사에서 원래 진출/속도 기록 일치900개,공간별 재고·정지 표본 합계6창 모두 통과. 정본9파일·입력·STOP 해시 유지. 수집 간격5초는 그대로이며 기록 시점 사이 실제 정지시간이나 차로 변경 순간까지 판정하지 않았다. 근거: protocol.json,assessment.json,native_quarters.json,cap_steps.json,pins.json,run.log.
