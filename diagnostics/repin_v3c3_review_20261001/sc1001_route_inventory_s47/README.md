## 기존 SC1001 후보의 SDMPC 미분 연결

위에서 기각한 결합 설정이 아니라 **기존 SC1001 후보** `candidate_config.json`(SHA f319982b…)를 실제 SDMPC 연속 예측 경로에 넣었다. 저장 seed47 2700초의 실제 직전 명령과 과거 head/VSL 이력을 사용했다. 이전에 검토했던 동일3축·두 차분 폭을 재사용하며 새로운 미세 차분 격자를 탐색하지 않았다.

- AD1회와 별도 query의 scalar13회. scalar 기준값을 AD에서 재활용하지 않았다.
-20개 비용 분할과 N_P·N_UF 두 자원의 기준 출력이 일치했다. 최대 비용 오차0, 자원 오차5.69e−14. 모든 중간 상태 Jacobian을 확인한 것은 아니다.
-변환 소스에 현재 `lane_offramp_runtime.py` SHA72f7a27e…가 포함돼 새 공유 접근로 코드로 계산한 것을 확인했다.

미터는 차량·시간/녹색1초, VSL은 차량·시간/(km/h) 단위다. 결과 원본은 정규화 좌표 미분을 기록하므로 미터는10으로, VSL은110으로 나눈 값이다.10490 좌우 미분은 약−0.03554/−0.03787로, 정확히5초 AD와도 다르다. 과거 양옆4.999/5.001초 시험의 통과를 이번 수정의 전체 검증으로 대신하지 않았다. 이 축은 전체 통과로 표시하지 않으며 더 작은 간격으로 반복하지 않는다.

10484의 국소 기울기가 음수이고 전체 완화 명령4→6→8초가 손해인 것은 모순이 아니다. 기준점의 미세 변화와3블록의 유한 변경은 다른 후보다. 실행 가능한 후보는 여전히 전체 비선형 비용과 제약으로 평가해야 한다.

VSL110에서 미분0은 VSL 전체 효과가0이라는 뜻이 아니다. 현재 설정에 `sdmpc_vsl_activation_secant=true`가 있고, 실제 `sdmpc.solve`가 비활성 VSL축의 실행 가능한 유한 변경 비용을 평가하는 경로는 유지돼 있다. 이번에는 최적화를 호출하지 않았으므로 그 fallback이 특정 후보를 선택했다고 주장하지 않는다. 도시green/offset의 독립 수치 미분도 이번3축 범위에 포함되지 않았다.

계산175.62초,1AD+13scalar, 최적화0회. 실행 소스·입력은 계산 중 변경되지 않았다. 앞선 첫 CLI 시도는 `--output-suffix` 제한에서 초기화 전에 실패했고, 올바른 `--probe-label`로 재실행했다. 실패 로그와 초기 프로토콜은 보존했다. 계산 전 프로토콜의 이전 튜닝 SHA/턴 분류 메모도 현재 값으로 정정했으며 시험 기준·차분폭·허용오차는 그대로다.
