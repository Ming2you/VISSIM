# 진출부 10682 주변 차로·경계 흐름 확인

2026-10-02 / REVIEW44. 기존 기록 진단 완료. **보정·제어 이득 검증은 미완료**이며 retained10638 기준을 유지한다. 새 VISSIM·FZP 스캔·예측·계수 보정·push는 없다. 생산7개 파일과 기존9000 STOP의 SHA가 그대로다.

사용자 순서인 **8개 off-ramp 진입·배수·저장 정합 → 필요한 셀 보정 → 공통 초기 제어 손익**을 유지한다. 현재 경계 유량 오류를 평균속도 계수로 보상하지 않는 것이 중요하다.

## 이번에 추가 확인한 내용

10682 분기는 셀11 시작 약10.3m 뒤에 있고, `through:10682` 검지기는 셀11→12 경계에 있다. 셀10–12의 기록은 모두 본선 link2이므로 아래 차로 번호는 같은 링크의 차로다.

기존 native 검지 기록의 450초 경계 통과:

|관측|1차로|2차로|3차로|4차로|
|---|---:|---:|---:|---:|
|seed43 NC,2250–2700초 통과 차량|96|136|267|290|
|같은 기간 MER 진입 평균속도[km/h]|36.2|21.4|67.4|68.1|

43의2차로와47의4차로에는 종료 직전 MER 쓰기가 한 대씩 늦은 기록이 있다. 차량 수는 원래 native 누적 검지 수에 맞춰 이 tail을 포함했고, 속도는 기록이 있는 차량만 평균했다. `assessment.json`의 `count`는 MER에 이미 기록된 수, `tails`는 아직 기록되지 않은 수다. 최종 통과 수는 `boundary_counts.json`의 `native_detector_count`를 사용한다. 기록 누락을0으로 처리하거나 속도를 추정해 채우지 않았다.

**2차로가 느리더라도3·4차로의 통과는 지속됐다.** 이는 모든 차로가 함께 막힌 상태와 구분해야 한다는 근거다. 서로 다른 seed·초기 상태·기간의 통과 수를 직접 비교해 RM 효과라고 해석하지 않는다.

seed47의150초 간격 관측에서 셀10의2차로 평균속도는18.1→75.5→99.0→90.4km/h로 회복됐다. 같은 시각 셀11의2차로는15.8→32.8→30.1→6.7km/h다. 따라서 셀11 저속만으로 상류 셀10 전체의 지속 혼잡을 예측하면 안 된다. 직전 단일 FD 후보가 이 상류 회복을 악화시킨 사실과 부합하지만, 어떤 항이 원인인지를 이 관측만으로 확정하지 않는다.

이미 추출한2220.1–2970.1초 5초 자료에서도 seed29 NC의 셀10 2차로 차량가중 평균속도는79.5km/h,seed43은21.1km/h였다. 셀11 2차로는 각각22.2/12.9km/h로 모두 느렸다. 평균 셀 속도만으로 다른 상류 반응을 구분하는 데 한계가 있다.

셀11 첫25m 내20km/h 미만 차량 존재를 살펴봤지만, **그 기준 하나로 전파 여부를 판별할 수 없다.** seed47 종료 시 가장 상류의 저속 차량은 시작점21.3m 뒤에 있지만 셀10은 원활했다.25m/20km/h는 관측을 요약한 기준이며 새 모델의 스위치나 보정값으로 채택하지 않았다.

10682의43 진입 과대 예측을 무조건 off-ramp 저장공간 부족으로 해석할 근거는 없다. 램프 배수는 진입보다 많았고 종료 재고도 작다. 기존 목적지 재고 장부에서 확인한 접근부 체류와 본선 차로별 흐름을 함께 봐야 한다. 이 장부만으로 구간 중 순간적인 spillback까지 없었다고 단정하지 않는다.

10643은47에서 도시 배수가 부족하지만43에서는 오히려 과대 예측한다. 고정 배수 상한을 일괄 올리는 보정은 적절하지 않다. 현재 공유 접근부·목적지별 차로 접근·녹색 중 실제 방출 관계가 먼저 남아 있다. seed47에서 진입도 과소 예측하므로 배수 하나만 맞춘 결과를 성공으로 처리하지 않는다.
