# REVIEW57 — 현재 큐, 도착, 차로 접근과 신호 시점 분리

큐와 도착을 구분해야 한다는 사용자 지적에 따라 기존 자료를 분리했다. **같은 초기 차량을 도착으로 다시 세는 문제는 이번 국소 재생에서 없었지만, 예측하는 동안 형성되는 차로별 큐와 목적지 구성이 틀어지는 증거가 나왔다.** 운영 모델 수정이나 이득 검증 완료는 아니다.

## 실측에서 서로 다른 두 종류의 무방출

seed47 선택 신호 조건의71번 도로:

- 5차로,3076–3110초 녹색: 직전3075.1초에2대가 정지해 있었고2대가 통과했다. 마지막 통과 뒤28.75초 동안 추가 통과가 없으며 이후5초 표본에는 정지 큐가 없다. 이 경우 녹색 총량이 부족하다고 해석할 수 없다.
- 3차로,3031–3073초 녹색: 직전3030.1초에11대가 정지해 있었지만2대만 통과했다. 현재 차로로 갈 수 있는 목적지7대, 다른 차로가 필요한 목적지4대였다.3035.1–3050.1초에는10635행 차량21111이73.39m에서 멈춰 있었고, 필요한4차로는 적색의 큐로 차 있었다. 이후에도 다른10635행 선두가 멈췄다. 현재 큐가 있다는 사실만으로 녹색에 방출 가능한 차량 수가 되지는 않는다.

녹색 시작 시각은5초 표본 사이에 있으므로 정확한 순간 큐와 동일하다고 하지 않는다. 두 사례는 직전 표본이 각각0.9초 전이다. 정지는5km/h 미만으로 분류했다. 목적지는 당시 route/next-link로 읽었으며 미래 출구로 역추정하지 않았다.

전체2700–3150초의native 녹색 통과량은 SG2가80→62대(녹색135→134초),SG5가55→51대(72→98초)다. 초기 출발은 대체로 약1초 뒤에 시작했지만 녹색 중·후반 공백이 길었다. 이를 모두 출발지연이나 총녹색 부족으로 보정하면 잘못된 원인을 흡수하게 된다.

## 같은40초에서 큐 상태를 맞춰 시작하면

선택 조건3030.1–3070.1초를 비교했다. 장기 국소 재생은2700.1초부터 같은 실제 도착·신호로445초 계산한 것이며, 관측 초기화 진단은3030.1초의 실제 위치·경로·재고에서40초만 계산했다. 계수와 서비스 법칙은 같다.

|71차로|실측 head 통과|장기 재생의 같은40초|실측 상태 초기화 후40초|
|---|---:|---:|---:|
|1|4|0|4.00|
|2|8|16.33|10.36–10.87|
|3|2|3.80|1.00|

범위는5초 도착 구간의 이른/늦은 끝을 쓴 민감도다. 모델은 head보다 약2m 뒤의connector 출구를 세므로 미세 차이를 정확 일치 실패로 해석하지 않는다.1·2차로 오차가 줄고3차로의 막힘도 표현하므로, **현재 상태의 방출 계수뿐 아니라 누적 도착·차로 배분·큐 순서 예측을 먼저 확인해야 한다.** 이것만으로 모든 서비스 오차가 해결됐거나 큐 전파가 유일한 원인이라고 확정하지 않는다.

장기 재생의3030.1초71번 재고는1차로 거의0대,2차로13.39대,3차로13.40대,4차로13.51대,5차로0.63대였다. 실측은 각각4,7,11,11,2대였다. 모델의 이 재고는 정지 큐가 아니라 이동 중 차량을 포함한 셀 재고다. 특히2차로에는 미배정 목적지 질량7.93대가 남는다. 현재 구현은 위치·목적지·유한 공간을 쓰지만 초기 차량 속도를 별도의 서비스 준비 상태로 유지하지 않는다. 따라서 단순 큐+도착 총량 공식이라고 부르는 것도 부정확하다.

## 도착과 신호 교차 진단

공통2700.1초 국소 초기 차량35대는두native 조건에서 정확히 같다. 각 조건의 이후 도착ID와 초기ID는 중복되지 않는다. 도착·신호를 교차한 재생은 미래 실측을 사용하는 원인 분리용이며 자율 예측이 아니다. 하류 출구 제약은 양쪽에서 해제한 국소 진단으로, 실행 가능한 전체망 명령의 증거가 아니다.

|2700.1–3145.1초 추적 코호트|유지 조건|선택 조건|
|---|---:|---:|
|초기 국소 차량|35|35|
|상류70에서 도착|93|91|
|10643에서 도착|93|84|
|10640에서 도착|18|20|
|종료 국소 재고|25|38|
|비정상 삭제(정상 방출 제외)|2|2|
|코호트 보존식 정상 방출|212|190|
|각자의 실제 도착·신호를 넣은 모델 방출|163.27–163.94|168.44–168.96|

실측 코호트 방출 변화는−22대지만 모델은+4.50~+5.69대다. 실제 도착을 넣어도 방향을 못 맞추므로 도착 총량 차이만으로 설명할 수 없다. **10643의 실제 도착은 이 국소 구간 상류의 실제 배수 결과다. 외생적인 희망 수요 감소라고 해석하거나 이 값을 자율 예측 입력으로 넣으면 안 된다.** 알려진 모든off-exit MER와head 차량은 보완된 코호트에 포함된다. head를 지나지 않는 짧은 통과가 모두 잡혔다고 보장하지는 않는다.

선택 조건의 차량25422는2930.27초10643 말단 검지기와2934.48초71 head를 지나5초 FZP에 국소 구간 행이 전혀 없었다. MER와정적경로10643→126→10641→71→10634로 이1대를 보완했다. 그 전의189대/−23대는 표본 코호트 값이므로 최종 값으로 쓰지 않는다. 보완 후에도 결론은 같았다.

## 보존한 실패와 계산 범위

처음 두 신호 교체 재생은 유지 조건의 출구 수용 예산에 이미 들어 있던 신호 제한을 그대로 가져와, 선택 녹색134초 중128초를 다시 막았다. `assessment.json`, `early.json`, `late.json`은 **유효한 반사실 실험이 아니다**. 원인을 확인하고 양쪽 모두 동일한 무제약 출구 진단으로 대체했으며 원본은 보존했다. 기존 운영 runner의 오류로 주장하지 않는다.

첫 도착 추출은5초 사이10638→70→10776→126을 건너뛴1건을 거절했다. 실제 경로와관측 next-link 연속성을 확인해 보완했으며 실패 로그를 보존했다. 추가 FZP 재스캔은 없었다.

- 새로운 국소 재생13회:445초11회(초기 무효2회와관측만 추가한 동일성 확인1회 포함),40초2회. 새 전체망450초 예측·계수 보정·VISSIM·push는0회다.
- 선택 조건의 완료 FZP442MB를 기존 추출기로1회 읽어7,132행의 작은 캐시를 만들었다. 추출 약2.2초. 유지 조건 캐시는 재사용했다.
- 초기/도착 중복 없음, 단계별 차량 보존, 기존 코호트 추출 정확 일치, 관측 추가 전후 기존 결과 정확 일치를 확인했다.
- 모든 생산 파일과9000 STOP 해시는 유지했다. 실패 자료와사용자 프로세스를 건드리지 않았다.

다음은126→10641→71에서 목적지별 도착이 어느 차로의 어떤 큐 순서로 쌓이는지와, 녹색 시작 시 접근 가능한 선두 집단을 검증하는 것이다. 이미 실패한 단순4↔5 교환률·공간 선호·조각 삭제 계열을 다시 무작정 탐색하지 않는다. off-ramp 진입·배수·저장 동역학을 고치기 전에 고속도로 셀 계수로 이 오차를 상쇄하지 않는다.
