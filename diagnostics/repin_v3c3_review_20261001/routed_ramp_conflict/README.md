# 목적지별 본선 유량과 램프 합류 간섭 정합 — 2026-10-02

코드 불일치는 수정했지만 제어 이득 예측은 거의 개선되지 않았다. 목적지 재고 옵션은 운영 기본값으로 채택하지 않는다. 현재 nonrouted SC105 후보, Ω TTT, 네트워크, 계수, 9000초 STOP은 유지한다.

## 수정

`lane_ramp_runtime.LaneRampRuntime.advance`에서 목적지 재고를 켰을 때만 기존 `offramp_routing.sending_requests`를 재사용한다. 본선 차량의 현재 목적지에 따라 진출 수요를 빼고, 남은 통과 수요를 유효 차로 수로 나눠 gap 간섭에 전달한다. 이전 코드는 본선 연속식은 현재 목적지를 쓰면서 램프 간섭에는 과거 진출 비율을 별도로 적용했다.

분기 수요를 줄이는 계수나 합류 capacity 보너스는 추가하지 않았다. 목적지 재고가 없거나 명시적 본선 lane plant가 있는 경로는 기존 계산을 유지한다. 여기서 간섭은 아직 **sending 수요 기반 근사**이고 하류가 수용한 실제 유량과 동일하다는 주장은 아니다.

## 같은 초기 상태·명령의 결과

기존 routed 후보의 수정 전 예측과 새6개450초 예측을 비교했다. seed43 네 조건, seed47 RM 유지/완화 두 조건이다. 물리 초기 상태·목적지 재고·명령은 같으며, 17주체 자원·램프 질량·목적지 분할 보존 검사를 통과했다. 두 상태는 이미 사용한 검증 자료이며 새로운 독립 seed가 아니다.

## 검증과 한계

- 신규5개 회귀시험 통과. 현재 목적지가 전부 통과/진출인 경우, 과거 비율 불변성, 빈 재고, 기존 경로 동일성을 확인했다. 수정 전 실패 로그와 소스 보존.
- 기존 route-inventory 시험21개 중12개 통과. 9개 시험은 이전 망 상태/설정 파일 부재로 미통과(하위 사례를 포함하면 오류·실패 기록11건). 전체 시험 통과라고 표시하지 않는다. 실패 로그 보존. 최초 평가 JSON의 단순 사건 수를 시험 수로 잘못 적은 메타데이터는 별도 보존 후 바로잡았다.
- 두 소유 계산24233/7936 모두 exit0. 6개 예측 시간 합162.843초이며 병렬로 수행해 전체 경과시간과 같지 않다. 최적화 iteration0, 새 native/FZP/fit/push0.
- 변경 함수는 `advance` 하나다. 이전 보존 대상12개 파일의 SHA가 같음을 확인했다. 현재 경로의 AD·SDMPC 선택 검증을 새로 수행하지 않았으므로 인증하지 않는다.
- 원인 분리용 미래 실측 대입은 앞선 supply 진단에만 있으며, 이6개 자율 예측에는 사용하지 않았다. 새 계수 탐색은 수행하지 않는다.

다음에는 본선 혼잡의 잘못된 전파가 gap 입력과 방출에 미치는 영향을 기존 예측에서 분리해야 한다. routed 수정의 효과가 작다는 결과를 무시하고 gap 계수를 더 크게 조정하거나 동일한 격자 탐색을 반복하지 않는다.

재현 명령은 기존 `sc1001_connection/check_connection.py --forecast --route-inventory --suffix=routed_gap47_v1`이며43은 `--four-arm --suffix=routed_gap43_v1`이다. 출력 덮어쓰기를 금지하므로 기존 완료 결과를 재실행하지 않는다. `assessment.json`, `verification.json`, `runtime_patch.diff`에 원본·보존 검사와 수치를 남겼다.
