# 7050초까지 무제어 대비 TTT와 실행 중단 오류 수정

사용자의 요청에 따라 **종료된 자료의 동일 0–7050초만 비교**했다. SDMPC는 7050초 관측 오류로 종료됐으며 9000초 완료 결과가 아니다. 0초부터 9000초를 재시작하지 않는다. 물리 모델·계수·목적함수·제어 명령 선택을 변경하지 않았다.

**Ω TTT만 작게 감소했지만 명확한 성능 개선으로 판정하지 않는다.** 동측 본선은 악화했고, Ω 밖 체류와 삭제가 증가했다. 삭제·경계 외 대기로 목적 영역 안의 체류가 줄어 보일 가능성을 분리해야 한다. 이 표만으로 각각의 인과 기여도까지 확정하지 않는다.

Ω는 고속도로와 도시 protected network의 합집합이다. 외부 비용은 진단으로 보고했으며 Ω TTT 목적함수는 유지했다. 미삽입 대기는 전체 망 체류시간에도 포함되지 않는다. 무제어의 9000초 종료 미삽입 값을 SDMPC 7050초와 비교하지 않았다.

두 native FZP를 각각 한 번 읽고 실제 7050초 차량 관측으로 마지막 구간을 닫았다. 동일 seed29·망 SHA256 `64cf5f55fe9990f3e25bc4fedebf4ab1e4634c8138dbcf5697a136c48cb559dc`·Ω 집계를 사용했다. 900초 초기 전체 차량 상태와 제어 전 431,233개 FZP 레코드의 시각/ID/link/위치/속도 열이 정확히 같았다. 기록 간격은 5초이며 누락 간격은 없었다. 전체 열의 제어 전 동일성까지 주장하지 않는다. 근거는 `partial7050/summary.json`, 재현 코드는 `compare_partial.py`다.

참고용 정상 유출 사건 추정은 47,714→47,531이지만, 5초 기록에서 Ω 내부 소멸의 경로가 해결되지 않은 624→659건이 있어 정밀 TTD 검증 완료 수치로 사용하지 않는다. 비정상 삭제는 정상 유출에서 제외했다.

## 7050초 종료 원인과 수정

실행 당시 `.err`가 파일 버퍼에 남아 관측이 6623.4초 경고까지만 읽었다. 6900–7050초의 삭제 6건을 놓쳤고, 그중 본선 차량 2대(동측 7046.3초, 서측 7048.4초)가 차량 보존 검사를 실패시켰다. 실제 종료 유출은 동측 213대·서측 139대인데 삭제 누락 상태에서 214·140대로 역산했다. 종료 후 확정된 삭제를 원인 분리 진단에만 넣으면 양 방향 31셀의 유량 보존식과 실측 종료 유출이 정확히 일치한다(`balance.json`). 과거 실시간 관측 파일을 덮어쓰지 않았다.

기존 runner의 150초 관측 시점에 `Vissim.Log`의 NOTE 표식과 제한된 패딩을 쓰고, 현재 실행·현재 시점의 표식이 완성된 파일 행으로 확인되어야 관측을 저장하도록 수정했다. VISSIM2020에서 NOTE 한 번만 쓰면 여전히 버퍼에 남는 것을 실제 COM으로 확인했으므로 두 개의 8KB NOTE로 기록 완료를 유도한다. 매 제어 시점 COM 호출 3회이며, 매초 차량 조회나 시뮬레이션 추가 진행은 없다. 표식 누락·이전 표식·중복·부분 행은 실패 처리한다. 차량 보존 검사를 느슨하게 하거나 삭제를 정상 유출로 바꾸지 않았다.

## 검증과 한계

- 관측기·runner 회귀 검사 92개 중 91개 통과, 기존 1개 건너뜀(`tests_v4.log`). 초기 실행 계정·한국어 경로·누락된 테스트 보조 함수 문제는 하네스에서 수정했다. 실패 로그도 보존했다.
- 실제 COM 151초 비교에서 392대의 FZP 데이터 6,028행이 모든 열까지 정확히 일치했다. 시뮬레이션 시각은 로그 쓰기로 진행되지 않았고 1·150초의 실시간 파일 복사본 모두 현재 표식이 완전히 기록됐다(`native_check_v3/verification.json`). 첫 시도는 종료 시 SimSec 초기화로 실패했고, 두 번째는 차량 기록 필터 때문에 FZP 데이터가 비어 있어 궤적 동일성 판정을 거부했다. 검증 복사본만 수정했으며 두 기록 모두 보존했다. 고정 진단 수요를 양쪽에 동일하게 쓴 시험으로, 원래 9000초 시나리오의 성능 비교가 아니다.
- 짧은 로그 검증이 9000초 폐루프 재검증이나 삭제가 많은 상태의 장기 검증을 대신하지는 않는다. 이번 수정은 중단 원인의 처리이며 TTT 손실이 해결됐다는 주장은 아니다.
- 원래 실패 실행본·결과·기존 STOP은 보존한다. 9000초 자동 재시작·추가 보정·push는 하지 않았다. 전체 이득 검증 상태는 **NOT_QUALIFIED**다.
