# SC1001 녹색·offset 감도 대조 — 2026-10-02

녹색 배분은 통과했고 offset은 통과하지 못했다. 전체 Ω TTT의 기울기가 비슷하다는 이유로 주체별 비용·N_P·N_UF 감도가 맞는 것으로 처리하지 않았다. 준비한 SDMPC 선택 시험은 시작하지 않았다.

## 동일 기록 상태 대조

선택망 seed47의 2700초 상태, 과거 head/VSL 이력, 450초 지평, 기존 SC1001 경계 후보(f319982)를 유지했다. 기존 진단 함수에 녹색의 현시 간 배분 벡터와 offset 연속 좌표를 추가했다. 제어 주기·양자화·허용 범위·목적함수·물리 계수는 바꾸지 않았다.

AD 1회와 독립 일반 수치 예측 9회를 130.56초에 완료했다. 현시 p2/p4 배분과 offset 각각 ±0.001, ±0.0005초를 대조했다. 이 작은 변화는 미분 진단 전용이며 실행 가능한 native 명령으로 승인하거나 적용하지 않았다.

| 기준 예측의 20개 비용·2개 자원 값 | AD와 독립 계산 일치 |
| 녹색 배분 | 두 차분 폭에서 20개 비용·2개 자원 감도 모두 기존 허용오차 통과 |

정규화 offset 좌표는 150초 척도다. 보고된 큰 정규화 오차와 실제 초당 오차를 혼동하지 않는다. 결과 원본은 integration_20260926/closedloop_recorded2700_budget_check_derivatives_sc1001_urban47이고, 선택용 작은 요약은 assessment.json이다.

## 원인 분리

기존 ExactBranchProbe를 SC1001 offset 한 축에도 허용하여 AD 1회만 추가했다(61.99초). 원래 비용·자원·감도와 **정확히 일치**했고 기록 누락은 0이었다. 실행에 사용된 변환 소스 98개 SHA도 현재 파일과 일치했다. 이 계측은 분기 선택이나 미분값을 바꾸지 않는다.

이 기록에서 접근로 물리 재고와 canonical 저장 재고 사이의 감도 불일치가 2790초에 처음 포착됐다. 일반 차량 수 차이는 0인데 offset 정규화 좌표의 재고 감도 차이는 −80이었다. 이는 전체 미래 궤적의 최초 차이를 완전히 추적했다는 의미는 아니며, 기존 계측이 포착한 첫 불일치다.

두 작은 합성 재현에서는 SharedSignalApproach의 아래 정리 경로가 활성 감도를 제거했다.

- advance의 방출 후 잔량 `<=1e-12` 제거: 잔량 약 1e−14대지만 감도 −1인 차량 묶음을 삭제한다.
- _mandatory_lane_changes의 큐 정리: 실제 차로 변경이 없어도 작은 잔량의 감도 +1을 삭제한다.

forward/reverse 두 방식 모두 재현했다. 일반 차량 수 오차는 약 1e−14대지만 감도 보존 오차는 ±1이다. 다만 이 두 재현만으로 기록 상태의 offset 오차 전부를 설명했다고 주장하지 않는다. 합성 계측의 namespace/MathProxy 초기 오류 두 건은 전체 롤아웃 전에 발생했고, 계측 설정을 수정한 최종 스크립트는 정상 종료했다.

## 다음 수정 범위와 종료 상태

공유 접근로에서 거의 비어 있는 차량 묶음을 정리할 때 활성 감도를 보존하고, 다음 방출·차로 이동·영역 회계까지 전달되는지 확인해야 한다. 단순히 0대 묶음을 남기면 FIFO 반복·차로 막힘 또는 0/0 배분을 만들 수 있으므로 그 변경을 검증 없이 넣지 않았다. 수정 후 기존 수치차분 자료를 재사용하고 일반 교통 결과가 유지되는지 확인한다. 그 뒤 현재 모델로 PFO 상한을 재계산하여 준비한 한 번의 SDMPC 선택을 수행한다.

이번 후속 검사는 교통 계수 보정이나 새 VISSIM 실행이 아니다. 기존 STOP·수요·망·운영 기본 설정과 진행 중인 사용자 프로세스는 그대로다. 모든 실행한 진단은 종료됐고 optimizer/native/push는 0회다. 목표는 ACTIVE / NOT_QUALIFIED이며, offset 문제를 해결하거나 이득 검증을 완료한 것으로 표시하지 않는다.
