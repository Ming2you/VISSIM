# 수정 후 seed47의 선택과 재생

## 판정 — 2026-10-02

**오프라인 SDMPC 선택 1회와 정본 실행 규약의 재생 2회를 완료했다. 물리 이득 검증 완료나 native 실행 결과는 아니다.** seed47의 2700초 기록과 과거 head/VSL 이력에서 시작해 3150초까지 예측했다. 후보는 SC1001 공유 접근로 연결 후보이며, 미래 실측 입력·새 계수 fitting·VISSIM·push는 없다.

공유 접근로의 잔량 감도 보존 수정 후 수행했다. 관련 87개 시험과 일반 숫자 2,880스텝의 수정 전후 정확한 일치는 [잔량 수정 보고서](../sc1001_urban_derivatives/cleanup_fix/README.md)를 따른다. **offset의 주체별 비용·N_P/N_UF 감도 실패는 남아 있다.** 이를 통과로 바꾸지 않고, 기존 일반 숫자 line search와 독립 실행 규약 재생으로 선택의 실제 예측 비용과 제약을 확인했다.

## 선택과 계산량

- 기존 PFO 2회 중 2회, SDMPC 2회 중 2회를 수락했다. 반복 한도 종료이며 수렴·Nash 해·최적성 인증이 아니다.
- 전체 선택 486.80초. 요청 59회 중 실제 예측 57회(일반 숫자 50회, AD 7회), 캐시 적중 2회다. 벽시계 제한은 기존 설정대로 비활성이며 계산량을 숨기지 않는다.
- 현재 모델의 PFO 결과로 N_P cap 577.442713대, N_UF cap 6023.902732대/h를 새로 산정했다. 과거 모델의 cap을 재사용하지 않았다. 각 cap은 PFO 달성값에 기존 margin 100을 더한 값이다.
- 세 개의 150초 명령 블록 모두 RM은 이전 녹색을 유지했고 VSL은 110km/h다. 도시 녹색과 offset만 바뀌었다.
- 기준 자체가 RM을 이미 사용한다. 동측 10639/10681/10490/10484의 녹색은 각각 2/9/5/2초이고 서측 네 미터는 10초다. 따라서 이 결과는 ‘RM이 꺼졌다’ 또는 ‘RM이 무효’라는 증거가 아니다.

단위는 차량·시간이며 차이는 선택−기존 명령 유지다. 이 표는 VISSIM 실측이 아니다.

Ω TTT 예측 감소는 **1.7481%**다. 최적화 근사 모델의 차이 −8.625697과 정본 실행 시간 규약의 차이는 0.148618 차량·시간이다. 예측 이득은 주로 도시 측에서 나왔고 본선·램프 비용은 소폭 늘었다. 외부 항은 모델에서 추적하는 재고의 체류시간이며 native 미삽입 전체 비용을 포함한 감사가 아니다. Ω 목적함수는 그대로다.

|---|---:|---:|---:|---|
| N_P [대] | 501.397490 | 491.056982 | 577.442713 | 둘 다 통과 |
| N_UF [대/h] | 5891.593025 | 5897.613999 | 6023.902732 | 둘 다 통과 |

N_P는 정본 17개 도시 주체의 경계 수지이고, N_UF는 실제 예측 수용 합류량의 8개 램프 합이다. 정본의 기존 집계 함수를 이용해 두 재생 결과에서 직접 계산했다. 새 quota나 대체 물리량을 만들지 않았다.

초기+150초 단위 저장 상태 4개씩의 Ω 재고/공유 접근로 회계를 검사했다. 램프 수지 최대 잔차는 5.19e−13대, 물리 자원 최대 초과는 8.89e−16대 이하이다. 선택 명령의 점수 대상·writer 파일 일치 검사를 통과했으며 native 적용 검증은 여전히 pending이다. 모든 초의 독립 상태/미분 검증을 뜻하지 않는다.

## 범위와 다음 판단

재생 전 변경한 진단 driver는 기존 `probe_levers`에 읽기 전용 제약·재고 검사를 붙인 것뿐이다. AST 비교와 8개 소스/config pin 검사를 통과했다. 생산 모델·보정값·목적함수·명령 범위는 선택과 재생 사이에 같다. 기존 9000초 STOP은 유지했다.

남은 문제는 (1) offset 미분의 하류 전달, (2) 독립 상태에서 RM/VSL/both의 물리 이득 방향과 크기, (3) 선택 명령의 native 반응이다. 이 선택은 도시 비용 감소를 확인한 진단이다. ALINEA+VSL의 고속도로 이득 재현이나 최종 9000초 자격을 대신하지 않는다. 실패한 작은 차분 격자나 계수 탐색을 반복하는 근거로도 사용하지 않는다.

검증 자료는 `assessment.json`, 실행 계획과 종료 상태는 `protocol.json`, 로그는 `run.log`와 `replay.log`다. `assess.py`는 완료된 JSON만 읽어 이 표와 소스 pin을 재검증하며 시뮬레이터나 예측기를 실행하지 않는다.
