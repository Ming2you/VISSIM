# 같은 수용식에서 실측 재고와 예측 재고를 구분

2026-10-02. 직전 목표 턴은 REVIEW39 시간별 경계 장부를 완성했으므로 progress다. 이번에는 기존5초 native90시점의 위치를 현재 모델의 공간으로 투영해 수용식을 평가했다. 새로운 자율 예측·VISSIM·FZP 스캔·계수 보정 없이 다음 수정 대상을 좁혔다. 목표는 ACTIVE/NOT_QUALIFIED다.

## 수용 상한보다 잘못 남는 하류 재고의 영향

모델과 동일한6m 간격·공간 셀·wave·capacity를 사용한다. 현재 위치가 주어진 각각의 시점에서 같은 수용식을 계산했으며, 미래 실측 상태를 예측 입력으로 사용하지 않았다. 아래 수치는5초 표본에서 평가한 평균 예산 [대/초]이고, 실제 지속 처리능력이나450초 총용량을 의미하지 않는다.

마지막 구간에서 차이가 약4.7배다. 동일한 수용식도 실제 재고가 빠지는 상태에서는 훨씬 큰 공간을 허용한다. 따라서 단순한 고정 수용 상한 증대가 먼저라는 근거는 아니다. 다만 이것만으로 수용식의 미시 정확성 또는 근본 원인을 입증한 것도 아니다.

하류에서도 같은 방향의 재고 오차가 보인다.3000–3150에서71번3차로 입구 셀 수용 예산은 실측 위치 기준0.2032/기존0.0375다.3차로 정지선 셀은0.1523/0.0374,4차로 정지선 셀은0.1429/0.0577이다. 반대로5차로 정지선 셀은0.1942/0.4348로 모델이 실제보다 비어 있다고 예측한다.1차로에서도 반대 방향 차이가 있어 모든 차로의 재고가 일괄 과대인 것은 아니다.

기존 기록에서 확인한3·4차로 적체와1·5차로 활용 부족을 같은 식의 상태 비교로 더 좁힌 결과다. 다음에는 **71에서 출구에 접근 가능한 차로 사이의 방출·공간 분배, 그 영향의10641→126 전달**을 검토한다. 합류점 우선권만 임의로 올리거나 본선FD로 보상하지 않는다. 이전에 기각한 대칭 차로 교환률 및126 이동률 후보를 그대로 반복하지 않는다.

## 짧은 연결부의 공간 표현 한계

10641의 길이는45.291m, 한 차로 고정6m 간격 용량은7.5486대다. native90시점 중23시점에서2차로에8대가 있어 기존 ReceivingEnvelope 초기화가 거부한다. 이23개 시점의 같은 상태 수용량은 **미지원으로 표시하고 평균에서 제외**했다. 누락을0대나0수용량으로 대체하지 않았고, 비교 모델 평균도 같은 유효 시점만 사용했다.126과71의 표에 사용된 모든 시점은 지원된다.

기존 모델의 위치−6m 점유구간 가정만으로 링크 내부 부분을 세면23시점 중17개는7.5486대 안에 들어간다. 나머지6개는7.5967–7.6817대로 여전히 초과한다. 링크 경계에서 차량의 일부가 인접 링크에 걸치는 표현과 고정 간격 근사가 함께 관련될 수 있다. 그러나 구간 밖 부분을 버리면 차량이 사라지고, 모든 부분을126에 배정하면 off-ramp에서 온 차량의 경로를 잘못 처리할 수 있다. 단순히 저장용량을8대로 올리거나 간격을 줄이는 수정은 하지 않았다.

이 약0.45대의 단면 용량 차이만으로450초 배수 부족33대를 설명했다고 보지 않는다. 저장·초기화의 일관성 문제와 동적 차로 활용·회복 문제를 분리한다.

## 검증과 시간 위상

- 실제 COM2700초 초기 위치로 복원한 모든 모델 셀 재고는 저장 초기 상태와 정확히 일치했다. 보존 잔차 최대1.78e-15대.
- native FZP 캐시는정수초+0.1초, 저장 예측 예산은정수초다. 초기 비교 실패0.1597대는 단순 반올림이 아니라 이 시간차에 따른 차량 이동도 포함했다. 같은 차량의 위치가124.503→126.96m로 움직인 사례로 확인했다. 이후 정확 초기 검증은 별도 pinned COM frame으로 수행했다.
-5초 진단 표본에는+.1초 위상을 그대로 명시했다. 이를 정확한 동시 미시 수용량 검증으로 부르지 않는다. 전체 신호·예측을 재실행하거나 기록 시각을 덮어쓰지 않았다.
- 공간 투영 최대 이동은8.04m다. 실측 위치 그대로의 모델이라고 부르지 않는다. 미래 자료는 개별 시점의 조건부 평가에만 썼다.
- 예측 총량·제어 손익·계수·생산 코드·설정은 변경하지 않았다. 원래9000 STOP도 유지했다. 현재 원인 분리가 끝났다고 선언하지 않는다.
