# 최소 차로변경 보정: 문헌 적용과 작은 재보정

2026-10-03. **문헌 검토·실제 구현·제한 보정·다른 상태 검증 완료. 후보는 불채택, 전체 이득 보정 목표는 미완료.** 새 VISSIM 런·FZP 스캔·push는 하지 않았다. 진행 중인 DATA9000의 동결 실행본·프로세스는 건드리지 않았다.

## 결론

차로변경을 모두 미시적으로 재현할 필요는 없다. 다만 이번에 시험한 **현재 진출 목적 차량 비율과 통과시간만으로 계산하는 유효밀도 보정**은 학습 조건에서는 개선됐지만, 다른 혼잡 상태에서 VSL의 큰 이득을 놓쳤다. 후보 수나 계수 범위를 더 늘리지 않았으며, 시험 추가분을 운영 소스에서 제거했다. 기존 사용자/이전 작업의 변경은 보존했다.

실제 유출량을 정지 차량 수의 설명변수로 바로 쓰는 것은 피해야 한다. 막혀서 나가지 못할수록 유출이 줄어들기 때문이다. 현재 진출 목적 재고 또는 예측 도착이 수요 측 설명변수에 가깝다. 이 구분만으로 효과가 충분히 표현되는 것은 아니다.

## 문헌과 실제 적용 범위

[Jin(2010), A kinematic wave theory of lane-changing traffic flow](https://arxiv.org/html/math/0503036), 식5·6·12:

```
rho_effective = rho * (1 + epsilon)
v_equilibrium = V(rho_effective)
epsilon = alpha * p_lane_change * t_lane_change / T_traverse
```

논문은 LWR 및 균일한 구간의 예시다. 비정상 METANET의 보편식이 아니다. 이번 **적용안**은 현재 예측 경로별 재고에서 진출 목적 비율p를 계산하고, 고정 구간의 차량 가중 평균속도로 `T_traverse=3600*L_km/v_kmh`, `epsilon=c_sec*p/T_traverse`를 계산했다. 진출 목적 비율은 실제 차로변경 필요 비율의 대리변수이며 모든 진출 차량이 변경한다는 뜻이 아니다. 정지 차량 수를 직접 예측하는 식도 아니다.

동측 물리 셀16–20(0기준), 약926m의 같은 구간에 공통 두 계수만 시험했다: c={0,10,30}초, rho_crit 배율={1,1.1,1.2}. 범위는 첫 실행 전에 protocol.json에 고정했다. c는 평균 변경 수·소요시간·대리변수 보정을 묶은 유효 계수로, 30초를 실제 한 번의 차로변경 시간이라고 해석하지 않는다.

기존 METANET의 이완 목표 계산에만rho_effective를 넣었다. 실제 재고·보존식·q=rho*v*lanes·TTT에는 원래rho를 썼다. 동적 진출램프 저장·배수, 실제 합류·램프 대기, anticipation·merge 식, VSL 이력과 액추에이터는 유지했다. 계수 배율은 영향 구간의 기존rho_crit에 함께 적용해 이미 FD가 흡수한 손실 위에 감속만 강제로 추가하지 않도록 비교했다. 시드·시각·명령에 붙는 보상은 없다.

논문 식10에서는 차로변경 시간도 속도에 따라 변할 수 있다. 따라서 VSL이 통과시간을 늘리면 항상 방해가 감소한다고 단정할 수 없다. 이번 고정c는 이를 단순화한 가정이다.

[Jin(2013)](https://www.sciencedirect.com/science/article/pii/S0191261513000994)은 weaving/non-weaving 구성을 구분한다. [Zhou et al.(2022)](https://doi.org/10.1016/j.trb.2022.09.002)은 필수 차로변경 차량의 정지·틈 대기와 상류 대기/하류 공백을 다룬다. 두 문헌의 전체 모형을 이번에 구현한 것은 아니다. 원문 식을 확인한 Jin2010 보조항을 먼저 시험했다. 전체 문헌 비교는 ../lane_interaction110/LITERATURE_MINIMAL_CORRECTION.md 참조.

Claude의 기존 FWW_STRUCT_CHECK §2.1/FWW_STRUCT_PROPOSAL F15도 참고했다. 다른 서측 망의 계수와 강한 FIFO 가정을 그대로 이식하지 않았다.

## 채택 여부와 남은 한계

**불채택.** 이번에 추가한 두 운영 소스 변경을 수정 전 SHA256과 일치하게 되돌렸다. 새 테스트도 운영 테스트 목록에서 제거하고 tested_sources에 보관했다. candidate.patch에 정확한 시험 변경을 남겼으며 run.py는 후보가 설치되어 있지 않으면 실패한다. 실패 결과를 기준 모델이나 SDMPC에 연결하지 않았다. 실행 중인9000초 런에는 처음부터 이 후보가 들어가지 않았다.

이 시험은 모든 단순 모형이 실패한다는 근거가 아니다. **현재 비율÷통과시간이라는 기억 없는 대리변수**가 이번 혼잡 상태의 제어 응답을 설명하지 못했다는 결과다. 향후 최소 모형에서도 차로가 막힌 부담의 지속·해소 또는 합류 차량으로 인한 차단을 표현할 필요가 있는지 분리해서 판단해야 한다. 새 계수 탐색보다 이 표현이 과거에 이미 시험됐는지 먼저 확인한다. 기존 lane-only/FIFO/receiving 후보의 실패를 반복하지 않는다.

원자료 재스캔·추가 후보·추가 native·push는 이번 작업에 포함하지 않았다. 전체Ω 이득 및 SDMPC 선택 검증은 통과했다고 주장하지 않는다.
