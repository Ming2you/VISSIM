# 10643 하류 차로 이동 확인 — 완료

기존 seed47 유지 FZP를 한 번 읽었다. 새 VISSIM 실행·COM 조회는 없다. 2550–3150.1초의 12개 관련 도로/커넥터 행만 캐시했다. 실제 기록 간격은 5초다. 2700초 이전은 사전 관측, 이후는 평가로 분리했다.

실제 71번 도로의 driving behavior는 FREELANESELECTION이며 coopLnChg=true다. 일반적인 자유 차로 변경의 가능성은 [PTV 2020 설명](https://cgi.ptvgroup.com/vision-help/VISSIM_2020_ENG/Content/4_BasisdatenSim/FahrverhaltensparameterFahrstreifenwechsel_bearb.htm)과도 일치한다. 이 설정만으로 개별 차로 변경의 원인을 확정하지는 않는다.

동일 도로의 연속 표본에서 다음 움직임을 확인했다.

| 구간 | 10635행 4→5 | 10635행 5→4 | 경로 미배정 71의 2→1 |
|---|---:|---:|---:|
| 예측 전 2550.1–2695.1 | 2 | 1 | 3 |
| 평가 2700.1–3150.1 | 12 | 0 | 3 |

현재 모델의 v2 off-ramp 관측은 exchange_rates=[]를 제공하고, 기존 진단 설정의 history_exchange도 false다. 따라서 목적지에 이미 접근 가능한 차로 사이의 이동이 없다. 필수 차로 변경은 별도로 이미 구현돼 있다. 입력 옵션만 켜면 빈 목록이므로 이 공백을 해결하지 못한다.

표는 5초 간격의 **관측된 순차로 변화**다. 그 사이 여러 번 움직인 사례를 놓칠 수 있다. 링크가 바뀌며 차로 번호가 달라지는 것은 차로 변경으로 세지 않았다. 짧은 출구 커넥터에서 관측한 통과 쌍은 MER의 정확한 정지선 방출량을 대체하지 않는다. None 목적지를 실제로 미리 알았던 회전으로 재해석하지 않았다.

이 근거로 사전 관측에서 공통 이동률 하나를 추정해 기존 물리 모델에서만 시험했다. 결과는 [후보 검증](../lane10643_exchange/README.md)에 있다. 후보는 미채택이며 현재 생산 소스에 남기지 않았다. 본선→10643 진입 부족과 하류 배수 오류의 분리가 다음 순서다.
