# 신호 앞 저장공간의 입구 수용 수정

2026-10-04. **공간 결함 수정·450초9회 확인 완료. 이득 검증 미통과, 목표 ACTIVE / NOT_QUALIFIED.** 새 계수 fit/VISSIM/FZP/9000초 분석/push 없음. 기존 STOP 유지.

## 변경

기존 `evaluation/controllers/physical_ramp_boundary.py`의 두 입구 경로가 하나의 `_admission_space_veh`를 사용하도록 수정했다.

`입구 여유 = min(전체 연결부 빈 공간, max(0, 신호 앞 길이×차로 수/간격 − 신호 앞 재고))`

신호 앞이 꽉 찼을 때 신호 뒤의 빈 공간을 빌리지 않는다. 녹색으로 차량이 신호를 통과하면 해당 공간만 열린다. 초기 관측이 명목 용량보다 크더라도 차량은 삭제하지 않으며 신규 진입을 막는다. 신호 위치0인 기존 경계 점 대기열 규약은 유지했다. 거리/신호/서비스 표/gap/속도식/수요/1초 적분은 바꾸지 않았다.

component 요청에서 거절된 차량은 기존 outside_component backlog에 남는다. 전체 도시부 결합 경로에서는 `current_admission_space`를 통해 받아들이는 양만 제한하고, 거절분은 기존 상류 소유 재고에 남겨야 한다. 작은 coupled-transfer 시험에서 거절 시 새 backlog를 만들거나 원 상태를 변경하지 않음을 확인했다. 실제 전체Ω·도시 결합·AD의 재검증은 아직 남았다.
