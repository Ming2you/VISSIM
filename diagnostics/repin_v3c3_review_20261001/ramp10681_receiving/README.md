# 10681 차로별 수용·신호 전후 반응 분리

2026-10-02. **PROGRESS / ACTIVE·NOT_QUALIFIED.** 직전 턴은 완료된 원격 검토를 다시 설명한 것으로 no progress다. 이번에는 실제 호출 인자와 차로별 수지를 기록하고, 실측 경계를 사용하는 제한된 조건부 진단으로 다음 수정 범위를 좁혔다.

## 실제 실행과 설정표의 차이

현재 후보는 `sc105_supply/candidate_config.json`이다. 이 파일 바깥 freeway 설정에는 `physical_ramp_lane_coupling: RM_C10681=[0,1]`가 남아 있지만 실제 v2 loader는 **manifest에 고정된 reference_config**를 사용한다. 해당 manifest는 `lane_groups=false`이며 reference에는 본선 차로 연결이 없다. `_load_sources_v2`는 이 모드에서 차로군 기능을 켜면 거부한다.

실제 450초×두 조건의 인자는 모두 차로별 별도 수용 예산이 없고, 두 램프 차로에 합산 gap 수용 예산을 절반씩 나눈다. 실제 gap 계수는 critical3.5초/followup1.5초다. 바깥 설정의3/2초와 혼동하면 안 된다. 이는 이번에 활성화하거나 바꾼 값이 아니다.

대화 중 바깥 설정만 보고 “이미 본선 차로별 조건에 연결”이라고 설명한 것은 잘못이었다. 실제 실행값과 manifest를 대조해 정정했다. 이번 계측은 buffer의 기본 metadata 대신 **runtime의 실제 mapping·receiving node와 매초 호출 인자/receipt**를 보존한다.

## 원래 예측을 바꾸지 않은 계측

- 기존 `probe_selected_arrival_path.py`의 `probe_levers` 안에서만 임시 관측 wrapper를 사용했다. 원래 메서드를 그대로 호출하고 반환된 receipt를 복사하며, scope 종료 시 원래 메서드를 복구한다. 운영 runner/adapter/물리 코드 변경은 없다.
- 같은 seed47@2700의 유지/선택450초 두 번, 총49.8196초(session16059 exit0). 전체 출력은 wall time 외 기존 값과 정확히 같다. 기존 trace도 추가한 두 필드 외 정확히 같다.
- 최초 호출은 별도 label이 없어 예측 전에 거부됐다. 실패 폴더/로그를 보존했고, label을 명시한 두 번째 호출만450초 예측을 수행했다. 수요/제어 변경이나 native 재시작은 아니다.
- 차로별 receipt를 이용해 국소 버퍼를 재생했다. 원래 모든 receipt와의 최대 차이는3.98e−13이다. posthead만 분리한 보존 계산도 매초 원래 합류/재고와 최대1.78e−15 차이로 일치한다.
- 새 VISSIM, FZP 재스캔, 최적화, 계수 탐색, push는0회다. 기존9000 STOP은 유지한다.

아래 세 행은 **미래 실측을 쓰고 본선 수용 예산을 기존 예측에 고정한 원인 분리용 계산**이다. 상류·본선 피드백이 닫힌 자율 예측, 실행 가능한 후보, Ω TTT 이득 검증으로 사용하지 않는다. 계수는 모두 원래 값이며 어떤 후보도 운영에 채택하지 않았다.

실측 도착을 넣어도 신호 통과가 각각19.57/28.00대 과대예측된다. 따라서 상류 공급 부족만 수정하면 해결된다고 할 수 없다. 현재 자율 예측의 종료 신호 전 재고는2.47/0.57대인데 native는36/38대다. 실측 도착 시각·차로를 넣으면16.43/10.00대로 늘지만 여전히 부족하다.

실측 head 통과를 넣은 posthead 진단에서도 합류는9.40/14.74대 과대예측된다. 종료 posthead 재고는8.60/5.26대로 native18/20보다 작다. 특히 마지막3000–3150초 합류는59.57/56.89대 대 native51/49대로 과대다. 신호 이전 반응 오차와 신호 이후 수용/이동 오차가 함께 있으며, 둘 중 하나만의 잘못으로 확정하지 않는다.

현재 자율 예측의450초 차로당 수용 예산은 유지114.40/선택114.48대다. 2차로는 이 예산을 모두 사용하고, 1차로가 대부분을 쓰지 못한다. 유지에서 약83.43대의 미사용 예산은 사실이지만 **동일 궤적에서 남은 예산**이며, 다른 차로에 넘겨 얻을 수 있는 추가 합류량이나 물리적 용량으로 해석할 수 없다. 실제 head를 주면 이미 배수를 과대예측하므로 pooling 또는 용량 증대의 근거도 아니다.

## native 차로 증거와 한계

- 완료된 ramp entry→head 차량 짝: 유지1→1 42대,2→2 106대,2→1 2대,1→2 1대; 선택1→1 40대,2→2 95대,1→2 2대다. 완료 통과 표본이며 아직 대기 중인 차량의 수요·전체 차로 변경률이 아니다.
- 1m 진입 검지기·head MER와150초 프레임은 기존 obs150 loader로 원본 hash와 tail을 검증했다. 여섯 창 도착/head 총수는 기존 native audit와 같고, 해당 램프 삭제는0이다.
- 진입 검지 위치는0m 경계와1m 차이가 있고, 조건부 사건을1초 계산창으로 묶었다. subsecond 정합을 주장하지 않는다.
- posthead 차로별 `head + 초기재고 − 종료재고`에는 횡방향 이동이 섞인다. 이를 실제 차로별 합류량으로 부르지 않는다. 합계는 native 합류와 일치하며 위 전체 posthead 과다 배수 결론은 이 차로별 모호성과 별개다.

## 다음에 바꿀 범위

상류 beta/service 격자나 램프 수용 예산 pooling을 반복하지 않는다. 먼저 **10681 합류 직전 물리 셀11→합류 셀12의 예측 수용 입력**을 native 본선 상태/유량과 대조한다(31개 물리 셀,0기준). 현재 gap 수용식이 평균 q만으로 혼잡·회복 시 수용을 잘못 평가하는지, 잘못 예측한 본선 q가 기존 식으로 전달되는지를 분리한다. 동시에 신호 전 통과 시점/신호 이후 저장 압력과 이미 실패한 posthead receiving 시험을 대조해야 한다. 이번 증거만으로 새 파라미터나 용량 보너스를 도입하지 않는다.

관련 코드는 기존 램프·수용 계산 안에서 다룬다. Ω 목적함수, 외부 비용의 별도 진단, 동적 off-ramp·명령·망은 유지한다. 큰 RM/VSL 손익과 독립 상태의 후보 순위, SDMPC 선택, 최종9000초 자격은 여전히 미완료다.

실행 증거와 입력 SHA는 `assessment.json`, 범위와 실패는 `protocol.json`, 변경 함수/소스 보존 검사는 `verification.json`에 있다.
