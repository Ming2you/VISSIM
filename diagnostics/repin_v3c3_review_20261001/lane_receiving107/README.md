# REVIEW107 — 차로별 수용 제한의 조건부 개선과 자율 예측 실패

2026-10-03. 완료, **후보 미채택**. 전체 이득 보정 목표는 ACTIVE / NOT QUALIFIED다. 새 VISSIM·FZP 스캔·계수 fitting·push는 하지 않았다. 실행 중인 불변 9000초 런은 변경하지 않았다.

## 질문과 범위

사용자의 “정지 차량과 차로 정보를 반영한 유효 차로 감소”를 검토했다. REVIEW106에서 대기 차량이 있어도 해당 차로의 방출은 계속됐으므로, 정지 차량이 있다는 이유만으로 한 차로를 완전히 닫지 않았다. 이번에는 **차로별 밀도에 따른 하류 수용 유량** 한 가지를 검사했다. 정지 대수·대기열 선두/후미를 직접 예측하는 모델을 완성한 것은 아니다.

셀19→20 경계에 현재 셀20의 고정 FD에서 유도한 삼각형 수용 상한을 추가했다. 셀 번호는 31개 물리 셀의 0기준이다.

`Q = rho_crit * v_free * exp(-1/a)`, `w = Q/(rho_jam-rho_crit)`

`R_g = max(0, min(Q, w*(rho_jam-rho_20,g)))`

`q_19,g = min(기존 sending, 물리적 잔여 공간/시간간격, R_g)`

명령별 capacity 보너스와 capacity drop 계수는 추가하지 않았다. 모든 조건에서 동일한 Q·w를 사용했다. 물리적 차로 수를 줄이는 기존 lane-drop 감속항도 수정하지 않았다.

## 현재 상태를 계속 제공하는 조건부 검사

완료된 seed29·43·67의 6조건 캐시를 재사용했다. 매5초의 현재 차로별 N/v를 넣고 다음5초 경계 통과를 평가했다. 이를30초로 합친 RMSE는 다음과 같다.

| seed | 기존 sending+공간 상한 | 차로별 수용 상한 | 감소율 |
|---|---:|---:|---:|
|29|4.834|4.749|1.7%|
|43|5.829|5.207|10.7%|
|67|5.711|5.083|11.0%|

단위는 대/30초다. 전체 RMSE는5.439→5.006으로7.95% 감소했지만 bias는−0.605→−2.070대로 더 음수가 됐다. seed67 중간150초의 VSL90−110 추가 방출은 실측+12대, 기존 순간 sending 합계−5.58대, 차로별 수용 상한+10.72대였다. 다른 구간에는 여전히 방향 오류가 있다.

이는 올바른 현재 상태를 알고 있을 때의 진단이다. 미래 상태를 모델이 맞춘 결과나 제어 이득 검증으로 해석하지 않는다. 기존에 이미 살펴본 seed를 새 독립 검증이라고 부르지 않는다.

## 미래 관측 없이 진행한 450초 예측

조건부 검사 통과 후, 실행 전에 예산을 최대6회로 명시했다(`dynamic/protocol_amendment.json`). default-off 전후2회, 기존 보존형 차로 모델2회, 수용 제한 추가2회다. fitting은0회다.

이전 `joint_lane_25`의 셀19–25 차로×목적지 재고 모델을 현재 경로 스키마에 맞춰 진단 프로세스 안에서만 연결했다. 정본 파일을 덮어쓰지 않았다. 초기 상태2670.1초, seed67, RM 완화, VSL110/90의 동일 명령 비교다. 미래 native 상태는 평가에만 사용했다.

아래 Δ는90−110이며 음수가 이득이다. TTT 단위는 차량·시간이다.

|지표|실측|기존 차로 모델|수용 제한 추가|

|동측 본선 TTT|−1.492|+0.265|+0.259|

이 표의 평가 영역은 **FW_E31셀+4개 on-ramp·4개 off-ramp 커넥터**다. 전체 Ω TTT·정상 Ω 유출과 다르다. 평가 영역 유출을 사용자 정의 TTD로 부르지 않는다.

동측 본선 반응 오차 감소는0.33%로 사전 기준20%에 미달했고, 의미 있는 이득의 부호도 틀렸다. 속도·밀도 RMSE는 차로 모델 대비 약0.4% 개선에 그쳤다. 이전에 채택하지 않았던 차로 모델을 조금 개선한 것이며, 현재 정본보다 나아졌다는 뜻도 아니다. RM 완화 조건 본선 TTT는 실측137.883, 현재 정본138.143, 차로 모델143.150, 수용 제한 추가143.262였다.

REVIEW106의2940.1초 관측 사례에서 셀20 1차로는 VSL110일 때29대/1.21km/h, VSL90일 때14대/26.54km/h였다. 이번 모델은 각각25.27대/5km/h,25.21대/5km/h로 예측했다. **현재 차로 상태를 이용한 방출 계산 개선이, 그 차로 대기의 발생·회복 예측 개선으로 이어지지 않았다.** 다만 한 시각의 평균만으로 원인 항을 확정하지 않는다.

## VSL이 차로 변경 시간을 늘린다는 설명

같은 거리에서 실제 속도가 낮아지면 이동 시간은 길어질 수 있다. 그러나 그 시간이 실제 목적 차로 진입 성공과 정지 감소로 연결되는지는 따로 확인해야 한다. 이번 모델의 차로 교환율은 시간당 일정하고 목적지와 무관하다. 시간 여유에 따른 교환 기회는 일부 표현해도, 출구 접근 차량이 어느 위치에서 필요한 차로 변경을 완료하는지는 설명하지 못한다.

앞선 REVIEW90의 동일84대 사후 선택 집단에서는 VSL90의10483 진출이 평균21.01초 빨랐으며 셀19·20 통과가 약16.51초 빨랐다. 해당84대의5초 인접 표본에서 동일 링크 내 차로 번호 변경은 양 조건 모두0건이었다. 따라서 이 자료만으로 “더 긴 차로 변경 시간”이 이득의 원인이라고 확정할 수 없다. 접근 속도 저하와 병목 대기 감소는 별개로 구분해야 한다. 주변 차량의 차로 변경·도착 간격 효과는 아직 남은 가설이다.

## 검증과 다음 판단

- default-off의 cells/flows/ports/ramps가 전후 정확히 일치했다.
- 모든 예측의 상태 유효성·보존 검사를 통과했다. 최대 연속방정식 오차5.69e−14대, 차로/목적지 재고 차이7.82e−14대다.
- 기존 helper10개 AST, 정본9개 파일 SHA, 기존 STOP이 유지됐다. 프로세스 내부 함수 연결도 복구했다.
- 6회 예측 및 평가19.05초. 이 시간은 VISSIM 실행시간 개선 수치가 아니다.
- 이 후보의 계수 grid, 추가 seed 확대, SDMPC 채택은 진행하지 않는다.

다음에는 기존 캐시에서 출구행/통과행을 구분해 **목적 차로에 들어온 위치·대기 시작·하류 수용 및 배수·회복**의 연결을 좁혀야 한다. 정지 대수만으로 물리 차로를 닫거나 VSL별 상수 용량 보너스를 넣는 근거는 없다. 이전 seed47 큰 RM 이득과 seed71 선택 순위 실패는 그대로 보존한다.

자료: `assessment.json`은 조건부 검사, `dynamic_assessment.json`은 자율 예측 판정이다. 실제 실행 소스·6개 예측·전후 parity·복구 검사는 `dynamic/`에 있다. `assess_dynamic.py`는 저장된 결과만 요약하며 예측을 재실행하지 않는다. Claude의 기존 worklog도 확인했으며 다른 망의 제한된 VSL 권한 해석을 이번 망의 무효 판정으로 옮기지 않았다.

별도 데이터 수집9000초 런은 이번 마지막 작은 로그 확인에서 실제4500초에 도달했다. 이전4050초 장애 지점은 통과했지만9000초 완료나 성능 검증을 뜻하지 않는다.
