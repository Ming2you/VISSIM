# 10643 하류 도착 구성과 차로 이용 조건부 진단

기존 자료만 사용한 국소 재생 8회를 완료했다. 이 시험은 **미래의 실측 도착을 넣은 원인 분리용 진단**이며, 자율 예측 성능이나 제어 이득 검증이 아니다. 새 VISSIM 실행·FZP 재스캔·생산 코드 변경은 없다.

## 범위와 보존

- seed47 RM 유지, 2700.1–3145.1초, 링크126·10641·71. 캐시 마지막 표본은3145.1초이므로450초 결과로 부르지 않는다.
- 최초35대, 도착204대, 종료25대, 비정상 삭제2대. 정상 방출은 보존식으로212대이다. 이는 모든 출구를 직접 검지해 센 값이 아니다.
- 직접 확인한5초 출구 전이는185대(10634:76,10635:57,10642:52). 일부 짧은 출구 통행은 표본 사이에 지나가므로 출구별 수치를 총 방출과 혼동하지 않는다.
- 실제 입구 도착을 각5초 구간의 앞/뒤에 배치하고, 기존 예측의 하류 수용량/제약 제거를 각각 비교했다. 받아들이지 못한 도착은 외부 FIFO에 남겼다. 구간 내 순서는 위치·차량ID 근사로서 정확한 미시 도착 순서가 아니다.
- 신호는 확인된 native 녹색 기록을 그대로 사용했다. 이 자료를 실제 예측 입력으로 연결하지 않았다.

## 지연 기록된 차량 삭제

2714.9초 차량17227,2730.3초 차량22978은 링크71의 차로 변경 실패로 삭제됐다. 두 사건은 뒤늦은3000초 ERR 묶음에 포함돼 있었다. ERR를 묶음 자체의150초 구간으로 잘라 읽으면 놓칠 수 있으므로 완료된 묶음 전체를 모은 뒤 사건 시각으로 분류했다.

삭제 없음/관측 삭제 시각에 남아 있는 해당 차량 질량만 제거한 진단을 별도로 수행했다. 후자는 정상 방출164.85/164.03대로, 이 모델 안에서는 큰 차이가 없었다. 실측 삭제의 교통 영향까지 작았다는 인과 결론은 아니다. 삭제는 정상 유출·TTD에 넣지 않았고 생산 모델의 배수 법칙으로도 사용하지 않는다. 이 국소 발견만으로 기존 전체 망 지표가 잘못됐다고 판정하지 않는다.

처음의 실행 전 검사는 이 두 삭제를 발견해 중단했다(`execution.log`). 결과를 보존하고 재생 시작 전에 진단 범위를8회로 수정했다. 이후 실행은 정상 완료됐으며 재생 계산 합계는 약4.83초다.

## 다음 후보의 근거

`route_free_outcomes.json`에서 초기4대+도착48대, 총52대가 목적지 미배정 연속 주행 집단이다. 이 가운데21대는10642,17대는10634로 나간 전이를 직접 확인했고,11대는 출구 표본 누락,1대는head만 확인,2대는 종료 잔여다. 누락11대의 목적지를 임의로 배정하지 않는다.

기존 모델은 이 집단에 자유 차로 이동이 없어10642 접근을 거의 만들지 못한다. 따라서 기존의 **지정 목적지 차로 간 이동 후보**와 달리, 목적지 미배정 차량에 한정한 공간 여유 기반 인접 차로 이동 한 가지를 시험한다. 목적지를 강제하거나 관측 출구 비율을 끼워 넣지 않는다. 계수는2700초 이전 자료만 사용하고,450초 자율 예측과 다른seed로 검사한다.

주요 근거는 `assessment.json`, `protocol.json`, `route_free_outcomes.json` 및 각 재생 JSON이다. 배출 정합은 아직 완료되지 않았고, 셀별 METANET 보정이나 새로운9000초 실행을 정당화하는 결과가 아니다.
