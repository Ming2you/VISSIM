# SC1001: 커넥터 배수와 정지선 방출의 분리 — 2026-10-02

## 확인한 문제

**우리 선택망에서도 10491 커넥터 배수를 너무 작게 예측하고, 실제 접근로에 있어야 할 재고를 커넥터에 쌓는 문제가 확인됐다.** 원격 v3c3의 수치를 옮긴 결론이 아니라, 선택망 64cf의 완료된 두 런과 기존 모델 예측을 대조한 결과다. 이것이 전체 RM·VSL 이득 오차의 전부라는 뜻은 아니다. 아직 물리 수정·재보정·수정 후 이득 검증은 하지 않았다.

이번 작업: 완료 FZP 두 개를 각 1회 읽어 해당 지역만 저장했다. 신규 VISSIM·모델 예측·최적화·계수 탐색·push는 모두 0회다. 이미 끝난 자료와 현재 원본 코드만 읽었고, 지난 검토에서 반영한 K1/K6 외에 생산 코드를 추가 변경하지 않았다.

10491 전체 배수는 **실측 128 / 모델 27.37대**다. 초기 재고는 둘 다 3대인데, 실측은 2대로 끝나고 모델은 38.58대로 끝난다. 첫 구간부터 모델 유입이 더 적은데도 과도한 재고가 생긴다. 10481은 모델 유입도 작아 가짜 누적의 양상이 다르므로 같은 비율로 일괄 보정하면 안 된다.

## 2. 차량은 포트를 나간 뒤에도 접근로에 남는다

선택망의 물리 경로:
- 10491 → 129 → 10777 → 127 → SC1001 정지선.
- 10481 → 127의 약 210m 지점 → 약 621.5m 정지선.
- 도시 입력 32도 이 접근로의 신호 서비스를 함께 사용한다.
- 링크127의 1·2차로는 SG2, 3차로는 SG5다. 이 둘은 별도의 녹색을 갖는다.

실제로 커넥터와 정지선 양쪽에서 같은 차량을 관측한 사례만 연결했다. 정지선 통과 구간의 시작이 900초 이상인 사례를 사용했다. 5초 기록 때문에 정확한 통과 시각 대신 시간 구간을 유지했다.

| 기존 런 | 출발 포트 | 관측된 완결 사례 | 포트 출구→정지선 시간의 중앙값 구간 | 포트 출구에서 SG2·SG5가 모두 적색인 사례 |
|---|---|---:|---:|---:|
| seed47 RM 유지 | 10491 | 574 | 135–145초 | 280 / 574 |
| seed47 RM 유지 | 10481 | 140 | 112.5–122.5초 | 72 / 140 |
| seed29 무제어 | 10491 | 1,986 | 145–155초 | 968 / 1,986 |
| seed29 무제어 | 10481 | 550 | 135–145초 | 277 / 550 |

이 시간은 **접근로 주행과 신호·교통 대기를 합친 값**이며 순수 출발 지연이 아니다. 시작·끝을 모두 관측한 완결 사례의 분포라서, 빠르게 커넥터를 건너 기록에 잡히지 않은 차량과 런 종료 시 미완결 차량을 대표하지 않는다. 두 런은 같은 망의 다른 운용 사례이며 제어의 인과 효과를 비교하는 공통 초기 상태 쌍이 아니다.

‘두 SG 모두 적색’만 따로 계산한 이유는, 정지선 직전 5초 사이에 차로를 바꿔 실제 통과 차로를 잘못 분류할 수 있기 때문이다. 이 부분집합은 나중에 어느 차로를 썼는지와 무관하게 **커넥터 출구가 신호 정지선과 다른 물리 경계**임을 보여준다. 포트가 자유롭게 배수된다는 뜻은 아니다. 접근로가 가득 차면 포트까지 실제로 막힐 수 있다.

두 native 원본 네트워크 SHA는 모두 선택망 `64cf5f55fe9990f3e25bc4fedebf4ab1e4634c8138dbcf5697a136c48cb559dc`와 같았다. SC1001 신호 파일 SHA도 모두 `014d6a384b3d4c2034904f3686e9d0331327c9de1d61d8e2e325d26820c6eec1`로 같았다. 고정 신호는 150초 주기/75초 offset, SG2 녹색45초·황색3초, SG5 녹색24초·황색3초다. 신호는 바꾸지 않았다.

## 3. 현재 코드와의 차이

`evaluation/controllers/lane_offramp_runtime.py::LaneOfframpRuntime.drain`의 신호형 off-ramp 분기는 다음을 한 번에 수행한다.

1. off-ramp movement 서비스율 × 해당 현시 녹색으로 **커넥터 배수**를 제한한다.
2. 커넥터 재고를 감소시키고 SC1001 정지선을 지난 `receiving_link`로 이동시킨다.
3. 그 이후의 도시 corridor 지연을 적용한다.

따라서 129·127에서 신호 전까지 이동하고 기다리는 과정과 커넥터 배수를 같은 방출로 축약했다. 현재 기록 초기화에서는 이미 링크127에 있는 차량은 도시 접근로 쪽에 배치되므로, 초기 접근로 차량과 예측 중 새로 off-ramp를 나온 차량의 처리 경로도 다르다.

설치된 포트 movement 서비스율은 E 413.06, N/S 각각206.53대/h다. 두 진출 흐름과 도시 접근로를 같은 head-resource로 묶는 명시적 계약도 이번 runtime audit에서는 없었다. 이 값만 크게 올리면 커넥터 가짜 재고는 줄일 수 있어도 접근로 대기와 공유 신호 비용을 건너뛸 위험이 있다. **1,800/차로 같은 값을 바로 대입하지 않았다.**

## 4. 정확히 확인하지 못한 부분

5초 FZP 정지선 카운터를 seed47의 독립 native head 기록과 비교했다. 900–2700초 12개 구간에서 native는 742대, FZP 통과구간 끝 시각에 배정한 값은 725대였다. 5초 시간 모호성을 허용해도 4개 구간은 native 수를 포함하지 못했다. 결과는 `FAIL_EXACT_CENSUS`로 보존했다. 관측 사이 차로 변경·짧은 링크 통과 등의 누락이 있으므로 이 카운터를 정확한 차로 서비스율 보정에 쓰지 않는다. seed29에는 이번에 대조한 native head 이력이 없어서 `NOT_AVAILABLE`이다.

사전 고정 기준 ‘녹색 중 모든 5초 표본에서 정지선 전120m 안에 정지 차량이 남아 있음’을 만족하는 SG2의 1·2차로 주기는 두 런 모두 0개였다. 기준을 사후 완화하지 않았다. SG5는 각각 3개/1개뿐이어서 새 포화율을 채택할 근거로 삼지 않았다. 원격 v3c3의 포화 관측 개수와 서비스율은 이 망에 그대로 적용할 수 없다.

원래 `*_summary.json`의 개별 head 차로 기준 적색 분류와 서비스 수치는 탐색용 표본 통계다. 채택 판단에는 뒤의 `*_validation.json`과 위 제한을 함께 적용해야 한다. 원래 추출·분석 소스는 `audit_stopline_executed_extract_analyze.py.txt`로 보존했다.

## 5. 다음에 반영할 최소 구조와 검증 범위

새 METANET 감속항보다 아래 도시 경계 연결을 먼저 고친다. 아직 적용하지 않은 작업 명세다.

1. **재고 소유 분리**: 실제 커넥터 포트 → 129/127의 유한 접근로 이동 재고 → 같은 물리 정지선 큐 → 기존 도시 corridor. 기존 도시 차량과 중복해서 세지 않고 Ω TTT에 한 번씩 포함한다. 커넥터 배수는 현시 녹색 대신 바로 다음 접근로의 수용 여유로 제한한다. 포트/접근로별 저장과 역류는 유지한다.
2. **경로 보존**: 10491에서 129의 on-ramp 분기와 도시 통과를 구별한다. 이미 선택한 목적지를 다시 뽑거나 모든 차량을 기존 W gate로 넣어 재분기시키지 않는다. 현행 도시 gate는 여러 물리 링크를 묶으므로 무조건 재사용하지 않는다.
3. **공유 방출**: 링크127 SG2의 1·2차로, SG5의 3차로에 대해 도시32·10491·10481이 같은 실제 신호/차로 서비스를 소비하게 한다. 신규 계수를 독립적으로 각 포트에 주지 않는다. 차량의 현재 위치·거리와 과거에 완료된 관측만 초기화에 사용한다.
4. **작은 검증부터**: 생산 기본값은 기존 동작을 유지하고, 커넥터는 배수되지만 신호 큐는 적색에 멈추는 경우, 접근로가 차면 포트까지 막히는 경우, 두 포트+도시 흐름의 서비스 합과 차량 보존을 먼저 확인한다. 그 뒤 동일 기록 상태의 450초 기준/수정 예측을 비교한다. 기존 seed47 RM 유지/완화와 독립 VSL 사례의 큰 손익 방향·대기 비용을 유지하는지도 확인한다. 단지 가짜 포트 만차가 줄었다고 이득 보정 성공으로 판정하지 않는다.

이 진단에서 계수 후보 탐색을 추가하지 않았다. 기존 9000초 STOP, 선택망, 신호, 제어 범위, 목적함수, 생산 보정값은 유지했다. 새로운 이득 검증이나 SDMPC 9000초 실행의 선결 조건이 통과한 상태는 아니다.
