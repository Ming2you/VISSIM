# Claude 큐·도착량 수정 기록 대조 — 2026-10-02

사용자 요청: 새 문제의 수정에 착수하기 전에 Claude의 기존 진단·코드·검증을 먼저 확인한다. 이 순서를 AGENTS.md 첫 항목에 저장했다.

## 결론

Claude는 U7에서 같은 계열의 문제를 이미 분리했다. 현재 큐, 접근 중 차량, 도착 시각, 목적지별 구성의 정합을 먼저 확인하는 방향은 재사용할 가치가 있다. 다만 U7은 하네스 시험이고, 현재 문제인 71번 도로의 차로 모델에 그대로 적용한 검증 결과는 아니다. 새로운 차로 선택 후보를 먼저 실행하지 않는다.

## 확인한 수정과 검증의 범위

- 출처: `claude/repin-v3c3-20261001`의 bd39205, 로컬 사본 `upstream_worklog/02_urban_b2/diag_c3_r2/{U7,C3V2_PROPOSAL,C3V2_CHECK}.md` 및 묶음 README.
- **U7a: 도착 시각.** 이동 잔차 +15초, 정지 잔차 +105초와 게이트 일괄 약34초 대신 현재 차량 위치에서 정지선까지의 거리와 관측 속도로 ETA를 만든다. 예측 지평 이후 차량도 보존한다.
- **U7b: 구성.** 정지선 큐를 링크 검지기 가중치로 분할하고 잔차를 도착 시 다시 β로 나누던 대신, 차로 접근 가능성으로 movement를 귀속하고 이동 중에도 태그를 유지한다. 다른 모듈이 소유한 재고·예약에는 중복 적용하지 않는다.
- **보고된 효과, 이번 재실행 아님:** v3b-s31의 SC1004|S(링크66, 약2.66km)에서 재고 MAE 52.5→6.3대, 150초 방출 편향 +53.4→−0.9대. 독립 검토 문서도 해당 접근로의 개선을 확인했다.
- **한계:** 전체 C3 v2 묶음은 여전히 관문을 통과하지 못했다. U8b의 이득은 관측 정의에 따라 부호가 바뀌며, 링크127의 큐 과대·이동 재고 과소가 서로 상쇄하는 문제도 남았다. 총재고만 맞는 것을 큐·도착이 맞는 것으로 평가하면 안 된다.
- **구현 상태:** U7 문서는 `u7_arm.py` 메모리 패치라고 명시한다. bd39205의 추적 파일에는 해당 하네스가 없고, 제안서 §2도 설명이며 구현 전이라고 명시한다. 원 하네스의 실제 소스·원자료를 이번에 독립 재현한 것은 아니다. STAGE6의 구현된 U6 램프 분기 ETA와 일반 U7을 혼동하지 않는다.

## 현재 코드와의 차이 — 읽기 전용 확인

1. `vissim_stackelberg_adapter.seed_urban_arrival_buffer`는 현재와 bd39205의 AST가 동일하다. +15/+105초 상수도 양쪽에 남아 있다. 현재 retained10638 설정은 `urban.arrival.seed_from_residual=true`, `conservative_initial_transit=true`이다. 따라서 일반 잔차 도착 경로는 U7이 고치려던 방식이 남아 있다.
2. 현재 큐 귀속은 `head_phase`와 명시적 head-lane 계약을 사용한다. Claude의 옛 검지기 가중치 투영과 전부 동일하다고 말할 수 없다.
3. 문제 구간 126→10641→71은 별도 물리 차로 모델이 소유한다. `lane_plant_runtime.initialize`는 현재 위치·차로·경로에서 초기화하고, 해당 재고를 이전한 뒤 기존 arrival/release 버퍼를 비운다(현재 소스 326–346, 348–385행). 따라서 **이 구간의 현재 오차를 +15/+105초 식 탓으로 바로 확정하거나 그 위에 U7 예약을 추가하면 안 된다.**
4. 앞선 REVIEW57에서 실제 상태로 재초기화하면 같은40초의 lane2 방출이 16.33→10.36–10.87대(실측8대)로 변했다. 큐·차로 구성의 전파 오차가 있다는 근거이며, 잔여 서비스 오차도 남는다. 이는 Claude의 링크66 실험과 다른 구간·망·진단이다.

## 이후 적용 순서

먼저 일반 도시 접근로에서 U7 방식의 도착 ETA·movement 태그가 실제로 필요한 소유 구간을 확인한다. 물리 차로 모델이 이미 소유하는 71 등에는 별도 도착량을 중복 생성하지 않는다. 두 경우 모두 같은 관측 정의로 정지선에서 서비스 가능한 큐, 이동 재고, 향후 도착, 실제 방출을 각각 검증한다. 확인 후 필요한 부분만 수정하며, 총재고 오차의 상쇄나 특정 접근로 개선을 전체 제어 이득 검증으로 확대하지 않는다.

이번에는 문서·코드 대조만 수행했다. 새 예측·보정·VISSIM·push는 없다. 실행 전 보관했던 lookahead 후보는 시험하지 않았고 원 소스로 복원돼 있다. 운영 소스와 STOP의 기존 핀은 별도 verification JSON으로 확인한다.
