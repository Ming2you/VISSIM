# 10682 접근부: 차로와 목적지 재고 연결의 첫 단계

2026-10-02 / REVIEW47. 현재 관측의 차로별 목적지 재고 초기화와 보존 검증을 구현했다. **차로별 동역학·수락 유량 전달은 아직 연결되지 않았고, 예측 개선이나 제어 이득 검증을 완료한 것은 아니다.** 기본 물리 예측·계수·망·수요·목적함수는 그대로다. 전체 목표 ACTIVE / NOT_QUALIFIED.

## 기존 결과를 재사용한 판단

10682 진입 과다의 차량 집단 분해는 이미 REVIEW42 `entry10682/README.md`에 있었다. seed43의 신규10682행은 확인된 인원144대 대 모델149대지만, 진출56대 대82.29대, 본선 잔류88대 대66.71대였다. 배수율이 아니라 접근부 체류·도착 시점이 주요 조사 대상이다. seed47은 같은 감소 보정을 적용하면 안 된다.

REVIEW43의 셀11 FD 후보는 셀11 속도만 개선하고 seed47 셀10 회복을 망쳤다. REVIEW44는 같은 셀의2차로 저속과3·4차로 통과가 공존함을 확인했다. 단순 FD 격자나 이미 완료한 경계 분석을 반복하지 않고, 기존 차로별 상태 모델과 목적지 재고 모델의 연결로 방향을 옮겼다. `lane_freeway_runtime.initialize_route_inventory`, v2 로더, `PhysicalLaneGroups`는 현재 이 조합을 거부하므로 플래그만 켜지 않는다.

## 이번 소스 변경

`evaluation/controllers/offramp_routing.py`의 기존 `initialize_inventory`에 선택 인자 `lane_partition`을 추가했다. 해당 관측의 차량ID별 물리 차로 그룹과 셀별 그룹 수를 받아, 기존 경로 분류를 그대로 차로별로 나눈다.

- `lane_cells`는 기존 `cells`의 목적지별 분할이며 별도 차량 재고가 아니다.
- 현재 확정 경로, NULL 경로의 기존 미래 선택 기대값, 이미 놓친 출구의 censored 경로 규약을 그대로 사용한다.
- 경로별 차로 합이 기존 셀 재고와 같아야 한다. 총 대수만 같고 목적지가 바뀌는 경우도 실패한다.
- 전체 본선 차량ID 누락·그룹 범위 오류·음수 질량·현재 시각과 다른 관측을 거부한다.
- 차로 분할 상태에 기존 aggregate `advance_inventory`를 호출하면 명시적으로 실패한다. 아직 연결되지 않은 차로 재고를 무시하고 예측 성공으로 처리하지 않기 위한 가드다.
- 기본 호출에는 lane 분할을 만들지 않는다. 기존 생산 설정이나 controller에 이 선택 인자를 연결하지 않았다.

기존 파일 안에서 초기화·검증·가드3개 함수만 수정했다. 나머지17개 함수는 AST가 같다. 새 runner/adapter는 만들지 않았다.

## 실제 관측으로 검증

seed43의2250/2700초, seed47의2700/3150초, 네 완전 관측을 사용했다. 각 시점의 현재 COM frame 경로를 기존 `bind_current_routes`로 붙였고, 네 자료의 망 SHA는 모두 선택망64cf5f55…와 일치했다. 미래 궤적을 예측 입력으로 넣지 않았다.

동측31셀 중9–12만 기존 차로 그룹 규약(1차로/2차로/3차로 이상)으로 나누고 나머지는 합쳤다. 서측은 기존 셀 그대로 합쳤다. 그룹별 실제 관측 차량 수와 경로별 분할 합이 모두 일치했다. 총 본선 재고는 각1648/1776/1640/1531대로 유지됐다.

검증8개가 통과했다. 기본 초기화는 변경 전 소스와 네 상태에서 재고·metadata가 정확히 같다. 기존 수락 유량에 따른 목적지 전달120스텝도 변경 전과 정확히 같다. 이120스텝은 **합성 수락 유량으로 재고 전달을 검사한 것**으로서 실제 METANET rollout·교통 결과 동등성 검증이라고 부르지 않는다.

## 남은 연결과 다음 검증
