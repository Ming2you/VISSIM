## 왜 수용식을 시험했나

현재 공유 차로 후보는 셀21에만 FD 기반 혼잡 수용율을 적용한다. 셀19 입구는 다음1초의 jam 저장 여유가 주 제한이다. 초기 셀19 1차로는 평균속도4.36km/h인데 모델 유입이 과했으므로, 이미 쓰는 수용식을 이 위치에도 적용하는 가설을 검토했다.

**동결132의 계수를 바꾸지 않고** 셀19와21에 동일한 기존 법칙을 적용했다.

`Q_i = rhoCrit_i * vFree_i * exp(-1/a_i)`

`w_i = Q_i/(rhoJam-rhoCrit_i)`

`R_i,g = min(Q_i, w_i*(rhoJam-rho_i,g), physical_space_i,g/dt)`

수락되지 않은 차량은 상류에 남는다. 목적지별 재고·총 차량 보존, 속도식, 합류 감속, 기존21 수용·10483 공유 FIFO, 동적 진출 저장·배수, 램프 대기 및 VSL 이력은 유지했다. 고정 용량 보너스나 명령별 보상은 없다. 실제 구현 변경은 기존 클래스의 허용 수용 셀 목록과 실행 spec의 `[21]→[19,21]`뿐이다. `plan`·`speed`·`ramp_supply` 등 다른 클래스 메서드는 AST가 같다.

기존107은19→20 경계의 수용20,124는20→21의 수용21을 시험했으므로 위치가 다르다. 과거 `lane_inlet67`·`lane_joint67`의 미래 실제 유입 제공만으로는 실패했던 결과, `lane_dn67`의 미래 하류 차로 밀도 조건부 진단도 읽고 재실행하지 않았다. Claude `REVIEW_CHECK`의 다른 망/계수/수요에 대한 한계를 유지했다. 다른 망의 수치를 옮기지 않았다.
