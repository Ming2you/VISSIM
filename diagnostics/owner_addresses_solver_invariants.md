# Address unit validation and the next three solver invariants

The unapplied candidate passed all **10 unit tests** in 0.031 s (isolated process wall 0.223 s). Results and before/after source pins: `owner_addresses_unit_validation_v1/result.json`; full unittest log: `owner_addresses_unit_validation_v1/stderr.txt`. Source changes were empty. Tests imported the actual `ControlAction` class and writer DSD helper, but built only the small address fixture: no traffic rollout, MPC, COM or VISSIM. Runtime, drivers, fixtures and the production target remain unchanged.

The address helper is necessary but leaves these three checks for canonical solver integration:

1. **One realized command must reach the local score, Ω score and writer.** After a copied candidate passes canonical `signal_actuation_contract.project_vector`, `written_offset_sec`, VSL head expansion/`segment_vsl` and `area_meter_finalization.finalize`, compare full realized values and physical CSV row identities/values with the scored candidate. `assert_owner_transition` checks numerical addresses only: it does not validate alias consistency, green budgets, offset wrapping or meter schedules carried in diagnostics. Include the physical meter commands/finalizer context in the command fingerprint; preserve non-owner commands after realization. Recheck writer assertions on that fingerprint. Any later guard/refinement/box-walk change invalidates its score and final certificate rather than retaining a stale marker.

2. **Every comparison uses the same fixed payoff and operational reference.** Freeze prices/references/weights/active channels, leader quantities/λ/ω, cfg/forecast/initial state and each round's operational inputs. Candidate queries clone `_prev_coupling`, Wu off-ramp caches and phase/refinement setup state; a query cannot commit its proposed updates into the next query. The address helper intentionally does not inspect these non-lever fields. Both price production and best response must use the same held joint action for `L_i`; compute marginal correction from matched `ΔJΩ−ΔL_i`, then charge local cost, active external-price channels and declared quantity terms once. Do not internally reoptimize VSL during a held-meter partial, double-charge scalar-green and phase-vector terms, or substitute JΩ for each owner's local payoff. Test repeat/permutation and exception paths before adding the game loop.

3. **One candidate-dependent physical allocation and a complete final deviation check.** Reuse the canonical coupled transition to spend each shared head/receiving budget once, preserving ready stock and accepted-transfer conservation. Fix non-owner controls, not their previous accepted discharge; congestion clipping is a physical response, not automatically an infeasible strategy. Re-score affected local interfaces/quantities after combining owner proposals. Check declared N_P/N_UF policy on realized quantities with their original units; an empty quantized equality domain returns infeasible, not a rounded target or zero residual. At the final incumbent, use the same fixed payoff/context to evaluate every admitted unilateral joint neighbor and report all 19 gaps. Missing resource correspondence, inconsistent local/coupled flow, incomplete enumeration or any later command/context change yields an uncertified result, not equilibrium.

These are integration requirements, not additional functionality already implemented by `joint_owner_addresses.py`. They follow `fixed_candidate_price_direction_design.md`, `joint_owner_shared_feasibility_design.md` and `joint_owner_neighbor_interface_draft.md`; the existing candidate domain, local-plus-marginal-price structure and physical constraints remain the reference. No new adapter or configuration change is proposed by this note.
