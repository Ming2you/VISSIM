# Evaluation trace v2: local candidates and a monitoring transport

The proposal is ready for root's integration review. Production, the running v1 tracer, its bootstrap, and the launcher have not been edited. This is a diagnostic observer; it neither replaces a model callable nor requests an extra endpoint. The final focused run passed 11 tests in 3.226 seconds; the preceding combined run passed the new 11 plus the original 10 tests in 5.048 seconds. These are synthetic/fresh-spawn and source-discovery checks. An actual installed MPC trace is still required before claiming coverage of its complete executed candidate stream.

Apply `diagnostics/evaluation_trace_v2.patch` only after reviewing it. It changes two diagnostic files: the old recorder's final writer delegates to `evaluation_trace_finalize.finish`, and the bootstrap selects the requested backend/local companion. It does not touch the launcher. The default remains the original profile backend without local records. For v2, the launcher should set `RW_EVALUATION_TRACE_BACKEND=monitor` and `RW_EVALUATION_TRACE_LOCALS=1` along with its existing evaluation-trace directory/manifest variables. Clear these two new variables from inherited environments in every other mode. Continue rejecting simultaneous phase trace, cProfile, or normal resource-counter mode.

Add four helpers to the launcher's diagnostic source pins: `evaluation_trace_local.py`, `evaluation_trace_monitor.py`, `evaluation_trace_finalize.py`, and `evaluation_trace_state.py`, in addition to the existing v1 recorder/bootstrap/launcher pins. At completion call `diagnostics.evaluation_trace_local.collection(directory, root_pid=process.pid, expected_child_pids=owned)`. This validates the original collection and every corresponding local sidecar. It returns both the unchanged v1 comparison hash and the additional local/operational comparison hash. Preserve both. An unchanged final action is not a replacement for local-candidate equality.

The transport uses CPython 3.12 `sys.monitoring`: global `PY_START` discovers code once, unselected locations return `DISABLE`, selected code gets local `PY_RETURN`, and only six counter-bearing functions get local `LINE`. Non-counter lines also return `DISABLE`. There are no builtin call callbacks, no global `sys.settrace`, and no `sys.setprofile` during model execution or shutdown. `PY_UNWIND` is necessarily global and is filtered. The callback reads the callee frame and checks `frame.f_code is code`. A selected function first called from another thread is armed before the main-thread filter, so that thread cannot accidentally disable the later main-thread observation. This remains explicitly main-thread evidence in each process; foreign-thread counts are exposed. Normal benchmarks remain separate.

The backend validates its real tool name, enabled global events, absence of competing profile/trace hooks, and each registered callback on removal. It then disables local/global events, unregisters callbacks, and releases the tool identifier. The common final writer takes this explicit backend owner. It never temporarily installs a profile hook to satisfy the old check. Source changes, callback/frame mismatch, exception unwind, serialization failure, unmatched calls, missing sidecars/snapshots, or candidate-counter mismatch prevent a valid collection.

The companion observes 26 exact source/qualified-function targets, discovered by read-only AST traversal. The current source has 15 complete-cost counter points: green, joint green/offset, ordinary offset, ramp offset, canonical link VSL sequence (one each), and ten metering seed/trial branches. Counter observations occur after all terms used by that branch and before its winner update. For metering, AST binds each counter to its actual preceding `_solve_with` assignment, selected meter vector, VSL result, score variable and nested evaluation count; no absolute source line is used to guess the branch. The sum of nested VSL counts must equal the function's final `evals_total`. Green/offset/VSL candidate counts must equal their final `evals`.

| Recorded layer | Input and result evidence |
| --- | --- |
| Urban candidate | Actual p1/offset/green vector, exact complete score, and actual green/arrival profile references |
| Phase candidate | Actual `scored(vec)` input and returned local-plus-price score, including local/ext/weight components |
| Joint phase candidate | Actual group/control and `_J()` return; enabled adapter path only |
| VSL sequence candidate | Complete horizon sequence, first vector, actual final scheduled control, and final cost including price/smoothness terms |
| Meter candidate | Actual meter map, nested selected VSL, complete branch score and nested evaluation count |
| Local price query | Ordered requested candidate groups and returned score lists; result cardinality must match each request |
| Local physical component | Actual derived model fields, queues, arrival/receiving/green profiles and ready seed, with the original returned component cost |

Components, complete candidates, and query results are different nested levels and must not be summed as separate evaluations. Filtered candidates that never reach a score point are not falsely marked evaluated; query requests returning explicit placeholder scores remain distinguishable from actual rollout children. Legacy freeway local/segment candidate bodies are outside the installed canonical link-agent contract and explicitly invalidate local coverage if reached. Source target/line inventory is in `evaluation_trace_v2_validation.json`.

The original v1 stream is not renumbered or augmented. Local rows have their own call order and a reference to the enclosing v1 call. Local snapshots are content-addressed with lossless typed-key/float-hex encoding and validated on collection. Parent order is retained. Worker local/operational descendants are grouped using the same v1 task key and normalized within the task; PID assignment/completion order are excluded, duplicate task multiplicity is retained.

Operational before/after snapshots additionally preserve follower `_prev_coupling`, standing lambdas and N_P corrector memory, segment trajectory, phase activation/override/context state, and nested `WuDistributedController` `_last_offramp_flow`, `_has_last_offramp_flow`, `_omega_p`, `_omega_f`. The link predictor updates the flow cache even during local price queries; it is an input to later frozen arrivals, not disposable timing data. Actual passed coupling and prices/ref/trust/weights are also retained. Outer previous/PFO center/cached evaluation, refresh step, link-share context and N_UF response cache have explicit handling. Cached evaluation snapshots retain scores/actions/Nash controls/convergence/residuals and the five exact diagnostics consumed by the existing fallback guard. `_signal_price_meta` is output/refresh-report data, not a branch input, and is not added to operational state. Its resulting decision output is checked separately by the existing preservation comparator. No generic `cache` or `timer` name filter exists.

The current density-based link-share setup makes `_omega_f` operational; the later `search` branch is dormant in the current configuration. Standing-lambda/corrector state is not described as frozen across all logical solves: the active leader and PFO branches differ. This instrument records what each boundary actually received and left behind. New configuration lookup-cache fields are not automatically excluded; any comparison allowance still requires a separate explicit cache-only proof.

Validation includes no-trace/profile/monitor stdout and return equality; identical v1 and local comparison streams across both tracing transports; parent plus two fresh workers/four task keys; complete green/phase/meter scores; omitted candidate filtering; exact metering counter bindings in real source; exception propagation and invalidation; first foreign-thread call followed by main; callback ownership tampering; missing/tampered snapshots; and a changed off-ramp flow memory that changes the local comparison despite an identical final result and unchanged v1 hash. Repeated unselected arithmetic calls also confirm their discovery location is disabled. No timing speedup estimate is inferred from these tests.

The monitoring behavior follows the official [Python 3.12 monitoring API](https://docs.python.org/3.12/library/sys.monitoring.html) and [PEP 669](https://peps.python.org/pep-0669/). Both specify callee-stack start/return events, interpreter-wide event ownership, per-code local events and `DISABLE`; the implementation checks the frame and thread behavior explicitly.
