## 계산 변경과 검증 범위

1. 같은 decision의 명령 검증 결과만 재사용한다. 행동·문맥·writer binding 변경은 캐시 적중으로 취급하지 않는다. 캐시 결과는 독립 복사하며 최대256개로 제한한다.
2. 아직 평가하지 않는 FW 후보의 전체 CSV 생성은 실제 점수 계산 직전으로 미룬다. 기존63개 후보의 행동값과 순서를 모두 비교해 일치를 확인했다. 방향별 후보 생성/검증 구간은 10.713→3.486초, 11.040→3.488초였다. 전체 decision 단축률이 아니다.
3. 누적 transfer/resource/state-bound 검증 기록을 각 coupled interval 뒤 변경 불가능한 바이트로 저장해 다음 상태 복사의 비용을 줄인다. 교통 상태와 모델 연산은 유지하며 응답을 꺼낼 때 전체 기록을 복원한다. 기본 OFF인 명시적 config 옵션이다.
4. packing OFF/ON 두 행동에서 각각 약203만 응답 값의 정확한 타입·부동소수점 비트·행 순서, 가변 객체 공유 관계가 일치했다. 모든 물리 상태와 ledger 동적 상태, Ω 목적값 및19개 owner 비용도 일치했다. 문자열 객체의 메모리 공유 형태는 달라지므로 내부 pickle 바이트까지 모두 동일하다고 주장하지 않는다. packing ON의 serial/spawn 결과와 원본 응답 토큰은 정확히 일치했다.
5. `round_robin_balanced`는 FW_W→SC1→FW_E→SC5… 순서로 제한 시간 내 두 계통을 먼저 평가한다. 이것은 **탐색 순서 변경**이며 순수 속도 최적화와 구분한다. 후보 영역·고정 박스는 유지한다.

관련188개 검사 PASS. 파라미터 검사 PASS(기존 calibration override 경고는 남아 있음). 결과 보존 검증과 마감 준수는 통과했지만 공통 가격 계산은 여전히 큰 비용이다. 시간 만료 시 이미 검증한 행동만 출력하고 gap은 null로 남긴다. SPSA는 앞선 동일 상태 실험에서 가격 오차가 커 채택하지 않았다.

## 실제 VISSIM 결과

첫 폐루프 런 `codex_physical8_fw080_u050_band5_v1`은 **실패**했다. 900초의 실제 decision은111.967초에 기존 명령을 유지하는 결과를 냈다(공통 가격80.508초, seed 예측5.353초). SC5 변경을 평가하기 전에 FW 후보 생성에서 마감에 도달했다. 이 런에서 선택 SC5의 교통 효과를 검증한 것으로 처리하지 않는다.

시뮬레이션은1050초까지 진행했으나 runner가 종료 시점에도 다음 decision을 계산했다. 이때 공통 가격 계산이 마감에 도달했다. 현재 관측으로 예측한 합류량2034.526038 veh/h는 이전 목표1887.525931보다147.000107 veh/h, 즉450초당18.375013대 많았다. ±5대뿐 아니라±10대도 벗어난다. 이미 검증한 현재 목표의 실행 가능 행동이 없어 `no_validated_response`로 실패했다. 전체 종료 검증도 FAIL이며 성공한 비교 런에 섞지 않는다. owned VISSIM은 종료됐고 실패 산출물은 보존했다.

또한 hold 검사에서만 남아 있던 동·서50:50 제약을 제거했다. Physical8 본 game과 동일하게8개 램프 예측 합계만 검사한다. 기존4그룹 모드는 보존하며 총합 N_UF 제약은 계속 검사한다. 관련 검사28개 PASS, 추가 profile/physical/hold 검사27개 PASS. 이 수정만으로 이전 목표의18.375대 불일치가 해결되지는 않는다.

새 시점마다 관측 기반 초기 N_UF 목표를 먼저 설정하고 탐색 중 고정할지, 계산 만료 시에도 이전 목표를 유지할지는 사용자에게 확인 중이다. 답변 없이 목표를 옮겨 실패를 성공으로 바꾸지 않았다.

별도 고정 재생 `codex_physical8_fw080_u050_band5_replay_v1`은 완료·종료 검증을 통과했다. 저장 상태에서 선택한 SC5 명령과213개 순서 있는 물리 CSV 행이 정확히 같음을 사전 확인했다(숫자 표기만 Decimal로 정규화, writer 모드 설명 metadata는 별도). 기존 diagnostic profile에8개 물리 SG의 기록된 녹색을 읽는 경로만 연결했다. preflight v1은 해당8개 녹색 부재로 실패했고, v2는통과했다. 새로운 adapter나 runner를 만들지 않았다.
