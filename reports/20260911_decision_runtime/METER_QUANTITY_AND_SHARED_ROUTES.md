# 미터 대수의 의미와 실제 경로 초기화 검증 — 2026-09-11

## 현재 실행의 대수 의미

현재 미터는 10초 주기 중 지정된 녹색 시간 동안 통행을 허용한다. 차량 한 대가 정지선을 통과하면 닫는 방식이 아니다. `scripts/run_real_world_stackelberg_controller.vbs`의 `RampStateAt`과 `ApplyRampMeterSignal`은 시간과 녹색 명령만 사용하며 누적 목표 대수와 실제 통과 대수의 오차를 사용하지 않는다.

`evaluation/controllers/vissim_stackelberg_adapter.py`의 `_measured_meter_allocation`은 차로별 녹색 방출표와 수요 힌트로 녹색 조합을 선택한다. `rw_meter_realized_*`는 그 계산 결과이며 실제 통과 대수 측정이 아니다. 특히 개방 상태에서는 모형 요청값을 유지한다. 과거 관측 통과량은 희망 목적지 수요를 직접 나타내지 않는다.

누적 대수 추종을 추가한다면 각 물리 미터 i에 대해 목표 누적량을 `Q_i += r_i * dt / 3600`으로 계산하고, 실제 정지선 통과 누적량 `C_i`와 오차 `Q_i - C_i`를 비교해야 한다. 예를 들어 300대/h의 150초 목표는 12.5대이며, 정수 반올림을 구간마다 버리지 않고 누적해야 한다. 이는 설계 설명이며 현재 구현된 기능이 아니다.

충분한 차량과 하류 수용 공간이 없으면 목표를 달성할 수 없다. 사용자가 지정한 녹색 변경 최대 2초, 10초 주기, 신호 반응 지연과 두 차로의 동시 통과도 구간별 정확한 대수 일치를 제한한다. 수요 부족이나 하류 차단 때문에 생긴 미달분을 무한히 쌓아 나중에 한꺼번에 방출하는 설계는 피해야 한다. 소수 대수의 반올림 잔차와 달성 불가능한 미달분은 구분할 필요가 있다.

미터 정지선 통과량과 고속도로 합류량도 구분한다. 두 경계 사이 차량 수가 변하면 같은 150초 구간의 두 통과량은 다를 수 있다. 램프별 목표·실제 정지선 통과·본선 합류·잔여 차량을 각각 대조해야 한다. 램프 합류는 Ω 내부 이동이므로 Ω TTD에 추가하지 않는다.

## 실제 경로를 유지하는 초기화 수정

기존 shared69 초기화는 현재 차량이 이미 선택한 경로를 사용하지 않고 모든 차량을 native1134의 12:1:3:0.25 비율로 분할했다. 선택적 설정 `urban.shared_approach_observed_initial_routes=true`에서는 완전한 현재 차량·경로 관측으로 확인된 STATIC1134 branch1..4를 그대로 보존한다. 아직 decision 이전에서 경로를 선택하지 않은 차량만 기존 비율을 모형 기댓값으로 사용하고 별도로 표시한다. 미래 수요와 경로 비율은 바꾸지 않는다.

실제 open_v2의 900초 관측은 branch1/2/3/4가 각각 20/1/1/0대이고 경로 선택 전 차량은 1대다. 1050초에는 21/1/7/2대와 선택 전 1대다. 전체 shared69 재고는 각각 23대와 32대로 보존된다. 16개 집중 검사가 통과했고, 설정 부재/false의 기존 초기화 결과는 변경 전 코드와 같음을 확인했다.

## 8개 분리의 완료 범위

`RAMP8_MAPPING.*`은 물리 connector와 직접 연결된 접근 link, 실제 합류 cell을 램프별로 확인한 자료다. `METER_BRANCH_OBSERVATIONS.*`는 900/1050초의 관측 분류, `METER_BRANCH_WINDOWS.*`는 별도의 무제어 9000초 기록에서 형성·첨두·회복의 세 구간을 읽은 결과다. 현재 production 동역학과 follower 미터 전략은 아직 4그룹이므로 8개 분리가 완료됐다고 해석하면 안 된다.

무제어 9000초 세 구간은 기존 색인으로 약57.45MB만 읽어 2.411초에 집계했다. 본선 첨두 정체가 모든 ramp connector의 정지 대기를 뜻하지는 않았다. 이 통과량으로 상류의 희망 수요를 대체하지 않는다. 이 기록과 open_v2는 warmup부터 완전히 같은 궤적이 아니므로 두 결과를 서로의 엄밀한 처리 효과 비교로 사용하지 않는다.

RED/GREEN만 사용하고 150초 결정 간 실제 녹색을 최대 2초 바꾸는 것은 사용자가 승인한 다음 규약이다. 누적 대수 피드백이나 한 대씩 통과시키는 제어는 아직 추가하지 않았다. 미터 timing writer와 사후 검사 변경의 완료 여부는 별도 검증 기록으로 관리한다.

## 사용자가 제시한 RM2의 적용 범위

사용자가 이전에 사용한 `RM2`는 점유율 오차로 목표 rate를 갱신하고, 녹색 시간을 조절하는 시간형 실행이다. 시간형 미터링 자체는 사용 가능하다. 누적 대수 피드백은 미터링 구현의 필수 조건이 아니라 목표와 실제 누적량의 오차를 줄이는 추가 방법이다. 녹색 중 정지선을 통과한 차량을 적색으로 바뀐 뒤 다시 멈추게 할 필요도 없다. 다만 1초 녹색이 항상 정확히 1대의 통과를 의미하지는 않는다.

검토할 부분은 다음과 같다.

- `r_sat = ramp_demand[...]`는 도착 수요이며, 대기열이 있는 동안의 포화 방출률과 다르다. 목표 유량을 녹색으로 변환할 때는 해당 미터의 실제 녹색별 방출 관계를 검증해야 한다. 단순식 `r ≈ s * g / C`도 충분한 대기 차량, 하류 수용, 출발 손실 등을 가정하는 근사다.
- 녹색 계산의600초와 전환 검사의 `time_interval_MV`가 같을 때만 시간 단위가 맞는다. 실제 미터 주기가10초라면600을 그대로 쓸 수 없다. `g >= C` 또는 음수이면 특정 시각과 같다는 조건으로 적색 전환을 놓칠 수 있다.
- 현재 정본은 상태를 `t % 10 < g`로 정하고 다음 전환 시각도 같은 함수에서 구한다. 이를 유지하면 중간 관측을 건너뛰는 실행에서도 필요한 전환을 예약할 수 있다.
- 유효한 점유율0과 관측 오류는 다른 상태다. `/3`의 의미와 `Criocc`의 단위, rate 상하한은 확인이 필요하다. 사용자 코드는 `r_sat != 0`을 확인하므로 수요0에서 무조건 나눗셈 오류가 난다고 진단하면 안 된다.
- 해당 점유율 제어식을 follower game 대신 넣는 변경은 하지 않는다. 현재 검증 대상은 같은 game 명령을 실제 미터에서 실행하는 방법이다.

[FHWA 램프 관리 지침](https://ops.fhwa.dot.gov/publications/ramp_mgmt_handbook/manual/manual/5_1.htm)도 한 녹색에 한 대 또는 여러 대를 방출하는 운영을 구분한다. 현재 망의 실제 방출량은 이 일반 설명만으로 보장하지 않고 native 기록으로 확인한다.
