# 새 제어 주기의 N_UF 초기화와 실행 검증 — 2026-09-11

**이전 목표를 다음 주기에 그대로 적용해 실행이 중단되던 문제를 수정했고, 실패 상태 재현과 실제1050초 폐루프 실행이 모두 통과했다. 물리 제어는 이번 런에서 그대로였으며 교통 개선은 달성하지 않았다.**

사용자의 “계속해줘”를 새 주기 시작에 현재 관측으로 N_UF 초기 목표를 갱신하고, 그 주기의 탐색에서는 고정하는 방식의 승인으로 반영했다.

## 수정한 동작

- `control_area_objective.refresh_nuf_target_each_decision=true`인 물리 8램프 구성에서만 사용한다. 기존 설정은 기본 OFF다.
- 현재 관측·450초 예측 수요와 **이전에 실제 실행한 명령**으로 8개 램프의 예측 본선 합류량을 계산한다. 합계 대수를 ×3600/450으로 환산해 이번 주기의 N_UF 목표를 초기화한다.
- 목표를 바꾼 전체 행동은 별도로 다시 예측한다. 이전 응답의 action token을 바꿔 재사용하지 않는다. 두 예측의 문맥·합류량과 19 owner의 물리 명령 토큰이 같아야 한다.
- 이후 leader seed와 follower 후보가 공유하는 N_UF 목표는 고정한다. 후보별 서비스율이나 유리한 예측값으로 다시 목표를 옮기지 않는다. N_P 후보/기존 cap, 녹색·offset·VSL·8미터 후보 영역과 실제 실행 행동 기준 변경 폭은 유지한다.
- 공통 외부 가격의 기준 행동은 실제 이전 실행 명령으로 유지한다. 새 주기 초기화가 가격 기준점이나 실제 명령을 움직이지 않는다.
- 비싼 가격 계산 전에 현재 목표에 대한 유지 행동의 모델·제약·writer 실행 가능성을 확인한다. 가격/탐색 시간 초과 시 이 증거가 완전할 때만 명령을 유지한다. 모델 오류, 누락, N_P 위반을 성공으로 감추지 않는다. 이 반환은 Nash 해가 아니며 gap은 미확인으로 남긴다.
- 최종 writer 검사에 남아 있던 물리 8램프의 잘못된 동·서 50:50 조건을 제거했다. 구형 4그룹의 조건은 유지한다. 물리 8램프는 사용자 정의대로 예측 합류량 **합계**를 검사한다.

고속도로80%·도시50%·seed13, 망/수요, 150초 제어, 450초 예측, beta=0, N_UF 허용폭 ±5대/450초(±40대/h), 전체 결정120초/출력 여유10초는 유지했다. 이번 수정은 목표의 주기 간 갱신 정책 변경이며 순수 계산 속도 개선으로 분류하지 않는다.

## 교통 결과와 공간 확인

900–1050초 Ω(고속도로+도시 protected network) TTT **47.952778veh·h**, TTD **464건**, 영역 재고1,034→1,240대다. 기준 런과 동일하다. TTD는 살아서 Ω 밖으로 이동한313건+검증된 망 종점 유출151건이며, Ω 내부 램프 이동은 제외했다. 관측에서 사라진6대는 TTD에 포함하지 않았다. 그중2대는 native 오류 기록의 차로 변경 삭제와 일치하고4대는 미해결이므로 `TD_requires_review=true`를 유지한다.

집계치만 비교하지 않았다. 8개 램프의 진입·정지선 통과·본선 합류·재고·정지시간·차로 변경, SC5의30초별 도착/정지/방출과 실제 녹색 창을 대조했고 모두 기준과 같았다. 램프 본선 합류 합계는90대이며10644의5km/h 미만 정지시간은17veh·s였다. SC5 접근도로1220018401의 정지355veh·s/최대 정지5대,1220014100은171veh·s/7대,Ω 밖1220019201은675veh·s/12대였다.

따라서 앞선 SC5 offset 이동에서 확인한 “후속 platoon 도착 전에 green이 끝나는 문제”를 이번 결과로 해결했다고 볼 수 없다. 이번에는 그 변경을 실행하지 않았고 교통이 완전히 같았다. 1050초 최종 명령 이후의 교통이나 첨두·회복 성능은 이 짧은 런에서 검증하지 않았다. 기존 network/simulation ERR와 run 소유 `VISSIG_Controller.dll.err`도 보존했다.

## 남은 일

1. 공통 가격78개 응답과 FW 후보 생성 비용을 줄여 실제 후보 탐색 시간을 확보해야 한다. 이번 결과는 N_UF의 주기 간 오류를 해결했지만 계산 병목을 해결하지 않았다. 동일 기록 상태에서 응답/가격/명령을 보존하는 변경부터 검증한다.
