# Snapshot 관측의 의미 검사

`diagnostics/test_meter_branch_snapshots.py`의 8개 검사가 모두 통과했다. unittest 본문 0.035초, Python 실행을 포함한 명령 경과 0.314초다. 새 모델·COM·VISSIM·FZP 읽기나 production 변경은 없다.

- 현재 decision ID와 route ID를 함께 조인하며 현재 경로에 명시된 미래 미터만 확정한다.
- 미선택 다음 경로, 경로 없음/비정적 경로를 미확정으로 남긴다.
- 현재 link가 경로에 없거나 반복돼 위치가 모호하면 배정하지 않는다.
- 경로의 물리 연속성과 현재 위치의 구간 경계를 요구한다.
- 이미 통과한 미터와 여러 미래 미터를 상류 목적지 하나로 잘못 배정하지 않는다.
- 두 차로의 정지선 위치가 다를 때 각각의 위치로 이전/이후를 분리하며 정지선과 같은 위치는 이전에 포함한다.
- 실제 900/1050초 자료에서 10646/10681의 미확정 차량 목록이 겹침을 확인하고, 도시47행1124:2와 미선택 후속 경로1124:1을 분리한다. 중복 제거한 미확정 정지 차량은 7/2대다.
- 실제 두 snapshot의 차량 ID 조인, 물리 재고의 정지선 이전+이후 수지, 정지 부분집합, 확정 상류 차량의 현재 route binding과 중복 없음을 확인한다.

검사는 원 진단 script를 실행하지 않는다. 실제 source AST에서 locator와 정지선 분리식을 추출해 작은 경계 사례를 검사했고, 실제 검증에는 이미 저장된 2개 상태 JSON과 약50KB의 집계 JSON만 사용했다. 입력 상태 SHA와 원 진단 script SHA도 집계의 source proof와 대조했다. 현재 결과는 snapshot 분류의 계약 검사이며 전체 원점 OD 또는 도착률 예측의 인증이 아니다.
